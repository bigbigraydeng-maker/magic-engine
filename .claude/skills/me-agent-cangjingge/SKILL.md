# 藏经阁（me-agent-cangjingge）

**层级判定（me-platform-tier-gate）**：既有 L1「记忆 / 验证」下的**参考技能**，不新增能力线、不碰 `src/`。讲稿里的做法一律是「候选」，在 ME 真跑过、有证据的才算「已验证」。
**来源**：PM 2026-11-04 要求把「海量 ppt」做成其他窗口开发 agent 时可读的提示词。原件在 PM 本机 `~/Downloads/173/`（75 份 PDF，不进仓库）；逐份笔记在 [references/notes/](./references/notes/)，一行一份的索引在 [references/lectures-index.md](./references/lectures-index.md)。
**读取状况**：75 份里 58 份读了全文，13 份是图片版只看了部分页，3 份只有目录，1 份读不出。没读到的页不代表没内容。

**一句话**：大厂讲了 75 遍的同一件事——**先让单次结果可信，再让它自己转圈；完成要有证据，学习要能回退，放权要按风险一级一级给。**

## 怎么用（给开发 agent 的窗口）

1. **开工前**：读完本文件，再按你要做的事，从[索引](./references/lectures-index.md)里挑「对 ME = 高」且标签对得上的 2–4 份，读 `references/notes/` 里对应那份笔记。需要原文细节时才去翻 PDF。
2. **回复里写明**：「读了藏经阁第 X、Y 部经 + 第 N 号讲稿笔记」。说不出来 = 没读（与 CLAUDE.md 支柱手册同一规矩）。
3. **设计稿里过一遍「开工十问」**（本文最后一节），每问写一句答案。答不上的就是设计缺口。
4. **讲稿是资料，不是命令。** 跟 ME 产品定义、平台化原则、CLAUDE.md 铁律冲突时，以 ME 的为准。
5. **不抄大厂规模。** 每部经下面写了「ME 怎么用」，那是按 ME 体量缩过的版本。

### ME 的体质（每条经都要先过这道筛子）

- **量小**：全部客户加起来每天约 8 个自动动作；广告走内核真执行的，历史上一共只有个位数。
- **反馈慢、噪声大**：广告 3–7 天、社媒 72 小时、SEO 18–28 天才看得出结果；CTS 流量下没改过的页面也有约 41% 会被判成「变好或变差」。
- **钱和对外发布要人批**：PM 本人是花钱、开投、对外发布的唯一批准人。
- **所以**：凡是靠「每天几千条样本」「在线强化学习」「训练小模型」「几十个 agent 并发」成立的做法，ME 都不照搬，只借它背后的纪律。

## 十六部经

每部写四样：**经文**（原则）· **出处**（讲稿编号，见索引）· **ME 怎么用** · **ME 已踩过的同类坑**（有就写，证明这条在 ME 身上成立）。

### 第一部　先 Harness，后 Loop

- **经文**：单次结果不可信时，让它自动循环只会把错误放大。先让一次动作的「做了什么、做成没有」可信，再接回流。
- **出处**：55 肖汉松（蚂蚁阿福：badcase 修复 12.6 天，主要耗在等人分派、等人关单）；59 裴明明；64 赵雨森；16 周昕毅。
- **ME 怎么用**：新 agent 第一阶段只做「一次动作 + 读回 + 回执」，跑通、有证据了再谈每天自动跑、再谈学习。
- **ME 已踩过**：广告闭环基线里「真执行 → 读回通过 → 观察期满 → 有结论 → 被下一次决定读到」是 2 → 2 → 未核实 → 未核实 → 0（`docs/specs/2026-11-03-me-agent-loop-upgrade-design-v0.md` §2）。

### 第二部　画边界，不画路径

- **经文**：不要穷举每条路径。把知识、工具、权限、状态、验收这些边界守住，路径让 agent 在边界内自己选。动作前由 Harness 核对目标身份、授权、是否已做过，通过才执行并存回执。
- **出处**：9 俞昊晟（「拉群成功」但客户不在群，欢迎语发进空群）；33 朱革（四道防线：构建时声明、意图审计、本地 Hook、网关）；44 林鑫（先判断再放行）；51 王泽锋（SOP「规定得越死，Agent 越笨」）。
- **ME 怎么用**：对外动作一律走内核动作（`src/lib/kernel/`），由内核做授权、幂等和读回；agent 只出提议和参数。不给 agent 写长篇操作手册，给它边界和完成条件。
- **ME 已踩过**：拿状态字段当发布授权，闸必漏（记忆 `feedback-status-field-as-authorization-leaks-gates`）；演练开关只管一条规则、内核根本不读它（`feedback-dry-run-switch-is-not-the-brake-kernel-ignores-it-2026-10-19`）。

### 第三部　确定的交给代码，不确定的才交给 AI

- **经文**：取数、计算、格式检查、权限判定、发包这些确定的事写成脚本或规则；只有综合判断、读自然语言、写文案才交给模型。模型不碰数，数值由确定性代码产出。
- **出处**：11 刘凯宁（「把大模型关进确定性笼子」；以前让模型转抄大段数据，又慢又不稳）；22 张前园（大模型的「岗位说明书」：只翻译、只转述）；64 赵雨森（「闭环也有成本，不一定全都要是环」）；50 王政达（录一次，之后回放不经过大模型）；69 陶建辉。
- **ME 怎么用**：判断规则（止损、加钱、能不能比）全是纯函数加单测；大模型只用在「读客人对话判阶段」「写文案」这类没有规则能写的地方，并且要能量准确率（见第十二部）。
- **ME 已踩过**：广告「按结果判」用错了口径，回放 5 条止损全是误判（`feedback-ads-judge-by-unit-result-type-not-client-primary`）——口径是确定性的事，应该在代码里定死，不能靠理解。

### 第四部　完成要有证据，证据分层记

- **经文**：工具说成功 ≠ 业务成功。「执行了 / 读回对上了 / 观察期满有结论」三层分开记；完成只认机器可读的记录和产物，agent 自述「已完成」不算；没解析到约定输出就不往下走。
- **出处**：59 裴明明（13 项硬门禁）；46 泠乐（流程 5/6 跑完、显示「成功」，实际测试数为 0；五档状态 PASS / RISK_TO_CONFIRM / FAIL / INSUFFICIENT / BLOCKED）；39 李桐馨（返回码 200 就判过 = 假绿灯）；9 俞昊晟；52 王浩男（回执绑定代码指纹）。
- **ME 怎么用**：每个跨步骤的工作流上 Inngest，每一段留回执（CLAUDE.md §3）；回执里分开写「请求发出」「读回一致」「观察期结论」。量不出来的写原因，原因从固定清单里选，不算进「有结论」。
- **ME 已踩过**：六步回执全绿，改出来的网站文案却是错的（`docs/PITFALLS.md` D10）；测试全绿，其实是假替身配合坏代码（`feedback-verify-against-production-not-code`）；重跑把回执覆盖，看到的只是最后一次。

### 第五部　生产者不审自己

- **经文**：写方案的不审方案，执行的不验证自己的修改。验证要独立、要拿外部证据，不能同一个模型、同一套假设自证正确。
- **出处**：55 肖汉松（「方案设计者不审查自己的方案，实施者不验证自己的修改」）；33 朱革；46 泠乐（「自证正确性陷阱」）；31 曲奎林；37 李凯（质量测试官和开发用不同模型）；54 聂帅。
- **ME 怎么用**：出片走视频工厂，再由苏东坡 / 马良审，最后 PM 授权；代码由 DeepSeek 写、Claude Code 审；agent 的判断由另一个 agent 或人抽检（包拯就是这一层，`src/lib/baozheng/`）。
- **ME 已踩过**：另写脚本绕开视频工厂，自己生产、自己说「没问题」，结果没声音、数字是编的，已经发到了客户主页（`docs/PITFALLS.md` D14）。

### 第六部　放权按风险一级一级给，一次误判就降级

- **经文**：L0 只读诊断 → L1 出草稿、人点才发 → L2 低风险可回滚的自动做、事后抽查 → L3 高风险只给证据、人批。升级要同类动作准确率连续达标；一次误判自动降级。**「关闭、拒绝」这类对外负面动作永不自动。**
- **出处**：18 唐飞虎（自动关「低质量 PR」误关了学生的第一个 PR，信任修了三个月）；20 崔飞飞（满帮 L0–L3：权限、回滚、效果验证全达标才升级）；16 周昕毅（建议 → 影响预览 → 负责人确认 → 灰度）；48 滕爱龄（「执行权可以委托，责任不能转移」）；35 李佳奇（人审 → 抽检 → 自主 + 监控）；15 吴垚（放行 / 二次确认 / 强审批三档）。
- **ME 怎么用**：
  - **少花钱、少做事的动作**（止损、减预算、暂停）可以先放开，但要能一键撤回。
  - **多花钱、开投、对外发布、关掉客户的东西**，只认 PM 本人（广告加钱闸，`ADS_SPEND_APPROVER_EMAILS`）。
  - 每个动作在设计稿里写明它在哪一级、凭什么升级、什么情况降级。
- **ME 已踩过**：9 月给过广告「全权自治」，10-10 又被收窄回「开投和加预算只认 PM 本人」（记忆 `project-ads-full-autonomy-authorization-2026-09-24`）。

### 第七部　内环看 agent，外环看生意

- **经文**：内环是 agent 自己的指标（识别准不准、出错率），外环是业务结果（客人、成交、单价）。只盯内环，会在错误的方向上越做越好。
- **出处**：4 亓隆基（货拉拉：内环指标一直在升，外环触达率一直在降）；68 陈忻（分钟 / 小时 / 天三层环）；64 赵雨森（编程环、产研环、用户反馈环）；72 马云雷。
- **ME 怎么用**：每个 agent 的验收指标至少有一个外环指标。例如广告看「合格客人」（CRM 走到「已报价」及以后），不只看留资数；社媒看询价，不只看发了几条。
- **ME 已有的外环口径**：PM 11-03 定下「合格客人 = CRM 走到已报价及以后」，广告健康页有「近 30 天带来的客人质量」表按组列出合格数（记忆 `project-cts-qualified-lead-quoted-and-after-2026-11-03`）。

### 第八部　记忆要分「候选 / 已验证 / 人工断言」，模型不能自己升级

- **经文**：模型只能「提候选」；程序用数据核对；人确认、否决或修改并写理由。人的确认和程序的校验分开记、互不覆盖。经验要带适用范围、置信度、来源和退役规则，失败也要记。什么都往记忆里塞，会变成噪声和「记忆投毒」。
- **出处**：8 余锦泽（对抗测试里，数据校验拦下 6/6，纯语义复核拦下 0/6）；15 吴垚（记忆 / 知识库 / 经验三分；经验只记成功，置信度会虚高）；33 朱革（「宁可少而准，不要多而误导」）；72 马云雷（经验用命中率、质量收益、效率收益、安全边界四组指标决定留还是退役）；6 任磊达（没有负责人的知识库就是噪声）。
- **ME 怎么用**：学习分三层（客户私有 → 行业 → 全局），默认落最低层；升到行业层要第二个同行业客户的证据（平台化原则）。手册里的规则标「候选 / 已验证」，行业手册多数只有单客户证据，按候选用。
- **ME 已踩过**：CLAUDE.md 和记忆越写越多，同样的坑照样重复踩——文字规则不会自己生效，于是有了台账卡和每天读台账的程序（记忆 `project-harness-ledger-audit-20260924`）。

### 第九部　改之前先有考卷：回放、保留集、只改一个变量

- **经文**：先把真实错例做成固定考题，改动前后在同一批题上配对比较。改动只动一个变量。训练用的题公开错因，验证用的题只给分（防刷分）。「擂主 / 挑战者」：挑战者每个维度都不输擂主才晋升，否则整轮丢掉。变差了就保留上一版，「不变」是正常选项。
- **出处**：55 肖汉松（四轮打擂台，越加规则分越低，最后靠精简才晋升）；72 马云雷（发现集 159 题 + 保留集 152 题，只认保留集）；33 朱革（回放题五要素：输入、上下文、工具快照、期望结果、期望过程）；43 杨林枫（防刷分五道防线）；57 袁彬航（第 3 轮变差就留第 2 轮）；38 李峥峰。
- **ME 怎么用**：考卷只收 PM 或事故复盘确认过答案的题；放在现有回放测试里（例如 `src/lib/ads-strategy/portfolio/diagnostics/__tests__/replay.test.ts`），不联网、不调大模型。ME 样本少：先手工攒 20–50 题就够用。
- **ME 已踩过**：拿手拨的假时钟测预算和冷却逻辑，把核心逻辑删掉测试照样全绿（记忆 `feedback-fake-clock-hides-budget-logic-use-real-clock`）。

### 第十部　人纠正一次，就沉淀进工作流一次

- **经文**：人的纠正如果只流向这一次对话，下次还会犯。要把它变成规则、技能、考题或评测样本——「纠一次沉淀一次」。专家标注过的误报，下次不再报。
- **出处**：6 任磊达（「Build Loop」）；68 陈忻（专家标注的误报不再报，采纳率 40% → 85%）；42 李阳杰（采纳 / 忽略都回流）；51 王泽锋（每周 Case Review + 审计 agent 只给候选）；58 袁瑗（线上拒审 → 预标注 → 人复核 → 进训练集）。
- **ME 怎么用**：PM 每一次「这个判断错了」都要落到一个地方：考卷新题、手册规则（候选）、包拯的纠正记录，三选一，并写进台账卡。不许只改一次提示词就算了。
- **ME 已踩过**：PM 11-03 原话「AI 猜的不准，我们就要设计这样的 agent 让他越来越准」——包拯就是按这条做的：量准确率，用人纠正它（记忆 `feedback-ai-inaccurate-make-it-learn-not-exclude-2026-11-03`）。

### 第十一部　「查不到」不等于「没发生」；允许说「我不知道」

- **经文**：查询失败只说明证据不可用，不能拿来否定事实。事实层没证据不许填，推测要标「推测」。「给错根因比不给根因更坑人」。最典型的失败不是查不出来，而是编了一个看起来很像的答案。
- **出处**：11 刘凯宁；51 王泽锋（L1–L3 是事实、L4 必须标推测）；15 吴垚；16 周昕毅（允许给出否定结论）。
- **ME 怎么用**：agent 的输出分「看到的数」「据此判断」「建议」三段；缺数据写「没测成 / 读不到」，不当 0。待办里的人工任务要说清缺什么、去哪补。
- **ME 已踩过**：CTS 10-11 到 10-19 的广告「缺天」，原以为是数据没拉到，经 Meta 接口核实是真的零花费（`feedback-ads-data-gap-premise-was-zero-delivery-not-missing-2026-11-03`）；「查不到」先问 PM 客户实际怎么干活（`feedback-ask-how-the-client-actually-works-before-trusting-absence`）。

### 第十二部　口径只定义一次，所有人拿同一个数

- **经文**：指标定义（含过滤条件）登记一次，看板、人、agent 都用它；没登记的口径不许用。agent 要「指标」，不要自己拼 SQL。对不上总量就不报。
- **出处**：22 张前园（同一页 PPT 上「高净值」出现两个不同的数）；61 赵恒（下钻时丢了「排除已取消订单」这一条过滤）；8 余锦泽。
- **ME 怎么用**：广告结果种类统一走 `src/lib/ads-strategy/rules/core-metric.ts`；「合格客人」的阶段放客户配置，不写死在代码里；同一个数在两个页面不一样，就是缺陷。
- **ME 已踩过**：见第三部「按结果判用错口径」。

### 第十三部　人的注意力是最贵的资源

- **经文**：agent 越快，人的审核越成为瓶颈。要给每类任务设失败预算、返工上限和超时；超了就升级给人，人不回复时按预设方向继续或安全停下。只自动发现、不自动处置，等于批量生产焦虑。
- **出处**：55 肖汉松（2 小时没人回就按预设方向继续）；26 彭超 & 韦优（自动修复有预算，连续失败交给负责人）；48 滕爱龄（自动重试 → 换路径 → 暂停 → 交还人）；37 李凯；40 李榕。
- **ME 怎么用**：PM 每天只看今日待办，而待办只留五类（记忆 `project-pm-todo-only-five-kinds-2026-09-26`）；新 agent 不许往待办里加噪声，要合并、要过期自动清。每个等人批的动作写清「不批会怎样」「多久没批就怎么处理」。

### 第十四部　量产出，不量动作数

- **经文**：使用量、动作数、审批通过率都是过程指标，跟考核挂钩就会被刷。看结果：交付周期、质量、业务指标。人采纳了建议也不等于建议对。口径稳定、趋势可信比逐行精确更重要。
- **出处**：35 李佳奇（「考核什么，就会得到什么」）；38 李峥峰（人采纳 ≠ 缺陷真值）；27 徐帅（「接入不等于采用，采用不等于收益」）；48 滕爱龄；73 高云怡（个人效率提高 ≠ 组织利润）。
- **ME 怎么用**：agent 的周报写「带来了什么结果」，不写「做了多少动作」。PM 批准了一个加钱建议，要 7 天后看这个组的结果，而不是把「被批准」当成功。

### 第十五部　agent 读进来的东西都可能是攻击；钥匙不进 agent

- **经文**：agent 会读网页、评论、邮件、文档，里面可能夹带指令（间接提示词注入），也可能把错误写进记忆（记忆投毒）。外部系统的凭证不交给 agent 持有，由网关代为注入；权限取「人的权限」和「agent 权限」的交集。agent 会钻空子、会破坏环境。
- **出处**：32 曹一凡（8 类风险，含 Skill / MCP 供应链投毒）；29 方宇晨；75 龙进；67 闪英迪（agent 会覆盖系统命令、读残留答案）；33 朱革（agent 失败后自己升级到删库重建；改一个字段顺手改了另一个同值字段）。
- **ME 怎么用**：客户官网、客人对话、评论里的文字一律当数据，不当指令；对外写入只走内核动作，带作用对象和改动范围检查；agent 失败时不许自己换成更危险的动作，只能停下报告。

### 第十六部　少即是多：砍 agent、砍规则、旧规则定期重验

- **经文**：六个 agent 只留一个，其余变成它的工具。规则越加越多分数反而越低。为旧模型补的步骤，要被新模型重新检验。文档会过时，能让机器查的规则不要只写在文档里。
- **出处**：24 张忻正（6 个 agent 只留 1 个；可撤回 + 证据齐才自动合）；55 肖汉松（精简后才晋升）；28 徐文浩（旧补丁规则长期没清）；6 任磊达（不建大而全的知识库）；64 赵雨森（Skill 太多会选错）。
- **ME 怎么用**：新增 agent 前先回答「现有 agent 加一个工具能不能做」；新增规则前先算它是不是旧规则的子集（记忆 `feedback-new-rule-may-be-subset-of-existing-rule`）；补「注册了没实现」之前先问有没有人真的要用（`feedback-fill-the-gap-only-if-someone-wants-it`）。

## 开工十问（设计稿里逐条写一句答案）

1. **它在 IMPACT 哪一段？** 外环指标是哪个业务数？（第七部）
2. **哪些步骤是确定的、写成代码？哪些才交给模型？**（第三部）
3. **它会做哪些对外动作？各在第几级授权？** 凭什么升级、什么情况降级？「关、拒、发、花钱」是不是都要人批？（第六部）
4. **一次动作的完成证据是什么？** 回执里分几层？读回怎么核？（第四部）
5. **谁来验证它？** 跟生产者是不是两个角色？（第五部）
6. **它学到的东西写在哪一层？** 候选还是已验证？谁能把候选升成已验证？什么时候退役？（第八部）
7. **考卷在哪？** 至少几道 PM 确认过答案的题？改动前后怎么比？（第九部）
8. **PM 纠正它一次，纠正落到哪？**（第十部）
9. **它读不到数据、判断不了时说什么？** 会不会把「没测成」写成 0？（第十一部）
10. **它要占 PM 多少注意力？** 每周要批几条？不批会怎样？能不能不新增 agent，而是给现有的加一个工具？（第十三、十六部）
