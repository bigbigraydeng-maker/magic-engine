# 广告发布统一流程（me-ads-launch-flow）

**层级判定（me-platform-tier-gate）**：这是既有「广告」支柱 L1 的流程技能，不新增能力线、不新增 capability、不碰 `src/`。规则全部沿用广告手册，本文件只负责「按什么顺序、查什么、谁批」。

- 规则库（红线编号 RL-xx、授权四档、日/周/月节奏）：[`docs/sops/2026-10-10-ads-agent-playbook-and-rules-v1.0.md`](../../../docs/sops/2026-10-10-ads-agent-playbook-and-rules-v1.0.md)。本文只引用编号，不复制条文；冲突以手册为准。
- 分层：**平台层**=本文件；**行业层**=行业手册（旅游/物流等，候选参考）；**客户层**=当期一页纸（`docs/clients/<客户>/`）。换客户时本文件不应需要改。客户的语言红线、禁用词只在一页纸里写，例如 `docs/clients/cts/2026-10-14-cts-promo-rules.md`、`docs/clients/east-inter/2026-10-14-ads-plan-one-pager.md`（仅作示例路径）。

## 铁律（PM 已定，不得绕）

1. **「计划批准」只能 PM 本人批。** FDE、统筹、别的窗口、台账卡、日历、转述的「PM 已同意」都不算。
2. **开投、加预算同样只认 PM 本人**，且必须在**执行这个动作的这个对话**里点名到层（系列/广告组/广告）。只说「开」没点名的层保持暂停，回问一句，不自己猜（RL-01、RL-02、RL-04、RL-17）。
3. **日预算上限字段为空 → 一律不起草、不开投**，并下发人工任务（见下「空上限处理」）。只提示不拦 = 违规。
4. 所有对象先建 `PAUSED`；读不到一律写「没法证明」，不当通过；名字不作数，以读回为准。
5. 不充值、不换付款方式、不新建广告账户、不删对象（RL-15）；不改账户国家/币种/时区（RL-14）。
6. 计划批准与开投批准是**两道独立的关**，各留一份回执；批了计划不等于批了开投，预算批准不等于上线授权。
7. 视频只走视频工厂（RL-11）；生产方≠质检方。

### 空上限处理（第 3 条的落地）

日预算上限字段（客户总上限 / 账户级上限）为空或无效时：不出草稿、不激活；当场下发一条人工任务进今日待办/执行看板，三件套缺一不可——

- **what**：哪个客户哪个账户的日预算上限没填，影响是所有起草和开投都被拦。
- **how**：到该客户设置页的广告账户处填日预算上限（数字由 PM 提供，不由 agent 估）。
- **href**：直达该客户广告账户设置页的链接。

## 六步流程

| 步 | 谁做 | 做什么 | 过关条件 | 批准 |
|---|---|---|---|---|
| **0 开户（按需）** | FDE/PM | 新客户先走 `me-meta-ad-account-setup` | 账户、主页、付款已就位（付款/充值是 PM 的事） | — |
| **1 计划** | agent 起草，FDE 补客户事实 | 先过 `client-promo-readiness` 三道门（前置，不合并）；再按下方「计划一页纸」写计划；Goal/Initiative 见 `docs/sops/goal-initiative-campaign-setup-for-fde.md` | 目标与关键词来自 `master_briefs`/`clients`，数字来自 DataForSEO/GSC，不编；每个客户同一时刻只有**一份**权威计划文件，顶部写批准状态；日预算上限非空 | **计划批准关：PM 本人** |
| **2 素材** | 工厂/内容窗口生产；苏东坡/马良审 | 视频走 `src/lib/factory/`；图文走内容窗口；价格日期当天核官网；真播放确认有声音；分镜自检 | 素材入池须 PM 批；page_id 属于该客户（RL-13）；客户红线/禁用词已查 | 素材入池：PM |
| **3 草稿(暂停)** | agent | 建三层全 `PAUSED`；官方 MCP 建的是「未发布草稿」有坑，要「暂停且已发布」走 Graph（RL-09）；新广告另建新组，不塞进在投组（RL-05） | 读回买家会看到的每句话、targeting 三项、版位（`audience_network`=0）、目标、预算、表单、落地页与 UTM；外链在客户自己域名（RL-11）；留回执并把草稿编号写入台账卡 | 无（不花钱）；**不得自动开启** |
| **3b 待命期** | 日检任务 | 每天**实时问 Meta** 三层自身状态与逐日花费，不读库快照；读回失败=「没法证明」；账户级兜底：清单外 ACTIVE 或有花费 → P0 | 全程仍 PAUSED 且零花费 | — |
| **4 批准（开投关）** | PM 本人 | agent 出一张对账卡（将被打开的层 × 预算 × 受众 × 文案）；PM 在对话点名到层 | 开投前**当场**重验开投前清单（下）；自下而上开（先广告、再广告组、最后系列） | **开投批准关：PM 本人** |
| **5 发布(激活)** | 执行窗口 | 只开点名的层；激活后立刻读回三层并存「前/后」两份 | 点名的开了、没点名的仍暂停；14 天冻结（不改预算/素材/受众/版位，单次加减 ≤ ±20%）；激活当天建日历 第 3/14/28 天 | 已在第 4 步；之后任何非 PM 授权的改动 → 当场停并报 |
| **6 复盘** | 广告支柱 agent，PM 看周报 | 按下方「复盘一页模板」 | 第 7 天只记不判；样本够（如累计 ≥25 条）才判成本，不够写「判不了」；开聊数与留资数不相加（RL-12）；断投日不进对照（RL-07）；学习期读不到不能当前置条件（RL-08） | 加预算/改受众/关系列：PM 本人（RL-02、RL-04） |

## 平台层开投前清单（第 4 步当场重验，任何一条不满足就不开）

抽自 CTS 上海团计划 §8.1/§8.5 的平台部分，客户事实不在此。每条标「我核了/沿用」，读不到写没法证明。

1. **付款与账户状态**：广告账户 `ACTIVE` 且付款方式有效；当天重读，出现付款被拒/已暂停/UNSETTLED 就不开，如实报 PM；不充值、不改付款（RL-15）。
2. **预算余量**：在投设定合计 + 已拍板待生效加钱 ≤ 客户总上限；多个账户用同一轮快照；读不全=不通过。日预算上限字段非空（铁律 3）。
3. **官网事实当天核**：价格、日期、人数、可点进的落地页与计划一致，落地页在客户自己域名。
4. **素材审查记录**：工厂配方对账 + 苏东坡/马良审查 + PM 入池批准，生产方≠质检方；真播放过。
5. **身份与主页**：`page_id` 属于该客户（RL-13）；Instagram/主页/像素连接就位；没连 IG 就只投 Facebook 并手动限定版位，不拖上线。
6. **表单/转化链路**：测试线索已落进该落进的表，来源（campaign 名）在列里。
7. **受众规则读回**：新受众池收人规则含本批素材；targeting 三项（地区、年龄、包含/排除）读回一致（RL-04）。
8. **广告支柱审查已记录**：涉及自动化（自治档位、自动调预算/暂停）的，审查窗口回执已落台账。
9. **授权**：计划批准回执存在且对应当前版本；开投点名原话与时间已记入回执；建议改过则旧授权作废。
10. **日历**：第 3/14/28 天提醒已建（标题写人话动作，描述写清查什么、怎么算成、不成第一步做什么）。

## 两道批准关的回执最小字段（沿用手册 §2.2b）

两道关各存一份，字段相同，`gate` 不同：

| 字段 | 说明 |
|---|---|
| `gate` | `plan_approval` / `launch_approval` |
| `request_id`、`client_id`、`plan_ref` | 请求编号、客户、权威计划文件路径+版本 |
| `object_ids` | 开投关必填：点名开的层及其对象 id（系列/组/广告） |
| `authorization` | `pending_pm` / `granted` / `denied` |
| `approver` + `quote` + `approved_at` | 批准人（必须是 PM 本人）、原话、时间 |
| `version_approved` | 批的是哪一版；之后改动则作废重批 |
| `cost` | 预算与上限口径（日上限 vs 月基金，手册 §7.1） |
| `before` / `after` | 改前改后读回（开投关必有） |
| `rollback` | 怎么撤回（后台直接暂停） |
| `created_at` | 回执时间 |

没有 `granted` + PM 原话的回执，不许标「完成」（RL-17：状态字段不是授权）。

## 计划一页纸（第 1 步，放客户目录，复用 promo-readiness 的外壳）

假设与目标（来源标注）· 指标与「一条转化」口径（须与 objective 一致）· 预算分配与口径 · 日预算上限 · 受众与版位 · 语言范围 · 周期与观察节奏（第几天看什么、几天后才能判、改后冻结几天）· 成本门槛与停止条件 · 账户/主页/像素/付款状态（只读）· 顶部写批准状态（未批/已批 + 谁 + 何时）。

## 复盘一页模板（第 6 步）

```
# <客户> 广告复盘（计划 <引用> · 第 N 天 · 日期）
- 结论：一句话（成/不成/判不了，及原因）
- 计划 vs 实际：花费、触达、目标指标（只报该广告自己的目标指标，RL-12）
- 动了什么 / 没动什么：每项带授权来源（PM 原话/回执），无授权的改动单列
- 数据是否可判：样本量、是否含断投日（RL-07）、是否在冻结期
- 下一步：要 PM 本人批的（加预算/改受众/关系列，一句话回法）；agent 可自行做的
- 写回：哪条经验写回哪一层（客户层；两家以上成立才升行业层）；没学到也写「无」
- 没核实的：逐条列
```

## 不在本流程内

`docs/sops/meta-ads-ai-invite-release.md`（只读报告产品的邀请发布）与发广告无关；Google 等其他渠道目前没有渠道手册，先出手册再接入。要把本流程做成后台功能（推广计划板块），必须先过 `me-platform-tier-gate`。
