# Meta 数据集搭建（me-meta-dataset-setup）

**层级判定（me-platform-tier-gate）**：既有「广告」支柱下的**做事步骤技能**，不新增能力线、不碰 `src/`。用到的零件都已存在：Meta 连接器（L3，`src/lib/meta/capi/`）、成交与线索阶段回传（`src/lib/conversions/`）、发布前追踪检查（`src/lib/ads-tracking-preflight/`）。每个客户的阶段名、数据集编号只进客户配置（L4）。
**来源**：PM 2026-11-10「帮我设计 CTS 应该如何搭建数据集，这是一个 skill，今后其他用户也会需要」。第一个实例在客户层文档，不在本文件。
**和 `me-meta-tracking-health` 的分工**：那个是**体检**（只读，查现有链路健不健康）；这个是**搭建**（定目标形态、出动作清单）。搭建第 1 步的盘点直接用体检的读法，搭完用体检验收。

**一句话**：一个客户只认一本账。官网行为、成交、客人进展都记进同一个主数据集，广告账户挂这一本；账记得越靠近真成交，广告找的人越对。

## 先讲清楚：数据集是什么

数据集 = Facebook 那边的一本账本。谁在客户这儿做了什么，往这本账里记；广告系统翻这本账学「什么样的人值得找」。

| 内容从哪来 | 谁在记 | 例子 |
|---|---|---|
| 官网追踪代码（浏览器） | 访客的浏览器 | 打开网页、看产品页、填表 |
| Meta 自动镜像（服务器） | Meta 自己，把浏览器事件再报一遍并去重 | 同上，带服务器来源标记 |
| ME 回报成交（服务器） | ME，人批准后发 | 收到定金 |
| ME 回报客人进展（CRM 线索阶段） | ME，每天自动发 | 表单线索走到「已报价」 |

Facebook 拿这本账做三件事：**认人**（对回哪条广告带来的）、**圈人**（按记录圈人群再投或找相似）、**学习**（照某一种记录去找更多类似的人）。

## 目标形态（标准搭法）

1. **一个商务账户只有一个主数据集。** 官网追踪代码、Meta 镜像、ME 成交、ME 客人进展全部进它。
   Meta 事件管理工具现在的 CRM 接入流程（连接数据 → CRM → 手动连接 → 用代码自行连接）就是把 CRM 事件挂到已有数据集上，不新建（2026-11-10 实测一例）。官方文档仍写「建议新建」，以页面实际流程为准，两者不一致时写进方案的「没核实的」。
2. **投广告的账户必须在商务账户名下，并挂上主数据集。** 个人名下的广告账户用不了「按合格线索优化」，商务账户里的数据集也没法直接给它用。
3. **同一个事件名只有一个服务器来源**（规则库 E-07）。分工固定：

| 事件 | 谁发 | 事件名 |
|---|---|---|
| 官网行为（打开、查看、官网留资、订阅） | 官网追踪代码 + Meta 镜像 | 标准名（PageView / ViewContent / Lead…） |
| 成交（收到定金） | ME，人批准 | `Purchase` |
| 尾款 | ME | `BalancePaid`（不叫 Purchase，一单不记两笔） |
| 客人进展 | ME，每天自动 | 客户配置里的阶段名，**不许跟标准事件重名** |

   所以：ME 不再发普通 `Lead`（官网那路已经在发，ME 再发就算重）；线索阶段第一档叫 `Initial Lead` 之类，不叫 `Lead`。在 ME 里对应客户配置 `leads_config.capi_send_kinds`。
   🔴 **这项配置没写时是「不限制」，一写上就只许名单里的几类**：漏写 `balance`，尾款就悄悄不回报了，而且不建发送记录。要停哪一类必须是故意的，写进方案。
   「阶段名不许跟标准事件重名」**代码不检查，靠人守**。
4. **多余的数据集不删。** 从没收过数据的留着并在方案里标注；官网上重复装的那套追踪代码，先查清谁在用再撤（见「决策表」）。

## 步骤

### 第 1 步：盘点现状（只读）

用 `me-meta-tracking-health` 的读法，至少拿到下面这张表，读不到的格子写「没法证明」：

| 要查的 | 怎么查 |
|---|---|
| 商务账户下有几个数据集、各叫什么、最近一次收到数据是什么时候 | Meta Ads MCP `ads_get_datasets`（**可能列不全**，要再看事件管理工具页面的列表） |
| 每个数据集近 28 天收到哪些事件、各多少 | `ads_get_dataset_stats`，`aggregation=event`，分别带 `event_source=WEB_ONLY` 和 `SERVER_ONLY` 各读一次 |
| 官网上装了哪几套追踪代码 | 两个数据集的浏览器事件数接近、同一批网址 = 同一个官网装了两套 |
| ME 的成交现在进的是哪个数据集 | 拿 ME 已发成交的发生日期，对 `SERVER_ONLY` 里 `Purchase` 的日期；对得上的那个就是。**别从环境变量名或文档推断** |
| 投广告的账户归谁 | `ads_get_ad_accounts` 的 `business_id`；为空 = 个人名下 |
| 表单线索编号有没有存进 ME | 查 `contact_touchpoints`（`source='meta_lead_form'`）的 `source_ref` 是不是 15–17 位数字，再算近 30 天走到目标阶段的客人里有编号的占比 |
| 线索量和阶段转化率 | 近 30 天表单线索数；走到目标阶段的人数 ÷ 线索数；其中多少是进线 28 天内走到的 |

### 第 2 步：定主数据集

挑那本**广告已经在认、数据最全**的：同时有浏览器和服务器两路、ME 成交已经在里面、挂着目录或自定义转化的优先。名字不作数，以读回的事件为准。

### 第 3 步：对齐成交回报

ME 的成交必须进主数据集。不在的话属于「改回传目标」：要 PM 本人原话，由执行窗口改环境变量、重新部署、读回，并把改动时间点告诉广告总控（见体检技能的停手条件）。

### 第 4 步：接上客人进展（线索阶段回传）

**先判够不够格**（Meta 官方条件，2026-11-10 核对）：

| Meta 的要求 | 不满足时 |
|---|---|
| 用 Facebook / Instagram 即时表单收线索，且存了线索编号 | 这条路走不通；只做成交回报 |
| 每月至少 200 条线索 | 先只回报、不拿它当广告目标 |
| 目标阶段的转化率在 1% 到 40% 之间 | 太低就往前挪一档当目标（例如从「已付定金」挪到「已报价」） |
| 目标阶段发生在进线 28 天内 | 超过 28 天的 Meta 用不上，按 28 天内的量重算上一条 |
| 每天至少回报一次 | ME 每天早上的日常任务满足 |
| 广告账户在商务账户名下 | 见决策表「个人广告账户」 |

**再配置**（写客户配置 `clients.leads_config`，写生产库要 PM 点头）：

```json
{
  "capi_send_kinds": ["purchase", "balance", "lead_stage"],
  "crm_stage_signals": {
    "enabled": true,
    "mode": "dry_run",
    "dataset_id": "<主数据集编号>",
    "lead_event_source": "Magic Engine",
    "initial_event_name": "Initial Lead",
    "stages": [
      { "event_name": "<阶段名>", "stage_keys": ["<客户管理页里的阶段 key>"] }
    ]
  }
}
```

定阶段时守三条：
- **阶段从前到后排**；到了后面的档，ME 会自动补报前面的档。
- **`stage_keys` 只列「人真的走到了这一步」的阶段**。补录老客人时批量打上的状态（如「已完成」「老客户」这类收尾状态）不要列进去，否则老订单会被错报成新成交。
- **阶段名一旦上线别改**。改名会以新名字再报一遍，Meta 那边撤不回。

**配置写错的后果（写完必须读回并看第二天的运行结果）**：
- 阶段名重复、第一档名字跟某个阶段重名、某一档 `stage_keys` 为空 → 整个功能当成「没开」，不报错，只在每日运行结果里记 `config_invalid`。
- `dataset_id` 必须是**带引号的文字**。写成不带引号的数字会读不出来，记录会永久停在「组装失败」，以后不会重试。
- 每天的运行结果里有各类跳过的计数（没开、种类不允许、客人拒联、没有联系方式、阶段早于线索），第一次跑完逐项看一遍。

**顺序**：`mode: dry_run`（只出预览，不真发）→ 看预览：每条带线索编号、目标数据集对、预检通过 → **PM 本人原话**（转述不算）→ 改成 `live`。真发还要求 `clients.conversion_stage = 'live'`。
**试运行要短，看完预览当天就定。** 试运行处理过的记录是终态，切正式后不补发；ME 只回报 7 天内的阶段变化，试运行拖一周就等于丢一周。

### 第 5 步：让广告用上它

1. 回报攒够数据（至少跑满两周，且目标阶段事件数能看出稳定节奏）。
2. 在事件管理工具里配置漏斗：把目标阶段设为要优化的那一档，其余阶段标成正向或其它（要商务账户管理员；属改 Meta 设置，要 PM 本人原话）。
3. 开一组「按合格线索优化」的广告，跟现有主力组**同素材对照**。走 `me-ads-launch-flow`：草稿 → PM 批 → 开投。**优化目标发布后不能改**，所以是新开一组，不是改老组。
4. 复盘看「每个合格客人花多少钱」，不看「每条线索花多少钱」。

### 第 6 步：验收

跑一遍 `me-meta-tracking-health`，再加三项：主数据集里出现各阶段事件且来源标成 CRM；官网原有的留资数没有因此变多；同一条线索同一档只出现一次。

## 决策表

| 遇到的情况 | 怎么办 |
|---|---|
| 同一个官网装了两套追踪代码，进了两个数据集 | **先查是不是有意双发**（看官网仓库的注释和历史）：常见原因是投广告的账户在个人名下，挂不上商务账户里的数据集，只好让官网给它自己的数据集也发一份。这种情况要先把账户归进商务账户、挂上主数据集，再谈撤。先定主数据集。另一套**先不撤**：查它有没有挂人群、自定义转化、正在跑的广告组；都没有，再请建站方撤掉那段代码；数据集本身不删。有挂着的，先把它们迁到主数据集 |
| 有从没收过数据的数据集 | 不删、不用，方案里标一行「空的，别往里接东西」 |
| 广告账户在个人名下 | 归进商务账户才用得了合格线索优化、才能挂商务账户的数据集。**归进去就移不出来**（Meta 归入页面原文：「添加后，你便不能从业务资产组合移除广告账户」，2026-11-10 所见），必须 PM 本人操作或本人原话。这跟「商务账户之间转移广告账户」是两回事，后者能不能做本技能没验证，见 `me-meta-ad-account-setup`。搬前查清：这个账户有没有同时给别的客户打广告、上面绑的是谁的付款方式、商务账户还有哪些管理员 |
| 一个广告账户给多个客户共用 | 不能归进任何一个客户的商务账户。`me-meta-ad-account-setup` 的红线是禁止共用，但没写怎么分户；先报 PM 定每个客户各用哪个账户，再回来搭数据集 |
| 线索不是 Facebook 表单来的（官网表单、私信、电话） | 线索阶段这条路用不了。官网表单走官网追踪代码的 `Lead`；私信成交走 ME 成交回报（带私信身份）；别硬造线索编号 |
| 客人第二次填了表 | ME 同一位客人同一档只报一次，挂在走到这一档之前最近的那条线索上；不会为新线索重报 |
| ME 的回传令牌是某个人的个人令牌 | 能用，但会过期、会随账号变动失效。方案里列一条「换成系统用户令牌」，不挡搭建 |
| 目标阶段量太少（每月个位数） | 照样回报（对报表有用），但别拿它当广告目标；往前挪一档 |

## 红线

- **撤不回的三件事**：发给 Meta 的事件删不掉；个人广告账户归进商务账户移不出来；优化目标发布后改不了。每件都要 PM 本人原话（转述不算），且先出预览或草稿。
- **搭建方案只读出方案，不动手。** 改 Meta 设置、改回传目标、写客户配置、开广告，各走各的批准。
- **不删数据集、不删追踪代码**，除非盘点证明没人用，且 PM 点头。
- **客户私有事实不进本文件**：数据集编号、事件数、阶段名、账户号都写客户层文档。
- **不把线索量、转化率估着写。** 都要从 ME 库和 Meta 读回，读不到写「没法证明」。

## 输出：一页搭建方案

写在客户层文档 `docs/clients/<客户>/<日期>-meta-dataset-setup.md`，开头一句人话结论，然后：

1. **现状表**：每个数据集一行（收什么、多少、哪路来的、判定：主 / 重复 / 空）。
2. **够不够格表**：第 4 步那六条逐条写读到的数。
3. **目标形态**：主数据集是哪个、哪些事件谁发、阶段怎么分。
4. **动作清单**：每条写清做什么、谁做、要不要 PM 点头、撤不撤得回、现在的状态。
5. **没核实的**。

## 没验证的（2026-11-10，改前先重测）

- 线索编号 ME 按文字格式发，Meta 示例是数字格式；试运行不真发，第一条正式事件的回执才能确认。
- 个人广告账户搬进商务账户之后，正在跑的广告、已有人群是否不受影响：只实测过一例搬完后账户状态正常，没有量化对照。
- Meta 文档说线索阶段集成「建议新建数据集」，页面实际流程挂到已有数据集，两者谁对广告学习更好没有证据。
- 「目标阶段要在进线 28 天内」对报表展示有没有影响没验证，只知道对优化有要求。
- `ads_get_datasets` 实测漏列过数据集（页面上有、接口没返回），原因未查。

## 与其它技能 / 手册的关系

- `me-meta-tracking-health`：盘点和验收用它的读法；本技能不重复它的判色规则。
- `me-meta-ad-account-setup`：账户归属、分户、合同退出条款在那边。
- `me-ads-launch-flow`：第 5 步开对照广告走它的草稿和两道批准。
- 代码：`src/lib/conversions/crm-stage-signals.ts`（配置解析与「哪位客人该报哪一档」）、`crm-stage-signals-run.ts`（每日写入与发送）、`src/lib/meta/capi/writer.ts`（组装）。
- 广告通用手册（记忆）：受众是广告账户级资产、跨账户不进池。
