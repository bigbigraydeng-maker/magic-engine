# Meta 追踪体检（me-meta-tracking-health）

**层级判定（me-platform-tier-gate）**：既有「广告」支柱 L1 里「追踪体检」（发布前追踪检查 `src/lib/ads-tracking-preflight/`）的**做事步骤技能**；读 Meta 用官方接口（L3 Connector 读取）；不新增能力线、不碰 `src/`。把读取做成每天自动跑的代码属于 capability 代码，另走 tier-gate 与五道 Build Gate（台账 `2026-10-20-ads-agent-read-meta-events-manager-health`）。
**来源**：PM 2026-10-20 提出「读懂事件管理工具是合格 Meta 广告 Agent 的基本功」；证据与对账见 [技能卡](../../../docs/skill-cards/2026-10-20-meta-events-manager-tracking-health.md)。客户私有发现不在本文件，在客户层文档。

**一句话**：广告好不好使，先看 Meta 收到的信号对不对。开投前、开投后和每周都要把事件管理工具的四个屏读一遍，每个问题都要有去向，读不到就写「没法证明」。

## 铁律

1. **只读。** 体检不改任何 Meta 设置，不发任何事件（包括带测试码的），不点向导里的「发布」，不创建或删除数据集和集成。改设置 = 改生产，要 PM 本人原话，并读回。
2. **读不到写「没法证明」，不当通过。** 名字不作数，以读回为准；接口和页面说法不一致时写「冲突，未解」，不挑一个当真。
3. **一个数据集上：浏览器像素 + 至多一条服务器回传路径，用 event_id 去重。** 多条并存或来源不明，先查清谁在发什么，再决定，不得先改。默认保留 ME 自己的转化 API 回传（已有 L3 Connector），Meta 推荐的第三方 / GTM / 网关向导默认不启用——**除非 PM 另有决定**（某个客户的决定不自动适用于别的客户，沿用前先问 PM）。
4. **客户私有事实不进本文件**（数据集编号、事件数、匹配质量具体值）：进客户层文档。
5. **Meta 页面上的「可降低单次成效费用 X%」是 Meta 自己的宣传口径，不是我们的证据**，不进规则。
6. **发现不许死在日志里：** 每条要么自动处理，要么下发人工任务（what 问题和影响 / how 点哪里 / href 直达链接），进今日待办或执行看板。
7. 发到 Meta 的事件没有删除接口：任何会让「发送」发生的动作都先问 PM。

## 什么时候跑

| 时点 | 做什么 |
|---|---|
| 开投前 | 作为 `me-ads-launch-flow` 第 4 步「平台层开投前清单」第 6 条的一部分，跑完整四屏；有红或「没法证明」→ 不开，除非 PM 书面接受风险 |
| 开投后第 1 天 | 读数据集近 24 小时事件、像素在线、服务器事件时间，对比开投前 |
| 每周复盘 | 四屏过一遍，对比上周：事件量、匹配质量、新出现的警告 |
| 改任何追踪设置前后 | 前后各一份读数，并记下改动、部署开始/完成、读回三个时间点，告诉广告总控（他要用来切数据前后） |
| Meta 页面出现「自某日起……」类通知 | 记日历，生效日后核对报表口径是否跳变 |

## 四个屏怎么读

| 屏 | 看什么 | 怎么读 | 怎么判 |
|---|---|---|---|
| ① 数据集总览 | 每个数据集近 28 天事件数、来源标签（像素 / 转化 API）、有没有「从未收到事件」的数据集 | Meta Ads MCP `ads_get_datasets`、`ads_get_dataset_details`（有没有 server_last_fired_time）、`ads_get_dataset_stats` | 广告账户名下的数据集 = 官网像素在发的 = ME 回传目标（追踪检查「数据集对齐」）；从未收到事件的数据集只记录，不删（RL-15） |
| ② 诊断工具 | 待处理 / 之前检测到 / 已忽略 的警告 | 目前**没有验证过能读的接口**（见下「没验证的」）→ 用 Claude in Chrome 只读读页面（PM 登录态，只看不点） | 每条警告按下表分类并给去向 |
| ③ 集成工具 | 已连接的集成：像素、转化 API、网关、GTM…… | 同上，页面只读 | 每个「已连接」都要说得出来源和用途；说不出 = 来源不明，先查清 |
| ④ 合作伙伴向导（连接数据） | 向导列表 | 只看不点 | 它是「再加一条路径」的入口，默认不用；点「发布」= 改设置，走铁律 1 |

**事件匹配质量与数据新鲜度**：`ads_get_dataset_quality`，按事件名看综合分、各匹配键覆盖率（email / phone / fbc / fbp / ip / user_agent）和上传频率。**和自己的历史基线比，不用绝对阈值下结论**；留资事件的匹配键缺口（邮箱、电话、点击 id 覆盖低）给具体动作（表单收集邮箱、保留点击 id 参数），不夸大。

## 诊断警告怎么分（每条必有去向）

| 类别 | 例子 | 去向 |
|---|---|---|
| **官网要改** | 事件缺参数（价格、货币无效）、同一事件价格全部相同、重复事件 | 先看这个事件是否被当前广告目标使用；被使用 → 派官网窗口（三件套）；不被使用 → 标「当前目标不依赖」，记入官网待办，不进红字 |
| **Meta 里要确认** | 域名归属 / 白名单、业务验证 | 属改 Meta 设置：给有权限的人 how + href，PM 或授权人去点；我们不点 |
| **当前目标不依赖** | 广告目标是点击、播放、私信，而警告属于留资/成交类事件 | 记录但不挡投放；目标换成留资/成交时重新评估 |

## 多条回传路径（重复计数）怎么查

1. 列出这个数据集上所有服务器端事件来源：官网自己的服务器、ME 转化 API、Meta 网关、GTM / Google 向导、第三方（Zapier、Segment、Stape 等）。
2. 每个来源：发哪些事件名、有没有 event_id、与像素是否去重。
3. 证据：接口里 `server_last_fired_time` 与 `last_fired_time` 同一时刻 → 有服务器事件；集成页的「已连接」清单。**两边对不上就写「冲突，未解」并开卡。**
4. 只有查清才允许改回传目标或增删路径；改完读回。

## 输出：体检回执（一页）

客户 · 数据集 · 读取时间 · 读取方式（接口 / 页面）· 四屏各一行状态（绿 / 黄 / 红 / 没法证明）· 警告去向表（每条警告一行）· 来源不明的服务器事件 · 动作（自动 / 人工三件套）· 没核实的。回执并入发布前追踪检查的回执体系（`src/lib/ads-tracking-preflight/`），不另起一套。

## 没验证的（2026-10-20 实测边界，改前先重测）

- 事件管理工具「诊断工具」里的待处理警告：Meta Ads MCP 没有对应读取项；Graph 的 `da_checks` 边实测只返回目录 / 动态广告类检查，读不到「事件缺价格货币」「域名待确认」这类警告；是否有别的接口：**未核实**。
- 「集成工具」已连接清单：同样没找到接口。
- 页面显示某集成「已连接」而接口返回「未接入」的原因：**未查清**（两边可能不是同一个东西）。
- 数据集字段名随版本变化：同一个字段在 MCP 里有、在 Graph v19 里报「不存在」，改读取前先试一次。

## 停手条件

- 要改 Meta 设置、回传目标、增删集成 → 停，要 PM 本人原话，读回，并通知广告总控时间点。
- 发现事件已重复计数 → 不撤销（Meta 没有删除接口），只报 PM，并说明影响哪段日期。
- 权限读不到 → 写「没法证明」，下发人工任务，不猜。
