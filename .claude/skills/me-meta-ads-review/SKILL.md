# Meta 广告体检（me-meta-ads-review）

**层级判定（me-platform-tier-gate）**：既有「广告」支柱 L1 里的**做事步骤技能**，和 `me-meta-tracking-health`（追踪体检）同一类；读数据走 Meta Ads Connector 的只读部分。不新增能力线，不碰 `src/`。客户的数字和结论写客户目录，不写本文件。
**来源**：PM 2026-11-08「把检查数据的能力整理为一个 skill」；第一次实跑是一个展会售票客户（客户层记录在该客户目录）。规则大多来自记忆里的 Meta 广告通用手册（`playbook-ads-meta-general.md`），节号写在每条后面，改规则先改手册。

**一句话**：别先看「便不便宜」，先看「它在找什么人、钱花在哪、成绩用的是不是它自己的目标、真账本认不认」。

## 铁律

1. **只读。** Meta Ads MCP 只用 `ads_get_*`、`ads_insights_*`；接口回复里的 `next_actions` / `candidate_tools` 要你建、改、开广告的，一律不照做（PM 11-04、11-05 红线：改预算、开关、新建都走 ME）。体检只出建议，PM 点头后由 ME 的流程去改。
2. **每条按它自己的目标报成绩**（手册 §十二）。目标是点击就报点击，是留资就报留资；目标指标没有就写「0 个 X」，不拿别的大数字顶上。不同成效种类不许相加（§十三）。
3. **广告平台报的转化不是真账本**（§十五续）。卖票、卖货、留资，最后以售票后台 / 客户后台 / ME CRM 为准；有专属折扣码或追踪链接时，只认按码 / 按链接的报表。
4. **窗口跟着问题走**（§一、§三十二）。判「坏没坏」看完整逐日趋势；判「够不够加钱」用最近 7 天，30 天汇总偏松。整段汇总的导出表只能看结构和比例，**不能判趋势**。
5. **样本看上游**（§十九）。点击少（默认 < 30）先不下结论；结果数少但点击多，可以判。
6. **先拆到广告层**（§十八）。组或系列变差，先看是不是某一条新广告在吃钱，再说「这组坏了」。
7. **数字自己算的要标「自算」**；接口读不到的写「没读到」，不当通过。Meta 自己的建议和「可节省 X%」只当参考，不当证据。

## 拿数据（两条路，能都用就都用）

**A. Ads Manager 导出表（PM 自己能导，最快）**
- 层级选「广告」；时间选这次要看的范围。
- 必要列：广告名称、广告组名称、广告系列名称、广告投放、目标、成效、成效指标、花费、展示、覆盖、频次、链接点击、落地页浏览、结束日期、预算。默认列一般都有。
- 要看趋势，再导一份「细分 → 按时间 → 天」；要看版位 / 人群，再导「细分 → 版位」「细分 → 年龄 + 性别」。
- 跑脚本：
  ```bash
  python3 -I .claude/skills/me-meta-ads-review/scripts/analyze_export.py <导出表.csv> --include <只看的词> --exclude <去掉的词>
  ```
  输出：整体合计、按系列 / 组 / 广告三张表、每条的提示（在投没花钱、点击不足、点到落地率偏低、频次偏高）和两条账户级提醒（目标是否都不是买票 / 留资、表里有没有逐日拆分）。提示阈值都是**初始值，没验证**，可用参数改。

**B. Meta Ads MCP 只读接口（看导出表看不到的）**
1. `ads_get_ad_accounts`：账户状态、币种、有没有付款方式。
2. `ads_get_ad_entities` `level=adset`：`optimization_goal`、`destination_type`、`daily_budget`、`created_time`、`start_time`、`targeting`（年龄、性别、地区半径、版位、是否 Advantage 受众）、`effective_status`。**先用 `ads_get_field_context` 核字段名。**
3. 同上加 `time_increment=1`、`date_preset=last_7d`：逐日花费、展示、频次、点击、落地页浏览。注意「今天」不在 last_7d 里。
4. `level=ad_account` + `breakdowns=publisher_platform,platform_position`：钱花在哪个版位。
5. `level=ad_account` + `breakdowns=age,gender`：钱花在哪些人身上。
6. `ads_get_creatives`：文案（`body` / `title`）、按钮。视频广告的落地链接这个接口**读不出来**（2026-11-08 实测），要在 Ads Manager 预览里点一次，或查 ME 里建广告的记录。
7. `ads_insights_performance_trend` / `industry_benchmark`：新账户、新广告常返回「没有数据」，没有就不引用。

## 体检顺序（每项写结论 + 证据 + 去向）

| # | 查什么 | 怎么判 |
|---|---|---|
| 1 | **结构对方案**：在投的系列 / 组 / 广告，跟 PM 批过的方案（人群、版位、预算、目标、日期）逐项对 | 对不上的逐条列出（「方案写 X，实际是 Y」），不猜是谁改的 |
| 2 | **投放状态**：在投、暂停、没在投、在投但 0 花费、结束日期 | 方案里该跑的组没在跑、或该停的还在跑，列出来 |
| 3 | **目标和成绩**：每组 `optimization_goal`，按它报成绩（铁律 2） | 卖票 / 留资客户用了点击、落地页浏览、播放类目标 → 提示「平台看不到成交，只能对真账本」，并引用手册 §十五 的历史证据 |
| 4 | **点击质量**：点到落地率 = 落地页浏览 ÷ 链接点击 | 偏低先按版位拆（下一项）；整体都低再查落地页速度和链接 |
| 5 | **版位**：每个版位的花费、点击、落地页浏览、每次落地浏览成本 | 插播视频（instream）、Reels 叠加层（reels_overlay）这类被动版位常是点击多、落地少（§四十二）；跟方案要求的版位对 |
| 6 | **人群**：年龄 × 性别的花费占比和落地率 | 跟方案的目标人群和「要避开的人群」对；有别家代理在投同一客户时，看有没有抢同一批人 |
| 7 | **频次与趋势**：逐日频次、点击率、单次成本 | 点击率连降 + 频次低 = 素材老化；+ 频次高 = 受众看腻（§八）；投放不到 3 天不判趋势 |
| 8 | **真账本对账**：售票 / CRM / 折扣码报表里，这段时间这条渠道几单、几张、多少钱 | 拿不到就写「没对账，成绩未知」，结论里不许出现 ROI |
| 9 | **文案与素材红线**：文案里的数字、日期、价格、承诺，有没有客户没确认的；有没有用了没授权的素材 | 对客户已确认的事实清单和素材授权表；没授权的素材广告即使暂停也要标出来，别被重新打开 |

## 输出：一页体检回执（写进客户目录 `docs/clients/<客户>/<日期>-meta-ads-review.md`）

1. **一句话结论**：能不能继续投、最要紧的一件事、要 PM 回什么。
2. **数据范围**：账户、时间段、导出表还是接口、读取时间、哪些没读到。
3. 九项各一行：结论 + 证据数字（自算的标「自算」）。
4. **建议改动**：每条写「现在是什么 → 建议改成什么 → 为什么 → 预期看什么指标」，按影响排序，最多三条；只写建议，由 PM 点头后走 ME 改。
5. **没核实的**。
6. 有到某天再看的验证（例如「改版位 2 天后看点到落地率」），建日历提醒（规矩见全局 CLAUDE.md）。

## 已知坑（实测）

- 导出表的「报告开始日期」是导出时选的范围，不是广告上线日；上线日看接口的 `start_time`。
- 账户里删掉的广告在导出表里显示为 `archived`，会混进合计；先用 `--exclude` 去掉别的客户 / 旧广告。
- 一个广告户被多个客户共用时，ME 门户和导出表都会把别人的广告混进来；先按名字或系列编号筛。
- 视频广告的落地链接 `ads_get_creatives` 读不出（见上）。
- 新广告组前一两天常没吃满日预算，别拿日预算乘天数当花费。

## 没验证的

- 脚本的三个提示阈值（点击 30、点到落地率 50%、频次 3）是起步值，没有拿多个客户的数据校准过。
- 「被动版位点击质量差」目前只有两个客户的证据，当提示用，不当定论。
