# 注册 Microsoft 应用（让 ME 能读客户的公司邮箱）

> 给 PM 用。**这件事一辈子只做一次** —— 注册的是 Magic Engine 自己的应用，
> 以后每接一个新客户，只要客户点一次「同意」，不用再注册。
> 2026-08-02 写。

---

## 先明确一件事

**你注册的是我们自己的应用，不是客户的。**

就像我们有一个 Facebook 应用给所有客户接主页一样，这里注册一个 Microsoft 应用，
给所有用 Outlook / Microsoft 365 的客户接邮箱。

**要拿到的就两样东西**，拿到给我就完事：

1. 应用 ID（Application / Client ID）
2. 应用密钥（Client secret 的值）

---

## 步骤

### 第 1 步 · 打开注册页

👉 https://portal.azure.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade

用你自己的 Microsoft 账号登录就行（**不需要客户的账号**）。没有的话现场注册一个免费的。

点 **「新注册 / New registration」**。

### 第 2 步 · 填三样

| 填什么 | 填成什么 |
|---|---|
| **名称** | `Magic Engine Mail` （客户同意时会看到这个名字，写得体面点） |
| **支持的账户类型** | 选**最后一个**：「任何组织目录中的账户 **和** 个人 Microsoft 账户」 |
| **重定向 URI** | 左边下拉选 **Web**，右边填下面那一行 |

重定向 URI 一字不差地填这个：

```
https://app.magicengine.com.au/api/auth/microsoft/mail/callback
```

> ⚠️ **账户类型一定要选带「和个人 Microsoft 账户」的那一个**。
> 只选「本组织」的话，只有你自己公司的邮箱能连 —— 客户一个都连不上。

点**注册**。

### 第 3 步 · 抄下应用 ID

注册完直接跳到概览页，上面有一行 **「应用程序(客户端) ID」**。

📋 **抄下来** —— 这是第一样东西。

### 第 4 步 · 生成密钥

左边菜单 → **「证书和密码 / Certificates & secrets」** → **「新客户端密码」**

- 说明：填 `ME mail`
- 有效期：选**最长的那个**（一般是 24 个月）

点添加之后，表格里会出现一行，有两列：**「值 / Value」** 和 **「密码 ID」**。

📋 **抄「值」那一列**，不是「密码 ID」。

> ⚠️ **那个值只显示这一次**。关掉页面就再也看不到了，只能删掉重新生成一个。
> 现在就抄。

### 第 5 步 · 加权限

左边菜单 → **「API 权限 / API permissions」** → **「添加权限」** → **「Microsoft Graph」** → 选 **「委托的权限 / Delegated permissions」**（不是「应用程序权限」）

搜索并勾选这三个：

- `Mail.Read`
- `Mail.Send`
- `offline_access`

点「添加权限」。

> **不要**勾 `Mail.ReadWrite` —— 读信不需要改客户的邮箱，多要的每一分权限
> 都是以后出事时说不清楚的地方。
>
> **不用**点那个「代表组织授予管理员同意」的按钮 —— 我们走的是「每个客户
> 自己点同意」，不需要管理员一次性授权全公司。

### 第 6 步 · 自己填进 Render（**别发给任何人**）

这两样是密钥。**发在聊天里就等于永久留在记录中**，而且会被搜到。
自己填进去就行 —— 谁都不需要看到它们的值，包括我。

1. 打开 Render 控制台 → **magic-engine** 这个服务 → 左边 **Environment**
2. 找到这两个已经准备好的空格子（配置文件里已经声明过，会直接列在那里）：
   - `MICROSOFT_CLIENT_ID` ← 填第 3 步抄的**应用 ID**
   - `MICROSOFT_CLIENT_SECRET` ← 填第 4 步抄的**密钥的值**
3. 保存。Render 会自动重新部署，几分钟。
4. 跟我说一句「**邮箱配好了**」就行。

我这边**不需要知道值**，只要知道填好了 —— 我会去验证连接能不能用，
验证方法是打开客户设置页看那个「连接公司邮箱」的按钮活没活。

> 万一不小心把密钥发出去过（群里、邮件、截图）：回第 4 步删掉那条密码、
> 重新生成一个新的，然后更新 Render 里的值。旧的当场作废。

## 卡住了怎么办

| 现象 | 多半是什么原因 |
|---|---|
| 找不到「新注册」 | 登录的账号没有 Azure 目录。用个人 Microsoft 账号登录会自动建一个，跟着提示走 |
| 重定向 URI 报格式错 | 前面的下拉要选 **Web**，不能选 SPA 或移动端 |
| 密钥的「值」看不到了 | 只显示一次。删掉那条重新生成一个 |
| 客户点同意时报「需要管理员批准」 | 客户公司的 IT 策略关掉了用户自助同意。这时要客户的 IT 管理员点一次同意 —— 告诉我，我给你一条直达链接 |

## 关于 Gmail 的客户（问一次答一次）

**CTS 用的是 Outlook 365，所以先做 Microsoft 这一个就够。**

将来遇到用 Gmail / Google Workspace 的客户：

- **不用再注册一个新应用** —— ME 已经有一个 Google 应用（现在用来接 GSC / GA4 / 商家页），加个读邮件的权限就行
- **但有一个真实的坎**：Google 把「读用户邮件」列为受限权限，用在生产环境需要通过一次**安全评估**（要花钱、要几周）。Microsoft 这边没有这道坎。

所以顺序上：**先把 Outlook 这条跑通、见到效果，再决定要不要为 Gmail 客户付那笔评估的成本。**

> 这条 Google 的限制我是凭已知情况说的 —— 开发机连不上 Google 的开发者站点，
> 没法当场给你官方链接佐证。真要上 Gmail 之前，我会先核准再报你成本。
