# YouTube Shorts 发布前清单 v2（与 Codex 窗口《Shorts发布强制规则》合并，**不一致处取更严者**）

- **适用**：ME 里还没有 YouTube 发布代码与服务端闸时，任何人 / 任何窗口发 YouTube Shorts 都按这页做。**这页是现在唯一的闸**；ME 服务端硬拦截要等 P3（A 级，三审 + PM 点头）。
- **来源**：Codex 窗口规则原文（生效 2026-10-16，PM 在对话里直接下达）在 `Dropbox/MagicLab_Studio/03_Enterprise/CTS/brandkit/youtube-operations/handoff-20261016/Shorts发布强制规则.txt`（Dropbox，不在仓库）；本页把它的七项与 97 号原 12 项合并成一份，**两边冲突取更严**。
- **总规则**：**失败、未知、未核实都不算通过**；任何一项不满足，停止发布并说明具体缺项；**不以创意认可、排期、其他窗口转述、工具输出替代本检查**。
- **勾选格式**：每项写「谁 + 何时 + 证据（链接或台账编号，不接受空话）+ **复核人（不能是发布人）**」。证据为空 = 没勾。
- **机器没拦**：封面是否生效、公开状态、授权是否存在，ME 目前都读不到；封面吸引力、前 1 秒是否最精彩这类**降低概率、不保证**，靠审查 agent 评分 + PM 点头。

## B. 发布后回执（**写进台账，一条发布一张卡**）

卡 id 形如 `YYYY-MM-DD-yt-shorts-<短名>`；卡头按 docs/ledger/README.md 的格式（id / title / status / owner / decided_on / source），**正文必填**：

1. 内部视频编号 / 版本
2. YouTube video ID 与链接
3. 频道名称与 channel ID
4. **平台实际发布时间与时区**（平台只显示日期就记录该日期，**另列本地提交 / 核实时间**，不把观察时间冒充精确发布时间）；**公开状态与平台处理状态分别记录**
5. **授权来源**：当前对话标识、PM 原文、对应版本
6. **封面上传与实际生效结论 + 证据**
7. 上表 10 项各自的勾选人、复核人、发布人（复核人 ≠ 发布人）
8. 出片工单号

**台账检查只校验卡头格式，不校验正文必填项**——所以回执齐不齐靠 97 号每天核对：发布当天未见回执就报警，收警报的是 97 号，抄统筹；超过 24 小时仍无回执，按「未经授权发布」处理，报 PM。**P3 做出来后改为代码硬拦。**
