# 团目录 SOP：新团必须补齐，才能安排上架

**规矩（PM 2026-10-26 定）**：新团在后台建好之后，下面「补齐清单」每一项都有了，才能排上架。缺一项就先补，不上架。
**为什么**：2026-10-26 录入 China Unveiled 时发现，客户发来的资料只有行程书和价格，没有图片、地图、网页标题等官网展示要用的内容。直接上架，官网上这个团会是光秃秃的一页。

## 流程（一步都不跳）

1. 收到新团资料（邮件 / 行程书）。
2. 后台 → 对应客户 → 团目录 → 「＋ 新建团」建空壳（只进草稿，不会上官网）。
3. 把行程、价格、出发日录全。
4. 按下面「补齐清单」逐项补。**补不出来的写进缺口，回头找客户要，不要编。**
5. 在后台看「上架前预览」，和官网同类团对一遍。
6. 过一遍下面的「SEO 检查」，缺一项就补或写明原因。
7. 清单全齐、SEO 检查过、PM 点头，才点「上架」。

## 补齐清单

| 项目 | 后台里在哪 | 要求 |
|---|---|---|
| 团名、短链、目的地、档次 | 新建团时填，**建好后不能改** | 档次和价位对得上，团名照同档次现有团的格式 |
| 天数、展示价、单房差 | 团详情 | 价格写法和同档次团一致，来自客户资料 |
| 出发日 | 班期 | 每个出发日有返程日；多个出发日航班不同的，写在行程里说明 |
| 每天行程 | 行程 | 每天有标题、内容、餐食；行程书里没有的不加 |
| 每晚酒店 | 行程每天的「住宿」 | **必须是客户给的酒店名**，不许编；没给就找客户要 |
| 主图 + 相册 | 图片 | 至少 1 张主图；相册同档次现有团有几张，这个团也要补到相近 |
| 图片来源 | — | 景点图首选 Unsplash / Pexels；**酒店、车辆、客户真实产品的画面只能用客户自己提供的**；图和景点对不上不用 |
| 途经城市 | 团详情 | 填全（只用于页面文字，**不会**自动出地图） |
| 亮点 | 团详情 | 3–6 条，只写行程里真有的 |
| 包含 / 不含 | 团详情 | 照客户资料，小费、保险、个人开销要写明 |
| 网页标题 + 搜索描述 | 团详情（网站内容） | 英文，AU/NZ 拼写，写进目标词 |
| 常见问题 | 团详情（网站内容） | 至少 3 条，答案都能在行程或客户资料里找到出处 |
| 一句话快答 | 团详情（网站内容） | 一两句，给 AI 搜索引用 |
| 路线地图 | **官网代码仓库**（不在 ME 后台） | 官网地图是手工做的图：桌面 + 手机两张 SVG 放进官网仓库 `public/tour-maps/<短链>.svg` 和 `<短链>-mobile.svg`，再把短链加进 `src/components/tours/TourRouteMap.tsx` 的名单；漏任何一步页面都不显示地图。底图用 Natural Earth 真实国界数据（见 cts-remotion 的 MapScene），别复用 Golden China 那个简化轮廓。目前 33 个团只有约 10 个有地图，多城市的团组才需要，单城市停留团可以没有 |

> 网站内容那几项只有 Magic Engine 管理员能改（后台权限限制）。

> **后台已自带提醒**：每个团详情页有「上架前补齐」进度卡（机器能查的项目自动打勾，查不了的列成「人工确认」）；上架弹窗里，如果这次要上架的新团还有缺项，会标红列出，并且要勾「我知道还没补齐」才能点确认。这是提醒，不是硬锁——要放行必须有 PM 同意。

## SEO 检查（上架前必过，让搜索引擎和 AI 搜索都能找到这个团）

依据：SEO 通用手册（关键词数据闸门、同主题页互相抢词、标题长度、新页面要人点头）。**数据都要真查，不能凭感觉。**

| # | 检查项 | 怎么算过 |
|---|---|---|
| 1 | 主关键词 | 每个新团定 1 个主词 + 2–3 个副词；搜索量和难度来自 DataForSEO（快照 14 天内），**查不到就写明「没数据」，不许当 0 放行、不许借别页的词**；词用客人真搜的英文说法，AU/NZ 拼写 |
| 2 | 会不会跟自己家抢词 | 把官网上同城市、同线路的团和博客列出来，看新团想排的头词是不是已经被它们占了；90 天内同一个词不给两个页用。抢词的，先改窄新团的定位，**要动别的页（改链接、合并、跳转）必须先报 PM 点头** |
| 3 | 网页标题 | 60 个字符以内（超了谷歌会截断）；主词放最前面；带上「从奥克兰出发 / NZ」这类本地词 |
| 4 | 搜索描述 | 约 155 个字符以内，写清天数、价位档次、一个卖点；不夸大，数字和团页一致 |
| 5 | 内容别太薄、别重复 | 行程每天有实质内容；和官网现有团（比如同样走广州、桂林的）比，不能大段原样重复 |
| 6 | 常见问题 | 至少 3 条，问法是游客真会搜的（来自 DataForSEO 相关问题或官网搜索数据），答案在行程或客户资料里有出处 |
| 7 | 一句话快答 | 一两句直接回答「这是什么团、几天、什么价」，方便 AI 搜索直接引用 |
| 8 | 图片 | 每张图的文件名和说明文字跟景点对得上；主图清晰不糊 |
| 9 | 站内链接 | 上架后，团列表页和同目的地的页面里要能点到它；该页没有「禁止收录」标记，页面指定的「以谁为准」网址是它自己 |

**上架后 SEO 验收**（看最终网页，不看系统回执）：
1. 官网团页打开，标题、描述、常见问题显示的就是后台写的。
2. 站点地图里有这个网址。
3. 用 `site:` 搜这个网址能查到才算收录；**没有可用的「请求收录」接口，不要写成「已提交收录」**，只能靠站点地图和站内链接等它被抓取。
4. 上架 2 周后看一次搜索数据：有没有曝光、主词排到哪。当场建日历提醒，写清查什么、怎么算成。

> 新增页面属于「新增内容」：SEO 手册规定一律要人点头才发布，所以第 7 步 PM 点头不能省。

## 红线

- 客户资料里没有的事实（酒店、航班、价格、景点）一律不写，缺口列出来问客户。
- 对外文案先对照客户官网同类团的写法，冲突以官网为准。
- 上架是对外动作，必须 PM 点头，录入的人不能自己点。

## 上架后

打开官网这个团的页面，核对：价格、出发日、图、路线地图（如有）、行程天数。有不对的当天改，改完再上架一次。
