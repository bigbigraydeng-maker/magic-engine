# DeepSeek Harness 当 agent 开发车间：调研与试验结论（2026-11-04）

来源：PM 窗口（研究 DeepSeek Harness 与 ME 的关联）+ 136 号窗口半天只读试验。试验原始报告与假数据在 PM 本机 `~/Projects/dsh-trial/`（不进仓库）。

## 结论

- **不当线上底座**：DSH 官方定位是单人本机工具，没有多客户隔离；定时任务关机就不跑、重启只补最近一次；SAFETY.md 写明未经安全审计；预览版约每周 1–3 个版本，会有不兼容改动。ME 线上 agent 继续用 Inngest + `src/lib/kernel/`。
- **可以当「agent 样品车间」，只喂假数据或去掉客户名的数据**：新 agent 写正式代码前，先在 DSH 里用中文 SKILL.md 做一次样品，用 ME 原代码算出的标准答案对比，判断准了再进正式开发（藏经阁第一部经「先 Harness 后 Loop」）。
- **接真 ME 暂不做（P3）**：要连新 ME，需要在新 ME 那边加一把只读专用钥匙，属于碰登录权限的 A 级改动；按 §11 打分是频率高 / IMPACT 低 / 收入低 → P3。

## 试验实测（DSH 0.2.1-rc.5，模型 DeepSeek-V4.1-Flash，约 1 小时）

| 问题 | 结果 |
|---|---|
| 装得起来吗 | 能。安装约 145 秒、占约 845MB；网页版只监听本机 |
| 能连新 ME 吗 | **不能**。新 ME 连接口只支持 OAuth 2.1 网页登录（授权码 + PKCE），DSH 的 MCP 客户端只支持请求头里写死钥匙，源码里没有 OAuth 流程 |
| 样品准不准 | 广告素材疲劳日检（D2），12 条手写假广告，标准答案由 origin/main 上 ME 原代码算出：**12/12 全对**，含显著性 p 值与停在第几步；从写完说明到第一次判断约 4 分钟，单次运行 38 秒 |
| 守不守规矩 | 模型层：说明里写「只读」时会先停下来问；**工作台层：「可写工作区 + 每次都问」不管 MCP 工具**，写入和对外工具没弹审批框直接调用（对着假服务器）；它还会在工作区外的 `/tmp` 写文件而不问；执行记录查看器能逐步看清工具名、参数、返回 |
| 其他 | 默认开遥测，发往 DeepSeek 服务器，本次用 `DSH_TELEMETRY_MODE=DISABLED` 关闭；花费远低于 1 美元上限（没拿到精确账单） |

## 用它做样品时的三条硬规矩

1. 只喂假数据或去掉客户名的数据，绝不连真客户账号。
2. 启动前关遥测（`DSH_TELEMETRY_MODE=DISABLED`）。
3. 不能指望它的审批拦住对外动作：样品里只放只读工具或假服务器。

## 没核实的

样品用的是假数据和简化规则（没测学习期、同组花费占比、多条广告一起校正）；真实数据上准不准未知。生态侧信息（约 8,650 个社区插件、同行把产品做成插件）来自官方文档与社区清单，没逐个读代码。
