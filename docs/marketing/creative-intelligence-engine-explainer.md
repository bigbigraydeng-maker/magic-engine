## 一、整体系统概览

Magic Engine 的 Creative Intelligence Engine 由三个核心技术模块组成，像流水线一样依次工作：

```
[视频/图片资产]
      ↓
[模块 1: VLM 视觉语言模型] — 理解内容
      ↓
[模块 2: pgvector 向量数据库] — 记忆内容
      ↓
[模块 3: XGBoost 机器学习] — 预测内容表现
      ↓
[输出: 投放决策建议]
```

这三个模块协同完成一件事：**让系统不只会"生成内容"，还能知道"什么内容对什么人有效"**。

---

## 二、模块 1：VLM（视觉语言模型）— 系统的"眼睛"

### 它是什么

VLM（Vision Language Model）是一种能同时理解图像/视频和文字的 AI 模型。代表产品：Google Gemini 2.0、OpenAI GPT-4o。

### 它做什么

当一条 Reels 视频生成后，VLM 自动"观看"这条视频，然后从 7 个维度给它打分：

| 维度 | 含义 | 低分示例 | 高分示例 |
|------|------|---------|---------|
| energy（活力） | 剪辑节奏、动感程度 | 慢镜头、长静止画面 | 快速剪辑、动态转场 |
| luxury（奢华感） | 高端质感、制作水准 | 手机随拍风格 | 电影级镜头、精致构图 |
| authenticity（真实感） | 纪录片感 vs 广告感 | 过度精修的商业广告 | UGC风格、真实场景 |
| emotional（情绪） | 情感共鸣深度 | 纯信息罗列 | 感人故事、情绪触动 |
| humor（幽默） | 轻松感、趣味性 | 严肃正式 | 幽默对话、搞笑元素 |
| urgency（紧迫感） | CTA 强度、稀缺信号 | 纯品牌展示 | "限时优惠""名额有限" |
| offer_signal（卖点强度） | 具体产品信息密度 | 纯氛围视频 | 价格、行程、具体卖点 |

### 工作流程图

```
Reels 视频文件（.mp4）
        ↓
Gemini 2.0 直接处理视频
  或
FFmpeg 抽取 8-12 帧截图 → GPT-4o 分析帧
        ↓
输出 JSON 格式的 7 维评分：
{
  "energy": 3,
  "luxury": 6,
  "authenticity": 7,
  "emotional": 5,
  "humor": 0,
  "urgency": 7,
  "offer_signal": 6,
  "dominant_persona": "Practical Buyer - Converter",
  "summary": "慢节奏城市美景配合强稀缺感文案",
  "recommended_audience": "35-55岁澳洲/新西兰计划出行家庭"
}
        ↓
结果写入数据库
```

### 真实测试结果（5条 CTS Tours 视频）

| 视频类型 | energy | luxury | urgency | 识别 Persona |
|---------|--------|--------|---------|------------|
| 文化慢镜头 | 6 | 7 | 0 | Luxury Aspirational |
| 北京行程推广 | 6 | 7 | 6 | Practical Buyer |
| 城市夜景建筑 | 3 | 7 | 0 | Calm Explorer |
| 标准行程广告 | 5 | 5 | 6 | Practical Buyer |
| 慢镜头+稀缺文案 | 3 | 6 | 7 | Practical Buyer - Converter |

**关键发现**：energy（视觉节奏）和 urgency（信息紧迫感）是完全独立的维度——一条视频可以画面很慢，但文案很紧迫。

## 三、模块 2：pgvector 向量数据库 — 系统的"记忆"

### 它是什么

pgvector 是 PostgreSQL 数据库的一个扩展，专门用于存储和检索"向量"（高维数字数组）。Magic Engine 使用的 Supabase 已内置此功能。

### 什么是向量（Vector）

用一个比喻理解：

- 传统数据库存"文字标签"：这条视频标签是"旅游、中国、文化"
- 向量数据库存"数字坐标"：这条视频在 512 维空间里的坐标是 [0.23, 0.81, 0.12, ..., 0.44]

这组坐标由 CLIP 模型生成，代表视频的完整视觉语义信息。

### 为什么用向量而不是标签

```
文字标签的问题：
  视频A标签：["旅游", "中国", "文化"]
  视频B标签：["旅游", "亚洲", "传统"]
  → 系统不知道 A 和 B 有多相似

向量的优势：
  视频A向量：[0.23, 0.81, 0.12, ..., 0.44]  
  视频B向量：[0.25, 0.79, 0.14, ..., 0.42]
  → 两个向量距离很近 = 视频风格非常相似
  → 系统能精确计算相似度
```

### pgvector 能做什么

**功能 1：相似创意搜索**
```
输入：一条表现最好的 Reels
操作：在向量空间里找最近邻
输出："这 20 条视频风格最接近，优先推这些"
```

**功能 2：风格聚类**
```
100条带向量的 Reels → K-means 聚类算法
输出：
  Cluster 1（共 34 条）：慢节奏文化系列
  Cluster 2（共 28 条）：高能城市夜景系列
  Cluster 3（共 38 条）：行程产品系列
→ 这些 cluster 就是系统自动发现的真实人格分组
```

**功能 3：内容缺口检测**
```
查询：luxury > 7 AND emotional > 7 的视频
结果：只有 3 条（严重不足）
对比：这类风格在 Markifact 中 ROAS 最高
输出警告："高奢侈感+高情绪共鸣的内容库存严重不足，建议优先生成"
```

### 数据存储结构

```
Supabase visual_assets 表

| id | asset_url | style_scores | embedding | markifact_roas |
|----|-----------|--------------|-----------|----------------|
| 001 | https://... | {energy:3, luxury:6, urgency:7...} | [0.23, 0.81, ...512维] | 3.8 |
| 002 | https://... | {energy:6, luxury:7, urgency:0...} | [0.71, 0.22, ...512维] | 2.1 |
```

## 四、模块 3：XGBoost — 系统的"判断力"

### 它是什么

XGBoost 是一种梯度提升机器学习算法，擅长从结构化数据（表格、数字）中学习规律并做预测。特点：

- 不需要百万数据，150-500 条记录就能出有效模型
- 训练快（分钟级），预测极快（毫秒级）
- 可解释性强，能告诉你"哪个特征最重要"

### 它解决什么问题

VLM 告诉我们视频"是什么风格"，但不告诉我们视频"能不能卖货"。XGBoost 填补这个空白。

### 训练数据从哪来

```
特征（X）：VLM 打出的 7 维风格分数
             [energy=3, luxury=6, authenticity=7, urgency=7, ...]

标签（Y）：Markifact 回传的真实投放绩效
             [ROAS=3.8, CTR=2.3%, CPA=45元]
```

每条有投放数据的 Reels，就是一条训练样本。

### 训练和预测流程

```
【训练阶段】（每月一次，数据量 ≥ 50 条时触发）

历史 Reels 数据：
  Reel #001: 向量[3,6,7,7,0,7,6] → ROAS: 3.8  ✓
  Reel #002: 向量[6,7,7,0,0,0,0] → ROAS: 2.1  ✓
  Reel #003: 向量[3,7,7,0,0,0,0] → ROAS: 1.8  ✓
  ... 共 150 条
          ↓
  XGBoost 学习：什么样的向量组合对应什么样的 ROAS
          ↓
  生成预测模型（保存到系统中）

【预测阶段】（实时，新 Reel 生成后立即）

新 Reel → VLM 打分 → 向量[5,7,7,4,0,4,5]
                          ↓
                   XGBoost 模型预测
                          ↓
         "预测 ROAS: 2.9（±0.3）"
         "最适合受众: Practical Buyer - Planner"
         "建议：加大 urgency 信号可能提升至 3.5+"
```

### XGBoost 最强大的功能：特征重要性

训练完成后，系统能自动告诉你每个维度的影响力权重：

```
对 Practical Buyer - Converter 受众：

urgency 的影响力      ████████████ 41%  ← 最关键
authenticity 的影响力  ████████    29%
offer_signal 的影响力  ██████      21%
luxury 的影响力        ██           6%  ← 几乎不重要
energy 的影响力        █            3%

结论：给这类受众做内容，花 80% 精力在
      "紧迫感文案" 和 "真实感"上，
      少花时间打磨画面质感。
```

## 五、三个模块如何协同工作

### 完整数据流

```
                    ┌─────────────────────────────┐
                    │     Magic Engine 生成 Reel   │
                    └──────────────┬──────────────┘
                                   ↓
              ┌────────────────────────────────────────┐
              │         VLM（Gemini 2.0 / GPT-4o）      │
              │  "看懂"视频 → 输出 7 维风格向量         │
              └────────────┬───────────────────────────┘
                           ↓
         ┌─────────────────┴──────────────────┐
         ↓                                    ↓
┌──────────────────┐              ┌─────────────────────┐
│  7 维风格分数    │              │  512 维 CLIP 向量    │
│  (可读，给人看)  │              │  (高维，给机器用)    │
│  energy: 3       │              │  [0.23, 0.81, ...]   │
│  luxury: 6       │              │                      │
│  urgency: 7      │              │                      │
└────────┬─────────┘              └──────────┬───────────┘
         │                                   │
         └──────────────┬────────────────────┘
                        ↓
              ┌─────────────────────┐
              │   Supabase pgvector  │
              │   （统一存储）       │
              └──────────┬──────────┘
                         │
              ┌──────────┴──────────┐
              ↓                     ↓
   ┌─────────────────┐   ┌──────────────────────┐
   │  相似创意检索    │   │  XGBoost 预测引擎     │
   │  风格聚类分析    │   │  输入：7维分数        │
   │  内容缺口发现    │   │  输出：预测ROAS/受众  │
   └─────────────────┘   └──────────┬───────────┘
                                    ↓
                    ┌───────────────────────────────┐
                    │        投放决策建议             │
                    │  "这条 Reel 预测 ROAS 3.8"    │
                    │  "最适合 Practical Buyer"      │
                    │  "urgency 维度还有提升空间"    │
                    └───────────────────────────────┘
```

### 三个模块的分工类比

用人类团队做类比：

| 模块 | 类比角色 | 核心能力 |
|------|---------|---------|
| VLM | 创意总监 | 看懂每条视频在说什么、什么感觉 |
| pgvector | 资深图书馆员 | 记住所有资产，快速找到相似的 |
| XGBoost | 数据分析师 | 从历史数据中找规律，预测什么能卖货 |

## 六、为什么这套系统比传统广告有优势

### 传统广告流程（现状）

```
创意团队凭直觉生成视频
        ↓
投放 → 等 2-4 周看数据
        ↓
人工判断："这条视频表现好，多做类似的"
        ↓
下一轮靠经验猜测
```

**问题**：决策依赖人的经验和直觉，慢、贵、不可复制

### Magic Engine 流程（目标状态）

```
AI 生成多风格 Reels（VLM 自动打标签）
        ↓
pgvector 立即检索：类似风格历史表现如何？
        ↓
XGBoost 预测：这条 Reel 的预期 ROAS
        ↓
只投放预测分高的 → Markifact 回传真实数据
        ↓
XGBoost 更新学习 → 下一轮预测更准
        ↓
飞轮自我强化
```

**优势**：数据驱动，每一轮都比上一轮更准

## 八、关键技术术语速查

| 术语 | 通俗解释 |
|------|---------|
| VLM | AI 的"眼睛"，能看懂图片和视频内容 |
| 向量（Vector） | 用一串数字描述内容的位置，相似内容 = 数字相近 |
| pgvector | PostgreSQL 数据库中专门存和查向量的工具 |
| CLIP | OpenAI 的模型，把图片转换成向量（让机器"理解"图像） |
| Embedding | 把内容（图片/视频/文字）转成向量的过程 |
| XGBoost | 机器学习算法，从表格数据中学规律并做预测 |
| 特征重要性 | XGBoost 告诉你：在所有输入变量中，哪个对结果影响最大 |
| ROAS | Return on Ad Spend，广告投入产出比 |
| Persona | 受众人格分类（Calm Explorer / Luxury Aspirational 等） |
| 冷启动 | 新客户刚加入时，还没有历史数据可学习的初始阶段 |
