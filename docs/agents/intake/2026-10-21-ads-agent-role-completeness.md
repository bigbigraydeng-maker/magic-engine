**三问：**
1. 让 PM 的哪个决定变好？——预算（每周分钱）和效果（哪条带来客人）是最近的；目前的复杂部分多半在「防出事」，而不是回答「钱花得值不值」。
2. 上游真有东西吗？——动作层有；**效果层的数据对应关系不全（4 行）**，数据新鲜度需要先修。
3. 怎么判断被用了？——`action_runs` 中 `triggered_by='agent'` 的条数、待办被处理率、学习库「已写进规则」条数。当前这三个数都是 0 或未建。

**设计师意见（初版）：** 暂停新增层（请求合同 / 回执台账 / 预告指纹 / 素材智能）；优先补「预算」和「效果」两个没人管的岗位的最小版；策略研究先推「待验证」落地，不再扩来源。决定权在 PM。
