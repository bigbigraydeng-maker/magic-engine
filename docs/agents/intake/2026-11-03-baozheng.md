## 附：子牙九问自答

1. 与现有架构有没有矛盾：没有。只读 CRM 表、写 `cron_run_logs` 和今日待办，都是现成通道。
2. 对记忆层写入权限：不写共享记忆；错题只在客户私有范围。
3. 输入为空 / 格式错 / 超大：没有 AI 判断 → 本轮写「无可复核」；原文缺 → 那一条不抽查、写原因；一周超过 500 条 → 抽查只抽 10 条，准确率照算全部。
4. 假设：人改阶段会写阶段记录（已核：写入路径都留记录，绕开的只有删阶段批量改派，量为 0）；AU/NZ 客人英文为主、偶有中文，抽查模型两种都能读。
5. 六个月后扩展：判对判错规则按「判断种类」做成接口，问询筛查、评论分流以后按同一接口接，每接一个算一次立项。
6. 对 agent 权限矩阵：新增只读 agent，档 1；不改其他 agent 的权限。
7. 失败谁先感知：运行记录 + 每周闭环巡检；连续 3 个周期零产出进今日待办问 PM。回滚 = 关总开关。
8. 跳过要留痕：开关关、没数据、模型调不通，都写进 `summary.reasons`，「判不了」和「判对」分开记。
9. 依赖定时任务：是。登记表时间和 Inngest 实际调度在第 3 关一起写，避开周五、周六和 7 的倍数天。
