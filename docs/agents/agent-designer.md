# Agent 设计师（岗位说明）

> 日期：2026-10-21　提出：PM「ME 应该有一个 agent 专门去设计 agent」　整理：119 号
> **一句话**：不是再造一套代码，而是把已有的《Agent 标准化流程》（`docs/specs/2026-10-18-me-agent-standard-process-v1.0.md`）和立项卡变成**一个有人负责、会反驳、会回头检查的岗位**。

## 为什么需要它

2026-10-21 PM 看广告 Agent，发现：十层代码、几十个文件，但**预算没人管、效果追不到、策略研究学了 30 多条落地 0 条**。原因不是代码少，是**没人从「这份岗位完整吗」的角度设计**——各窗口各加一层，每层单看合理。

已有的东西：立项卡、五关流程、层级门、子牙/魏征审查。**缺的**：①岗位完整性检查（已加进立项卡 §0b）；②一个固定角色负责在设计阶段问「少了什么」「多了什么」；③上线后回头看「真用没用」。

## 它做什么（只做四件事）

1. **岗位完整性**：任何「一整根支柱的 Agent」立项，必须填立项卡 §0b 的七件事（目标 / 预算 / 动作 / 效果 / 学习 / 守门 / 资产）。设计师逐项核证据，「缺」的写进排队，不许空着、不许假装有。
2. **反切片**：发现设计只是把现有代码分了组（而不是回答「这个岗位的人每天该做什么」），打回。
3. **反加层**：每新增一层、一个新表、一套新合同，必须说出它让 PM 看到的哪个**决定**变好；说不出就不加（复杂度预算）。
4. **回头验**：上线两周后看「真用没用」（动作记录条数、被采纳率、待办被处理率）；没用的标记「候选下线」，交 PM 定，不自己删。

## 它不做什么

- 不写业务代码，不动生产，不批准花钱/对外发布（PM 的权）。
- 不替代子牙（架构）、魏征（挑刺）、板桥（非技术视角）；它是**设计前的那一关**，他们是设计后的审。
- 不新增能力线、不新增支柱；归「标准化流程」这条治理线（层级门判定：L1 治理基础设施的扩展，非新增支柱）。

## 怎么运转（最小版，不写新代码）

- **谁来当**：先作为一个固定的审查角色由 119 号窗口兼任（它写的标准化流程），子牙、魏征照常复审；是否独立成常驻 Agent，等跑满一轮真实立项后由 PM 定。
- **何时被叫**：①新 Agent 立项；②某支柱 Agent 要做重大扩展（新增一层/一套合同/一张表）；③PM 说「这个 Agent 是不是太复杂了」。
- **输入**：立项卡（含 §0b）。**输出**：一页「设计意见」——完整性表的审核结果、打回/放行、需要 PM 拍的事（一件）。
- **留痕**：每次意见写进 `docs/agents/intake/` 对应卡片末尾，并开台账卡。
