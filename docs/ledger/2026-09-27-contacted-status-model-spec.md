PM 2026-09-25 提的需求 2（系统自动回 ≠ 已联系）终于写成定稿。之前一直被 PM 自己的追问往后推（他先要界面、后来转向合并板块、再插队 WhatsApp、再问电话），小秘书 2026-09-27 提醒别让主线被盖过去 —— 这笔是我欠的，当天补上。

## 三个数字（全部实测）

- CTS **451 人**标着「已联系」，其中 **447 次机器推的、4 次真人改的**（99.1% 机器）
- 但逐人查真人动作：**389 人确实被联系过，62 人（14%）一条都找不到**。**不是 447 人 —— 把「机器记录的」当成「没发生过」会把问题夸大 7 倍**
- 根因不是判得不准：**全库 2074 条出站记录里，标了「机器发的」是 0 条**。判据函数是好的，只能认出那 25 条群发。**不是判不准，是没东西可判**

## 我更正了自己一个错报

曾跟 PM 说「14% 只是下限，真实更高，因为我们自己的自动回复看起来像真人」。查了生产：**那条自动回复一次都没跑过**（发送记录 5 条、机器人 0 条，发件人全是真人）。代码路径确实会分不清，但它没污染任何数据。**拿一条 0 行的路径论证是错的。**

## 稿子里最关键的一条

**`stage` 是「我们认为他到哪一步了」，不是「有人联系过他」。**

AI 判阶段没有错（971 次判断 971 次带理由和客人原话）。错的是把它的结论当成「有人联系过他」。前者可以由 AI 判、判错改一下就行；后者只能由「真人做过一个动作」这个事实决定，**不能由任何判断推导出来**。

这跟记忆里「状态字段当授权用，闸必漏」是同一个形状：让一个可被 AI 写的字段去证明一件只有事实能证明的事。

## 修的顺序不能反（五个漏口）

S1 先修 `isHumanActor`（它把 `governed-reply-agent@magicengine.cloud` 判成真人，因为判据是「含 @ 就算人」）→ 不先修它，写入侧补完了读侧照样认错。
S2 写触点时带发件身份 + 把 `isAutomatedPageMessage` **已经算出来但被丢掉**的结论落库。
S3 `mail-send.ts` 别再硬写 `automated: false`（那是主动的假话）。
S4 才让 `segments.ts` 开始读 `automated` —— 放在前面等于白改一轮（库里还是 0 条标记）。
S5 回填。S6 界面三态（不做二值开关：今天 2049/2074 都是「不知道」）。

**S4 的方向必须是错杀不是错信**：判不准的一律当真人。错杀一个真人 = 线索多露一次面；错信机器是真人 = 热线索被埋，而且是静默的。

## 验收口径要写清（防自己骗自己）

修完之后「没人碰过」的人数**可能变大**（现在算成真人的那些被认出是机器了）。**变大是对的。**「数字变好」不是验收标准，「每个人为什么在名单上说得清」才是。
