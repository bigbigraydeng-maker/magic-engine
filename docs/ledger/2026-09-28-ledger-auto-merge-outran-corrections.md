2026-09-28 卫青同一夜踩两次：PR #2094 后续提交在合并前才推上，只能另开 #2095 补；更严重的 #2141 在 12:05 UTC 合了 `2026-09-28-ads-pullback-red-for-a-month` 的第一版，两轮更正 12:10 才推上分支——主干上那张卡写着作者已撤回的修法（按「客户」归类预期内跳过），正确判据是 (客户 × 数据源 × 失败原因)，照主干那版做会把 9/16 那次 GA4 权限故障埋掉，比不改更糟。补送 PR #2143，并当场通知正在拿这张卡派活的广告构建控制窗口「别读主干那版」。
自动合本身没错（只改台账免 PM 审批是 2026-09-25 拍板的），错在把「还在改的东西」放进会自己合的通道；台账尤其危险，因为它是每个工作日程序会读一遍、别的窗口派活也会读的地方。
作者侧做法（本窗口起照此办）：结论还可能变 → `gh pr create --draft`，定稿再 `gh pr ready`；已经合了才发现要改 → 立刻另开补送 PR，不等「下次顺手带上」，并主动告知在用这张卡的人。
推完更正回查 `git merge-base --is-ancestor <sha> origin/main`，「我推上去了」不等于「主干上是这版」。
本卡只钉这个流程缺口，未改任何机制代码。
