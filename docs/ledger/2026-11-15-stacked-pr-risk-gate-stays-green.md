verify_by: 2026-11-22
verify_how: 本修复合进主干后，找一条 GitHub 原生叠放、且其他条件已满足（已签字、必过检查全绿、审查对话已解决、不是草稿、不用人亲手合的敏感文件）的拉取请求：Risk gate 为绿，摘要写明叠放不支持自动合并、需从栈底手动合，且自动合并未开启。另找一条同样满足条件但不是叠放的拉取请求，确认自动合并仍会开启。缺签字或检查未绿的叠放请求必须仍是红的。
---
GitHub 对叠放的拉取请求拒绝打开自动合并。合并闸把这次拒绝记成检查失败，必过检查一直红，请求合不进去。
修法：其他条件都已通过、本来就要开自动合并时，先看是不是叠放；是就通过，并写明要有权限的人从栈底手动合。其他开启失败仍判红。
当场跑不了：这个环境不能对一条真实的叠放请求触发打开自动合并。合进主干后按 verify_how 核对。
