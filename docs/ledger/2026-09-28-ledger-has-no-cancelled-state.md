2026-09-28 实测：`src/lib/ledger/walk.ts` 的 `classify` 里，`verified` 直接 `return null`（不再出现），而 `failed` **无条件**变成 `verification_failed` 待办，没有任何按 `verified_ref` 或接替卡抑制的分支（Codex 复审指出，卫青读码确认）。
**撞上它的实例**：15 秒素材重测那张卡（[[2026-09-26-nal-messenger-15s-retest]]）因为所在广告系列 9/28 被整个停投而**取消**——它既不是「验过了成」，也不是「判出来不成」，而是没机会跑。我把它标成 `failed`（诚实），代价是从下一封每日邮件起会天天催 PM「重做或关闭」一件已经取消的事。
**为什么不标 `verified` 了事**：`verified` 的定义是「验过了、成」。为了让待办清静而标它，就是用一条假的成功换清静——那正是这两天在修的那类毛病（假绿 / 假红让人学会忽略真信号）。
**优先级（§11）**：频率 低（偶尔才有卡被取消）/ IMPACT 低（不在产品闭环）/ 收入 低 → 三个低 → **P3** 待认领。在它修好之前，取消类的卡一律照实标 `failed` 并在 `check_note` 写明「取消、不是判出结果」。
