2026-09-28 卫青在推 PR #2131（A 级）时实测发现：闸门要 `ziya/weizheng/direnjie` 三个签字，但 GitHub 仓库变量 `ME_SIGNOFF_TRUSTED_LOGINS`（工作流里映射成进程环境变量 `SIGNOFF_TRUSTED_LOGINS`）是空的（运行日志里该变量打印为空值，不是遮掩的密钥），而 `selectTrustedSignoffMarkers` 在可信名单为空时会丢掉所有签字标记（另外永远排除 PR 作者本人）。**所以三方签字在今天这套配置下无法被任何人满足。**
**后果不是「多一道人工步骤」，是闸门给出的信息有误导性**：#2131 实际由子牙 + 魏征真审过、并按意见改了三处、复签了 SHA，但闸门显示的仍是「缺签字，由 PM 决定是否绕过」——**真审过的 PR 和没人看过的 PR，在 PM 眼前长得一模一样**。PM 每次都只能选「绕过」，久了就会不读而绕过。这跟同期在修的「假红让人学会忽略真红」是同一个病。
**修法两条，哪条都行，但不能不动**：①把 B3 签字自动写入路径建成并上线，再给 GitHub 仓库变量 `ME_SIGNOFF_TRUSTED_LOGINS` 配上值——只配变量、不建写入路径，签字仍然写不进去，这条路照样是死的；②在此之前，把 A 级不通过的文案改成「签字机制未建成，请人工核实审查记录」，并要求 PR 正文写明谁审过、签的哪个 SHA。
**优先级（按 ENGINEERING_QUALITY_GATES §11）**：频率 高（每个 A 级 PR 都撞上）/ IMPACT 闭环关键度 低（本卡已明确这只卡治理闸门，不在产品 IMPACT 闭环里）/ 收入关联度 低 → 两个低、一个高 → **P3**（记入 ROADMAP 待认领）。
本卡只钉事实，未改闸门代码（`.github/` 与 `tools/ops-review-loop/` 都是受保护路径，改它们自己又是 A 级，得走同一道门）。
