自动审查（Codex）第六轮指出：`findDrops` 判 CBO 连坐时，`children` 只取当前快照里的子广告组（`account.snapshots.filter(r => r.level === 'adset')`）。如果一个别家主页的子组已经从快照删除，它不会被算进 `children`，所以不会触发「整个系列连同子组都不判」；孤儿处理（`orphanIds`）只会把这一个已删除的组自己排除掉，客户自己还在投的兄弟组和系列本身仍会被判 own，进入 D5/O3 的预算对比。

评估：这不违反"别家的钱算给客户"这条核心不变式——已删除的别家子组自己的花费仍然通过孤儿处理被排除、不算进客户账下；受影响的只是 D5/O3"同角色预算单位公平不公平"这条比较，可能因为系列历史上曾经和别家共享过预算分配而不够准。要堵住需要把 D5/O3 用的日数据 `parent_id` 也接进 CBO 连坐判断，识别范围从"当前快照里的子组"扩大到"窗口内出现过、按日数据能关联回这个系列的所有子组（含已删除的）"，改动会牵涉 `findDrops` 的系列/广告组两层遍历逻辑，工作量和这条 P2 的实际可达性（要求一个 CBO 系列里恰好混过别家子组、且已经删除）不成比例，本 PR 未采纳。
