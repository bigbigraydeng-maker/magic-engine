这一页原先只按「最近联系时间」平铺，**谁该先被联系看不出来**。现在多一个按钮切到 4 段：客人在等你 / 还没搭上话 / 先放着系统盯着 / 不在今天名单。口径跟「今天要联系」那一页共用同一套判据，不是这一页自己另算。默认仍是平铺，老用户打开看到的东西一个字没变。

当场试跑（生产真数据喂进真页面，不是手搓假数据）：
- CTS 1010 人 → 217 / 74 / 643 / 76，自定义列「感兴趣的团」也跟着出来了
- NAL 197 人 → 22 / 7 / 167 / 1
- 两个客户 13 项检查全绿：收起来的段照样显示段头和人数、人数认接口给的 total、展开的段每个人都画出来、点段头真的带着它重新要数据

试跑当场抓到两处，都在合并前改掉了：
1. **探针自己判错**：CTS 有个客人把备注写进了姓名栏（`Hong  Nguyen. no  pbone  call please`，中间双空格）。页面画出来了，探针却报「少 1 个」——testing-library 会规范化 DOM 里的文字但不规范化你传进去的字符串。狼来了比不报更糟，已压空白后重跑全绿。
2. **为了能验真路径，顺手把 `responseRowFor` / `stageMetaOf` 从 678 行的路由文件搬进 `lib/crm/contact-response-row.ts`**。不搬的话脚本导不出这两个函数，只能自己另写一份「差不多的行」去喂页面——那验的是另一条路。2026-09-26 NAL 止血就是栽在这：验了「Meta 会放行」，没验「我们自己的代码会放行」。

还欠着的：`crm/all/page.tsx` 现在 965 行，超了仓库的 800 行线。R6 第二轮（把 ContactDetail / MarkWonPanel / ImportantMarkerEditor 也搬出去）下一轮做，主干上现在没别人动这块目录了。

## 两方复审（子牙 + 魏征，2026-09-27）判「改完再合」，已全部修掉

三个都是「员工以为自己做了某件事，其实没有」，都在这页跟进团队每天开的页面上：
1. **段头写 217 人、表里只有 100 行，剩下 117 个人没有任何入口** —— 服务端 `?p_<段>` 早就收了，前端一次没发过。已接上段内翻页 + 明写「共 N 人、正在看第几到第几」。
   写的时候差点二次犯错：我先按「累加」做了个「再看 100 个」按钮，查了服务端才发现它是 `slice` 翻页——那样会让前 100 个人凭空消失，正是这条要修的毛病换个方向再犯。
2. **分段模式下点⭐，库改了页面星星不动** —— 乐观更新只写了平铺那份数据。点两下没反应，人只会以为坏了。
3. **分段模式下表头排序是死按钮**，箭头还会变一下骗人；而平铺那句「排序只对当前页生效」在分段下反被藏起来。

顺带修掉：四段全收起时冒出「大家阶段都空着」的假话；展开到数据回来之间一片空白（「在加载 / 真的空了 / 坏了」三件事长得一样）；`?contact=` 那一段关不掉且每次白跑一整轮。

**测试和探针为什么没抓到**：它们都在验「页面忠实画出了接口给的东西」，没有一处验「接口给的东西就是人该看到的全部」。魏征重做变异，我自选的 5 个全被杀、他另挑的 5 个全存活，其中 M11 最典型——把页面转发 `?contact=` 那两行删掉，那条名叫「直达链接自动展开那一段」的测试照旧绿，因为假服务端无条件回 focus。现在假服务端只在请求真带了 contact 时才回。
我自己补的⭐测试也先绿错了一次：断言写的是页面上有没有「⭐」这个字，而**表头那一列的标题本身就是「⭐」**，恒真。改成认 aria-label 才真的钉住。顺带发现 fixture 少了 `pinnedAt` 这个键（真接口永远有），少了它点⭐会走成「取消置顶」。

**魏征那条依赖版本的意见，查证后两边都不对，最后整个依赖去掉了**：他说 `@types/jsdom` 该写 `^29` 对齐 `jsdom@29.1.1`。实测 DefinitelyTyped 没发过 29.x（27 / 28.0.0–28.0.3 / 30.0.0，中间是空的），`^29` 装不上。但真正的问题是**这个依赖本身不该加**：合并闸把任何 package.json 改动判成 A 级（引入新依赖 = 供应链面），于是整个 PR 要 PM 手动点合并 —— 为一个只在探针脚本里用的类型包换来每次打扰 PM 一次，不值。改成 `scripts/types/jsdom.d.ts` 里一份手写最小声明（只声明用到的两个成员，漂移了立刻编译报错），依赖清单回到跟主干一字不差。
