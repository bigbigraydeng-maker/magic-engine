## ME 的关键词/SERP 数据源统一是 DataForSEO，不是 Semrush

- 规律：所有 SEO/SERP/关键词研究一律用 `src/lib/dataforseo/` 封装，不用 Semrush MCP。
- 为什么：PM 纠正过一次误用 Semrush MCP 的实例——Semrush 的 MCP 是账号级历史授权，跟 ME 系统栈无关，拿它的数据会跟 ME 判断对不齐。 · 证据：doc:docs/DECISIONS.md#2026-05-18 · operational experience（2026-08-28 PM 纠正）
- 怎么用：任何 SEO 任务第一步查 `src/lib/dataforseo/` 有没有现成封装（`serp.ts` 拿 SERP、`labs.ts` 拿关键词面、`client.ts` 拿竞品/反链/排名、`business-data.ts` 拿 GMB/Reviews、`search-volume.ts`/`onpage.ts`/`domain-analytics.ts`），缺了才写脚本直调。Location codes：AU=2036，NZ=2554；NZ 用 `google.co.nz`，AU 用 `google.com.au`。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 自动改客户网站文案必须先过"信息完整闸门"，缺一项就跳过

- 规律：自动改标题/描述/摘要前，6 项闸门全过才允许改，缺任何一项该页跳过并写回执说明卡在哪。
- 为什么：首次上线自动改文案时合并了 2 个改动全错且已上线——关键词匹配按"共享 token"挑最高曝光词导致抢别页的词；生成的摘要跟原文事实相反；DataForSEO 实际没调用成功。当场撤回。 · 证据：pr:201 · pr:202 · doc:docs/PITFALLS.md#d10 · doc:docs/DECISIONS.md#2026-09-20
- 怎么用：
  - 闸门清单（缺任何一项 = 跳过）：
    1. 目标词有 DataForSEO 搜索量+难度（快照 <=14 天或现场查到）
    2. 实时 SERP 前 3 名标题已取
    3. SERP 里客户排名的 URL 就是这一页（不是客户自己另一页）
    4. 词含这一页的主题词，且是受众语言
    5. 同一个词 90 天内没被别的页用过（防两页抢同一词）
    6. 新文案不与原文事实矛盾
  - 长尾词数据不够时三级取法：(1) 客户主 location 的 DataForSEO 数据 (2) 客户级配置的兜底 location（这是客户级配置项，不是平台默认行为，换客户要 PM 单独点头） (3) 全客户通用兜底：需求量用该页 GSC 真实曝光 >=30，难度用实时 SERP 前 3 域名强度估算。三级都拿不全 = 跳过，"没数据当 0 放行"永远禁止。
  - 上线前先跑 `dry_run`（只出方案不改网站）给决策者看过再打开自动开关。
  - 验收看最终改出来的文字本身——曾出现过六步回执全部 completed 但改动内容其实是错的。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 判"页面内容太薄"之前先排除"抓取被反爬挡住"这种脏数据

- 规律：看到"内容太薄需要补内容"的判断，先确认该行数据的抓取状态是正常抓到的真实页面、不是被目标网站反爬机制（WAF）拦截返回的验证页/中间页。
- 为什么：多个页面被误判"内容太薄"，实际是对方网站防火墙返回的人机验证页（标题类似 "Robot Challenge Screen"），不是真实页面。分类逻辑只看 `word_count` 没联动 `crawl_status`，同系统其它消费方都排除了脏行，唯独"收录状态"这条链没对齐。 · 证据：operational experience（2026-09-08 实例，2026-09-26 生产复查）
- 怎么用：
  - 代码落点：`seo-patrol/index-check.ts`、`blog/content-gate.ts`、`seo-patrol/page-signals.ts` 用 `.eq('crawl_status','crawled')` 排脏行。
  - 检测器：`src/lib/site-audit/antibot-detector.ts` 的 `detectAntibotChallenge(markdown,title)`。
  - 注意检测器漏检：当 Jina 回来的 title 为空，爬虫退回取正文第一个大标题（=裸域名），而 "Robot Challenge Screen / robot-suspicion.svg" 只出现在正文里，正文指纹表没有这几个词——生产可能所有行都是 `crawl_status='crawled'`。查法：`markdown_content ILIKE '%Robot Challenge Screen%' OR ILIKE '%robot-suspicion%'`，别按 title 查。
  - 别清 `first_not_indexed_at`：「没收录」是 GSC 给的结论，跟 ME 自己抓没抓到正文无关；清掉会把真没收录的页面藏起来。收录结论照常查照常报，只有「内容太薄」这类看正文的判断跳过被挡的行。
  - 重新爬一次不代表自动纠正历史脏数据——如果修复逻辑刻意保留旧 title/word_count，旧误判不会自愈，需单独跑数据修复。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## SEO 自动化人工把关分界线：小修全自动，新增内容/内链要等人点头

- 规律：标题/描述/旧文小更新全自动；新文章、新页面、加内链一律进待办等人工点头。每客户每周最多 1 篇博客。先修断的问题再上新。
- 为什么：PM 拍板的四条界线——"改已有内容小地方"风险可控能马上看出改错了，"新增内容/新增链接结构"做错纠错成本高（新页面可能已被搜索引擎收录、内链已影响权重分布）。 · 证据：证据待补
- 怎么用：自动执行范围 = 标题/描述/旧文小修 + 周报可见。超出范围的（新文章/新页面/加内链/改 canonical/跳转/内链拓扑/合并页）= 先出方案 + dry_run → PM 点头 → 执行。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## AI 事实核对闸门不会自己想到"范围被缩小也算事实冲突"，必须显式列进提示词

- 规律：用 AI 判官做"新文案跟原文有没有冲突"的事实核对，提示词里必须显式加"服务范围/地理覆盖被收窄或含糊化"这一类矛盾，否则判官大概率漏判。
- 为什么：AI 判官对[旅游客户]全站最赚钱的商业页判了"通过，无矛盾"，但人工核对发现新标题把服务范围从"两城出发"收窄成了"一城出发"——该页正文明确写着另一座城市出发的信息。判官的提示词只列了"价格/签证/日期/库存/地点"，没有"覆盖范围被缩小"这一类。这类错误不是"说了假话"而是"把真话说得更模糊"，AI 天然不敏感。 · 证据：operational experience（2026-09-23 复核）
- 怎么用：
  - 提示词里除数值型矛盾外加一类"服务范围/地理覆盖被收窄或含糊化"。
  - 转化型商业页（报价页/落地页/主要询盘入口）叠加硬规则：新文案丢掉旧文案里的具体数字/专有名词（价格/日期/出发城市/认证资质）= 跳过转人工。
  - 商业/转化页建议单独列"不许自动改"名单，跟内容型页面分开处理。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## "没收录"能自动到哪一步：外部边界

- 规律：谷歌 Indexing API 只准用于 `JobPosting`/`BroadcastEvent` 页，普通页用 = 违规；GSC"请求编入索引"按钮没有 API 接口；站点地图 ping 已失效；IndexNow 不含 Google。能全自动的只有"每天查 + 按谷歌原因归类 + 剔掉不是问题的 + 送待办"。
- 为什么：2026-09-26 官方文档逐条核实。谷歌官方写明滥用 Indexing API 会收回权限且普通页请求被静默丢弃；`google.com/ping` 回 404、`bing.com/ping` 回 410；GSC API 只有 `searchanalytics.query` / `sitemaps.*` / `sites.*` / `urlInspection.index.inspect`，全是只读。 · 证据：operational experience（2026-09-26 官方文档核实）
- 怎么用：
  - URL Inspection 配额：每站每天 2,000 次/每分钟 600 次，只读。ME 目前每客户每天 20 次。
  - 按谷歌原因分"不是问题"的：`Page with redirect`（目标页收录即可）、`Alternate page with proper canonical tag`、有意的 noindex、插件/参数垃圾网址、商品标签归档页。
  - `Discovered` = 谷歌还没爬，别跟「爬过没收录」混成一类。`Crawled - currently not indexed` 官方说 "no need to resubmit"，是谷歌自己的质量判断。
  - 「改网站」只在 ME 有写权限的站做，noindex/规范网址/跳转这类一改错就把页面踢出谷歌的改动要人点一次头。
  - 「让谷歌收录」谁都做不到，别承诺。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 说"某个 SEO 动作有效/无效"之前先过三关

- 规律：拿 SEO 效果数据下结论前必须过三关——动作真执行过吗？比的是单页还是整站？经验库里的 SEO 经验能不能信？
- 为什么：2026-09-26 生产实查发现三层问题。(1) `flywheel_actions` 里 SEO 建议在生成时就写了 `executed_at`，`execution_item_id`/`action_run_id` 全空，没有一条带执行回执——给没发生的事打分。(2) SEO 归因全是整站 28 天前后差（单页结论 0 条，因 GSC 快照只存前 50 页/前 50 词），整站涨跌跟单个动作没有可比性。(3) SEO 经验 112 条"有效"+89 条"失败"当噪音看——同为"更新旧文章"，[客户 A] 记"+77.5%"、[客户 B] 记"-43.2%"，两家都没人动过文章，只是整站流量一涨一跌。 · 证据：operational experience（2026-09-26 生产实查）
- 怎么用：
  - 关一（真执行过吗）：查 `executed_at` 不够，要看 `execution_item_id`/`action_run_id` 和配套动作卡是否完成。
  - 关二（单页还是整站）：按产品定义只能记单页/单词级比较，整站差只能记"不知道"。代码：`flywheel/attribution/gsc-bridge.ts`，快照参数 `SNAPSHOT_ROWS=50`（`src/lib/gsc/client.ts`）。
  - 关三（经验库能信吗）：`memory/extractor.ts` 转出的 SEO 经验当噪音看。诸葛亮出处方时默认读最新 15 条有效 + 10 条失败经验（`memory/format.ts`）。下架走 `is_active`，可逆，但属改正式数据要 PM 点头。
  - 附带：`flywheel-seo-weekly` 上线后 0 条写入——`recentlySnapshotted` 闸按 flywheel='seo' 查，被每天 GSC/GA4 拉数堵住。查"周任务有没有真干活"要看它自己来源的数据行，别看 cron 状态。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 多页同题必先做"自家自相残杀"体检

- 规律：一个站对同一主题堆了多页时（枢纽页 + 分类页 + 商品页 + 博客），当枢纽页是该主题在自家页面里曝光第一名时它才排得进谷歌第一页；被兄弟页压在下面就沉底。先修自相残杀，再改标题补内容。
- 为什么：[旅游客户]多城指南页实测——枢纽页是"自家第一名"的城市恰好在谷歌第一页，被兄弟页压住的城市全排不进前 20。很多"排不上"是被自家页抢了词，不是页面差。 · 证据：operational experience（2026-09-28 实测）
- 怎么用：
  - 体检三步：(1) GSC 页级：同主题所有自家页按曝光排序，看目标页排第几。(2) DataForSEO `site:域名 主题词`：看谷歌为该主题优先给哪个自家 URL；再对头词跑实时 SERP 看外部哪个自家 URL 在露面。(3) `site:域名/具体网址` 单独查：确认页面还在索引里——能查到 = 收录着，问题是"没被选中"不是"没收录"。
  - 修法分寸：高曝光但意图不同的兄弟页是好长尾，别删，把内链往枢纽页汇；真正跟枢纽页抢同一个头意图的（分类页/薄商品页/泛泛重复页）才动——改窄定位/改标题岔开，或 canonical/跳转到枢纽页。
  - 权限：改 canonical/跳转/内链拓扑/合并页 = 先出方案 + dry_run + PM 点头；单纯改标题/描述走信息完整闸门 + dry_run。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 取数陷阱三条：别用页面标题里的词当目标词 / 低量词 SERP 单次不算数 / 实时 SERP 参数必须固定

- 规律：(1) 别看页面标题写着什么就当目标词——先拉这一页真实排的词和量。(2) 低搜索量词（月搜 10-50）SERP 极不稳定，单次拉取不能当依据，同参数多拉 2-3 次取一致结果。(3) `serp/google/organic/live/advanced` 的 `depth` 不同会拿到不同快照，前后对比必须固定全部参数。
- 为什么：(1) [旅游客户]某指南页标题以 A 词开头，直觉要改成 B 词，实查 B 词量只有 A 词的 1/26——改了等于把大词让出去换小词。(2) NZ 小市场大量词月搜只有 10-50，谷歌信号少，第一页混着 Reddit/Quora/论坛/别国站/PDF，名次天天变。(3) 同一词同 location，`depth=20` 和 `depth=30` 返回两份完全不同的结果列表（top3 域名全不一样），据此写下的"排名剧变"全是参数不一致造成的假结论。 · 证据：operational experience（2026-09-28 实做）
- 怎么用：
  - 动标题前：先跑 `dataforseo_labs/ranked_keywords`（按 URL 过滤）拿该页实际排的词+位次，再跑 `keyword_overview` 把候选词量摆在一起比。"这类页面的头词通常是 X"是假设不是数据。
  - 低量词：同参数多拉 2-3 次，取一致结果。
  - 参数纪律：同一轮前后对比的所有 SERP 调用，`depth`/`location`/`language` 全部固定。
  - 该接口返回的 organic 列表本身会出现同一域名/URL 重复——看到"自家网址出现两次"先看同一份结果里别的域名是不是也在重复，是的话是列表假象。
  - 词级自相残杀只能用 `ranked_keywords` 查，GSC 页级看不出"哪个词是哪一页在排"。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 北极星是整站曝光+点击，不是"指定那几页上第一页"

- 规律：客户/PM 交代的往往是"这几页、这几个词"，但真实目标几乎总是整站曝光和点击。指定页和指定名次只是手段不是目的。每轮 SEO 任务必做一次"近门槛机会扫描"，把比指定任务更大的机会主动报给 PM。
- 为什么：被指定要冲第一页的多个页面头词 NZ 月搜只有 10-70；而范围外一个页面在月搜 210、难度 4 的词上排 #17，后者往第一页推一步的点击增量比前者整组加起来还大。月搜 10 的词就算冲到第一名点击增量约等于 0。PM 拍板："一切最终目标都是提升网站的 impression 和 click，我遗漏没有提到的，你主动发现很好。" · 证据：operational experience（2026-09-28 PM 拍板）
- 怎么用：
  - 扫描步骤：(1) `ranked_keywords` 拉全站 #11-30 且有真实搜索量的词。(2) GSC 页级拉曝光高但均排名 8-20 的页。(3) 按量 x 差多少名估潜在增量排序（不按"能不能进前 10"排）。(4) 把比指定任务更大的机会主动报给 PM。
  - 纪律：主动报，不擅自扩范围去改。汇报时把"指定范围的上限"和"范围外机会的上限"放一起比，PM 才能判。
  - 判效果回到北极星——看单页曝光/点击真实增量（单页比，不拿整站涨跌邀功），名次是中间指标。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 诊断"排名不错但没人点"，本地拉不到 GSC 词级数据——这是真实工具边界

- 规律：`fetchGscQueriesForPage`（`src/lib/gsc/client.ts`）是单页词级查询封装，能诊断"曝光高点击率异常低"，但所需的 `GOOGLE_SERVICE_ACCOUNT_CREDENTIALS` 只在 Render 生产环境有，本地/worktree 拿不到。
- 为什么：实测低 CTR 页面诊断时撞到此边界。DataForSEO `ranked_keywords` 按 URL 过滤是替代方案，但对低量长尾词经常整页查不到任何词（实测 7 个可疑页里 6 个没有数据），不能替代 GSC 精确的每词点击率。 · 证据：operational experience（2026-09-28 实测）
- 怎么用：
  - 如实报阻塞，不去生产环境挖密钥（红线：不读 `.env.local` 补生产密钥）。
  - 不需要词级数据也能坐实的问题：结构性自相残杀（两个页面讲同一件事，从 GSC 页级 + 站内检索直接可发现）。
  - 没有词级数据支撑时，"标题不够吸引人"只能算未证实猜测，不能当诊断结论写进报告。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 标题被谷歌截断是可核实的机械原因，别急着当成"文案不够吸引人"

- 规律：谷歌显示标题超过约 60 字符会被截断成"..."。这是可以直接数字符数验证的机械原因，跟"文案好不好"是两件独立的事，应该先查截断（更容易验证、更容易改）。
- 为什么：实测点击率差的几页标题 62-76 字符（截断，截掉的往往是最能体现卖点的部分）；同站点击率好的对照页只有 48 字符。但也实测到反例：一页 46 字符（不截断），CTR 依然全场最差之一（0.28%），问题是用词太抽象（地区名而非具体地名）。长度和用词是两个独立问题，都要查。 · 证据：operational experience（2026-09-28 实测）
- 怎么用：
  - 先查标题长度是否超 60 字符——这是机械检查，不依赖判断。
  - 再查用词——但"标题看起来好不好"是主观判断，没有词级 CTR 数据支撑时不能当结论。
  - 同一主题被拆成"独立页 + 博客"两份、内容和标题高度重叠，是比"标题写得好不好"更该优先查的病因——常规体检项，不是偶发。
