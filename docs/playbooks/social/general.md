## 做 Reel 前必须先查数据配方，不能凭感觉手搓蒙太奇

- 规律：排 Reel 前先查 `viral_reference_library` 该行业的高播放量样本，逐列自检"这一列怎么满足"。只满足节奏参数（镜长、切点）、跳过需要换素材形态才能满足的列（真人出镜/航拍/真实质感）= 没照配方做，成品是"卡得很准的幻灯片"。
- 为什么：连续两次同类事故（相隔 6 周），做出的成片被批"结构雷同、不是爆款结构"。两次都绕开了已有数据配方。第二次更严重——只抄了"改个数字就行"的列，真正排名最高的几项一条没动。 · 证据：doc:docs/PITFALLS.md#d5
- 怎么用：
  1. 查配方 → 逐列自检 → 尤其检查"需要换素材形态"的列
  2. 做不到就诚实标缺口，不假装靠调参数能补齐
  3. 开场钩子：纯风景空镜是**最差**钩子；赢的是视觉冲击/文字悬念/UGC 自拍感/声音钩子。第一帧禁用纯风景空镜
  4. 风格追求真实粗糙感，不是精致广告感；logo 开场+尾卡是低分特征
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 竖版视频安全区：关键文字必须落在 y=270~1248 之间

- 规律：1080x1920 竖版视频中，顶部 y=0~270（14%）和底部 y=1248~1920（35%）是平台 UI 死区，右侧约 120px 是互动栏占用区。关键文字和 CTA 必须避开这些区域。
- 为什么：多次实际事故——文字/CTA 被 Facebook/Instagram UI（状态栏、点赞侧栏、caption 截断区）盖住，客户一眼看出。 · 证据：证据待补
- 怎么用：
  1. CTA 不烧进画面，交给发帖 caption 处理（正文写钩子，CTA 放首评，见本手册"发布铁律"一节）
  2. 字号用 `vmin` 单位换算：1080x1920 里 1 vmin ≈ 10.8px；大标题约 8-10 vmin，品牌名/标语约 3-4 vmin
  3. 导出前必须逐帧看一遍（或叠加 y=270/y=1248 两条参考线自检）
  4. Instagram Reels 同规格同规则；Stories 底部死区略小（~250px），拿不准按 Reels 标准做
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 屏幕字幕必须短句大字，绝不把完整业务介绍句子当字幕铺满屏

- 规律：烧进画面的字幕一律短句（一行 ≤6 词），长句只能放 caption 正文区。任何要烧进画面的文字，先问"这行能不能一眼读完"，读不完就是错的。
- 为什么：客户反馈"中间字幕太小"——根因是把整段产品介绍文案直接当屏幕字幕，系统为了塞下超长文本自动把字号压得很小。 · 证据：证据待补
- 怎么用：
  1. 屏幕字幕字段一律短句（价格/钩子/CTA，一行 ≤6 词）
  2. 模板兜底也不许用完整业务介绍句子当屏幕字幕
  3. 生产层最好加"字幕超长自动截断 + 保底最小字号"双保险
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 所有对外交付的视频成片统一带客户 logo 水印

- 规律：logo 水印是硬性标准，不是"模板恰好带了才有"的可选项。挑选或新建视频模板时先确认有没有 logo/水印图层，没有就手动补一个。
- 为什么：换新模板做风格区分时，新模板本身没带 logo 图层，第一版成片被要求"所有视频统一都要加 logo"。换风格模板不能当作跳过 logo 的理由。 · 证据：证据待补
- 怎么用：
  1. 水印图层放最上层、常驻整个时长
  2. 客户 logo 素材从该客户 VI 包目录拿
  3. 每次换模板时第一件事确认 logo 图层存在
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 素材真实性判断只能按来源事实，绝不能按文件名/场景标签猜

- 规律：只有"客户实拍"的素材才能当"产品/展厅承诺"对外发布。图库图片、AI 生成/图生视频输出一律只能做纯氛围内容或内部测试，绝不能冒充客户真实产品对外发。判定依据是素材的来源事实记录，不是文件名或场景标签。
- 为什么：真实事故——用"文件名是否带某种后缀"当判据，结果把 AI 图生视频输出误判成客户真实产品素材，险些当真实承诺发给客户，触碰"货不对板"红线。 · 证据：doc:docs/PITFALLS.md#d6
- 怎么用：
  1. 启发式判断（文件名不带某后缀就当真实）已出过误判事故，必须查来源事实记录
  2. 内容生产分两层：**Premium 层**（真实素材驱动，用于价格/产品承诺场景，一条素材"榨干"多种变体）和 **Ambient 层**（图库素材撑频次，只做纯氛围/品类教育/生活方式内容，发布前必须过"是否冒充真实产品"这道闸）
  3. 多数客户的真实素材供给是"不定期批量投喂"，不是每天都有
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 授权图片（CC-BY 等需署名协议）不能走"抓图-AI洗版权"管线

- 规律：素材管线中的"批量抓图 → AI 重绘脱版权 → 进出片池"路径会主动抹掉作者署名。合法但需要署名的 CC-BY/CC-BY-SA 授权图片走这条管线 = 给本该署名的图片抹了名字再发布，是实打实的违约。
- 为什么：管线设计初衷是处理"来路不明"的图片，AI 重绘 prompt 里明确排除水印/署名文字。授权素材走同一条路等于把署名义务洗掉。 · 证据：证据待补
- 怎么用：
  1. 授权素材走"原样直接用、不改写"的独立路径，数据层单独存好协议类型/作者信息，发布前有专门的署名环节（片尾字幕或首评）
  2. 想完全避开署名麻烦，自动化流水线优先只用 CC0/公有领域图片 + 客户自拍素材
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 视频供给两条技术路线，按场景分别用

- 规律：两条路线不能互相替代——真实感路线（蒙太奇）保留 100% 真实像素，AI 动感路线（图生视频 i2v）画面被 AI 重新绘制。目标是保留真实感就走蒙太奇，不要把真实照片喂给 i2v 再指望"看起来还挺真"。

| 路线 | 做法 | 特点 | 适用场景 |
|---|---|---|---|
| **真实感路线（蒙太奇）** | 真实照片 + 运镜/卡点剪辑，像素不被改写 | 100% 真实 | 产品/场景承诺类内容 |
| **AI 动感路线（i2v）** | 静态图喂 AI 生成运动画面 | 有运动感，但画面被重绘 | 概念/氛围类，可接受艺术化处理 |

- 为什么：静态图一旦进入 i2v 路线必然被重绘，没有"真图只加运动效果"的中间选项。i2v 通病跨引擎跨模型都成立：人脸/地标细节容易变形、会静默删除或添加画面元素、"浅景深"描述容易让整段画面糊掉。 · 证据：doc:docs/PITFALLS.md#d6
- 怎么用：
  1. 需要观众看清的主体放大放前景，密集人脸/密集小字的题材直接别用 i2v
  2. 运镜提示词避免"浅景深"类描述
  3. 验证生成结果时，看成片里实际用到的那一小段剪辑区间，不是整条生成素材
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 社媒发布铁律：一律用 Reel 格式，CTA 链接放首评不放正文

- 规律：发布格式一律 Reel（不发普通图文动态）。CTA 链接放在发布后自动追加的"第一条评论"里，不放正文。首评链接必须带追踪参数。
- 为什么：Facebook 自然 Reel 正文里的链接不可点击，且带链接的正文会被平台压低触达。多客户通用的发布规则拍板。 · 证据：证据待补
- 怎么用：
  1. 发布一律走 Reel，Instagram 同理
  2. 正文只写钩子+价值主张+引导去看评论
  3. 首评链接带追踪参数（来源/渠道/campaign/内容标识），否则无法区分哪条内容带来效果
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 执行层技能（卡点剪辑/转场设计感）买比自建划算——但先确认瓶颈是不是真在这里

- 规律：遇到"剪辑不够有设计感"的反馈，先分清是"节奏/转场参数的问题"还是"素材形态本身撑不起想要的效果"。后者不是靠调参数能解决的。如果确认瓶颈是执行层技能本身，优先买现成工具/模板。
- 为什么：多轮尝试复刻流行模板化剪辑风格，每轮技术上都做出来了，审美反馈始终不满意。复盘发现真正瓶颈是素材形态（全靠图库静态图拼接），换更贴近实拍质感的素材后反馈明显变好。后续另一客户项目中，用 FFmpeg 手写打码滤镜连续撞底层 bug，换成已购的 Creatomate 原生元素一次做对——连技术实现类的执行层能力也是同样道理。 · 证据：证据待补
- 怎么用：
  1. 先分清瓶颈是参数问题还是素材形态问题
  2. 确认是执行层技能缺口时，先查手边有没有已经买好的工具，不要凭"自己写更可控"就跳过
  3. 几轮尝试都摸不准决策者标准 = 不是靠加参数能补齐的能力缺口
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 衡量视频效果看可拿到的指标，不要承诺拿不到的指标

- 规律：写效果验收标准前，先确认当前账号权限实际拿得到哪一档数据。没有洞察权限就只承诺基础互动数据，不写"看播放量/完播率"这类拿不到的指标。

| 数据档位 | 包含指标 | 权限要求 |
|---|---|---|
| 基础权限 | 点赞/表情、评论数、分享数 | 默认可用 |
| 洞察权限 | 观看次数/播放量、观看时长、触达/展示、独立观看人数 | 需额外申请+平台审核 |

- 为什么：到时候必然兑现不了"看播放量"的承诺。某些平台的 Reel 对象可能不返回分享字段，属于平台限制不是故障。 · 证据：doc:docs/STATE.md
- 怎么用：判断一条视频素材好不好（有完整播放数据时）看三个数字组合：① 开头几秒留存率（吸睛率）② 播放进度曲线有没有"跳水点" ③ 平均播放时长 / 视频总长（完播比例）
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 写客户对外内容前，事实必须以客户官网当下内容为准

- 规律：任何具体的产品/行程/服务运营细节（地点、时间、流程、含项），必须先查客户官网当下真实页面内容当事实来源，不能凭品牌调性"合理推测"。官网 vs 内部文档 vs 交接记录 vs 记忆库打架时，永远以官网当下数据为准。
- 为什么：写内容时为了钩子编造了官网原文没有的运营细节——把"清晨出发"写成了"日出出发"，官网根本没有这个说法。这类错误比编造数字更隐蔽，看起来只是文字修饰。 · 证据：operational
- 怎么用：
  1. 品牌简报只给方向和支柱配比，不含具体运营细节，不能当事实来源
  2. 官网 > 内部文档 > 交接记录 > 记忆库
  3. 发布前逐句给内容标来源："官网可溯（带链接）/ 内部文档可溯 / 未经证实"，未经证实的要么删掉要么找人确认
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 搜索找素材时，"搜索词命中"不等于"内容真的是那件事"

- 规律：任何"搜完还要标注/署名/当作事实引用"的素材使用场景，必须核对来源自己写的原始描述（图库摄影师描述字段/地理位置元数据/新闻标题首段），不能因为搜索关键词命中就当作内容属实。
- 为什么：多次事故——用地标名搜图片库，搜索引擎按词面相关性排出的结果，摄影师原始描述其实完全没提这个地标，甚至根本不是同一个地方，只是长得像。 · 证据：证据待补
- 怎么用：找不到能对上原始描述的证据就诚实标"未验证"，换一个更宽泛不那么具体的表达，不要硬凑。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 新客户接入 Facebook 主页发布令牌（OAuth 授权流程）

- 规律：让 ME 代客户往 Facebook 主页发帖子/Reel/视频的授权，和广告账户授权完全独立——广告跑得起来不等于 ME 能发内容。令牌约 60 天有效，到期需重新授权。
- 为什么：新客户接入过程中梳理出，适用于所有需要 ME 代发内容的 Facebook 主页客户。 · 证据：doc:docs/STATE.md
- 怎么用：
  1. 操作入口：ME 客户设置 → 平台连接标签 → Facebook 主页区块 → "重新授权 Meta 发布权限"按钮
  2. 弹窗需要客户/有主页管理权限的人亲自点击——ME 无法替代触发 OAuth 弹窗
  3. 令牌存储：`platform_oauth_connections` 表，按 `client_id + provider='meta' + account_id=主页ID` 索引
  4. 主页 ID 的坑：Facebook 个人主页风格的 Page URL 里显示的 ID 和 Graph API 真实主页 ID 可能不同。确认方式：Graph API Explorer 切到该主页令牌后调 `/me?fields=id,name`，返回的 `id` 才是真实 Graph API 主页 ID
  5. 建议在 Google Calendar 里提前两周设置续期提醒

**完整四步接入清单**：

| 步骤 | 谁操作 | 干什么 | 频率 |
|---|---|---|---|
| 1. 广告账户授权 | 客户/代理在 Meta 商务管理后台 | 让 ME 管广告/读数据 | 一次性 |
| 2. 绑卡 | 客户自己 | 让广告有钱跑 | 一次性 |
| 3. 主页发布令牌 | 客户点一次 OAuth 弹窗 | 让 ME 代发帖子/Reel | 每 60 天续一次 |
| 4. ME 后台信息登记 | ME 自己 | 广告账户号/主页 URL/主页 ID | 一次性 |

广告账户侧流程见 `docs/playbooks/ads/general.md`。

- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 封面大字标题：按画布比例定死字号+允许换行，不用 shrink-to-fit

- 规律：封面/缩略图这类"字号要震撼"的场景，不要用 shrink-to-fit 让内容长度反向决定字号。先定字号（按画布宽度的固定比例，如 15%~19%），标题长就自然换行成多行。
- 为什么：封面文字被连续三轮打回"不够大/不够震撼"。前两轮改字号数值和字体粗细仍不够——根因是 shrink-to-fit（先定大字号上限，超出画布就缩小直到塞进一行）。字号被标题字数反向限制住了。第三轮改成字号定死+允许换行后通过。 · 证据：证据待补
- 怎么用：
  1. 字号按画布宽度固定比例（15%~19%），允许换行
  2. 中文粗体字重要实际加载字体查真实字重名（如 macOS Hiragino Sans GB 的 ttc 文件里 index=2 才是 W6 粗体）
  3. 标题文字居中、卡在画面上方约三分之一区域，账号水印在最上面，标题块紧贴其下
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 关注卡片等提醒类 UI 元素，中途可以再弹一次

- 规律：给"提醒观众关注/行动"的 UI 元素设计第二次出现的时间点（视频时长正中间，不是固定第 N 秒），弹入-停留-淡出完整窗口，两次之间留出明显间隔。
- 为什么：原设计只在开头弹入一次后消失，看到中段才划进来的观众永远看不到。 · 证据：证据待补
- 怎么用：第二次出现用视频时长的相对位置（正中间），不是固定秒数——不同长度的视频固定秒数会落在完全不同的相对位置。不是从中间开始一直挂到结尾。
- 证据等级：单客户候选
- 最后核实：迁移于 2026-09-28，未复核

## 账号水印文字必须带背景色块

- 规律：账号水印这类需要"任何背景下都清楚可辨"的文字，一律加一块半透明/实色背景色块垫底，不要指望"文字颜色选深/选浅就够了"。
- 为什么：纯文字直接浮在视频画面上，跟真实拍摄背景的亮度不稳定混在一起容易被忽略。跟"封面标题需要暗色渐变遮罩才能在任意照片上保持可读"是同一类问题——真实素材背景没有设计插画的"保证的对比度"。 · 证据：证据待补
- 怎么用：半透明/实色圆角矩形色块垫底即可。
- 证据等级：单客户候选

## 多段视频的背景音乐按内容情绪分段选曲

## ASR 自动转写会编出"看起来合理但其实是错的"词，字幕必须逐句人工核对

- 规律：字幕上屏前必须人工通读转写稿全文，专门留意"听起来像正常词但上下文说不通"的片段——比明显乱码更容易漏过自动纠错。

## 成片剪辑点要人工听到源素材最后一秒
