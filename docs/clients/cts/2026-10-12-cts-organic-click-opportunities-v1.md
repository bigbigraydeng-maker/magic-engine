## 7. ⑤ 哪些机会可以做成「agent 预写好改动稿，PM 只点一下批准」（S3 思路，**只设计，不开工**）

**一句话**：agent 把每一页的改动**整份写好、自己先过完所有检查**，PM 面前只剩一个「批 / 不批」。这正是 44 号稿的 S3，也是解决「清单没人领」的办法。

### 7.1 改动稿包长什么样（每页一份，统一格式）

| 栏 | 内容 |
|---|---|
| 页面与标识 | 网址、是否在保护名单（是 → 档 3，PM 本人批） |
| 线上现状 | 读回的真实 `<title>` / 描述 / 规范网址（不用抓取表里的 H1 冒充标题） |
| 证据 | 本页自己的 GSC 词、搜索量 / 难度（带取数日）、实时搜索结果前 3 名标题、点击率与同名次对照 |
| 改动稿 | 新标题 / 描述（含字符数）/ 要加的内链 / 要补的小节；**逐句标：官网可溯 / brief 可溯 / 未证实（未证实 = 删）** |
| 六条闸门结果 | 逐条通过 / 不通过 + 原因（手册 §5.1） |
| 风险与回退 | 风险级、保护标记、怎么一键回退（GitHub Revert） |
| 失败判据 | 「28 天后该词排名没上移 ≥3 名，判没起效」，**不写点击归因**（手册 V-02） |
| 批准方式 | 过渡期 = **PM 合并 PR 即批准**（合并账号与时间是记录）；将来有批准按钮后 = 点按钮 |

### 7.2 哪些适合做成 S3 包（按适合度）

| 机会 | 适合 S3？ | 原因 |
|---|---|---|
| **O2 12 大页的标题 / 描述** | **最适合** | 量大、同一格式、可批量出稿；每批 ≤5 页让 PM 一次批 |
| **O1 `/china-tours` 保护页** | **适合，但只能给 PM 本人** | 改动稿同上，但批准人必须是 PM；一页一包 |
| **O4 四个团页（文案 + 班期 + 内链 + 结构化数据）** | 适合，**前置：CTS 先确认班期** | 稿子里的日期价格只能来自官网 / CTS，不能 agent 编 |
| **O5 内链** | 适合 | 每条 = 「A 页第 N 段加一句链到 B 页」，可机器核对 |
| **O8 新文章** | 适合（已是「草稿 → 人批」） | 先补选题与拒稿原因 |
| O7 / O6（规范网址、跳转、合并） | **只做稿、不放进批量** | 站点结构，一改错页面掉出谷歌，**每包单独批** |
| O9 结构化数据 | 适合，**前置：核对结果** | 模板改全站页头，对保护页有影响 |

### 7.3 这个设计成立的两个前提（还没满足，需要 PM 定）
1. **批准记录**：现在没有「批准 / 不批准」按钮（PM 10-12 回「先不做」）。**S3 在没有它时能不能跑：能**，用「PM 合并 PR 即批准」顶着；但「到期没人理的包会被系统悄悄收尾、看不出谁批的」这个缺陷仍在，需要在包里写「到期保持待批，不自动关闭」（手册 RL-S11）。
2. **付费体检预算上限**：O3 的词级抢词体检（`ranked_keywords`）是付费，**上限没定之前只用已落库数据**，所以 O3 的稿会少一层证据。
