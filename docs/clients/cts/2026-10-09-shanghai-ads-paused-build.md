## 6. 方案要修正的地方（统筹已说他统一排期，本窗口没改方案文档、没改日检代码）

### 6.1 §5 有半个理由是错的：不存在「v4 表」

方案 §5 说「加预算/出发时间两题会被路由进 v4 表」。**生产库里没有 v4 表。** 实查 `client_lead_sheet_routes`：CTS 只有**一条**路线 `cts-fb-lead-sheet`（`match_any_answer_fields: []`，是兜底路线），落 `Sheet1`；`when_are_you_hoping_to_travel?` 和 `whats_your_budget_per_person_nzd?` 两题的答案落在**同一张表的第 33、34 列**。

**不加那两题的决定不变**——理由是填完率证据（同组同人群实测，点击→填完从 **15.1% 掉到 3.0%**：410 点击 62 条 vs 105 点击 3 条），这条照样成立、而且够硬。只是「会被路由进另一张表」这个附加理由不成立，**别再用它当论据**。

### 6.2 §8.5 第 8 条自相矛盾：台账卡写不了 14 位的系列编号

方案要求台账卡正文写一行「草稿系列编号：<系列编号>」，但台账的格式检查**禁止全文出现 10 位以上连续数字**（`src/lib/ledger/parse.ts` 里 `/\d{10,}/`，CI「Ledger entries valid」任何分支都跑、不豁免），而 Meta 的系列编号是 14 位。**照方案写卡，机器会直接判不合规。**

本次的处理：编号写在**本文档 §2 的表里**，台账卡用 `doc:` 指针指过来。**日检要改成从本文档读编号。**

### 6.3 接口建出来的对象可能落在「未发布草稿」区，日检读不到

今天实测到的机制：用官方 Meta 广告 MCP 建对象，**落在广告管理工具的「未发布草稿」区**（读回带 `status: EDITING`、`action: add`），不是「已发布但暂停」的对象，而且**暂存状态默认是「启用」**。更麻烦的是 `ads_create_ad` 的说明里写着「发布那个系列之后，发布出来的对象会变成启用（ACTIVE）」——也就是说**我无法在不发布的前提下，证明暂存成暂停到底管不管用**。

**所以我换了路线**：改用主页令牌走 Graph 接口直接建**已发布但暂停**的真实对象（就是 §2 那七样）。这样三层自身状态读回都是 `PAUSED`，日检按方案 §8.5 第 7 条读已发布对象就能读到，不用改日检逻辑。

**遗留一点**：先前用 MCP 建的那套草稿（1 个系列 + 2 个广告组）删不掉——Graph 对草稿对象返回「应用没有权限执行此操作」。我把那个**草稿系列的暂存状态改成了 DELETED**，Meta 随即给它挂上一条校验错误「新建系列必须是启用或暂停」→ **这个草稿已经发布不出去了**，零花费风险。但它还躺在草稿区、带着一条红色校验错误。要彻底清掉需要在广告管理工具里点一下「丢弃草稿」。**我没有把这件事写成清单推给 PM**；要我自己去浏览器点掉，统筹说一句就行。

**建议的日检改法**（给统筹，不是我自己改）：待命期每日核对改成两件事一起读——①已发布对象里，名字带 `CTS · Shanghai · Always-on` 的三层自身状态必须都是 `PAUSED`、逐日花费必须读得到且为 0；②未发布草稿区里不存在任何名字带 `CTS · Shanghai` 的可发布草稿。任何一步读不到，一律报「没法证明」，不能当通过。

### 6.4 三条新摸出来的机制坑（都与具体客户无关，建议进通用层手册）

1. **`targeting_as_signal` 这个字段会让建广告组整个失败**，报的是 `(#3) Application does not have the capability to make this API call.` ——一句看起来像「权限不够、没救了」的话，实际只是**某一个字段被限制**。我是靠逐字段二分才定位到它的：去掉它，同样的 targeting（含版位、排除受众、Advantage+）一次就建成。**教训：`#3` 不等于此路不通，先逐字段减到最小再判。**
2. **视频互动型受众必须用「老规则格式」建**：`[{"event_name":"video_view_50_percent","object_id":<video id>}]`。新格式（`event_sources` + `filter`）Meta 会明确拒绝并提示「规则格式不适用于视频互动受众，请改用之前的受众规则格式」。而**官方 MCP 的 `ads_create_custom_audience` 自己的校验器会把老格式判成「Invalid rule JSON format」**——也就是说这条路**只能走 Graph 接口，走不了 MCP**。
3. **Advantage+ 打开时，年龄不能当控制项设到 25 岁以上，只能当「建议」；而这个建议读回里查不到**，所以「建议已生效」无法用读回证明（见 §2.2）。

### 6.5 两张在用表单的介绍卡还写着「25 years / since 1928」

见 §2.4 的提示。改在投表单不在本窗口范围，登记在此。

## 12. Reuse Statement

- **复用了什么平台能力**：官方 Meta 广告 MCP（建系列/广告组 + 读回）· Meta Graph 接口（建表单 / 受众 / 已发布暂停对象）· 库里的 `platform_oauth_connections` 客户授权与 `src/lib/cms/crypto.ts` 的解密口径 · `src/lib/ads-strategy/launch-budget-headroom.ts`（余量核算纯函数）· `src/lib/lead-sheets/{route-match,row}.ts`（归表规则，用来证明落表）· 官方账户既有的排除名单受众 · 旅游与 Meta 通用手册 · 卫青审查流程 · 台账与窗口纪律。**以上全部一行代码没改。**
- **新增的东西**：本文档 + 一张台账卡。**没有新增代码，没有改任何共享运行时**（本 PR 不含 `src/` 改动）。
- **platform-shared（建议升级进通用层手册，都与具体客户无关）**：
  1. `targeting_as_signal` 会让建广告组整体报 `#3`，而 `#3` 的字面意思会误导成「此路不通」——**先逐字段减到最小再判**；
  2. **视频互动型受众只能用老规则格式建，而官方 MCP 的校验器会把老格式判成非法** → 这条路只能走 Graph；
  3. **接口建出来的对象可能落在「未发布草稿」区且暂存状态默认是启用**，所以「建成暂停 + 日检读回自身状态」这套做法要么覆盖草稿区、要么改走 Graph 直接建已发布暂停对象（本次选后者）；
