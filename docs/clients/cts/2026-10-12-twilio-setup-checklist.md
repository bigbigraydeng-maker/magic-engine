# CTS · Twilio 试用测试清单（给 PM / 统筹）

**目的**：用 Twilio 试用账号，让一通真实来电经过 ME 的接收口，验证「事件进来→通话状态→CRM 一条触点→录音记引用」。
**规矩**：开发窗口不输入密码、卡号、账号令牌。注册 Twilio、拿令牌、往 Render 填环境变量，都由 PM 本人做；令牌不要贴进聊天、PR、日志。
**状态**：代码在 PR（见台账卡 `2026-10-12-cts-twilio-adapter`）；字段按 Twilio 官方文档实现，**未用真实回调核对**；生产库要先「同意」应用第二份迁移才能建连接。

## 1. PM 做（Twilio 控制台）
1. 注册 Twilio 试用账号（试用账号有限制：只能拨打已验证的号码，通话开头会有试用提示语——够做第一次测试）。
2. 记下 **Account SID**（`AC…`，不是密码，可以告诉我）。**Auth Token 不要告诉任何人**。
3. 在 Twilio 里买/领一个测试号码（试用额度内；新西兰本地号码需要地址证明，第一次测试可用 Twilio 提供的任意可用号码，**不要为此付费升级账号**，卡在这里就停下来告诉我）。
4. 把你自己的手机号在 Twilio 里做「已验证号码」（试用账号的要求）。

## 2. PM 做（Render 环境变量）
- 新增一个环境变量，名字例如 `TWILIO_AUTH_TOKEN_CTS`（名字必须以 `TWILIO_AUTH_TOKEN_` 开头，服务只认这个前缀），值是 Auth Token。**只告诉我变量名**。
- 可选：`TELEPHONY_PUBLIC_BASE_URL=https://app.magicengine.com.au`（不设则按请求头还原，反向代理下建议设）。

## 3. 开发窗口做（等 PM 回「同意」后）
1. 应用迁移 `20261012100000_telephony_twilio_connections.sql`（先预检）。
2. 用 `scripts/telephony-twilio-connect.ts` 生成连接的 SQL（参数：客户编号、Account SID、变量名、员工手机号 E.164、员工号码→登录邮箱对照），执行后得到 **连接编号**。

## 4. PM 做（Twilio 号码设置，把下面的地址填进去）
地址里的 `<连接编号>` 换成上一步得到的。方法一律 POST。
- **A call comes in（Voice URL）**：`https://app.magicengine.com.au/api/webhooks/twilio/<连接编号>/voice`
- **Call status changes（Status callback URL）**：`https://app.magicengine.com.au/api/webhooks/twilio/<连接编号>/status`
- 员工那一段结果和录音的回调地址由来电的回应自动带上，不用手填。

## 5. 验收（受控号码，先告诉我拨哪个号码、PM 同意再拨）
用你已验证的手机拨 Twilio 号码：①员工手机接听聊 20 秒挂断 ②另打一次不接 ③再打一次接通后让录音完成。每次做完让开发窗口查：原始事件进了没、通话状态、CRM 触点（一条）、录音状态。

额外必测一项（审查提出）：**④ 来电者在员工手机响铃时挂断**——要核对 Twilio 此时是否仍回调「员工那一段结果」。如果没有回调，这类漏接会被转人工确认而不是记成漏接来电，需要改成按响铃时长推断。

## 已知限制
- 🔴 **员工手机转到语音信箱时，会被记成「接通」**（运营商语音信箱接起来，Twilio 就认为通了）。第一次测试前请把测试手机的语音信箱关掉（或把转接超时调得比信箱响铃短）；真正上线前要做「按键确认接听」（来电后让员工按一个键才算接通），这一块还没做。
- 员工那一段结果没到时：不会记成漏接，也不会记成有效联系，转「待确认」（页面还没做）。
- 来电转接+录音已做；**员工点击拨号（外呼）没做**。
- 来电显示号码、录音告知语音（目前是英文默认文案）、新西兰号码合规，都还没验。
- 试用账号的提示语和限制会影响体验，但不影响验证事件链路。
