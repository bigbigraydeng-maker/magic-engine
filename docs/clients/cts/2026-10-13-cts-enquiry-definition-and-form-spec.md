# CTS「一条询盘」口径 + 表单字段规格 + 对账方法（v1，2026-10-13）

> 对应策略 v2 §9、§12 第 4 件事。**所有数字基线现在是「未知」**——口径与字段上线后才有基线。第一次出数日期写在台账卡 `2026-10-13-cts-enquiry-definition-form-and-organic-report`。

## 1. 什么算「一条询盘」（我拍的，PM 可改）

**主口径：一次到达感谢页（/thank-you）或联系页提交成功，记为一条询盘。**
上线新表单改动后，统一以 GA4 事件 **`enquiry_thank_you`** 为准（本次覆盖的 4 个表单——团页、圣诞/新年活动页、联系页、/china-tours 顶部表单——提交成功都会发这一个事件，不管页面跳不跳转；**没覆盖的表单见 §3**）。

**为什么要新事件**：旧口径「感谢页浏览」会漏掉联系页（提交成功是页内显示，不跳转），所以 28 天只有 26 次，比 `form_submit` 的 78 次少约 3 倍。这是**最可能的原因，但没有逐条核实**。注意 `form_submit` 是 GA4 自动事件，站内非询盘的表单也可能触发，**它不是真值，只是个对照**。

**并列的对账口径（人工）**：同一时间窗里，公司邮箱（info@）收到的**真实询盘封数**。以它为「真值」，用来检查事件有没有低估或重复。

**已知偏差（写明，不回避）**：
- 感谢页浏览（旧口径）：**低估**（联系页不跳转）。
- `enquiry_thank_you`（新事件）：用户屏蔽广告/统计脚本时漏记。**去重只有一层**：感谢页按「团名」在同一个浏览器标签页内去重，所以同一标签页里对同一个团再提交一次，会**少记**；直接打开 /thank-you 链接（例如内部验收链接）会**多记**；换设备不去重。
- 邮箱：含员工自己的测试单、同一客人重复提交——对账时要剔除。
- 三者永远不会完全相等；只要**差距稳定且可解释**就可用，差距忽大忽小说明有问题。

## 2. 两个度量（策略 v2 §9 的定义）

| 度量 | 定义 | 能不能现在算 |
|---|---|---|
| **团页询盘数** | 28 天内，自然搜索渠道、**当次访问第一个落地页是团页（/tours/*、/campaigns/*）**、且发出 `enquiry_thank_you` 的次数 | **改动上线并有数据后可算**（ME 新报告已写好，见 §5） |
| **攻略页引导的询盘数** | 第一个落地页是攻略页、**提交前浏览过团页**的次数 | **要两步**：①表单改动已把「浏览过的团页」写进事件；②GA4 里要把事件参数 `viewed_tour_paths` 注册成自定义维度（一次性后台设置，**还没做**）。注册前只能看到「攻略页落地的询盘总数」 |

**一个诚实的限制**：GA4 的「落地页」是**这一次访问**的第一页，不是这个人第一次来站的第一页。隔天回来下单的人算在回来那天落地的页上。表单里记的是**浏览器会话内**的第一页（同一个标签页关掉就重来），所以两者都有这个限制，只是比单看提交页更接近真实路径。

**基数很小**（旧口径 28 天全渠道只有 26 次；自然搜索占多少**还不知道**，上线后看报告）：只当辅助指标，**不当趋势 KPI，不设目标值**。

## 3. 表单字段规格（官网改动，PR 见台账卡）

提交时额外记录（全部**可选**，缺了不影响提交）：

| 字段 | 含义 | 去哪里 |
|---|---|---|
| `first_landing_path` | 这个浏览器会话第一个落地页（只存路径，不含 `?` 后面的内容） | 邮件新增行 `First landing page`；GA4 事件 |
| `submit_path` | 提交表单所在的页 | 邮件 `Submitted from`；GA4 事件 |
| `referrer_host` / utm | 第一次进站的外部来源（如 `www.google.com`）、广告参数 | 邮件 `Arrived via`；GA4 事件 |
| `viewed_tour_paths` | 提交前浏览过的团页/活动页（去重，最多 5 个） | 邮件 `Tour pages viewed`；GA4 事件 |

**邮件**：新增 4 行，加在原有行**之后**，邮件标题、原有字段顺序、收件人**都不变**，不影响现有收信习惯。
**不收集**：不记 IP、不记姓名/邮箱以外的新个人信息；路径去掉了 `?` 后的参数（参数里可能带点击编号）。
**覆盖范围**：团页表单、圣诞/新年活动页表单、联系页、/china-tours 顶部表单（共 4 个，已用代码核对）。
**未覆盖（已用代码核对）**：
- 定制行程表单（`TailorMadeForm`、`TailorMadeQuickPlan`、重庆定制页 `ChongqingCustomEnquiry`）走 `/api/tailor-made-enquiry`，是否算「询盘」要 PM/CTS 先说。
- `/api/campaign-enquiry` 这个接口代码里存在，但**没有任何页面在调用**（疑似废弃）。
- **官网已有的一个问题（不是这次引入的）**：重庆定制页提交成功后跳到 `/enquiry-thank-you`，而站内**没有这个页面**，访客会看到 404。已记入台账卡，请 CTS 官网窗口另行处理。

**一句话回退**：在 GitHub 上对这次 PR 点 Revert，四个表单、邮件、新事件一起回到原样；新增字段都是可选的，**没有数据库改动、不需要数据迁移**。
**回退后仍会留下的**：上线期间已经发到 GA4 的 `enquiry_thank_you` 事件会留在历史数据里（GA4 不能删单个事件）；如果之后把 `viewed_tour_paths` 注册成了自定义维度，该维度只能归档、不能删除。两者都不影响现有报表。

## 4. 对账方法（要一位有 info@ 邮箱权限的人做一次，agent 不读邮件正文）

**做法（约 10 分钟）**：在 info@ 邮箱里搜索，**只数封数、不点开、不转发**。窗口选一个整周（例如 2026-09-14～09-20，旧口径用）和改动上线后的第一个整周（新口径用）：
1. 主题以 `Tour enquiry:` 开头的邮件数（团页/活动页表单）。
2. 主题以 `Contact form:` 开头的邮件数（联系页 / 顶部表单）。
3. 从中**减去**名字里带 TEST 或员工自己的测试单、以及同一个客人 5 分钟内的重复提交。

**填这张表**（请把结果回给统筹，或直接填进台账卡证据文件）：

| 窗口 | 邮箱 Tour enquiry | 邮箱 Contact form | 邮箱合计（剔除测试/重复后） | GA4 旧口径：感谢页浏览（自然搜索 + 全渠道） | GA4 新事件 `enquiry_thank_you`（全渠道） | 差值与解释 |
|---|---|---|---|---|---|---|
| 旧：09-14～09-20 | | | | | 不适用（还没上线） | |
| 新：上线后第一个整周 | | | | | | |

**怎么读**：
- 新事件 ≈ 邮箱合计（差 ≤ 10%）→ 口径可信，用它。
- 新事件明显 < 邮箱 → 有漏记（多半是屏蔽统计脚本或事件没发出），写原因，决定要不要改用邮箱计数做主口径。
- 新事件明显 > 邮箱 → 有重复或误触发（参考 8 月 `generate_lead` 虚高 341 次的教训），**先别用**。
