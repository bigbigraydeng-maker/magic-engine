## 一页看懂

**问题不是内容不好，是发信的架子会误伤人。**

上个窗口已经查清：newsletter 打开率 33–42%（行业均值 20–25%），内容没毛病。坏的是三件事：

1. **发信机制会「发失败就群发全表」** —— 7 月 20 日 PM 自己重复收到 E1 就是这么来的。已经停了 8 天。
2. **同一个客人散在 4 个地方各算一次**（FB 表格 / Mailchimp / info@ 邮箱 / Messenger），所以「谁回过信」是瞎的、已经买单的人还在收「快来订」。
3. **只会按日子群发，不会按人的状态发。** 一个团 NZD $3,399–$10,899，320 个人的名单，群发太糙。

**结论：CTS 不是「做 newsletter」的生意，是「一个一个跟进 + 偶尔广播」的生意。** 配比大约 8 成按人触发、2 成群发。

## 三、第一步：把「发失败就群发全表」的架子换掉

### 1.1 为什么必须换，不能修

现在的机制是：复制一份模板 campaign → 改收件人为小分段 → 发。
**改收件人这一步失败时，它不会停，它会按模板原来的收件人发。** 模板原收件人是全表 300 人。
这不是配置写错了，是**这个做法本身没有「失败就停」的概念**。参数调不好这件事。

### 1.2 换成什么

**换成 Mailchimp 自己的自动化流程（Journey）。**

理由（不是我的偏好，是机制差别）：
- 群发是「把这封信推给这批人」，推错就是全体。
- 自动化流程是「谁满足条件，谁自己走进来」，一个人只会走一遍。**没有「全表」这个概念存在**，所以没有全表可以误发。

**技术上怎么接（已核实，不是猜的）：**
Mailchimp 官方 API 有一个「把某个联系人推进某条自动化流程」的接口
（`POST /customer-journeys/journeys/{journey_id}/steps/{step_id}/actions/trigger`）。
**前提是这条流程要先在 Mailchimp 网站上搭好一次**，搭的时候 Mailchimp 会给出这条流程的编号，之后 ME 就能用程序把人推进去。

来源：[Mailchimp Customer Journeys API trigger](https://mailchimp.com/developer/marketing/api/customer-journeys-journeys-steps-actions/customer-journeys-api-trigger-for-a-contact/)

### 1.3 分工

- **PM 点的**：在 Mailchimp 里把流程的**壳**搭出来（每条流程一次性，之后不用再碰）。这一步 API 不能代替，是 Mailchimp 的限制。
- **ME 自动的**：判断谁该进哪条流程、什么时候进、进之前先过抑制名单 —— 全部由 ME 跑，不需要人。

### 1.4 旧机制怎么处理

- **做什么**：那套「复制 campaign 改收件人」的脚本 **不要重新启用**，也不要修。让它保持关闭。
- **怎么验证**：确认它的定时触发器是关的。
- **失败会怎样**：只要它还能被触发，7/20 的事故就会重演。**这是本方案里唯一一个「什么都不做」就是正确答案的地方。**

## 四、第二步：一个人一条记录（地基已有 8 成）

### 2.1 已经有的部分

第 1.1 节那套表就是唯一真相源，**不要另建**。一个人一条 `contacts`，多个邮箱/电话挂在 `contact_identities` 上，所有接触记录进 `contact_touchpoints`。335 个 FB lead 已经在里面了。

### 2.2 缺的三块，按重要性排

**缺口 A：info@ 邮箱没进来（最重要）**

这是「谁付了定金 / 谁成交了」的**唯一来源**。没有它，安全闸永远挡不住「已经买单的人还在收快来订」。

- **做什么**：把 info@ 的往来邮件同步成 `contact_touchpoints` 里 `channel='email'` 的记录，按邮箱地址自动并到已有的人身上；再用 AI 从邮件正文里判断这个人到了哪一步（问询 / 已报价 / 已付定金 / 已成交）。
- **谁做**：ME 自动跑。**PM 不用点** —— info@ 的授权早就配好了（bdm@ 账号对 info@ 有完全访问权，已验证可读 70 天内的邮件）。
- **用什么**：现成的 Outlook/Graph 通道 + 已有的备注解析模块（`note-parser.ts`）扩一组「成交阶段」的判断。
- **产出落哪**：`contact_touchpoints`（channel=email）+ 每个人身上一个「到哪一步了」的标记。
- **怎么验证**：18 个回过信的人，在「今天该联系谁」页面里落到「客户回信了」那一段；已成交的人自动进抑制名单。
- **失败会怎样**：不做这块 → 已成交客户继续收培育邮件 → 这是最伤客户关系的一种错，比不发信糟糕得多。

**缺口 B：Mailchimp 那 322 人没并进来**

- **做什么**：把 Mailchimp 的订阅者按邮箱并进 `contacts`。已经在的人加一条「他也在 Mailchimp 里」的身份；不在的人新建，标来源为 Mailchimp。**反向也要同步**：ME 这边标了「别再联系」的，在 Mailchimp 里必须同步成排除。
- **谁做**：ME 自动跑（依赖 0.3 的 API key）。
- **怎么验证**：并完之后总人数应该**少于** 335 + 322 = 657（因为有重合）。重合数是多少，本身就是一个有价值的答案 —— 今天没人知道。
- **失败会怎样**：不并 → 同一个人两边各算一次，所有数字都是虚的。

**缺口 C：Messenger 没数据**

- **做什么**：`conversations` 表是 0 行，同步任务已经注册但没跑出数据 —— 先查是权限没配还是任务没执行。
- **谁做**：ME 自查自修。
- **优先级**：**排最后。** Messenger 影响的是「发信时不知道 AI 正在跟他聊」，比前两个轻。

### 2.3 一个人身上要能看到什么

做完之后，每个人身上应该有：**到哪一步了**（新线索 / 联系过 / 已报价 / 已付定金 / 已成交 / 别再联系）+ **从哪来的**（FB 广告 / 官网表单 / Mailchimp / 私信）+ **想去哪个团**（表单里已经有了，347 条）。

⚠️ **一条设计纪律**：「到哪一步了」要**从接触记录算出来**，不要做成一个让人手填的下拉框。CTS 那份手工 CRM 就是死在这 —— 128 行里「阶段」列 0 个人填。这条纪律已经写在现有代码的注释里了，照做。

## 五、第三步：四条按人触发的流程

> 前提：第 0 步验证通过 + 第一步的壳搭好。**在那之前一条都不许开。**

四条流程，**从投入产出比最高的往下排**：

### 流程 1：新 lead 欢迎（按他选的团分内容）

- **触发**：新 lead 进来，24 小时内。
- **分几种**：按表单里选的团分 5 种（还没想好 159 / Best of China 113 / Tale of Two Cities 35 / Silk Road 32 / Shanghai 8）。
  - 选了具体团的 → 直接讲那个团。
  - **选「还没想好」的 159 人（占 46%）→ 这是最大的一群，给一封「怎么选」的对比邮件**（10 天 vs 15 天 vs 18 天、什么人适合哪个），比推单个团有用得多。
- **写什么**：一切行程/价格/日期只能来自 §1.6 那张表和官网行程正文。**不许用官网好评里的内容**，**不许写「since 1928」**。
- **怎么验证**：一个新 lead 只收到一封欢迎信，且内容跟他选的团对得上。
- **失败会怎样**：分错团 → 客人收到跟自己无关的内容 → 退订。

### 流程 2：静默 14 天唤回

- **触发**：14 天没有任何接触记录（不只是「没打开邮件」—— 电话、私信、回信都算接触）。
- **注意**：那 110 个电话打不通的人，正好是这条流程的主要对象 —— 现有分级逻辑已经把他们标成「该换渠道了，别再打电话」。
- **怎么验证**：进这条流程的人数应该跟「打不通 + 聊过没约下次」这两段的人数对得上。

### 流程 3：已报价没付的临门一脚

- **前提**：**必须先做完缺口 A（info@ 接进来）**，否则系统根本不知道谁被报过价。
- **触发**：已报价，N 天没动静。
- **怎么验证**：这条流程的名单要能一个个点开看到那封报价邮件。
- **失败会怎样**：阶段判断错了 → 对已经付了定金的人催单。**所以这条流程必须排在缺口 A 之后，不能并行。**

### 流程 4：已成交转推荐

- **触发**：成交后 / 回国后。
- **优先级**：最后做。做前面三条的时候顺手把数据攒上就行。

### 广播那 2 成留着做什么

出发日期公布、名额告急、季节性内容 —— **发给所有人，但永远先过抑制名单**。这部分保持现有内容水准就行，它本来就不差。
