## 四、已知误差与坑（都是这三天实测出来的）

| 坑 | 正确做法 |
|---|---|
| `platform_oauth_connections.last_synced_at` 只在令牌续期时更新 | 判断邮箱收信有没有在跑，看收信任务每一轮的结果，不看这个字段 |
| 只按一个包编号查 Story，漏看换过的新包 | 每次查该客户全部包，以当时有效且已授权的为准 |
| 「走的是演练」被说成「开关失效」 | 只报这一轮走演练还是真发；演练轮会留 OK 的检查记录、尝试次数为 0 |
| Story 迟到超过 20 分钟判错过（`MISSED` / `SLOT_PASSED`） | 记为错过，不记为发布失败 |
| 工厂默认草稿模式：工单「已发布」、平台上是草稿 | 每轮读平台 `published` 字段 |
| 先传草稿再转公开的 Reel 接不上读数 | 草稿上传时写的动作行记的是「草稿」、之后不回写；读数接线看到草稿就跳过。已公开 4 条的历史读数补不回来，已接受 |
| Story 观看数读不到 | 现有授权返回 `(#3) Application does not have the data permission`，换合法指标名也一样；74 号裁定不加权限，已知、接受，不再每天报 |
| 工厂 Reel 首评链接末尾紧贴 33 个隐形字符 | 链接能开，但 `utm_content` 会被污染；只有上海 Reel v5 那条有，已报 75 号 / 工厂 |
| 不带登录访问 Reel 地址，Facebook 一律返回 400 | 无法用这个判断「未登录能不能看」，记未核到；应用内浏览器是已登录状态，不能当未登录用 |
| 台账卡的标题与判据是冻结字段，CI 会拦 | 要改判据就新建一张卡，旧卡正文注明「已过时」 |
| 文本匹配找禁用字样会误报、漏报 | 命中要人看一眼再定；封面和视频画面接口读不到，记未核到 |
| 「13 条 Reel 待审」看起来像审查积压 | 实为上游原因：带价画面需确认实拍；无价模板已合并、无价版在复审。归因写「无价版重出中，在复审」；工单变成待审不等于可发，要过审查 agent 那一关 |
