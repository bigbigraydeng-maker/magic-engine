# EV Expo · 官网 GA4 买票追踪方案（2026-11-08）

> **11-08 更新：做法以 `2026-11-08-tracking-utm-design-v2.md` 为准。** 本文件第一节的核实事实仍然有效。第二、四、五节原来是「要现有 GA4 查看权限 + 改 Squid 的 Tag Manager」，已改为：ME 自己的 GA4 直接写进页面，付款完成事件 `ticket_order_complete` 当主账本，不碰 Squid 的东西。广告继续落官网，购票框接追踪链接代号只是可选项。邮件草稿已按 v2 重写。

**一句话结论：官网不用新装 GA4，它已经有了；真正缺的是「买票完成」这一步没送进 GA4。** 请网站设计公司做两件小事：给 ME 开现有 GA4 的查看权限，再加一个「买票完成」事件。做完后，我们能在 GA4 里看到「从 ME 广告进官网的人，有几单买了票」。

标记：**我核了** = 我今天（2026-11-08 凌晨 1:20 前后，新西兰时间）自己抓页面或查接口看到的；**没核实** = 没查到或查不了。

### 2. 买票是在官网里，还是跳去 Eventbrite

- **在官网里。** 官网所有「GET TICKETS」按钮都指向官网自己的 `/register` 页，这一页**内嵌了 Eventbrite 的买票窗口**（活动编号 1989458060614），客人不离开官网就能付款。（我核了，抓 `/register` 源码）
- 内嵌窗口自带一个「付款完成时通知页面」的接口（`onOrderComplete`）。官网现在已经接了这个接口，但接上后**只在浏览器后台打一行字**，什么都没记。（我核了）
- 这个接口会不会把订单号一起交出来：社区帖子说会，Eventbrite 官方开发文档页面我没读出内容。（没核实，装好后测一次就知道）

**这一点是整件事的关键**：因为付款发生在官网页面上，只要把这个「付款完成」通知接进官网自己的 GA4，就能记下买票，**不需要 Eventbrite 管理员权限**。

### 3. Eventbrite 后台能不能直接填 GA4 编号

- 能。Eventbrite 官方帮助文档写着：登录主办方后台 → 选活动 → 营销 → 追踪像素 → 添加 Google Analytics → 填 GA4 编号保存，之后会自动记「看活动页」「打开下单表」「买票」三件事。（我核了，读了官方帮助页 [Set up a tracking pixel with Google Analytics](https://www.eventbrite.com/help/en-us/articles/475328/)）
- **要登录主办方的 Eventbrite 后台，ME 现在没有这个权限。** 文档没写哪种角色能加。（没核实）
- 文档只讲 Eventbrite 自己的结账页，没提嵌在别人网站里的窗口。嵌入窗口在 Eventbrite 自己的网址里跑，记下的访问很可能跟官网上那次访问对不上，看不出是不是从我们广告来的。（没核实，推测）
- **所以不走这条路。** 要权限、要客户去点，而且大概率连不上广告来源。

## 二、方案：新建 ME 自己的 GA4，还是要现有 GA4 的查看权限

| | A. ME 新建自己的 GA4，让对方加进 Tag Manager | **B. 要现有 GA4 的查看权限（推荐）** |
|---|---|---|
| 要对方做什么 | 加一套 ME 的 GA4 代码 + 买票完成事件（发给两个 GA4） | 开一个查看权限 + 加买票完成事件（只发给现有 GA4） |
| 要 ME 做什么 | PM 登录谷歌账号新建一个 GA4，把编号发给对方 | 什么都不用建 |
| 重复计数 | 两个 GA4 各记各的，单个 GA4 里不会重复；但官网上多了一套追踪代码 | 不新增追踪代码，没有重复问题 |
| 会不会弄坏 Squid 的追踪 | 只是新增，不改原有代码；风险跟 B 一样，都在「发布 Tag Manager 时会不会把别人没发布的改动一起发出去」 | 同左。邮件里已要求对方先看清再发布 |
| 历史数据 | 从装好那天起才有 | 现在就能看到 11/6 开投以来 ME 广告带来的访问（买票完成只能从装好那天起算） |
| 数据归谁 | 归 ME，项目结束后还在 | 归客户（或 Squid），项目结束后权限可能被收回 |
| 时间 | 多一步建账号、多一轮来回 | 最快 |

**推荐 B。** 原因：
1. 展会 11/13 开始，只剩 5 天，B 少一轮来回。
2. 官网不多装一套追踪代码，手机页面不会更慢，也不会多一个可能出错的地方。
3. B 能立刻看到 11/6 以来我们广告带来的访问，A 看不到。

数据归属的代价：项目结束后可能看不到了。做案例要用的数字，结案时（11/17）导出存档就行。

如果对方到 11/10 中午还没给权限：请他们每天截一张 GA4 报表图发过来，先顶着用，不再改走 A。

## 三、广告链接的来源标记：以主窗口的设计为准

**PM 11-08 定：来源标记和 Eventbrite 追踪链接的整体命名，由 EV Expo 主窗口统一设计**，见 `docs/clients/ev-tech-expo/2026-11-08-tracking-utm-design.md`（v1：`utm_campaign=me_evexpo26`，组代号 `me_g1_family` 等）。本文件不另定命名规则，以后新建广告怎么写标记、GA4 里怎么筛，都以那份为准。

**跟那份 v1 对不上的两处事实（已告诉主窗口，怎么定由主窗口和 PM 拍）：**
1. v1 写「我们的广告直接链到 Eventbrite、不经过官网」「现有 5 组都没有来源标记」。实际是：6 条在投广告**全部落在官网买票页**，**全部已带来源标记**（见第一节第 4 条）。
2. 两条路不能同时都要：
   - 广告继续落官网买票页 → 本方案的「买票完成」事件能记到 ME 带来的单。但 Eventbrite 追踪链接很可能记不到，因为内嵌窗口只认活动编号，页面网址上的追踪参数会不会传进窗口没核实。
   - 广告改链 Eventbrite → 追踪链接能记票数和金额（真账本）。但官网 GA4 看不到我们的客人，本方案加的事件只会记到别人带来的单；要看 GA4 就得在 Eventbrite 后台另加，需要管理员。

本窗口只交给主窗口下面几条已核实的事实，供设计时参考：
- 现在在投的 6 条广告各自带的标记，见第一节第 4 条的表。（我核了）
- 落点都是官网买票页 `https://www.evtechexpo.co.nz/register`，买票就在这一页里完成，不跳走。（我核了）
- 在投广告的活动名有 `women30`、`segments`、`students`、`magicengine` 四种，来源有 `meta`、`facebook` 两种。在投广告改链接等于改广告，会让它重新学习，而且必须走 ME。（我核了；改不改由主窗口和 PM 定）
- 只按来源筛不够：Squid 的广告可能也写 `facebook`。Squid 实际用什么标记，没核实。
- GA4 自带的「渠道分组」可能把 `meta / paid` 归成「付费其他」而不是「付费社交」。（没核实）

## 四、请网站设计公司做的事（邮件草稿见 `2026-11-08-ga4-email-draft-design-shore.md`）

1. 给 `hello@magicengine.cloud` 开 GA4 媒体资源（编号 `G-YR0BVY2DX5` 所在的那个）的**查看者**权限；能的话再开 Tag Manager 容器的**只读**权限。
2. 在 `/register` 页，把现在那个只打一行字的付款完成接口改成往页面里发一个信号 `ticket_order_complete`，带上订单号。
3. 在 Tag Manager 里加一个 GA4 事件：收到这个信号就记一次 `ticket_order_complete`，订单号记在 `transaction_id`。
4. 不动、不停、不删任何现有代码（GA4、Google Ads、Meta 像素、OpenAI 像素都不碰）；不往 Meta 像素加「购买」，不导入 Google Ads。
5. 用新的工作区改，先预览再发布，发布前确认没有别人没发布的改动被一起带出去。
6. 做完回邮件：几点发布的、版本号、预览里看到事件触发的截图。

**事件名为什么不叫 `purchase`**：GA4 里如果有人把 `purchase` 导进 Google Ads 当转化，Squid 的谷歌广告转化数会跟着变。叫 `ticket_order_complete` 就不会碰到他们。

**这个事件能看到什么、看不到什么**：
- 能看到：ME 广告带来的人里，有几单在官网付款完成。
- 看不到：每单几张票、多少钱。16 岁以下免费票的订单也会算一单。
- 广告拦截插件、拒绝追踪的客人记不到，所以会**少算**，不会多算。
- 票数和金额仍然只有 Eventbrite 后台有。

## 没核实的

- 现有 GA4 和 Tag Manager 归谁，谁有发布权限。
- 付款完成接口会不会交出订单号（装好后第 5 步测）。
- Eventbrite 后台加 GA4 需要什么角色；嵌在官网里的窗口会不会因此也记进去。
- Squid 的广告用什么来源标记，会不会跟我们的活动名撞上。
- GA4 会把 `meta / paid` 归到哪个渠道。
- OpenAI 像素和那段「付款完成」代码是谁装的。

## Reuse Statement（复用说明）

- **复用了什么**：客户官网现成的 GA4 和 Tag Manager、Eventbrite 内嵌窗口自带的付款完成接口、Meta 只读接口（广告预览读落地链接）、筹备清单 §4 已定的来源标记规则。ME 没写新代码，也没新建任何账号。
- **平台通用的**：「售票窗口嵌在客户官网里时，在官网这边接付款完成事件，不用售票平台后台权限也能记买票」这个做法，以后别的嵌入式售票、预约客户也能用。目前只有这一个客户的证据，验证通过后考虑补进 Meta 广告手册 §十五。
- **行业层**：无。
- **客户层**：GA4 编号、容器编号、广告标记对照表、邮件，都只在本客户文件夹里。
- **共享代码**：没有改动，没写进任何客户名或编号。
