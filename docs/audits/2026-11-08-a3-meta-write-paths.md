# A-3 Meta 广告写入入口清单（2026-11-08）

对照规则：改广告必须走「申请 → 确认卡 → 守卫 → 人点确认 → 执行 → 回读 → 台账」。
这里的「过卡」只认 `decideConfirmationCard` 返回已确认，且这张卡没过期、没作废。
内核信封里自动执行、内核待办上的批准、服务密钥，都不算过卡。

基线：fetch 后的 `origin/main` `16dc2f6c1`。没有调用 Meta。没有改 `#3685` 的文件，也没有重做赢家暂停、过期卡拒绝、暂停广告组卡、赢家只出卡。
Google / TikTok 的旧执行路由不在这张清单里。

## 没过确认卡

### 新洞，不适合在这一支里改

| 入口 | 现在怎么写 | 为什么不在这一支改 | 最小改法 |
|---|---|---|---|
| `POST /api/clients/[id]/meta-ads/draft` | 登录的付费客户直接建成暂停广告 | 暂停草稿卡只收单个广告组；这条路由还收多个组。接进去会改谁能建、返回什么 | 这条路由改为只出卡。多个组要先有一张认多个组的卡，不能塞进现有的单组卡 |
| `POST /api/clients/[id]/meta-ads/draft-listing` | 先把素材传到广告账户，再直接建成暂停广告 | 上传发生在出卡之前，而且草稿形状是房源专用的 | 先出卡；上传和建广告只放在点确认之后 |
| `POST /api/clients/[id]/ad-health/stop-loss` | 内部账号点了就走内核，信封内会暂停系列或下调预算 | 暂停的是系列，现有暂停卡停的是广告组；下调也不是预算卡那张单 | 这个路由只出对应的卡，不要在这里调用内核执行 |
| `POST /api/clients/[id]/ad-health/budget-change` 的下调 | 同上，复用止损提交 | 同上 | 同上，改走出预算确认卡 |
| 成绩单上调，以及 `POST /api/clients/[id]/ad-health/o1-scale` 和它的批准路由（算一条：两个门，同一次加预算） | 先等人在内核待办上批准，再由后台任务改预算。没有三十分钟确认卡 | 加钱批准人、历史核对、后台排队是另一套批准，不是把函数换个名字就能接上确认卡 | 提交只出确认卡；点确认且人仍是花钱批准人之后，才排队写 |
| `POST /api/clients/[id]/ad-health/auto-pause/[runId]/decision` | 待办上点批准就暂停广告组。内核批准，没有确认卡过期 | 这个动作的批准执行是专用入口，通用批准面不准带执行 | 批准改为点确认卡；过期卡不得调用暂停 |
| `POST /api/internal/meta-ads/pause-only` | 服务密钥加总开关，直接暂停名单里的系列。开投后盯盘会来调它 | 没有点卡的人，硬接确认卡会改掉这道服务入口的身份 | 没有一张未过期、已确认、且系列对得上的卡，就拒绝。盯盘只负责申请，不负责写 |
| 素材双审通过后的上传 | 成片验收通过就把视频传到广告账户 | 验收流程里没有确认卡的点击人 | 验收只出卡；点确认之后才上传 |
