# 把 Remotion 接进 ME 视频工厂：方案（只是方案，没改任何代码）

**一句话结论**：能接，工作量不大；工厂已有 7 成现成零件，缺的是「把内容从代码里拆成配置」和「三道新守门」。
**推荐**：先在本机跑（不上服务器、不自动发布），分两步走，第二步碰数据库所以算 A 级，要你亲口说「合」。
**不推荐**：现在就上 Render 服务器或 Remotion Lambda（云端按次渲染，要另开 AWS 账号）。
**要你拍板的 1 件事**：同意先做「第一步」（约 1 周，B 级、机器自动合、不碰数据库不碰发布）吗？回 `开做` 就行。
**先说一个坑**：~/Projects/cts-remotion 在仓库外面，正是 D14 事故那种「绕开工厂」的形态。接进来之前，它出的片只能当样片，不许发布。

## 1. 现在的 Creatomate 线怎么走，Remotion 接哪几处

**一句话流程**：PM 在看板点「确认选题」→ 建一条出片任务 → 发一个「请出片」的通知 → 后台取真实照片、配旁白 → 调 Creatomate 用模板出片 → 成片存回我们自己的库 → 任务变「待审」→ 再发通知让马良（AI 质检员）逐镜看图/字/logo → 过不了的标「返工」，全程不发布。
读自：`src/app/api/clients/[id]/content-factory/[postId]/route.ts` 174-195 行；`src/lib/inngest/functions/factory-creatomate-render.ts`；`src/lib/inngest/functions/maliang-render-check.ts`。

Remotion 作为第二个出片引擎，**最少接这 5 处**（都是照 Creatomate 抄一份，不是新造）：

| 接哪里 | 现状（读自） | 要做什么 |
|---|---|---|
| 数据库「用哪个引擎」那一列 | 只允许 `ffmpeg`/`creatomate` 两个值（`supabase/migrations/20260909130548_creatomate_render_engine.sql`） | 加 `remotion` 这个值。**碰数据库 = A 级** |
| 客户配置里的 engine | `client-config.ts` 167 行和 343 行：不认识的值**悄悄当成 ffmpeg**（没报错） | 改成认识 `remotion`，否则配了也静默不出片 |
| 「请出片」通知 | `me/factory.creatomate_render.requested`（`src/lib/creatomate/events.ts`） | 新增一个 `me/factory.remotion_render.requested`，同样只带 job/client/post 的 id |
| 素材放哪 | 成片存 `visual-assets`（`store-result.ts`）；真实照片来自 `client_assets`（`client-asset-pool.ts`） | 成片同样回存我们自己的库；素材走同一个素材池（见第 8 节） |
| 回执 | 每次写一条 `cron_run_logs`，带 request_id/client_id/source_record_id/cost_usd/`no_publish:true`（`factory-creatomate-render.ts` 里 finish-receipt） | 照抄，job 名固定写死 `remotion-render`，多记「配置指纹」和「素材清单+来源」 |

**两个容易漏的断头**（不处理 = 失败静默）：
- 失败待办只扫 `render_engine='creatomate'`（`src/lib/pm-todo/manual-content-items.ts` 77 行、`maliang-render-items.ts` 129 行）。Remotion 出片失败不会进今日待办，必须一起改。
- 马良自检读的是任务里的 `captionText`/`visualSource`，和「模板里有没有 logo」（`maliang-render-check.ts` 的 `scenesToInput`/`logoExpectedFrom`，后者读 Creatomate 专属配置）。Remotion 要按同样形状写回，否则自检拿到空字幕、空 logo 判断，会降级成「看不出问题」。

## 2. Remotion 在哪跑：推荐「先本机」

Remotion 靠一个看不见的 Chrome 浏览器逐帧截图再拼成视频。所以要求：Linux 要装一串浏览器依赖库、共享内存要调大（Docker 默认 64MB 太小，建议 1-2GB）、不能用 Alpine 系统、内存给到 8GB 是官方示例值（来自 Remotion 官方 Docker 文档，网上查的，非本仓库）。

| 方案 | 好处 | 坏处 |
|---|---|---|
| **A. 本机跑（推荐第一阶段）** | 现在就在用，零费用；已验证能出 3 种片型 | 要有人/机器开着；仓库里现有那台 Mac 工人**没有进程守护也没有掉线告警**（`docs/STATE.md` §4.4），Remotion 上去要补「心跳」，否则静默卡住 |
| B. Render 上单开一个专用后台服务 | 全自动，不占 Mac | 要自己写 Docker 镜像；**不能**塞进现有网站主服务（会抢内存拖垮网站）。主服务规格仓库里查不到（`render.yaml` 明说它不在这个文件里），Render 内存档位价目我没核实，只能估「每月几十美元起」，**没验证** |
| C. Remotion Lambda（云端按次渲染） | 渲染快、不占机器 | 要新开 AWS 账号和权限，多一个供应商，多一套钥匙要管 |

**推荐**：第一阶段 A（本机，通过任务表领单，不自动发布）。**等每周出片超过一个人手动盯得过来的量**（我的判断线是每周约 10 条以上，是估计不是数据）再上 B，不走 C。
**渲染耗时、单条成本**：本机没有记录，**没验证**；第一步 PR 里会实测并写进 PR。
**授权费（重要，没验证你们人数）**：网上查到 Remotion 对 3 人及以下团队免费（含商用），4 人及以上要买公司授权：做手动出片约每人每月 US$25，做自动化约每条 US$0.01、每月最低 US$100（来源：remotion.dev 授权页，网上查的）。Magic Lab 是否算 4 人及以上，我不知道。自动化上服务器前必须先确认，这是钱的事。

## 3. 片型配置怎么存（为什么不违反平台化铁律 §0）

**现状问题**：现在 Remotion 工程里，价格 4080、出发日期、城市列表、视频文件名都**直接写在代码里**（`~/Projects/cts-remotion/src/BocReel.tsx` 文件开头的常量和价格场景那一行），4 个片型共 556 行。换一个产品就要改代码，这正是「客户特供」。

**怎么拆**（三层，对应 CLAUDE.md §0 的「共享 / 行业 / 客户」）：
- **片型（路线地图 / 悬念问答 / 清单）= 共享代码**，放仓库里，不含任何客户名、价格、城市。
- **每个产品一份配置（城市、价格、出发期、素材清单、字幕）= 客户配置**。落库沿用现成位置 `clients.factory_config.render.remotion`（和 Creatomate 的 `render.creatomate` 并列，形状照 `src/lib/creatomate/types.ts` 的 `CreatomateTemplateContract`）；真实价格/出发期**直接复用已有的 `offers` 事实字典**（同文件，`offers` + `postFieldSources`，那是「确定性映射、不让 AI 改写」的设计），不另存一份。第一步先用文件放 `tools/remotion-reels/configs/`，进了第二步再落库。
- **「路线地图」这个片型本身带旅游味**（路线、出发期、人均价），归**行业剧本（旅游版）**；悬念问答、清单更通用。分层由层级门登记，不由我拍。

**换客户自检**：明天换成悉尼地产客户，代码要改吗？片型代码不用改，只换配置；但「路线地图」换到地产没意义，它会留在旅游版剧本里，不硬塞成通用能力。

## 5. 风险级别与要不要你亲自说话

按 `docs/ENGINEERING_QUALITY_GATES.md` §2：
- **第一步（本机工程 + 配置 + 自检脚本）：B 级。** 理由：不碰数据库、不碰权限、不发布、不花供应商钱，独立小包，不进主程序依赖。但它引入新依赖（Remotion），按 CLAUDE.md §4 算「大任务」，要**子牙+魏征两个人审**（设计一次、做完一次）。B 级由机器判级、检查全绿自动合，**不需要你说话**。
- **第二步（接进工厂：改数据库那一列 + 通知 + 回执 + 待办）：A 级。** 理由：改数据库结构、加状态流转、客户内容链路。要保持草稿、正文写明「风险级别：A」，**必须你在对话里回 `合` 才合**；转述不算数。
- 实际级别以 diff 计算（`tools/ops-review-loop/src/risk.mjs`）为准，我自报是下限。

## 6. 分阶段、不做什么、怎么验收

**第一步（≤1 周，B 级）**：
1. 把 cts-remotion 3 个片型搬进仓库 `tools/remotion-reels/`（独立 package.json，不动主程序依赖），1GB 的 out 草稿不进仓库。
2. 内容从代码里拆成每产品一份配置，带校验，缺字段直接报错。
3. 新建自检脚本：配方对账表必填、字幕安全区检查、数字/日期/价格对官网来源、本地抽 9 帧缩略图。
4. 一条命令出片，把 CTS 现有 3 条样片用配置重出一遍。

**明确不做**：改数据库、Inngest 通知、上传存储、发布、Render 服务器、Lambda、新增片型、买歌曲/图库、改任何在投广告。

**当场试跑验收**（CLAUDE.md「当场试跑」）：①3 份配置各出一条成片，记退出码、耗时、文件大小；②故意造 3 份「坏配置」（价格对不上官网、字幕压出安全区、少来源链接），必须全部非零退出码并说明原因；③自检报告 + 9 宫格图贴进 PR 正文「## 当场试跑」一段。没拦住坏配置 = 不算做好。
**第二步**（A 级，另开 PR）：第 1 节的 5 处接线 + 两个断头，当场试跑用测试客户跑通到「待审」且 `no_publish`。
**第三步**（有量再说）：上 Render 专用服务；先确认授权费。

**层级门 inline**：
> [跟班 · Tier] 这是 L3（又一个出片引擎适配器，和 Creatomate 并列）挂在社媒/视频工厂下；片型模板里「路线地图」归 L2 旅游版，问答/清单可能是 L1 候选；每产品配置是 L4。不新增能力线，不需登记候选。

## 8. 素材获取（已知瓶颈：真实视频约 15 条）

**现状**：样片台账写明素材库见底，约 15 条真实镜头，Natural China 因此没做（`docs/ledger/2026-10-04-cts-christmas-sample-reel-awaiting-pm.md`）；西安一镜是 iStock 图，能否用于付费广告待 CTS 确认（同目录 `2026-10-04-cts-old-i2v-clips-istock-exposure.md`）。

**现有素材池能不能承接？大半能**：
- 现成：客户素材表 `client_assets`（带来源标记、客户/楼盘/房源隔离，`client-asset-pool.ts`）；真实视频入库 `video_clips` 且只收真拍原件、9:16 优先、≥1.5 秒（`real-footage-ingest.ts`）；客户上传免登录链接（该文件头注提到）。
- 缺口：①来源标记里没有「授权范围」（例如「可用于付费广告」），iStock 问题就是这么漏的；②Remotion 要新写一个读 `video_clips` 的加载器；③没有「同一素材最近用了几次」的复用上限，片型多了会千篇一律（没验证是否已有）。

**推荐（主 + 补，不罗列）**：
1. **主力：CTS 同事竖拍 SOP。** 质量最高、零授权风险、能给真价背书。不让同事自己琢磨拍什么：**由片型配置里的「镜头槽位」自动生成一页拍摄清单**（每个片型要几条、什么景别、拍几秒），上传走现有上传链接，进素材池自动分析。
2. **补位：Pexels/Unsplash 免费视频**，只用于泛场景，**不许打地名大字**（样片台账已因拍摄地无法证实把西湖、龙井改成泛称）。这是 CLAUDE.md §8「素材不足去全网抓」的首选，但真实产品/真实价格画面只能用客户自己的。
3. **暂不扩：付费图库**（授权待 CTS 回）；**不做：AI 图生视频当主力**（PITFALLS D6：画面里有字或人脸必崩）。
4. **防千篇一律的硬规矩**：每个片型配置声明「至少几条不同素材」，同客户 30 天内同一素材复用次数设上限，超了不出片并转人工待办「需要新素材」。这条放第二步做。
