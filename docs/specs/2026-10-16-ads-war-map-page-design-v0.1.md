## 0. 平台层级（Inline）

- **层级**：L1 既有能力的扩展。不新增能力线、不新增支柱。现成的「广告体检」页（`src/app/dashboard/clients/[id]/ads-health/`）和每天写一行的经营视图 `ads_growth_states` 已经是这块的底座，本稿只是把它们**拼成一张按天盯的整体版面**，并补上「观众池」「频率」两块之前没有放在一起看的数。
- **行业 / 客户差异**：团名、毛利率（直接 20% / Agent 或 Sales 10%）、盈亏线、每团起点预算来自推广计划数据和客户配置，不写进共享代码；换成地产或电商客户，「团」换成「楼盘」或「品类」，骨架不变。
- **不重复建**：不另建诊断引擎（`portfolio/diagnostics` 已有 D1–D11、`opportunities` 已有 O1–O3）；不另建对账（推广计划页已有 `ReconcileTable`）；客户版沿用 `growth-client-view.ts` 的裁剪方式。

## 2. 页面结构（一页，从上到下）

1. **顶部条**：距开投几天、距内部目标日（11/30）几天、账户状态灯、**数据日**与**取数时间**（两个时钟都要显示：业务日期停在 10/10 不等于取数坏了）。
2. **① 观众池怎么样**：每个池一行——名称、账户、人数（下限，带「≥」）、近 7 天长没长、哪些广告组在用它。灯：够大且在长 = 绿；人数 ≤ 1,000 或读到 −1 = **判不了**（不是 0）；一周缩一成以上 = 黄。
3. **② 频率有没有过高**：每层（L0 攒池子、L1 暖、L2 冷、L3 收割）一行——7 天不重复频率、点击率相对自己基线的走势、红线 3。高于红线且点击率在掉 = 换人；低于红线且点击率在掉 = 换素材。
4. **③ 今天要怎么调**：按轻重排的动作清单，每条写清「做什么 / 为什么（数字）/ 谁批 / 改完冻结到哪天」。
5. **四团进度**：每团剩座（上限，待 CTS 确认）、广告目标座、起点预算、盈亏线；开投后加三列：今天花了多少、线索几条、已订涨几个，对比「应到进度」。
6. **底部三种「没有数」**：读不到（接口出错）· 还没巡察（今天没有这一行）· 判不了（数据不全）。**都不许显示成 0**（沿用 `growth-panel.tsx` 的规矩）。

## 3. 每个格子的数据从哪来、有什么坑

| 格子 | 来源 | 刷新 | 已知坑 |
|---|---|---|---|
| 数据日 / 取数时间 | `ad_daily_insights.insight_date` 与 `fetched_at` | 每天一次 | 账户停投时业务日会停住 |
| 账户状态 | `ad_entity_snapshots.account_status`（1 = 正常） | 每 6 小时 | 状态码 3 = 欠款；恢复要看当天有新数据行 + 线索回流，不能只看状态 |
| 池子人数与趋势 | `ad_entity_snapshots` 里 `level='audience'` 的 `audience_count_lower` 历史 | 3–6 小时 | 显示值 ≤ 1,000 是下限；−1 = 读不到；趋势用 D11 的中位数口径，别用两端点相减 |
| 谁在用池子 | 广告组的 `included_audience_ids` / `excluded_audience_ids` | 同上 | 排除会盖过包含（策略稿已记过一次） |
| 频率 | `ad_daily_insights.frequency_7d`（campaign / adset 层） | 每天 | `reach` 不能跨层相加；7 天频率才是给人看的，当天值天天跳 |
| 疲劳判断 | `ad_health_narratives` + `rules/fatigue.ts` | 每天 | 低量广告点击率噪音大，样本不够就写判不了 |
| 要调的动作 | `ads_growth_states.payload`（D1–D11、O1–O3）+ `goal_pace` | 每天 | 目标挂的是旧目标时，进度会误报「落后」；新目标转进行中前先别当真 |
| 每团进度 | `crm_bookings` + 推广计划 + `me_sale_outcomes` | 手工 / 每天 | **已订是手工录入的下限**；`me_sale_outcomes` 现在不分团（116 已记，转进行中前要加按团过滤） |
| 线索归到哪个团 | `contact_touchpoints.attr_adset_id / attr_ad_name` | 随线索 | 要靠广告组名里带「团名 + 出发日」才分得开；命名约定要先定 |
| 起点预算、盈亏线 | 推广计划数据 + 客户配置 | 随计划 | 毛利率放客户配置，不写进共享代码 |

## 4. 规则：沿用现成的，新增的标「候选」

- **现成**：频率红线 3；单次改动 ≤ 20%；两次改动隔 72 小时；改完冻结 7 天；样本 < 25 条线索不下结论；池子一周缩 > 10% 报黄（D11 候选）。
- **审批档位按手册（2026-10-10）**：停和减需人批；加预算、挪预算、改受众、开新广告、关整个系列要 PM 本人。页面只给**建议**，批准走今日待办，页面不放任何「直接改」的按钮。
- **新增候选（只有 CTS 一家证据，开投后用真数据校准，不当定论）**：①覆盖率 = 近 7 天不重复触达 ÷ 池子人数，高于 60% 报黄；②盈亏线线索价 = 每座毛利 ÷ 每座对应线索数（Sales 成交 10% 时上海约 12、Tale 约 16、Best of China 约 18、Natural China 约 33）；③「应到进度」= 阶段预算 ÷ 每座成本的累计座位数。

## 5. 分几步做（每步你都能在页面上看到）

| 步 | 内容 | 级别 | 前置 |
|---|---|---|---|
| S1 | 只读页面：顶部条 + ① 观众池 + ② 频率 + ③ 今日动作，全部读现成的行，不建表、不加定时任务 | B | 无 |
