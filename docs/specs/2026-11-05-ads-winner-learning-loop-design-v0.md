## 1. 层级判定与 Build vs Connect

**Tier Classification（Full，动视频工厂与广告诊断两块共享代码）**

- **建议层级**：既有 L1 的扩展。发现、对比挂在「广告」支柱；照骨架出片挂在「社媒」支柱的视频工厂；状态与复核属「记忆 / 验证」基础设施。**不新增能力线、支柱、agent。**
- **换客户测试** ✓：Oztop、NAL 同样有「哪条广告在自己的结果种类上最便宜 → 拆骨架 → 照骨架出片」。差异只在结果种类、事实来源、骨架里的字——来自客户配置与事实接口。
- **换行业测试** ✓（有前提）：地产、物流没有团目录，所以事实必须走一个**通用事实来源接口**（§3.5），各行业各自实现；事实位清单放行业层登记表。
- **红线**：1 ✓ 不叫「赢家智能层」；2 ✓ 骨架与数字只在客户私有行；3 ✓ 既有 L1 扩展；4/5 ✓；6 ✓ 走五道门；7 ✓ 行业层只装事实位与门槛。
- **Build vs Connect**：
  - **Connect**：Meta 只读、Remotion 出片机、团目录、官网、CRM。
  - **Reuse**：素材成绩单、结果种类、合格客人、马良 v2、价格数字闸、事实比对、工厂下单 / 变体单、素材池推广期、今日待办、Inngest。
  - **Build（平台共享）**：共享赢家读取函数；骨架 → 出片参数生成函数；价格开头版式；对账赢家列；事实位来源接口。

## 3. 设计

授权级别沿用藏经阁第六部：L0 只读 · L1 出草稿、人点才做 · L2 低风险可回滚自动做 · L3 高风险只给证据、人批。
回执：Inngest 事件 + 机器可读回执（CLAUDE.md §3 字段）。**回执存哪**：赢家状态变更存 `winner_structures.performance` 的 `program_check` / `pm_decision` 段；出片相关存工单 `content_work_orders.output.winner_check`；跨步骤事件另进现有 `flywheel_actions`（动作卡契约，Agent 闭环升级 v0.1 §4）。

### 3.1 本轮只做的两件事（刀 1、刀 2）

1. **工厂只认 PM 确认过的赢家**（§3.3）。
2. **工厂能照赢家骨架出广告片**（§3.4、§3.5）。

六步闭环里的「① 自动发现」「⑤ 投后对比」「⑥ 升级退役」先写清规则、不实现，按 §10 重启条件再开。

### 3.2 骨架长什么样（结构化，不是自由文本）

```
hook    = { seconds, visual_kind, fact_slots[] }            # 例：[price, room_basis, departure_date, departure_city]
scenes[]= { seconds, place, inclusion_slot }                # 例：{ place: "Suzhou gardens", inclusion_slot: duration_days }
endcard = { seconds, fact_slots[], url_slot }
style   = { pace_s_per_scene, text_size, safe_area_ok }
footage = { source: client_licensed | stock | ai_i2v, landmark_matches_itinerary: bool, audio_present: bool }
copy    = { body_matches_screen: bool, cta_type, form_kind }
win_reason_tags[]（固定词表）
```

**拆骨架不另调模型**：直接用马良 v2（`maliang/render-check-v2.ts`）逐镜输出（镜头表 `shots`、音轨、文字）当拆解结果。**独立复核只认确定性部分**：首帧画面文字里能不能识别出价格与 twin share、切点数与每镜时长、正文；「每景是不是一地一包含」这类语义项由 PM 看截图核。拆骨架这一步**不核**「首帧价格 = 团目录现价」（旧 winner 当时的价可能就不同），现价比对放出片步（§3.5）。

### 3.3 工厂只认 PM 确认过的赢家（刀 1）

- **一个共享读取函数**：`src/lib/factory/winner-gate.ts`（新）导出 `loadUsableWinners(clientId)`，**所有下单入口**（`evaluateSignal`、后台下单、变体单）只许调它，不许各自查表。
- **关闭即失败**：一条赢家算「可用」必须同时满足：`status=active`；`performance.program_check.state` 在固定取值 `{ passed }`；`performance.pm_decision = { decision: "approved", by, event_id, at }` 且能在确认回执里对上（人 = 该客户名单里有权确认的人、事件编号、时间；见 §4 / §11 第 2 题）。缺键、解析失败、不在固定取值 = **不可用**。
- **两块分开存**：`program_check{}`（程序复核结论）和 `pm_decision{}`（PM 决定）各存一段；写入只**合并**对应段（`jsonb ||`），不整块覆盖 `performance`。
- **核两次**：建单时核一次；出片机领单时按工单上的 `winner_structure_id` 再核一次（赢家在中间被撤认 / 退役就拒单）。
- **Winner Intake 人工通道**：照旧能写，但写进来的行没有 `pm_decision`，自动「不可用」；客户匹配改为按客户编号，不再按名字模糊匹配（属刀 1 范围内的最小修）。
- **排序**：`pickWinner` 改为在可用赢家里，按**该赢家所在广告组自己的结果种类**的单次成本排序（`rules/core-metric.ts`）；缺这个数的行算「不可用」，不是排到最后。
- **11-04 那条的顺序**：刀 1 合并后它会变「不可用」（没有 `pm_decision`）→ 刀 1 当场跑一次复核（马良 v2 读这条视频，约 0.05 美元）→ 今日待办给 PM 一条「认 / 不认」，附截图与复核结论 → PM 点「认」才恢复。这**不算重复问 PM**：11-04 PM 说的是「记进工厂」，没有核骨架本身。

### 3.4 照骨架出广告片（刀 2，A 级）

- **出片层**：走 Remotion（CTS 现在 135/137 张工单就走它）。在 `src/lib/factory/` 新写「骨架 → Remotion 出片参数」生成函数，参照 `src/lib/factory/remotion-daily-plan/montage-props.ts` 的写法；模板侧给明信片新增一个**价格开头版式**（价格卡放第一镜，片尾复述）。价格数字只进价格卡，数字闸复用 `src/lib/content/price-claim-gate.ts`，不改明信片现有「其它位置不许出价格」的规则。
- **升级顺序**：先升级出片机（Remotion README 包 C：旧出片机不认识新模板会拒单），再允许建新版式工单；CTS 需在 `FACTORY_REMOTION_CLIENT_IDS` 准入名单内。
- **入口**：后台「下单」与「变体单」（`variant-order*.ts`）在客户有可用赢家时**默认带上它**，页面写「照赢家 <编号> 做」；要换别的骨架须选理由（固定选项）写进工单。Creatomate 的「内容卡片 · 生成视频」入口**不算广告片入口**，不受这条约束。
- **工单记录**：`order_type = variant_from_winner`、`winner_structure_id`（字段已有）。
- **CTS 换出片引擎**：从 Creatomate 默认配置切到 Remotion 价格开头版式，是客户配置变化——在后台客户设置里显示「广告片出片方式：照赢家骨架（Remotion）」，PM 看得到、能改回。
- **对账表加列（出片交回那一步卡）**：现有 Remotion 出片机交回时对账；明信片模板目前**没有缺项清单**，刀 2 要补。

| 列 | 怎么判 | 不满足 |
|---|---|---|
| 第一镜是价格卡 | 出片参数 + 出片机回执 | 拒单 |
| 每景一地一包含 | 出片参数 | 拒单 |
| 结尾复述事实 | 出片参数 | 拒单 |
| **footage_source**（客户授权实拍 / 图库 / AI 图生视频） | 素材记录 + 客户配置开关 | 价格卡底图：开关关（平台默认）= 只许客户授权实拍；开关开（已定只对 CTS，§11 第 1 题）= 也许图库 / AI 图，但只许景点风景、图库须可商用并留出处、AI 图过马良逐镜自检；不满足拒单 |
| **landmark_matches_itinerary**（地标属于这个团的行程） | 景点 ↔ 团目录行程 | 拒单（PITFALLS D6） |
| **audio_present** | 出片机响度回执 | 拒单（PITFALLS D14） |
| 单景时长、字号、安全区 | 出片机回执 | 拒单 |

  后三类「要换素材才能满足」的列（素材来源、地标、声音）**不许降级放行**（PITFALLS D5：只满足改数字的列 = 没照配方做）。
- **出片后**：照旧马良审（审片对照骨架并入本刀）+ 苏东坡审 + PM 授权；分镜自检表照出。

### 3.5 事实位从哪取（刀 2）

**通用事实来源接口**：`FactSource.load(clientId, productKey) → { slots }`；旅游实现读团目录，地产 / 物流以后各自实现。事实位清单放行业层登记表（旅游一张），不进共享代码。

| 事实位 | CTS 从哪取 | 备注 |
|---|---|---|
| price | 团目录 `displayPriceText`（文字） | 经 `price-claim-gate` 解析成数字；解析不出 = 拒单 |
| room_basis | **客户配置**（CTS 价格一律 twin share） | 必填位；客户配置没有 = 拒单 |
| departure_date | 团目录出发日 | 多个出发日多档价时，第一帧取**最近一个仍在售**的出发日及其价格；已取消 / 已关闭的出发日不取 |
| departure_city | 客户配置（团目录没有此字段） | 必填位 |
| duration_days / meals / flights_included | 团目录「包含项」原文 | 目录没写的说法 = 拒单 |
| url | 团目录团页链接 | — |

- **官网复核**：建单时用 `evaluateClaims`（`messenger-agent/verifier/content-claims-gate.ts`，社媒每周闭环同款）把成片要说的话跟官网团页对一遍，对不上拒单。
- **上线后改价**：走素材池推广期（`creative-pool/approve`、`promo-window` 路由），推广期不超过该价 / 该出发日的有效期；团目录改价或下架时，今日待办提议撤素材（人批，不自动撤）。

### 3.6 先写清、暂不实现的规则（重启后才做）

- **① 发现**：复用素材成绩单 `entity-tree/creative-compare.ts`「能不能比」；门槛按修复方案 v0.5 的「平台默认 + 行业 + 客户」分层；Meta 三项排名 src 里没人拉，规则里**不用排名**。
- **⑤ 验证判定线**：每组至少 50 个结果才比，不够一律「未决」；「变好」= 单次成本 ≤ 赢家 0.7 倍且下一个窗口仍成立；「未决」不进今日待办，只进周报。变体**另建组**，不放进赢家所在组（要预算 → PM 批，算清这笔钱）；**换团算新测试，不算变体**（修复方案 v0.5 第 109 行）。认出「这条广告是照骨架做的」靠 `ad_creative_links`——只有两条建广告路径会记，在 Meta 后台手建的对不上，这是前置条件。外环：合格客人只记录，14 天观察，人判 / AI 判分开。

## 13. 疲劳 → 对症优化闭环（v0.2 新增 · 2026-11-05 · PM 要求记入 agent loop）

> 起因：PM 11-05 看出 CTS 现役赢家组累计频次已到 2.6、单次留资成本逐日走高，并定了处方：**真正能解决的只有两样——新的素材角度（照赢家骨架换团、换景点）和新的受众来源（如拿合格客人做相似受众）**。这两样在做、没做完。本节把「发现疲劳 → 判断病因 → 开处方 → 验证 → 记住」写成固定流程，之后每个客户、每条赢家都走这条路，不再靠人临场判断。
> 只写设计，不改 `src/`，不碰 Meta 与库。

### 13.0 大白话（5 行）

1. 一条广告跑久了会被同一批人看腻：点击率往下掉、千次曝光成本往上走、留资变贵。
2. 光「加预算」治不了：钱只会更快把同一批人刷烦。**能治的是换内容、换人，两样都要。**
3. 系统要在「还没烂到红线」时就提醒「该准备新素材 / 新人群了」，并且说清楚是素材老了还是人看腻了，还是两者都有。
4. 任何实验开工前先写清「它回答哪个根因问题」，答案不是根因就不开（11-05 的拆组实验就是这么被 PM 叫停的：同人群同素材多给 60 块，治的不是看腻）。
5. 动到「投给谁」「拿客人名单给 Meta」「花钱」的步骤，全部要 PM 本人点头；本节不新增任何自动开投、自动加预算。

### 13.1 触发：什么叫「疲劳了」（只读发现，L0）

用**三个信号同时变坏**，不看单一指标：点击率比自己的基线掉、千次曝光成本（CPM）上升、单次结果成本（按单元自己的结果种类，见 `rules/core-metric.ts`）上升；再加**覆盖信号**：在投广告组的累计触达人数偏小而频次偏高。

**测试用例 Q8（CTS 赢家组，11-05 只读拉数；2 天合计 → 逐日）**

| 日期 | 花费 | 留资 | 单次成本 | 点击率 | CPM | 频次 |
|---|---|---|---|---|---|---|
| 10-30 / 31 合计 | 173.5 | 44 | 3.94 | 6.37% | 17.7 | 1.77 |
| 11-01 | 82.71 | 16 | 5.17 | 5.37% | 13.71 | 1.36 |
| 11-02 | 96.83 | 18 | 5.38 | 5.23% | 15.72 | 1.32 |
| 11-03 | 100.98 | 22 | 4.59 | 4.55% | 17.46 | 1.27 |
| 11-04 | 99.69 | 18 | 5.54 | 4.90% | 18.51 | 1.38 |
| 11-05（半天，不判） | 28.59 | 4 | 7.15 | 3.98% | 19.95 | 1.20 |

9 天累计触达约 1.24 万人，该广告组累计频次约 2.6（系列层 3.15，但含已暂停的另一组 4.59，不能当这组的数）。**读法**：点击率 6.37% → 4.90%（−23%）、CPM 17.7 → 18.5、单次成本 3.94 → 5.54，三项同向；半天数据只有 4 条留资，**不进判断**。

**这个用例暴露的缺口**：D2 现行规则要求点击率比自己基线掉 ≥ 25%（`D2_MIN_CTR_DROP`），按首期 6.37% 粗算 11-04 只掉 23%，**还没触发**；等触发时已多烧几天（粗算口径，D2 实际基线窗口没在本地重算）。所以需要一个**比 D2 早、只提示不动钱**的「该准备新货了」档。

### 13.2 诊断：先分清是哪种看腻（L0）

输出的是**主因 + 次因**，不是二选一：

| 看到 | 判断 | 处方走哪条 |
|---|---|---|
| 频次不高 + 点击率掉 | 素材老了 | 素材轨 |
| 频次高 + 点击率掉 | 这批人看腻了 | 受众轨（素材轨同步准备，因为同一批人看新货也只能缓一阵） |
| 频次中等（2–3）+ 触达池小（累计 < 约 2 万人）+ 三信号同向 | **池子太小，两种叠加**（Q8 就是这种） | **两轨都开，素材轨先**（不碰钱、不改投给谁） |
| 点击率稳 + 单次成本涨 | 问题在点进去之后 | 沿用现行 `review_offer`，不在本节 |

诊断必须附：用的是哪一层数据（在投广告组 / 含暂停组的系列）、窗口多长、样本多大。样本不够写「判不了：<原因>」，不当 0。

### 13.3 处方：两条轨，各有边界

**素材轨（新的素材角度）**
- 做法：照赢家骨架（首镜价格 → 每景点配一项「包含什么」→ 结尾再报价，见 §3.2）**换团、换景点**。换团算**新测试，不算变体**（修复方案 v0.5 第 109 行），自己带比较口径。
- 产出路径：§3.4 照骨架出片（刀 2）；或外部成品走 admit-finished 入口 → 马良审 → PM 批 → 进素材池并声明推广期。
- 事实位全部现取（§3.5）：价格、出发日对团目录并与官网核对，对不上就不出片、不凑合。
- 本轮候选团由「新团事实单」窗口出（价格 / 日期冲突在事实单里列，等客户确认），本节不替它定。

**受众轨（新的受众来源）按风险分三档，由低到高：**

| 档 | 种子 | 是否交出客人个人信息 | 授权 |
|---|---|---|---|
| ① 平台内部 | 现有视频观看 / ThruPlay 自定义受众（几万人级）建相似受众；先查已有相似受众是不是已失效（INACTIVE） | 否 | PM 点头（改变投给谁、要花钱）；保留「已留资 90 天」排除项 |
| ② 站内互动 | 官网访客、表单打开未提交（要先核像素数据是否可读） | 否（平台自己的事件） | PM 点头；读不到写「判不了」 |
| ③ 合格客人名单 | CRM 里走到「已报价」及以后的客人（173 人，其中已付款及以后 43 人） | **是——把客人联系方式上传给 Meta** | **必须 PM 书面同意**；A 级 |

第 ③ 档的两条红线：
1. 上传名单 = 把客人个人信息交给第三方，**只有 PM 本人在对话里明确同意才做**，转述不算；上传前先核隐私声明是否覆盖、名单里没有「别联系」标记的人、只传加密后的联系方式。
2. 它和 11-03 那条规则是**两件事**：「合格客人」的定义**不回传给 Meta 当优化目标**（不变）；这里是用名单**做受众种子**。PM 同意第 ③ 档不等于同意回传。种子人数偏少时（已付款 43）相似受众质量存疑，用 173 人的大名单；Meta 对种子最少人数的要求属平台规则，**开工前查官方文档再写进方案**（本稿未核实）。

### 13.5 验证与学习（IMPACT 的 Check / Tune）

- **判定线沿用 §3.6 ⑤**：每组至少 50 个结果才比；不够一律「未决」，只进周报。
- **素材轨**：新片 vs 原赢家组，同期、同版位、同结果种类；成功 = 单次成本 ≤ 0.7 倍赢家且下一个窗口仍成立。对症指标另看：原组频次是否回落、点击率是否回升（新片分流之后）。
- **受众轨**：新受众广告组的「触达中新人占比」、频次、单次成本；合格客人占比走外环（§3.6，14 天观察，人判 / AI 判分开）。**质量比数量贵**：留资便宜但合格率低的受众不算赢。
- **回执**：每步写机器可读回执（诊断依据、层级、窗口、样本、PM 授权人、no_publish 状态）。**这是只读设计，本稿不新增 Inngest 事件；刀 1 只读提示不触发外部副作用，不需要；后续刀 2/3 的出片、受众创建要接事件，届时在各自设计里定名。**
- **学习分层（同 §5）**：这个客户的「疲劳到了什么程度、哪种处方有效」先记客户私有；要第二个同行业客户出现同样证据才升行业层；全局层只写纪律（见 13.8）。

### 13.7 开工十问（本节）

1. **IMPACT 哪段？** Inspect/Measure（三信号）→ Prescribe（两轨处方）→ Act（沿用现有授权）→ Check/Tune（13.5）。
2. **确定 vs 模型？** 三信号、阈值、层级选择全是代码；素材判读沿用马良 v2；本节不新增模型调用。
3. **对外动作与授权？** 见 13.4；本节无自动外发。
4. **完成证据？** 诊断卡（含依据与样本）、PM 授权回执、新片 / 新受众的验证回执。
5. **谁验证？** 规则：考卷 Q8；素材：马良 + 苏东坡 + PM；受众名单：PM 书面同意。
6. **学到的写哪层？** 客户私有先行，同行业第二家出现才升行业层（13.5）。
7. **考卷？** 新增 Q8（合成数据：Q8 逐日表，期望「素材 + 受众两轨、主因池子太小」，半天数据不判，系列含暂停组时拒用系列频次）。
8. **PM 纠正落哪？** 补考题或改阈值，记台账。
9. **读不到说什么？** 「判不了：<原因>」，不当 0。
10. **注意力？不加 agent？** 不加 agent；每条疲劳处方卡最多一次推 PM（沿用 §7 节奏）。

### 13.8 通用纪律：实验开工前先写「它回答哪个根因问题」

ME 已踩过的：**任何实验开工前，必须先写清「这个实验回答哪个根因问题」；答案不是根因，就不开。** 11-05 拆组实验（同人群、同素材，另给 60 元/天）回答的是「预算分散会不会多触达」，而根因是「池子小 + 素材老」，PM 叫停——正确。该条候选纪律已加到广告手册（见 `docs/playbooks/ads/meta-general.md`），全局层只写这一句，不写客户数字。
