# 素材「推广期」闸：过期视频不得再推广 · 设计稿 v0.1（只设计，未写代码）

- 日期：2026-10-21　窗口：119　风险级：**A**（改素材批准闸、改广告暂停的自动化、碰内核 → 影响真实投放与花钱）
- 来源：PM 10-21 新规则：视频里可能烧入出发日期/价格，早鸟视频还要强调日期，所以每条视频有「推广期」，到期必须自动停。经 74 号转述。
- 状态：草稿，待 74 号过平台层级门，再送子牙+魏征审；审完前不写代码。

## 0. 先说结论

1. **这是现有「素材批准」闸的补全，不是新能力**：素材池（`ad_strategy_configs.creative_pool`）已有「批准」唯一入口，广告草稿门（`marketing-plan/promo/gates.ts:164`）已核对「用到的素材必须是 approved」。加的是第二个条件：**批准时必须有推广期，用的时候推广期必须覆盖整个投放期**。
2. **一个必须先说清的坑**：素材池是 JSON 字段，读取时 `parseCreativePool`（`ads-strategy/config.ts:63`）会**丢掉所有不认识的键**。只往库里写 `promo_start/promo_end` 而不改解析器，推广期会被读取方静默丢掉——闸形同虚设。解析器和类型必须同一个 PR 改，并有测试证明「写进去、读出来」。
3. **自动暂停的粒度问题**：内核现有的暂停动作是**广告组级**（`ads.pause_unit`）和系列级（`ads.pause_campaign`），没有「只停一条广告」的动作。一个广告组里常有多条视频；某一条过期就整组停，会误伤没过期的。所以第一刀**只检测不暂停**；自动暂停分两种情形设计（见 §4.b）。
4. **我没法替你们定每条视频的推广期**：它取决于视频里烧的日期和价格，必须由工厂工单（或 PM）给出，系统不得猜。回填方案（§5）是「列清单、你们填、系统校验」，不是系统推断。

## 1. 数据（①）

**推广期的形状**（不是两个可空日期，避免「空=默认放行」）：
```
promo_window: { kind: 'dated', start: 'YYYY-MM-DD', end: 'YYYY-MM-DD' }   // 新西兰日期，end 含当天
            | { kind: 'evergreen' }                                      // 明确声明：视频里没有日期/价格
```
- 存放：`creative_pool[i].promo_window`；解析器与类型同步改；解析**失败/缺失一律当作「未声明」**，不当作 evergreen。
- 来源：
  - 工厂工单（`content_work_orders`）：推广期写进 `brief`（已是 jsonb，**不需要改表结构**）；工单创建时必填，且工厂对账表里新增一列「画面里有日期/价格吗？→ 有则必须 dated」。
  - 旧的 `meta_video` 类条目（已存在的 5 条）没有工单可追溯 → 由 FDE/PM 在批准界面补，见 §5。
- 约束（机器强制，不靠约定）：`dated` 要求 `start ≤ end`；`end` 不得早于今天（新批准时）；画面含日期/价格的工单**禁止选 evergreen**。
- 批准入口（`creative-pool/approve/route.ts`）目前只接受 `{ref}`、`approved_by` 服务端派生。**保持这两条**，推广期不由客户端自由传入：从工单读（`work_order` 条目）；`meta_video` 条目则新增一个同样受限的入口让内部员工补推广期，写审计。
- **没有推广期（未声明）的视频：批准接口返回 422，拒绝入池。**

## 2. 拦截点（②）

通用纯函数（可复用，不含客户/行业）：
```
promoVerdict(entry, now, usePeriod?: {start, end}) →
  'ok' | 'undeclared' | 'not_started' | 'expired' | 'expires_before_use_end'
```

**a) 批准 / 发布 / 启用时拒绝**
- 批准入池：`undeclared`、`expired` → 422。
- 起草广告（`promo/gates.ts`）：用到的素材除 approved 外还要 `promoVerdict` 对「广告组计划起止」为 ok；`expires_before_use_end` → 拒绝并提示「请缩短投放期或换素材」。
- 启用广告：`ad-publisher.ts` 的 `activatePublished`（把 PAUSED 改 ACTIVE 的地方）启用前再核一次（草稿到启用之间可能过了几天）；失败 fail closed，不启用。
- 内核层（A 级重点）：`ads.*` 里**会增加曝光的动作**（加预算 `scale_unit_budget`、`add_retargeting_adset`、`swap_creative` 换入新素材）的信封事实里加一条「涉及的素材推广期有效」，不满足 → 拒。收类动作（暂停/降预算）**不受影响**。

**c) 新建 / 复制广告组时 end_time 封顶**
- ME 自建：`ad-publisher.ts:237` 现在是 `end_time = now + durationDays`。改为 `min(now + durationDays, 所用视频中最早的 promo_end 当天 NZ 23:59)`；若封顶后已早于 start → 拒绝。
- **在 Meta 后台手工复制的广告组 ME 拦不住**——只能事后发现：每日任务（b）对比「在投广告组 end_time 与其视频 promo_end」，晚于的写入待办。这一点要如实告诉 PM。

**b) 每日自动任务**
- 时间：新西兰每天 00:05（过了 `promo_end` 当天的次日凌晨，不拖到上午），Inngest 定时函数（按 CLAUDE.md §3 默认工作流层；**新增写运行记录的 Inngest 定时函数会被机器判 A，需登记 cron 表**，见记忆 `project-new-inngest-cron-function-is-a-level`）。
- 对每个开了该功能的客户：读在投广告（`ad_entity_snapshots` 广告级行已有 `creative_video_ids[]`）→ 对每个视频查 `promoVerdict`；
  - **整组视频全部过期** → 提交 `ads.pause_unit`（广告组）走内核，留回执，AI 信封的 72h 冷却对「首次因过期暂停」无影响；
  - **只有部分视频过期** → 第一版**不自动停**，写待办（what：哪组里哪条视频过期了/影响；how：把该广告在广告管理里暂停或换素材；href：直达），因为没有广告级暂停动作，整组停会误伤；是否新增 `ads.pause_ad`（A 级能力）作为第二刀单独审；
  - 发现 end_time 晚于 promo_end → 待办。
- 回执：每次运行一条（客户、检查了几个广告组/视频、停了几个、待办几条、dry_run 与否），业务可读事件名如 `ads.creative_promo_expiry.checked`。
- 待办：运行结果为「已自动停 N 条过期视频」（N>0 才出），归广告车道；N=0 不打扰。
- **新开关，默认演练**：`creative_promo_expiry_mode: 'off' | 'detect' | 'enforce'`，默认 `detect`（只写待办不暂停）。**不复用 `autopilot_dry_run`**（那个只管 D3，我之前查过，复用会让两件无关的事互相牵连）。翻到 `enforce` 需 PM 本人，独立于 D3。

- 已 approved 但没有推广期的两条：给宽限——到回填完成前**不暂停**（避免误停正在跑的 CTS 官方户广告），但：不得被新广告组引用、不得启用新的、检测任务持续写待办「还没填推广期」；回填完成或 PM 设定的截止日到了，再按 `promoVerdict` 正常执行。截止日由 PM 定。
- 提醒与既有 PM 规则不冲突：10-14 定的「CTS 广告社媒禁用『还剩几周/倒计时』」是对**文案**的限制；推广期是内部有效期，不要求在画面上写倒数。早鸟视频画面里的日期是真实日期，不属于倒计时文案——但要保持一致，由工厂分镜自检把关。

## 4. 风险级别 / 最小第一刀 / 两周验证（④）

- **A 级**：碰素材批准闸、内核信封、自动暂停。设计阶段子牙+魏征双审；实施后再审；碰内核加狄仁杰攻击验证。A 级 PR 保持草稿，合并只在 PM 回「合 N」且 head 与签字 SHA 一致后。

**最小第一刀（只检测，不暂停，不改内核）：**
1. 解析器/类型加 `promo_window`，读写往返测试（含「写了却被丢」的反例）。
2. 纯函数 `promoVerdict` + 批准入口 422（未声明/已过期）+ 起草广告门（含 `expires_before_use_end`）。
3. `ad-publisher` 的 `end_time` 封顶与启用前复核。
4. 每日检测任务 `detect` 模式：写回执与待办，**不暂停**。
5. 回填清单（只读 Graph 拉 end_time）。

**第二刀（另审）：** 内核层「曝光增加类动作核推广期」；`enforce` 模式整组全过期自动暂停；是否新增 `ads.pause_ad`。

**两周怎么验证：**
- 单测 + 变异：去掉任一校验对应用例必须变红；「写进去读出来」不丢。
- 当场试跑：对测试数据造一条 `promo_end` 为昨天的视频 + 在投广告组（用夹具，不碰真广告），检测任务必须产出待办与回执；用 CTS 真实数据只读跑一次（不暂停），应只列出「未声明推广期」的 2 条 approved。
- 日历/台账：检测任务第一次自动运行后（次日 NZ 上午）查回执与待办；第 7 天复核有没有误报（把未过期的判成过期）；第 14 天决定是否进第二刀。
- 不验证：自动暂停的实际效果（第一刀没做）。

## 5. 其他客户的影响（⑤）

- 不存在「静默默认」：每条视频批准时必须选 `dated` 或 `evergreen`。NAL 等视频没有日期/价格的，批准时选 `evergreen` 即可，不影响现有流程，只多一次选择。
- 已 approved 的存量条目（NAL 等）：迁移时**逐条显式标成 `evergreen`（由内部员工确认）**，不能用「字段为空=放行」；确认前它们属「未声明」，只受「不得被新广告引用」约束，**不会被暂停**。
- 工厂自动判断：工单对账表含「画面有日期/价格」→ 强制 dated，禁止 evergreen（这条是客户无关的通用规则）。
- 客户差异（哪些行业的视频一般带日期）→ 行业 Playbook；具体日期 → 客户配置/工单；共享代码里没有任何客户名、日期或旅游语义。
- 其他客户暂时不开 `detect`：该开关按客户配置，默认 `off`，CTS 先开 `detect`。
