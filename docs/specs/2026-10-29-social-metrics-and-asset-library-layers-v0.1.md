## 0. 一句话结论

**指标分四级、素材库分三层，沿用「平台 → 行业 → 客户」同一条分层规则。但有两个事实先说在前面：**
1. **现在没有一个社媒指标可以直接当 PM 的"结果目标"**：线索归因代码把自然社媒记成付费广告；私信读取拿不到"是不是广告带来的"。要先修归因（A 级），才谈得上"社媒对线索负责"。
2. **素材库的"行业层"目前只有一个标记**，没有行业归属、没有跨客户读取、没有授权记录；要做真正的行业层是新增的隔离面（A 级）。

## 1. 社媒指标

### 1.1 四级指标，并对应到平台现有的"结果分级"

平台已有一套共用的结果分级（`strategy/outcome-levels.ts`：**曝光/点击 → 联系成功 → 未筛选线索 → 合格线索 → 成交**，每个目标指标键要映射进 `METRIC_KEYS_BY_OUTCOME_LEVEL`）。**本稿的 L1–L3 只是讲给人听的叫法，不进分级代码；落到具体指标键时，一个键只能对一级（`strategy/outcome-levels.ts`：「One catalog key, one level」），且「联系成功」一级故意留空——开了聊天不能证明联系成功**；L0 不是结果，不进分级。

| 级 | 对应现有分级 | 例子 | Facebook 现状（对照主干代码）| 能不能当目标 |
|---|---|---|---|---|
| **L0 内容健康** | —（闸，不是结果）| 发布成功、保真、首评写入 | 可做（IMPACT 保真判定）| 不当目标 |
| **L1 互动** | 曝光 / 点击 | 点赞 / 表情、评论、分享 | 点赞、评论**可读**；分享**部分可读**（Reel 平台不一定返回，现有读数把这种情况记「未核实」）；发后 T+4 / T+72 | **只作测试与调优信号**；单条常只有几个〔候选，未实测〕，噪音大 |
| **L2 行动意向** | 私信会话 → 未筛选线索；首评链接点击 → 曝光 / 点击 | 新开私信会话；首评链接点击 | 私信：能读到**会话数**，**读不到来源**（见 1.2）；点击：按单条拆**未验证** | **现在不能当社媒目标**（见 1.2）|
| **L3 业务结果** | 表单 / 询盘 → 未筛选线索；报名 → 成交 | 表单提交、询盘、报名 | **现有归因把自然社媒记成付费**（见 1.2）| **修好归因前不能当社媒目标** |

**不可读（没有洞察权限）：** 触达、展示、观看、完播。**不能用「涨播放」当目标或验收。**

### 1.2 两个会推翻"社媒对线索负责"的事实（复审核实）

1. **线索归因把自然社媒记成付费。** CRM 的归因函数（`crm/attribution.ts` 的 `attributionFromUtm`）**只看 `utm_source`**：来源是 `facebook / fb / ig / instagram / meta` 的，一律判成付费 Meta，**不看 `utm_medium`**。CTS 首评链接约定的是 `utm_source=facebook&utm_medium=organic_social`，所以**只要真有人从首评链接进站、再填官网表单，这条线索在 CRM 里就会被记成广告：社媒自己的线索数是 0，广告成绩会被多记（现在实际有没有这样的线索，未核实）**。另外，这个函数把 `utm_content` **整串**当素材标识，**并没有按前缀解析**（前稿写的"已按前缀解析"不符）。
2. **私信拿不到"是不是广告带来的"。** 私信是通过读接口同步的，"点广告进来"的标识（referral）**只在 Facebook 主动推送的事件里才有**，读接口拿不到，所以私信触点的来源字段是空的；CRM 的规则是**读不到来源就不能记成自然社媒**（标成自然反而是撒谎）。想用私信做社媒目标，要先接上推送里的 referral，并实测送达率——订阅着不等于消息走推送进来，有前例只有约 2% 经推送。〔该 2% 为既有记忆记录，本稿未复核〕

**因此：**
- 在以上两条修好之前，**社媒不单独背"线索"或"私信"目标**。PM 的线索目标仍然落在**客户整体的获客目标**上（如 CTS 现有「11 月 China Tour 推广」留资目标，出处：目标表 2026-10-29 只读查询），社媒的作用以**可读的过程指标**汇报：发布完成率（分母 = 已授权条目，分子 = 实际发出）、读回覆盖率（分母 = 已发布条目，分子 = T+4 / T+72 读到回执；**现状接近 0——CTS 近 30 天 25 条发布动作、新读数 0（出处：2026-10-29 只读查询）——是已知缺口的体现，日报要写明，不能看起来像出了故障**）、L1 互动趋势、L2「含广告的总私信会话数」（明确标"含广告"）。
- 修好之后再把"社媒自然渠道归因线索数"升为社媒目标。

### 1.3 指标键：复用现有，不另造

现有目标指标目录里**已有两个社媒键**：`dm_conversations`（私信对话数，手工上报）、`social_followers_growth`（社媒粉丝增量，自动取数）。
- **`dm_conversations` 保持现在的意思**：所有来源的私信总量，个人 IP 处方的广告开投检查（`ads/prescription-launch-check.ts`）在读它；**不收窄成自然社媒**——收窄会让广告读错口径、社媒与广告第三次重复计数。它正好对应要报的「含广告的总私信会话数」。**自然社媒私信另开新键**（候选名 `social_organic_conversations`），**等 WH 修好私信来源之后**再入目录。
- **M1 交付含**：把新 / 改的键映射进 `METRIC_KEYS_BY_OUTCOME_LEVEL`；要变自动取数，还要接 `strategy/check-source.ts` 和定时任务 `goal-current-value-refresh`（后者本身是 A 级）。
- 与广告的 `messaging_started`（"广告产生的私信会话"）**口径分开**，不共用。

### 1.4 三层放法

| 层 | 放什么 |
|---|---|
| **平台层** | **「平台 × 指标 × 可读状态」表**（可读 / 部分可读 / 未验证 / 不可读），随平台运营思路手册维护，M0 实测后更新 |
| **行业层** | 结果在这个行业叫什么（**参数化的行业剧本**）。**沿用广告剧本的做法与行业键（`clients.industry`，先归一化再匹配）**，但**不把社媒字段加进广告剧本的类型**（那是广告专用类型名，会让广告剧本跨支柱）；建议抽出共享的"行业键 + 归一化函数"，社媒剧本平级另放。复用前先对齐两处不一致：`AdsPlaybookKey` 里的 `retail` 对应文件是 `ecommerce.ts`；`logistics` 不在行业词表里。词表里电商的结果名词是「订单」。**代码侧剧本与文档侧 `docs/playbooks/social/` 的三层手册要写明对应关系，不出现第三处。**行业举例（旅游「咨询」等）仅作示例，**只有旅游有证据，其它行业是空白** |
| **客户层** | 目标数字与期限、名额、「邀请私信」槽位与读取小时数、追踪后缀约定（目标契约 + 客户设置，不进共享代码）|

## 2. 社媒素材库：不另建，和客户在 ME 的素材库打通

### 2.1 现状（线上库只读，全库口径，2026-10-29；复审核对过加总）

- **`client_assets`**：`ownership`（`client_exclusive` 147 + `industry_shared` 6 = 153）；`source`（`client_verified` 47 · `unknown` 44 · `ai_generated` 25 · `stock` 17 · `client_provided` 11 · `fde_shot` 9 = 153）。另有 `verified_by / verified_at`（标「客户实拍已确认」必须同时有核实人和时间的数据库约束）、`listing_id`（房源）、`project_id`（楼盘）、`recommended_use`、`hook_score / middle_score / cta_score`（AI 分析分）。
- 相关模块：价格背书规则 `assets/provenance.ts` 的 `canBackRealPrice`（只认「客户实拍（已确认）」和「FDE 自己拍的」）、`content/price-claim-gate.ts`、素材库检索 `/api/clients/[id]/asset-library/search`、工厂选图 `rank-assets-by-prompt` / `factory/client-asset-pool.ts`；相关表 `viral_reference_library`、`visual_assets`、`asset_storyboards`、`client_audience_assets`。
- **CTS 实测**：客户实拍且已确认 46 张，最新入库 2026-09-13，新素材 6 周没更新（D0 试跑记录）。

**⚠️ 修正前稿的两处说多了：**
1. **`industry_shared` 只是一个标记，不是"行业层雏形"**：`client_assets.client_id` 必填且客户删了素材跟着删，所以每张"行业共用"图都挂在某一个客户名下；表里**没有行业归属列**；全仓**没有任何代码**按它跨客户取图。全库那 6 张都是图库图，都挂在 CTS 名下。
2. **客户素材升行业层——PM 2026-08-02 已拍板"客户自己实拍的素材坚决不可共用"**（见素材归属迁移的头注）。本稿**默认继续遵守**，不再把它当新问题问 PM；若要推翻，必须 PM 明确提出并写清风险。

### 2.2 三层怎么放（修正后）

| 层 | 放什么 | 怎么存 | 红线 |
|---|---|---|---|
| **平台层** | **规格与模板，不是照片**（画幅、安全区、字数、封面 / 字幕模板、水印位置）| 平台规格表与视频工厂模板；不进 `client_assets` | 与客户 / 行业无关 |
| **行业层** | **外购或有授权的行业共用图**、行业爆款配方（`viral_reference_library`）、行业角色枚举与事实模板 | 目前只有 `industry_shared` 标记。**要做成真正的行业层，必须：①有行业归属（新列，或按所属客户的 `clients.industry` 推）；②图不挂在某个客户名下（避免被客户删除连带删掉）；③有授权记录（见下）；④新增跨客户读取路径** | **只做氛围，绝不撑价格 / 产品承诺**；**别的客户使用行业图时，来源一律按「图库」处理，不继承原记录的来源值**（防止把别人的"客户实拍（已确认）"带进新客户去撑价格），并加测试固定；带署名要求的授权图不走"抓图—AI 洗图"管线 |
| **客户层** | 客户自己的素材（`client_exclusive`）、VI（master brief）、事实库 | `client_assets` + `master_briefs` + 事实库 | 价格 / 产品承诺只认来源记录（`canBackRealPrice`）；**客户实拍不得升到行业层（PM 8-02）**；地产要按**房源一级**核对价格（`listing_id` 绑定后不可改）|

**授权记录缺口**：行业图每张都需要来源与授权记录，但素材表里没有授权、署名、许可证等字段，只有 `source = stock`。建议加一列「授权范围」（只能本客户用 / 同行业可用 / 署名要求）——**改表，A 级**。

**两条要补的闸（复审提出）：**
- **8-02 拍板目前只靠自觉**：数据库只分别限制「来源」「归属」两列，不限制组合，客户实拍仍可被标成「行业共用」。IND 切片加一条数据库约束：归属为「行业共用」时，来源只能是图库或 AI 生成，并加测试固定。
- **价格闸只拦报了价格的文案**：行业图配「这是我们的酒店」这类不带价格的产品说法，价格闸拦不住。「行业图绝不撑产品承诺」靠谁拦：苏东坡 + 马良审核（发前清单加一项），或在词表闸里加一条〔候选，IND 实施前定〕。

### 2.3 取用顺序（扩展现有检索，不另写选图逻辑）

先**客户层**（按内容类型核来源是否够格）→ 客户层不够再取**行业层**（只限氛围，且来源一律按图库）→ 平台层提供**模板**。实现上**扩展 `asset-library/search` 与 `rank-assets-by-prompt`**。**不能因为客户层没图，就拿行业图冒充客户产品**；缺口记「缺口」，不编。素材上的 AI 分析分（开头分 / 中段分 / 结尾号召分）**不用作选图依据**，除非另行决定。

### 2.4 "打通"要补的两个缺口

1. **素材 ↔ 内容连接。** 现状已有一部分：`asset_storyboards` 记了开头 / 中段 / 结尾素材编号和 Reel 草稿；配图生成不存素材编号而是事后按图片链接回查；Story 条目存了图片链接和内容哈希 `media_sha256`；工厂取图池按链接取图。**口径：在「挑图那一刻」记下原素材的编号或哈希**（不要拿最终成品的哈希反推：工厂和配图流程会裁图、叠字，Story 存的 `media_sha256` 是成品哈希，和原图对不上，否则所有素材会永远是「使用情况不明」、SO4 永不触发）。 落点：写进现有 jsonb 字段才可能是 B；**在表上加列就是改表结构，A 级**。
   - **「使用情况不明」不等于「未使用」**：员工手动发帖用过的图不会被系统记录；机会信号 SO4「久未使用」对没有使用记录的素材要标「使用情况不明」，不当成"未用"去推荐（否则又是"读不到当没有"）。
2. **素材表现回流。** 验证模块的判定落到素材维度，**只作客户层学习候选**，不自动改素材分、不自动升层。

### 2.5 谁能改什么（沿用，不新增权限）

价格资格仍由现有来源规则决定，agent 与任何系统模块**不得**把来源写成「客户实拍（已确认）」或「FDE 自己拍的」。行业层图的入库与授权记录由人 / FDE 做；agent 只读。

- "单条常只有几个互动"来自快速部署稿，**没有实测出处，标〔候选〕**。
