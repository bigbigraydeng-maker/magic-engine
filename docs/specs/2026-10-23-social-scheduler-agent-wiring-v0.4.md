## 0. 给 PM 的一页话

**统筹排期 Agent 的设计已经有了（发布日历），缺的是接线。** 我查了代码：没有候选表，没有排期逻辑；「本周总览」只读了 Story 周包和 Reel，图文帖还没接进去（`src/lib/social/week-overview/build.ts` 文件头注释写明）。

**现在每日计划是直通的。** 提交每日计划时系统只查格式、活动链接、图片归属、7 张图不重复（`campaign-daily-plan/route.ts`、`daily-plan.ts:423`），不会和 Story、Reel 放在一起比较。

**必须先说清的一件事：现有两条发布路都不看日历。** 自动发布和手动发布只认「授权 + 版本号 + 每天条数上限」（`daily-plan-auto-publish.ts`、`campaign-daily-plan/publish/route.ts`）。所以日历上写着「没能进日历」的帖子，只要授权开着，**照样会发出去**。日历在 B 步接上发布闸之前，**只是参考，拦不住任何发布**；页面上必须这样写明，不能让人误以为有一道闸。

**建议的第一步（A）只做「看得见」：不建表，页面读取时现算。**
1. 「本周总览」补上图文帖一行（读每日计划里已存的内容）；
2. 现算「这一天三条线加起来用了几个名额、有没有超、有没有重复的图」；
3. 补「没能进日历」一栏，写明被哪条规则挡；
4. 全程只读，不写任何新记录。

做完你打开页面就能看到「今天三条线加起来发几条、谁超了、为什么」。

## 2. Agent 管什么（对应 PM 10-13 四个问题）

| PM 的问题 | 谁负责 | 现状 |
|---|---|---|

排期 Agent 边界：只写候选、排时段、写草稿，**不发布、不授权**；对外发布仍是 PM 本人在自己会话里点授权（v0.3 §4）。

## 3. 分步（与 v0.3 的差别已标出）

| 步 | 做什么 | 风险级 | 验收 |
|---|---|---|---|
| **A** | **只读现算**：总览补图文帖行 + 名额用量 + 「没能进日历」栏；页面写明「仅供参考，拦不住发布」 | B（不建表、不改发布接口） | 提交一份每日计划后，总览能看到 7 条图文、每天三线合计用量、每条是否被规则挡及原因；库里无任何新记录（发布记录、演练记录、候选均无新增） |
| **B** | 候选表 + 来源自动报名 + 排时段 + 写草稿周包；**同时让两条发布路先过日历这道闸，不过则拒发** | **A** | 一周内容从产出到授权全程无人搬文件；被日历挡下的帖子真的发不出去 |
| **C** | 超额才接模型挑选 | B | 出现真实「挑了 A 没挑 B」且写出理由 |

**与 v0.3 的差别**：v0.3 第①步是只读页面、第②步才建候选表。本稿 A 步沿用这个顺序（子牙指出：A 步只演练，不必建表）。**首批自动报名的来源按 v0.3 §2.1 是图文/Story 周包与工厂 Reel；每日计划保持关着、将来才作为候选报名，本稿不改这条。** 本稿 A 步读取每日计划只是为了在页面上看见图文帖，不是把它当报名来源。

**冻结令说明**：A 步在已有「本周总览」页内补一行一栏，不新增页面、模板、按钮、报表；它闭合 IMPACT 的 **Check** 一环（让 PM 能核对「这周实际排了什么」）。

## 4. 进入 B 步前必须定的事（A 步不阻塞，但不许带着没定的东西进 B）

1. **发布闸**：两条发布路（自动、手动）如何先过日历判定、不过则拒发；失败时给 PM 的可见位置。
2. **08:00 写死 vs 每天 2 条**：谁迁就谁。A 步不需要，B 步前必须定；候选的时段字段**先留空，不许预填 08:00**。
3. **候选与每日计划的作废关系**：候选挂在「计划编号 + 版本号」上，版本号沿用自动发布已用的 `command_meta.received_at`（`daily-plan-auto-publish-deps.ts:75`）；计划被锁（已发布/已排队）时候选不作废；计划写成功但候选写失败时要有对账办法与可见记录（不许死在日志里）。
4. **图片判重口径**：用素材编号或文件哈希（`media_sha256`），不用 `story-lite` 授权指纹（那是整包内容校验，不是图片去重）。
5. **候选字段通用化**：v0.3 的「讲哪个团」是旅游说法，共享表字段改叫「推广对象」，旅游版里填团编号。
6. **名额配置列**：`publishing_calendar_config` 的建列迁移由谁出，需先核实。
7. **Inngest**：A 步同步只读、无对外动作，不接；B 步起「排期 → 草稿周包 → 授权 → 发布回执」必须走事件，每段有回执。
8. **新表**按 service-role 模板写 RLS（`FOR ALL TO service_role USING (true)`），迁移由 PM 说「go apply」才应用。
9. **日期口径**：一律换算成新西兰日期再按天归；Story 是带时区的时刻，需显式换算，否则 08:00 前后的条目会算到错的一天。
