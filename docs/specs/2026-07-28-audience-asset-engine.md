## 0. 一句话(v0.3)

**冷广告灌池 → 暖池便宜转化 → 智能化判断每个人走到哪一级并自动递进。**

## 1. 广告柱三块分工(边界铁律)

| | **Ad Strategy Engine**<br>(账户大脑) | **Creative Lifecycle Engine**<br>(作品层) | **Audience Asset Engine**<br>(本蓝图 · 资产层) |
|---|---|---|---|
| **判定单元** | campaign / 漏斗层 / 账户 | 单条 creative | **受众池 / 阶梯级别 / 名单** |
| **核心问题** | 账户健不健康?预算怎么流? | 这条创意该活该死? | **这笔钱沉淀下什么?人走到哪一级?归谁?** |
| **时间尺度** | 每日 | 每 6h | **每周 + 每季** |

**边界铁律**:资产层**永不**裁创意、**永不**动预算 —— 只输出**信号**(谁升级了 / 哪个池在衰减 / 哪条内容推进最有效),经契约交 Ad Strategy Engine 决定预算。

**共用地基**:`getMetaTokenForClient()` · `google-data-pullback-daily` · 6 支柱 'ads' · **`contacts` 三表**(L3)。

## 2. 为什么是拳头产品

**市场空位**(Roman Discovery 实证):4 家高端竞对 9 维度全撞同一堵墙 —— 无付费 Meta、无私域池、无中文自媒体。行业普遍**把广告当消耗品**。

**产品杠杆**:同一笔广告费,竞对花完归零;ME 客户花完**留下一个还在滚的暖窗 + 一份永久名单 + 一套知道每个人走到哪一级的系统**。

**中介最痛的不是广告贵,是抢不到 listing。** 但对"怎么帮他抢"的说法必须严格 —— **卖动作,不卖人头**(§8.3)。

### 3.3 ⭐ A 线机制验证:**通过**(2026-07-29 · ME 自有真实数据)

> **§11 kill criteria 的判据。零新增预算 —— 直接从 CTS 现有投放读出。**

**对照条件**:同账户 `2775766642787274` · 同期 **2026-07-01 → 07-29** · 同指标 **Leads(表单)** · 均 ACTIVE · 样本量足

| | **暖池组**<br>`Retargeting - VideoViewers + FormOpeners` | **冷启动组**<br>`Reborn-Winner-Stand-in-Front` |
|---|---|---|
| 定向 | **3 个自定义受众**(视频 50%·365d / ThruPlay 15s·365d / 表单打开未提交·90d)<br>**排除**「已提交表单·90d」 | 无自定义受众 · 广投 |
| 受众扩展 | **`advantage_audience: 0`(关)** | `advantage_audience: 1`(开) |
| 花费 | NZ$665.30 | NZ$1,623.20 |
| Leads | 100 | 146 |
| **单 lead 成本** | **NZ$6.65** | **NZ$11.12** |
| CPM | NZ$21.94(**更贵**) | NZ$15.25 |
| 触达 / 频次 | 12,089 / 2.51 | 50,968 / 2.09 |

**结论:暖池 CPL 比冷启动低 40%(冷启动贵 1.67 倍)。**

**信号形态支持因果**:暖池 **CPM 高 44% 却 CPL 低 40%** → 省钱来自**转化率**,不是买到便宜流量。这是 retargeting 的典型签名。

**⚠️ 三条诚实**:
1. **不是受控实验** —— 两组创意/目标不同,存在混淆。但同客户、同期、同指标、n=100/146,**方向性结论站得住**。
2. **有反例**:同一个视频 50% 暖池投 **Messenger 对话**(`CTS - WA CTWA - Video 50% - Warm`)单次成本 **NZ$38.53**,n=5,已暂停。→ **"暖池更便宜"不是万能,取决于转化动作**;表单 lead 明确,消息对话未验证出优势。**这条直接关系 30 Kiteroa(走 Messenger)。**
3. **暖池不可无限扩量** —— 触达仅 1.2 万、频次已 2.51。**$1,623 砸进这个池子频次会爆。** 所以正确读法**不是"全投暖池"**,而是 §4 的三段循环。

## 4. ⭐ 三段模型:冷广告 → 暖池 → 智能化营销(v0.3 新增)

> PM 2026-07-29 提出的框架。**不是设想 —— CTS 生产环境已跑着一个四级阶梯。**

### 4.1 三段各自的角色(互相咬死,缺一不可)

| 段 | 角色 | 经济特征 | 验证状态 |
|---|---|---|---|
| **① 冷广告** | **灌池** —— 唯一的新人来源 | 贵($11.12)但**可无限扩量** | ✅ 实测 |
| **② 暖池** | **便宜转化** | 便宜($6.65)但**池小 + 会衰减 + 频次天花板** | ✅ 实测 |
| **③ 智能化营销** | **判断每个人走到哪一级,并自动递进** | 决定前两段的效率上限 | 🟡 部分在跑 |

> **为什么三者缺一不可**:只有冷 = 永远付全价;只有暖 = 池子一年归零且扩不了量;没有智能 = 所有人收到同一条广告,不管他是第一次看到还是已经打开过表单。

### 4.2 意向阶梯(CTS 生产版四级 · 已验证)

| 级 | 状态 | 池子 | CTS 实况 |
|---|---|---|---|
| **0 冷** | 不认识 | 无(广投) | ✅ CPL $11.12 |
| **1 看过** | 看了内容 | ThruPlay 15s · 365d | ✅ 在用 |
| **2 深看** | 看了 50%+ | 视频 50% · 365d | ✅ 在用 |
| **3 有意向** | **打开表单没提交** | leadform dropoff · 90d | ✅ 在用(最热的匿名档) |
| **4 已转化** | 提交了 | leadform submitted · 90d | ✅ **用作排除** |
| **5 具名** | 进 CRM,可 1:1 触达 | **L3 `contacts`** | 🔵 表已有,管道未建 |

> **级 0–4 不是我设计的,是 CTS 已经在跑的。** 产品要做的是**标准化 + 自动化 + 复制**,不是发明。

### 4.3 智能化的三个动作

| 动作 | 说明 | 状态 |
|---|---|---|
| **① 自动排除** | 已转化的人不再花钱投 | ✅ **CTS 已做**(排除 leadform submitted) |
| **② 自动递进** | 人升级了,投给他的信息也升级(而不是一直投同一条) | 🟡 CTS 手工分组在做,**未自动化** |
| **③ 内容归因** | 哪条内容最能把人从级 1 推到级 2/3 → 反哺内容排期 | 🔴 **度量仪器不存在**(§9) |

**边界**:资产层只**判定 + 输出信号**,预算动作交 Ad Strategy Engine(§1 铁律)。

### 4.4 与「内容即分层」的关系 + 关键限定

**内容即分层**:Meta 不让按 suburb 过滤池子 → 不过滤,**用内容当漏斗**。「看过 Remuera 内容的人」本身就是 Remuera 池。→ **内容工厂和受众库是同一台机器。**

> ⚠️ **限定条件(双重印证)**:**只在关掉受众扩展时成立。**
> - 推理侧:30 Kiteroa 用 **Advantage+ + 15km 半径**(跨多个 suburb)→ 池子装的是「Meta 认为便宜的人」
> - 实操侧:CTS 那条**跑赢的暖池组 `advantage_audience: 0`** —— 独立印证同一条

**产品硬规则**:
1. 用于建 L1 的内容,**要么纯 organic,要么投放时关扩展 + 收紧地理**
2. 台账**区分 organic 灌入 vs paid 灌入**
3. **地产内容的天然重度观众是业主、邻居、同行中介** → L1 池天生含大量非买家(§8.3 话术的根据)

L3 只需新增:suburb / 预算 / 语言标签 + 上传批次记录。
**硬闸**:`do_not_contact = true` **一律排除出任何上传批次**。

### 5.2 ⭐ L1 参考实现(CTS 生产版 · 直接抄)

**v0.1/v0.2 把 L1 当作"要发明的东西"是错的。** CTS 那三个受众的真实规则结构:

```
视频池(逐条视频 object_id 列表,context = Page id):
  event_name: video_view_50_percent  → 级 2「深看」
  event_name: video_view_15s         → 级 1「看过」
  retention: 365d

意向池(lead form 源):
  event: lead_generation_dropoff     → 级 3「打开没提交」· 90d
  event: lead_generation_submitted   → 级 4「已转化」· 90d · 用作排除
```

**这就是 L1 + 意向阶梯的模板** —— 换 Page id 和视频 id 即可复制到任意客户。

## 7. 归属与合规(PM 已拍板)⭐⭐

### 7.1 🔴 归属 = 中介(红线)

> **PM 2026-07-28**:「归属中介,这是红线。我们卖的是服务的方法论 —— 我们有能力帮中介/渠道持续投流出更便宜的用户池子。」

**v0.1 那句「换代理商池子带不走」已删除** —— 与红线矛盾,且**对 L0/L1 事实上是假的**:

> L0/L1 数据源是**中介自己的主页**,ME 账户里的池子**只是一条规则**。中介随时能在自己账户里重建。

**对客户话术**:
> 「你的主页互动记录本来就是你的。我们做的是把它整理成可用的分区名单 + 判断每个人走到哪一级。哪天你不做了,规则清单给你,你自己重建,数据一条不少。」

**合同写明退出交付物**:池子命名清单 + 分层规则 + 阶梯定义 + 台账历史 + L3 名单导出。

**黏性来源**:①停了就不再灌,暖窗衰减 ②ME 内容产能 ③ME 跨客户积累的方法。**不靠扣押。**

**⚠️ L2 特殊风险**:Pixel 装客户域名却归 ME 业务组合 → Privacy Act 下「**谁是收集方**」必须在合同 + 客户官网隐私声明写明。

### 7.2 🔴 无独家 + 客户必问题的答案

> **PM 2026-07-28**:「不需要独家。我们平行服务多个 agent,同一个买家可能是不同 agent 的潜在客户,这点我们不要去减少自己的 agent 客户。」

**必须写死的区分**(否则被误读成违反红线):

| | 合规吗 |
|---|---|
| 同一个人同时在 A、B 两个中介池里 —— 因为他**分别**跟两家互动过 | ✅ **完全合规** · 两池**各自独立采集**,无数据流动 |
| 把 A 的池**给** B | ❌ **红线** |

> **红线是「绝不搬」,不是「不重叠」。** 买家本来就会接触多个中介。

**中介必问「你会不会卖给我对门?」标准答**:
> 「会,我们平行服务多个中介。但**我们从不把任何人的名单给别人** —— 你的池子只从你自己的主页和内容长出来。你买的不是"别人不能用这套方法",是"**我们持续帮你把池子灌得更快更准**"。正因为服务多家,我们才知道哪种内容推进最有效 —— 这个经验免费给你用。」

### 7.3 合规链条(NZ Privacy Act 2020)

| 环节 | 要求 |
|---|---|
| **IPP 3 收集时告知** | 客户官网 / 表单 / Messenger 首条 |
| **明确同意** | 用于广告定向 |
| **🔴 IPP 12 跨境披露** | v0.1 完全漏掉 —— 传名单给 Meta 是**向境外主体披露个人信息**。**hash 不会让它不再是个人信息** |
| **IPP 9 不超期保留** | 保留期 + 删除 |
| **IPP 6/7 查阅与更正** | 池子建在 ME 账户 → **ME 自己就是一个 agency** |
| 客户离场 | 名单删除条款 |

**三条红线(升级为对外服务承诺 · 印在合同第一页)**:
1. **绝不跨 agent 搬人**
2. **L3 必须有同意**(含 IPP 12)
3. **绝不编造数字** —— 占位值(`<1000`)**不得用于任何对外话术**

### 7.4 开发商付钱建的池归中介 —— 对外口径

30 Kiteroa 是开发商付费,但池子在给中介攒私域。**建议写进开发商合同**:项目期内受众资产用于本项目;项目结束后作为**渠道方(中介)的持续资产**;开发商**可在下个项目复用该渠道**。

| ② 池 size 快照 | **自动** — 写 `flywheel_metrics` 的 `ads.audience.*`。**⚠️ 新 cron 必须 link `me-shared-cron-secret`**(不 link 每天静默 401,`daily-cron-digest` 曾哑 51 天) |
| ③ 台账「**净增 = 新进 − 到期掉出**」 | **自动** — ⚠️ 不能只画总量爬升给客户看 |
| ④ **阶梯分布 + 递进信号** | **自动** — 各级人数变化 → 输出信号(不动预算) |
| ⑤ 内容覆盖哪些 suburb / 缺哪个区 | 人工判断 |
| ⑥ 月报审阅 | 人工(系统出草稿) |

> ❌ **v0.1「有效性体检(看池子互动率)」已删** —— 池子匿名,**不存在该指标**。判池质量唯一的路是**真投一次比 CTR/CPL**。替代:用 campaign insights 的 reach / video_view 做**代理指标**并明标"代理"。

### 8.3 🔴 vendor 材料:卖动作,不卖人头

> **两位审查者独立撞到同一点**:「我有 N 个 {suburb} 暖买家」**每个字都不可核实**,且是**持牌中介对 vendor 的陈述** —— REAA 2008 / Fair Trading Act 1986 下,无法佐证的量化 claim 是**误导性陈述的典型形态**。炸的是中介的牌照。

**为什么不可核实**:成员名单读不到(业主/邻居/同行占比极高)· 无种族语言细分 · **NZ 地区只到 region** · 小池只给占位数。

**生成器硬闸**:
1. **禁用「买家/buyer」描述广告池** → 「**看过我 {suburb} 内容的本地受众**」
2. 低于显示下限的 suburb → **系统直接不生成**
3. 每个数字**强制带口径脚注**

**一页纸只放三样能证实的**:该区 90 天**触达人次** · **互动趋势** · **上市第一天推送计划**(动作,不是承诺)。

> **房主要的不是"你有多少人",是"你上市第一天有动作,别人只会挂 TradeMe 等"。**

**⚠️ 待确认**:Roman 现有 vendor deck 已写「500+ Chinese buyer database」,口径需 PM 与 Roman 确认 —— **风险可能已在他手上**。
**⚠️ 法律折扣**:Overseas Investment Act 2018 下非居民买 NZ 住宅普遍受限 → **「华人受众规模」≠「有效买家」**,定向以 NZ 境内居民为主。
