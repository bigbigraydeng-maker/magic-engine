# Story 自动发布「最小版」设计（2026-10-12，PM 拍板）

**为什么有这份**：PM 问「有没有过度开发」后，把此前 8 张表的方案砍成最小版。完整的老设计（v0.4–v0.6）已作废、没有合进主干：它在已关闭的 PR #2490（分支 `feat/story-auto-publish-design`）里留作历史，大部分零件**搁置不用**（见
`docs/ledger/2026-10-12-story-lite-shelved-parts.md`）。风险级：A（对外发布副作用）。

**PM 的三句决定（2026-10-12）**：①批准做 Story 自动发布，要自动发、不要手动；②Story 不带链接贴纸，链接放当天图文 Post 的首评；③做最小版（本文）。相关 PR：最小版 #2504、预览页 #2508、预览页提速 #2513。

## 只保证三件事
1. **PM 授权后才发**：一个周包，PM 点一次「授权这一周」（管理员才能点）；没授权、已撤销、已过期都不发。
2. **发之前看得到内容**：预览页列出每条的图、文字、时间和问题；确认授权必须带上预览返回的指纹（`content_hash`），预览之后包被改过就拒绝。
3. **发错能停**：一键「停」= 撤销整包，没发的都不会发；已发出去的 Story 系统不会撤下（平台没有撤回接口），回包会列出已发出的，手动在 Facebook 删。

## 做了什么（刻意只有这些）
- **2 张表**：`story_packs`（周包 + 授权/撤销都在这一行）、`story_items`（每条 Story + 发布状态 + 回执）。建表 SQL 只写不执行：`docs/migrations-sql/2026-10-12-story-lite-NOT-APPLIED.sql`。
- **接口**（仅全局管理员）：`GET /api/clients/[id]/story-lite/[packId]/preview`，`POST .../authorize`、`POST .../revoke`。
- **1 个每 10 分钟的发布函数**（Inngest，`cloud-story-lite-publish`，不重试、不并行）：到点 + 已授权 + 未撤销 + 内容指纹对得上 + 文件哈希对得上，才发。**先抢占再发**（一条原子更新，抢不到就不发）。
- **默认只演练**：`STORY_AUTO_PUBLISH_LIVE` 必须严格等于 `true`，且客户在 `STORY_AUTO_PUBLISH_CLIENTS` 名单里，才会真发；否则只做全部检查并记下结果，不碰 Facebook。
- **结果不明不重发**：发布结果拿不准（超时等）→ `UNKNOWN_OUTCOME`，永不自动重试，转今日待办（PM 去主页看一眼）；平台明确拒绝 → `FAILED`；超过时间窗 20 分钟 → `MISSED`（不补发）。
- **今日待办**（照搬每日图文那套的拉模式）：没发出去 / 不知道发没发出去 / 授权了却没动静。
- **只做 Facebook**；Instagram 等 CTS 账号登记后再接（表里的渠道列已留位）。

## 刻意没做（砍掉的不再加）
逐条打开记录、整包哈希快照与不可改触发器、熔断标记、值班表、价格实测（Story 图上不放价格；文案里出现价格会在预览里被标出来，并**挡住授权**）、素材使用硬拦（Facebook 拒绝只是这条失败）、发布租约、状态机触发器、Instagram 两段式。

## 失败怎么落地
| 情形 | 结果 |
|---|---|
| 文件被换 / 文字被改 / 页面账号对不上 / 客户非活跃 | `BLOCKED`，不发，进待办 |
| 文件暂时下不下来 | 退回 `PENDING`，下一轮再试（只在时间窗内） |
| Facebook 限流 | 退回 `PENDING`，时间窗内再试 |
| Facebook 明确拒绝 | `FAILED`，进待办 |
| 结果不明 / 抢占后进程挂了（15 分钟） | `UNKNOWN_OUTCOME`，永不重发，进待办（待办只提醒到 Story 发出后 36 小时：24 小时后 Story 自己消失，再往后没有意义） |
| 发出去之后写库失败 | 标 `UNKNOWN_OUTCOME`（原因 `SETTLE_FAILED`），把 Facebook 返回的编号留在日志和事件里，本轮继续处理别的条目 |
| 抢占后、发送前被撤销 | 发送前**紧贴着**再查一次包是否还有效；失效就退回 `PENDING`，不发 |

## 谁能做什么
授权、撤销、预览：仅全局管理员（受限管理员账号一律 403）。写入类接口只收 `application/json`。
