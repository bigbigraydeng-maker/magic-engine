## 0. 一句话结论

查下来，广告 Agent 的毛病不是「规则坏了」，而是**它跟真正在调广告的人是脱节的**：

- **预算**：规则每天都在比，结论多半是「没有错配」，但一个字都不写下来，看着像死了；同时人当天就凭判断在 Ads Manager 里挪了预算（10-30 组 C $50→$28、组 A $50→$72，11-02 组 A 再到 $100）。系统的门槛比人保守：两组单次成本差 1.84 倍，规则要差到约 2.2 倍才吱声。
- **结果**：Meta 的留资数能按广告组拿到，但质量没人看；近 30 天能对上广告的 154 个客人里，只有 15 个（约 10%）走到了「已报价」或之后；26 个有效报名只有 5 个对得上广告。
- **素材**：同一个组里 Meta 分钱很不均匀，一条素材 78 个留资，另一条 7 个，现在没有地方能并排看。

所以这一版不追求「系统自己拿主意」，先做三件人马上用得上、也能验证的事：

1. **每天一张广告成绩单**：每个组花了多少、出了几个**它自己那种**结果、单次成本、来的客人里有几个成了**合格客人**（CRM 走到「已报价」及以后）、样本够不够；预算规则的判断原样写上去，三态（错配 / 没错配 / 还差几个结果）。
2. **人在 ME 里点一下就能调预算**：复用已有、从没用过的按组加减预算动作，人批、内核执行、读回核对。这样人的预算动作第一次进系统，后面才有东西可以回头看。
3. **素材成绩单**：同组素材并排，结果太少的不比。

「下一次决定读上一次结果」放到最后：要先有真进系统的动作和站得住的回看结论。

## 2. 讲稿里对广告 Agent 最要紧的原则

只列适合「2 个付费客户、两周约 $1,500 广告费」这种体量的。需要海量数据的（在线强化学习、素材价值排序模型、读模型内部打分）都不抄。

| # | 原则 | 出处 | 落到 ME |
|---|---|---|---|
| 1 | 指标先登记定义，没登记就不判；大模型不碰数字 | 张前园、刘杨 | 结果种类按广告组认（`rules/core-metric.ts`，D3 已改，PR 3535） |
| 2 | 外环业务指标定义什么算错 | 亓隆基（货拉拉：对话越做越好，成交在掉） | 成绩单带合格客人列：留资多不等于客人好；还没走完流程的新客人标「观察中」，不算差（讲稿：没成熟的数据单独标） |
| 3 | 判定三态，不确定要说缺什么 | 陈忻、刘凯宁 | 预算判断写成「错配 / 没错配 / 还差 N 个结果」 |
| 4 | 每次尝试是限时小实验，先写停止线 | casa（一人公司） | 每次在 ME 里调预算，都填好「观察几天、什么算成、什么情况改回来」 |
| 5 | 建议 → 影响预览 → 负责人确认 → 观察窗 → 回报 | 周昕毅 | 调预算卡片：改前看到预计影响，改后 7 天回报 |
| 6 | 执行不等于决定经营策略 | 亓隆基 | 加钱、开投永远是人拍板（10-10 规矩）；系统只备证据、执行、核对 |
| 7 | 一次只改一处，并排比 | 张凯寓 | 素材只在同组同受众同表单里比 |
| 8 | 先有评测，再搭框架，最后才自动循环；错例进考卷 | 肖汉松（阿福）、陈忻 | **拿人做过的真实决定当考题**：10-30、11-02 两次调预算 |
| 9 | 读过往结果要由代码强制 | 余锦泽（给了查记忆工具，只有约三分之一真用） | 最后一刀：出建议前代码先查上次结论 |
| 10 | 经验分三档：候选、已验证、人工断言 | 余锦泽、陈忻 | 「某素材打法对 CTS 有效」先当候选 |
| 11 | 只给有人真会用的环节做闭环 | 赵雨森 | 每刀写明谁看、看了做什么；两周没人用就停 |
| 12 | 防假绿灯：接口成功 ≠ 业务成功 | 李桐馨、俞昊晟 | 调预算后读回 Meta 金额，再 7 天看结果，三层分开记 |

讲稿之间的分歧怎么取：
- **要不要先建评测**：任磊达反对、多数人赞成。取中间：只用 ME 自己的真实历史日子和人做过的决定当小考卷，不建通用评测套件。
- **人不回复时怎么办**：肖汉松超时后按默认方向继续；ME 碰钱的动作反过来，超时就不改。

护栏（全程不许变差）：
- **G1 误停在投广告 0 起**，止损提议不许被压住。
- **G2 PM 每周要批的条数不比动工前多**：成绩单不进今日待办，只有「预算错配」这种结论才进，每个客户每天最多 1 条。
- **G3 新增外部接口费用每周不超过 B0 + 5 美元**：本方案不新增外部接口。

## 4. 测试环境

- **考卷（离线、确定性）**：沿用 `diagnostics/__tests__/` 回放测试和第 0 步考卷，每刀先写当前代码答错的题。
- **生产回放（合并门槛）**：拿近 30 天生产数据的真实形状（每个组的真实优化目标、目的地、日花费、结果数，编号只留尾号），喂给改后的纯函数逐天跑，同时跑主干对照。验收看两样：
  1. **跟人的真实决定对得上**：10-29、11-01 的成绩单是否让人一眼看出「组 A 便宜、组 C 贵」，跟人 10-30、11-02 实际做的调整同方向；
  2. **不出假信号**：WhatsApp 组、点击组、视频组不被当成「最差的组」。
- 不拿「出了几条结论」当门槛：「没有错配」本身就是一条正确结论。

## 5. 分刀方案

全部 A 级、Ray 亲手合；每刀不超过约 400 行代码，一刀一张改动单。按 §11 打分定先后。

### 第 1 刀　每日广告成绩单 + 预算判断写出来（只读，约 1 周）

按 §11：频率 高（每天）/ IMPACT 高（测量和处方两环都要它）/ 收入 高（直接管预算）→ **P0**

- **做**：在每日巡察里给每个获客 / 再营销单位算一行：
  - 花费、**它自己那种结果**的个数（复用 PR 3535 的 `mismatchedMetric` 口径）、单次成本 vs 目标；
  - 来的客人里有几个成了**合格客人**，以及单个合格客人花了多少钱。口径（PM 11-03 定）：CRM 里现在或曾经走到「已报价」及以后——CTS 是已报价、已付定金、已付全款、即将出行、已出行归来；后来变成「无下文」「短期内不考虑」的，只要报过价也算。只算 `contacts.attr_*` 对得上这个组的客人，对不上的写「对不上 N 个」。进来不到 14 天的客人可能还没来得及报价，单独标「观察中」，不算进比例；
  - 哪几个阶段算「合格」放在**客户配置**里，不写死在共享代码（地产客户的阶段完全不一样）。CTS 的阶段表是 `client_pipeline_stages`，它的排序号不是流程先后（「无下文」排在「已报价」后面），所以不能按排序号切，要逐个登记；
  - 样本够不够：不够就写「还差 N 个结果」；
  - 预算规则 D5 / O3 当天的判断原样写上，三态：错配 / 没错配（差距 x，门槛 0.15）/ 还差 N 个结果。
  - 广告健康页显示；不进今日待办（只有「错配」结论按现有规则进）。
- **验收**：生产回放 10-26 → 11-02：10-29、11-01 那两天的成绩单能看出组 A 比组 C 便宜 1.8 倍左右、合格客人列有数（并标出多少还在观察中）；WhatsApp / 点击 / 视频组单列，不进预算比较。
- **停止线**：PM 两周里一次都没打开 → 停，不往下做。
- **不做**：改 D5 / O3 门槛；NAL 质量列（私信来源要等 Webhook）；报名回传 Meta；多触点归因。

### 第 2 刀　追踪断了时，「花钱没结果」只提醒不自动暂停（约 3 天）

按 §11：频率 低（30 天 1 次整段断）/ IMPACT 高 / 收入 高 → **P1**，排第二是因为它守 G1

- **做**：广告日数据缺天、或「数据齐不齐」标记显示不齐时，D3 当天的命中改成只提醒（`autoPauseEligible: false`），标题写明「数据不全，系统不会自动停」。顺带修好那个标记：10-13 → 10-20 日数据整段没有，却标成「齐」。
- **为什么不跟「止损不许压」冲突**：止损提醒照样出、照样进待办，只是不让系统在数据坏的时候自己动手。
- **验收**：回放 10-13 → 10-20：标记变成「不齐」，那几天的 D3 都不可自动暂停。
- **不做**：另起一套对账比例。

### 第 3 刀　在 ME 里点一下调预算（约 1 周）

按 §11：频率 中（人每周调 2–3 次）/ IMPACT 高（第一次让人的预算动作进系统）/ 收入 高 → **P1**，要第 1 刀有人在看才做

- **做**：成绩单每行加「加 10% / 加 20% / 减到 X」按钮，复用已上线的 `ads.scale_unit_budget`（一次最多 +20%，信封核日上限）和 `ads.cut_unit_budget`；点了先出预览（改前改后金额、对日上限的影响），再走现有内核审批，执行后读回 Meta 金额。加钱的按钮只给 PM 本人（10-10 规矩）。每次调整必须填「观察几天、什么算成」，默认 7 天。
- **验收**：用测试账户或演练模式走通一次完整链路，贴读回结果；动作行带 `action_run_id`。
- **停止线**：两周里人一次都不在 ME 里调、继续去 Ads Manager → 停下问原因（可能是 Meta 后台本来就顺手），不加功能。
- **不做**：系统自己提「该挪多少」；跨角色挪钱。手搭的测试组（例如素材对照、版位对照）保护功能：先看第 1 刀有没有误导，误导了再加。

### 第 4 刀　改完 7 天回看，带同期对照（约 1 周）

按 §11：频率 中 / IMPACT 高 / 收入 中 → **P1**

- **先回放再开工**：存档分支 `feat/agent-loop-step1-ads` 的 `change-review` 今天就能回放。近 30 天表单组的 3 处预算改动里，11-02 那处要 11-09 才满 7 天；10-30 那处改前只有 4 天数据，而且当天所有组留资一起大涨。**回放要加同期对照**：同期没改的组怎么变，从改了的组里扣掉。
- **做**（回放有结论才做）：第 3 刀在 ME 里做的预算调整满 7 天，自动出「变好 / 变差 / 持平 / 说不清（缺什么）」，带同期对照；结论先只写运行日志（影子 14 天），PM 回「开」才写进 `flywheel_outcomes`。
- **停止线**：回放 0 条站得住的结论 → 不做，等第 3 刀攒够真实动作。
- **不做**：暂停的回看；跨广告账户比（CTS 10-20 换过账户）。

### 第 5 刀　素材成绩单（只读，约 1 周）

按 §11：频率 中（每次换素材都要看）/ IMPACT 中 / 收入 中 → **P2**

- **做**：广告健康页里，每个广告组下面并排列每条素材：花费、结果数、单次成本、上线天数。**结果数少于客户配置的最低数（现在 5 个）的素材标「还不能比」**，不给排名。同组里表单或受众中途换过的，标「前后不全可比」。
- **验收**：组 A 的两条素材（78 vs 7 个留资）能看出差别；组 C 四条里 12 个那条能比，1 个、0 个的标「还不能比」。
- **停止线**：两周没人看 → 停。
- **不做**：疲劳三选一待办（D2 自 10-20 起没命中过，没东西会触发它）；自动生成、上线素材；素材评分模型；开赢家素材自动加量。素材生产仍走视频工厂和苏东坡审（CLAUDE.md §8）。

### 第 6 刀　下一次决定读上一次结论（约 3 天，最后做）

按 §11：频率 中 / IMPACT 高 / 收入 高 → **P1**，要等第 4 刀有结论了才有东西可读

- **做**：成绩单上，这个组 14 天内上一次调预算的回看结论直接显示在那一行；上次加钱后「变差」，加钱按钮旁写明。止损永远不压，只多一行标注（闭环升级 §4 收放分开）。
- **验收**：第 0 步留的考卷第 2–4 题转成通过。
- **不做**：自动生成新规则；大模型参与判断。

## 7. 不做（本轮）
