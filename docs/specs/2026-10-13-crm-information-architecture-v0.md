# CRM 信息架构 v0（页面怎么合、各块归谁）

**状态**：草稿，给统筹和 PM 过目；**这一版不改任何代码**。
**起因**：PM 2026-10-13 反馈「CRM 不同页面很割裂，决策清单、付款总览像临时 page」。
**参与**：本窗口（付款进度/付款总览/团目录销售情况）、60 号（客人页「该做什么」状态合成）。两边已对过方向（2026-10-13）。

## 1. 现在的样子（2026-10-13 main 上实际有的）

| 位置 | 是什么 | 谁做的 |
|---|---|---|
| 页签「全部客人」 | 全部客人表 + 「今天该联系」热/冷名单 + 「付款要催」面板 + 「谁能用付款进度」名单卡 + 客人抽屉 | 多窗口累加 |
| 页签「决策清单（只读）」 | 只读优先级视图 | CI-WP01 |
| 页签「付款总览」 | 按出发日的订单与收款进度 + 全部订单 + 29 位「付过钱没订单」 | 本窗口 |
| 页签「销售进度」（PR 2537，未合） | 按出发日：上限/已订/剩余 | 60 号 |
| 「相关工具」 | 客户消息 / 商务收件箱 / 同行渠道（不在 crm/* 下，点过去就离开这组页签） | B1 |
| 团目录团面板「销售情况」（PR 2535） | 这个团各出发日的订单与收款进度 | 本窗口 |

**割裂的根源**：按「功能」一个个加页签；同一件事（某个团卖得怎样）有 3 个入口（付款总览 / 销售进度 / 团目录销售情况），同一件事（谁没付款）有 2 个入口（付款要催 / 付款总览）；管理名单的卡片混在日常页面里。

## 2. 目标：员工按「今天要办什么」工作，页面只分三种视角

1. **今天**（默认进来看到的）：一个列表，每行一个人 + 一句原因（「定金到期没收」「意向高没回复」「快出发还差尾款」…）。热/冷名单、付款要催都是这个列表里的「原因 + 筛选」，不再是并排的几块。
2. **全部客人**：查人、翻看、搜索（现有表格）。
3. **按团看**：一个入口，里面切换「收款进度」（原付款总览）和「座位/上限」（原销售进度）；团目录团面板里的「销售情况」是这个视角的就近入口，链到这里。
- 「决策清单（只读）」：给不亲自动手的人看，保留，但放到「相关工具」那一排，不占主页签。
- 点任何一个人，永远打开**同一个**客人抽屉（「订单与付款」是抽屉里的一块）。
- 「谁能用付款进度」名单卡：挪出日常页面，放进「按团看」页的设置里（只有管理员/名单内的人看得到）。

## 3. 各块归谁（避免撞车）

| 块 | 归属 | 说明 |
|---|---|---|
| 「今天」列表、原因文字、筛选、客人抽屉整体 | 60 号 | 它已有热/冷名单与状态合成；列表里加「付款类原因」时，数据读本窗口的付款进度读取代码 |
| 付款要催（数据与规则）、订单与付款抽屉块、付款总览、团目录销售情况、名单管理 | 本窗口 | 只改入口与挂载位置，不改数据和规则 |
| 销售进度页（座位/上限） | 60 号 | 并入「按团看」 |
| 页签总入口 `CrmTabs.tsx` | 谁先动谁负责，另一方等合并后再改 | 避免同文件冲突 |

## 4. 必须保留的硬约束

- **名单闸**：「按团看」（收款进度、座位/上限）只对 ME 管理员和名单内账号开放（现在是 info 与 baker 两个邮箱）；探针不通过时页签不显示，不暴露这个功能存在。合并入口时这道闸不能丢。
- 不存也不显示金额（PM 2026-10-13「不要金额」）。
- 抽屉里的「订单与付款」仍只对名单内可见。

## 5. 分步（每步独立、可单独回退，都是 UI 级改动，不碰数据库）

1. 「按团看」合并入口：付款总览 + 销售进度合到一个页签下切换；团目录「销售情况」链到它。（本窗口 + 60 号配合，等 PR 2537 合并后做）
2. 把「谁能用付款进度」名单卡挪进「按团看」的设置。（本窗口）
3. 「今天」列表吃进「付款要催」（作为一类原因 + 筛选）。（60 号主导）
4. 「决策清单」挪到相关工具排。（谁动 CrmTabs 谁做）
