## 0. 给 PM 的一页话

**第一件事：这套能力做的是「从外面学，用自己的数据验，验过的才写进 Agent」。**
每月自动看一批专家视频，把每个做法拆成「能力点」。和 ME 现有规则对一遍：不适用的 pass 掉，值得试的派给负责窗口用真实数据验证，验证成立的写进 Agent 的规则手册。

**第二件事：护城河是「验过」这一步，不是视频本身。**
视频谁都能看。ME 独有的是：每个做法都在我们客户的真实数据上验过，留下了「成立 / 不成立 / 查不了」的记录。时间越久，这本验证过的账越厚，别人抄不走。

**第三件事：广告这条线已经跑通。**
已学 17 张笔记（主干上 9 张、63 个能力点；另 8 张在待合并的 PR 2855），9 件派出去验证，第一批 4 条规则已进广告 Agent 手册。后台「Agent 学习库」页能看到每个点走到哪一步（PR 2865，待上线）。

**第四件事：社媒起号照同一套做，不另起炉灶。**
Codex 照这份文档的第 3 节做社媒版：同一个学习流程、同一个页面（加一个「支柱」筛选），只换素材来源、对账用的社媒规则、验证负责人（社媒统一归 97 号）。

### 1.1 素材怎么读（都实测过）
| 平台 | 办法 | 成本 | 坑 |
|---|---|---|---|
| YouTube | PM 的 Chrome 打开视频 → 简介「Show transcript」→ 读整页文稿 | 0 | 官方接口读不了别人视频的字幕；只用接口核标题/时长/播放 |
| TikTok | Apify `clockworks/tiktok-scraper` 关键词搜 + 下载平台自动字幕（取 ASR 轨，不用机翻轨）；字幕链接要带钥匙下载 | 约 $0.003/条 | 不登录网页一次只出约 12 条；广告教学类播放普遍低，门槛放到 1 万 |
| Facebook | Apify `piotrv1001/facebook-video-transcript-scraper`：按专家主页列 Reel，再对选中的开 AI 转写 | 列表几乎 0；转写约 $0.02/分钟 | 没有关键词搜索；主页名要核实（猜的名字返回 0 条）；转写会听错人名 |
| 抖音等 | Chrome 打开 → 硬字幕区截图逐帧读 | 0 | 每帧等画面真换了再读；没字幕不猜 |
| 已有封装（**复制前先核实能不能用**） | `src/lib/supadata/client.ts`（Supadata：YouTube/TikTok/Instagram/Facebook/X 转写） | 已付费供应商 | 本窗口没核实钥匙是否有效；按「已买的供应商优先」原则，社媒版应先试它 |

Apify 账户有月上限（当前 $90，10 月已用约 $82），与 ME 其他功能共用；额度用完返回 403，任务退回网页读法，不许自己提额。

### 1.2 从踩过的坑里得出的规矩（社媒版必须照搬）
1. **专家说的 ≠ 对我们客户成立。** 默认不改 ME；没验证的一律叫「候选」。
2. **对账不能只靠关键词搜索。** 下「忽略 / 与 ME 冲突」之前必须读规则原文、写出编号和原文一句。独立复核发现：只搜关键词时 48 条判断里有 4 条错、11 条存疑。
3. **不许说满。** 「没找到」只能说「在 X 范围没找到」；不能写「经受住了检验」。
4. **复核更正要回写机器索引**，否则页面显示的是过期结论。
5. **验证分三种**：讲道理就能定的、翻历史数据能查的（都不花钱）、必须真投放才知道的（用客户已批预算，一次只改一样；加钱、客户看得到的改动先问 PM）。
6. **派出去必须开交接卡**，只在卡里写「交给 N 号」等于没派（实测 9 件全卡在这里）。
7. **「学会了」的标准是规则手册那一行写着来源卡文件名**，不是「查完了」。
8. 客户名、客户私有数字不进共享规则；单客户证据只算候选。

## 2. 数据契约（复制时不许改形状，只许加支柱）

### 2.1 技能卡
模板见 `SKILL.md`「技能卡模板」。卡头已有 `支柱：…` 字段。

### 2.2 机器索引（每张卡末尾）
```json
{"points":[{"key":"短英文唯一","text":"一句话能力点","state":"verifying","handoff":"<台账卡 id>","rule":"C-18","note":"≤40 字","merged_into":"<卡id>#<key>"}]}
```
state 词表与必填字段见 `docs/skill-cards/README.md`「机器索引」节：learning / pm_decision / verifying / adopted / not_applicable / tried_failed / cannot_check / already_in_me / merged。

格式见 `docs/ledger/README.md`；id 含 `skill-handoff`；标题「交 N 号：…」；`source: doc:<主技能卡路径>`；`verify_how` 写清查什么、怎么算成、拿不到算 failed。

## 3. 复制到「社媒起号」：给 Codex 的做法

**目标**：社媒 Agent 从专家「起号」内容（新账号冷启动、选题、开头钩子、发布节奏、互动、账号定位、算法变化）里学，验证后写进社媒 Agent 的规则手册。**同一套能力，不是第二套系统。**

### 3.1 开工前必须先过的
1. 读 `CLAUDE.md`、`docs/roadmap/2026-08-19-me2-platformization-principle.md`，跑 `me-platform-tier-gate`（Codex 无 Skill 接口时读 `.claude/skills/me-platform-tier-gate/SKILL.md` 全文）。预期判定：已有 L1「学习/验证」机制扩到社媒支柱，不新增能力线。
2. 读本文件、`SKILL.md`、`docs/skill-cards/README.md`、`src/lib/skill-cards/`（PR 2865 合并后）。
3. 社媒现状必读：`docs/specs/2026-10-13-social-daily-agent-design.md`、`docs/specs/2026-10-09-social-agent-skill-gap-and-oss-survey.md`（已调研过开源技能库，别重做）、`docs/sops/2026-10-15-video-factory-handoff-to-97.md`。
4. 社媒归 **97 号**统筹（PM 10-15）：交接卡默认交 97 号；涉及出片交 106 号。开工前在 97 号窗口登记写入范围。

### 3.2 社媒缺、广告已有的前提（要先补）
| 广告有 | 社媒现状 | 要做 |
|---|---|---|
| 仓库里的规则手册（能力库） | **没有**。社媒经验手册只在 Claude 本机记忆 `playbook-social-general.md`，Codex 读不到、页面也读不到 | 先在仓库建 `docs/sops/<日期>-social-agent-playbook-and-rules-v1.0.md`：从记忆手册与上面两份设计稿整理带编号的规则表（如 SO-01），行格式照广告手册 `| **SO-01** | … |` |
| 规则摘要 | 没有 | 建 `docs/skill-cards/ME-SOCIAL-RULES-DIGEST.md`（同广告摘要格式，方括号标签） |
| 验证用的数据 | 发后 4h/72h 回看、评论、工厂出片记录已在库里（见社媒日常运营设计稿第 1 节） | 验证方案优先用这些只读数据 |

规则手册是 A 级文件（改它要 PM「合 N」），新建 v1.0 也按 A 级走。

### 3.3 要改的代码（平台化，不复制粘贴）
1. `src/lib/skill-cards/load.ts`：把单一 `RULEBOOK_PATH` / `DIGEST_PATH` 改成**按支柱的配置表**（`ads` → 广告手册与摘要，`social` → 社媒手册与摘要）。子牙审查时已提过「以后按支柱配置成列表」。
2. 机器索引或卡头解析出 `pillar`（卡头已有「支柱：」行；建议在机器索引里加 `"pillar":"social"`，缺省视为 `ads` 以兼容现有卡）。
3. `board.ts`：校验 `adopted` / `already_in_me` 时按点所属支柱选对应手册与摘要。
4. 页面：同一个 `/dashboard/learning` 顶部加支柱切换（广告 / 社媒 / 全部），不新建第二个页面。
5. 测试：沿用现有三个测试文件的写法，补「社媒卡对社媒手册校验」「广告卡不会拿社媒手册校验」两类。
6. 不改：state 词表、交接卡格式、「学会了」的判定标准、致命错误规则。

改共享代码属 B 级以上；按 `CLAUDE.md` 第 4 条大任务两审（子牙 + 魏征，设计一次、实施一次）。按 PM 2026-10-15 规定，**不用 Codex 审代码**。

### 3.4 每月任务的社媒版
新建一个本机定时任务（或在现有任务里加社媒一节，二选一，由写入者定），照 `daily-youtube-ads-learning` 的提示词改：
- 搜索主题：新账号起号/冷启动、短视频开头钩子、发布节奏与时段、选题与系列化、评论互动、Reels/Shorts/TikTok 算法变化、旅游/本地服务类账号案例（优先 AU/NZ、中老年受众）。
- 每月约 10 个：YouTube 英文 4、中文 2，TikTok 2，Instagram/Facebook 2。
- 对账读社媒摘要与手册；交接卡默认交 97 号。
- 建好后**当场手动跑一次完整链路**，看到 PR 开出来才算做好（`CLAUDE.md`「当场试跑」）。

### 3.5 社媒版的验证从哪里下手（不花钱的优先）
- 已发帖子的回看数据（4h/72h 点赞、评论、观看）能回答「开头钩子/时段/格式」类问题。
- 评论表能回答「互动方式」类问题。
- 视频工厂的配方库 `viral_reference_library` 已有行业配方：新学到的出片做法先和配方对账。
- 一律只读；发帖、下架、改账号设置不在验证权限内。

### 3.6 验收
- 社媒手册 v1.0 与摘要在主干；至少 5 张社媒技能卡带机器索引；学习库页面切到「社媒」能看到四个数字且无红区；至少 1 张社媒交接卡交给 97 号；社媒每月任务当场跑通一次并开出 PR。
