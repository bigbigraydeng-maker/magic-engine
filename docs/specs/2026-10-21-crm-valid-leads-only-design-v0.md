## 1. PM 要什么（原话）

ME CRM 里「今天要联系谁」判断得不准；这里应只自动提取「有效 Leads」——只保留有效咨询的客人信息，
自动过滤类似 Guardian-reports、Cuong Nguyen Manh 这样的。

## 2. 事实（只读生产库，2026-10-21，用线上真代码重算）

**数字已和 PM 页面对上（统筹 18 要求①）**：用页面同一条取数路径（`crm/contacts/route.ts` 的
`getPriority`：取全量联系人和触点 → 去掉系统账号 → `enrichContacts` 合并身份 → `buildPriorityView`）
重算 CTS：**「今天要联系」= 352**（replied 219 / clicked_link 86 / new_untouched 47），「先放着」= 842。
和 PM 截图的 352 完全一致。（我第一版的 364 少了「合并身份、去系统账号」两步，作废。）

| 项 | 数 | 说明 |
|---|---|---|
| 今天要联系（页面口径） | 352 | |
| 其中**只靠陌生邮件进来**的 | 18 | 名下每条记录都是对方发来的邮件，没人回过、没电话、没表单私信；全部在这 352 里 |
| 这 18 人里不是咨询 | 16 | 作者逐封读过，列在 §4 |
| 这 18 人里是真咨询 | 2 | 「Attn BAKER」两封：旅行社同行在催我们之前的报价 → **绝不能筛** |

**所以预期：352 → 约 336（挪走约 16）。** 这是人工读出的上限；系统实际判中多少要靠干跑回答。

**根因**：系统把「info@ 收到一封邮件」一律当新客人。现有防线都不管「这个人说了什么」：
`mail-sender.ts` 只拦 noreply 地址；`contact-kind.ts` 只按域名分散客/同行/员工；
`automated-touch.ts` 只判我们发出的信是不是机器发的。

**诚实交代：名单大头不是垃圾邮件。** 352 人里 162 人最后一次来往在 31–90 天前、48 人在 90 天前
（第一版口径，量级参考）。「客人来过消息、我们没回」不分多久都算今天要联系。
要不要加「多久以前不算」的年龄线是**另一个业务口径**，本稿不做；统筹 18 定干跑给 PM 看过之后再问。

## 3. 查了哪三处平台能力（Reuse First）

1. **`contact-kind.ts`**：按域名分散客/同行/员工，域名来自 `clients.leads_config`。复用「客户差异走配置」；
   **同行（trade）无条件不进筛选**（魏征 NOTE 3）。
2. **`mail-sender.ts`（`classifySender`）+ `mail-ingest.ts`（`isAutoReply`）**：入库时只看发件地址形状。
   复用 `isAutoReply` 词表（原来只用于我们发出的信，这次也用于对方来信）。
3. **`conversation_briefs`**：AI 的 `intent_level` **不用**（PM 2026-10-10 判过未校准，不许决定谁进名单）。

另查到两处必须对齐的现有机制：
- **`stage-infer.ts`（每小时、大模型读往来记录给 `stage IS NULL` 的人填阶段，操作者 `ai:conversation-read`）**。
  事实：这 18 人里 16 个已被它填了阶段（15 个「新线索」、EJ/Paola「短期内不考虑」、Sarah「无下文」）；
  只有 Gordon Earl、L Earl 两个真咨询阶段还是空。它的写法 `.is('stage', null)`（`stage-infer.ts:269,366`）
  保证不会改已有阶段 → 我们改成「非咨询」后它不会改回去。**实现时必须有测试钉住这一点。**
- **`actors.ts`**：机器身份约定 `ai:` / `system:` 前缀 + `describeStageActor`（`actors.ts:56-78`）。

`travel-agent-customer-extract.ts` 是「邮件内容交给大模型」的先例（gpt-4o-mini，对外封装名 Content Engine；
把邮件当数据不当指令的提示词写法可参考）。

## 5. 设计

### 5.1 谁能进筛选（缩小误伤面；全部满足才进）

1. **客户配置打开**：`clients.leads_config.enquiry_screen.enabled = true`，且该客户阶段表里**有**
   `not_enquiry` 这一阶段。否则整条链路在第一步就退出（**不调模型**，其他客户零影响）。
2. **只看邮件 / WhatsApp**：这个人名下的触点全部是「对方发来的邮件或 WhatsApp 消息」，来源按**白名单**列出
   （实现前先 `select distinct channel, source` 核实真实取值；已知邮件有 `email/microsoft_mail`、`email/outlook`、
   `email/outlook_info_scan` 入站，WhatsApp 有 `whatsapp/whatsapp` 入站）。出现下列任一就不进：我们人工发出的任何触点、
   电话、**Facebook 广告表单 / 网站表单（默认就是有效咨询）**、Facebook 私信、`email_conversation`、Mailchimp 出站
   （Mailchimp 的打开/点击不算他「说话」，也不让他进）。WhatsApp 的内容同样走 5.2 的两层判断，
   「是咨询」的正面证据和 5 类「不是咨询」同样适用（目前 CTS 只有 3 个纯 WhatsApp 来客在今天要联系里，量很小）。
3. **不是同行**：`contactKindOf(...) !== 'trade'`，且不是员工。
4. **阶段只被机器动过**：当前阶段是空 / 新线索 / 短期内不考虑 / 无下文，**并且这个人的全部
   `contact_stage_events` 的操作者都是机器**（`isAutomatedActor`，`ai:` / `system:`）。有任何人工改过阶段 → 不碰。
   （第一版写「阶段为空或新线索」是错的：16/18 早被 `stage-infer` 填了阶段，会导致命中 0 个。）
5. **等够时间**：这封邮件到现在已过 **2 天**（可配置），期间没有后续。刚到几分钟的第一封信不下判。
6. **确定性硬否决（不管模型怎么说都不筛）**：预览/主题里出现价格、报价、行程、日期、人数、订位类词
   （quote / price / itinerary / book / pax / 日期格式 / 货币符号…）；提到我们员工的名字；引用我们发出的信
   （`Re:` 我们的主题）。

不满足 → 一律不筛、行为和今天完全一样。

### 5.2 两层判断，宁可漏筛

- **第一层（确定性规则，不花钱）**：自动回复主题（复用 `isAutoReply`）；通用群发服务中转域名。命中 → 判不是咨询并写原因。
- **第二层（大模型，仅对第一层没判掉、且过了 5.1 的人）**：Content Engine（gpt-4o-mini，同
  `travel-agent-customer-extract.ts`）。输入：主题 + 已存的前 255 字预览（`raw`，库里本来就有）。
  输出：类别（5 类 / enquiry / unsure）、confidence、一句原因、依据原文的短引文。
  **只有「类别 ∈ 5 类」且「confidence ≥ 阈值（可配，默认 0.9）」且「引文真的在原文里」才判不是咨询；
  其余（unsure、解析失败、调用失败、超时）一律不筛。** 邮件内容当数据不当指令；
  **引文校验只防幻觉、不防注入，所以 5.1 第 6 条的确定性硬否决才是兜底。**
- **外发边界**：每封只把「主题 + 255 字预览」发给大模型供应商——和现有 `travel-agent-customer-extract.ts`
  对同行邮件做的一样，不新增数据类型。
- **费用**（估算，**未对账单核实**）：每封约 400 词元进 + 80 出，约 $0.0001/封；一次干跑（18 人 + 校准集约 150 封）不到 $0.02。

### 5.3 判完怎么办：不让人凭空消失；仍只有「今天要联系」「先放着」两张名单

- 判为不是咨询 → 把阶段改成新阶段「**非咨询**」（`not_enquiry`），用现有 `advanceContactStage` 写，
  事件里 `changed_by = ai:enquiry-screen`（新增常量并在 `describeStageActor` 里加一行「系统判成不是咨询」），
  `note` 写原因（如「不是咨询：疑似供应商推销（地接社来信）」）。
- **这个阶段的「营销动作」只能选现有五种之一，选「停止营销（suppress）」**：它的真实含义是
  「不再自动发内容 + 移出今天名单、仍能在『先放着』里找到」，正是我们要的。
  系统里**没有「无」这个动作**（`pipeline.ts:11`），我在稿里不假装有。
- 「先放着」里那一行读阶段事件的最新 `note` 当原因（读侧只批量取阶段 = 非咨询的人，几十行，需新增一次查询）。
- **一键拉回**：销售点「这是真客人」→ 现有改阶段入口改回「新线索」，事件是人写的；此后 5.1 第 4 条保证机器**永不再判他**。

#### 5.3.1 🔴 被挪走的人再来真咨询，必须自动回到名单（魏征 B1 / 子牙 B1）

`segments.ts:700` 的 `stageSuppressed` 在「客户回了话」之前就判 `excluded`，所以光靠阶段，
张三第一封像推销、一周后来信问「2 人 3 月多少钱」或打电话进来，会永远躺在「先放着」。

**规则（读侧、确定性、不靠模型、不靠人记得）**：阶段 = `not_enquiry` 且最近一次改阶段是
`ai:enquiry-screen` 时，**只要这次改阶段之后出现任何一条「对方发来的消息」（任意渠道：邮件、私信、
WhatsApp、电话打进来、表单，打开/点击不算），这个人就不再被当作停止营销**，回到正常分段
（多半是「客户来消息了」→ 今天要联系）。人工把阶段拉回的人不受影响。
实现：`buildContactModel` 多收一个「这个人上次被机器判非咨询的时间」（读侧批量取 `contact_stage_events`，
只取阶段 = 非咨询的几十人），在算 `stageSuppressed` 时比较。**安全方向：多放进来，不少放。**
新来的邮件另外会再走一遍 5.1/5.2（若又像推销，会再次被判走）。

### 5.4 什么时候判

- **新来的**：邮件同步新建/更新联系人后旁路调用（同 `runAgentCustomerHook` 位置，`writeTouchpoints` 之后，
  失败只告警、不影响主同步）。**逻辑放新文件，`mail-ingest.ts`（902 行，已超 800 行规矩）只加一行调用。**
  必须幂等（每小时线程会被重读）：入口先查 5.1，已判过的不重判。
- **存量**：一次性**干跑脚本**，只读，不写库、不外发消息。

### 5.5 开关、干跑、打开、回退

- **关着时**：新代码**什么都不做**——不调模型、不写库、不外发（魏征 B4）。只有干跑脚本会调模型。
- **干跑**（PR-1 的主产物）：对 CTS 全量只读跑，输出：①「352 → N」（和页面同口径，见 §2）；
  ②**第一层命中几个 / 第二层命中几个 / 因硬否决或阈值被放过几个**；③**至少 30 个被挪走者名单（不足则全部）+ 每人原因 + 原文前 120 字**，
  供 PM 抽查；④把「打开前的现状」导出成备份文件（每个将被改的人：id、原阶段、原阶段更新时间）。
  干跑会调用大模型（约 $0.02、每封只发主题+255 字预览，见 5.2）——**我只在二审过后才跑**。
- **打开（统筹 18 要求③；需 PM 本人一句话）会写生产库，范围写死**：
  | 写什么 | 哪张表 | 几行 |
  |---|---|---|
  | 加阶段「非咨询」（动作=停止营销） | `client_pipeline_stages` | **1 行**（CTS） |
  | 打开开关 | `clients.leads_config`（jsonb 字段内一个键） | **1 行**（CTS） |
  | 把命中者的阶段改成「非咨询」 | `contacts.stage` | **M 行**（M = 干跑名单人数，预期约 16） |
  | 记改阶段事件 | `contact_stage_events` | **M 行** |
- **一键回退（脚本在干跑时就备好并演示）**：只还原「事件操作者是 `ai:enquiry-screen`、`to_stage='not_enquiry'`、
  且这个人**当前阶段仍是 `not_enquiry`**」的人（事后被人改过的不动）；用备份文件里的原阶段还原
  `contacts.stage`（原来是空的还原成空——`advanceContactStage` 做不到，所以回退脚本直接写），
  并为每人补一条回退事件（`ai:enquiry-screen-rollback`）。再把开关关掉。回退脚本先对备份做**只读演练**，输出「将还原 M 人」。
  **注意**：`advanceContactStage` 写 `contacts` 失败时会删掉刚写的事件（子牙/魏征提示），所以回退依据以
  「`contacts.stage` 当前值 + 备份文件」为准，不只靠事件。

## 6. 判据怎么校准（用生产数据，不靠感觉）

- **金标准二（补幸存者偏差，魏征 NOTE 4）**：随机抽一批**我们没回**的入站邮件，**作者先人工标注**，
  再把标注 + 模型判定一并列给 PM 抽查 10 个（不要求 PM 全标）。**「把真咨询判成不是咨询」的容忍线 = 0。**
- **反例集**：§4 的 16 个，目标 ≥ 14/16 被判中；漏掉的留在名单里可以接受，错筛不可接受。
- 「Attn BAKER」两封必须保持「是咨询」。
