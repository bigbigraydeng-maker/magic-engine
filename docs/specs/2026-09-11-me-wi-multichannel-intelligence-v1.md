# ME Web Intelligence 多管道外部情报需求 v1

状态：需求登记，待分阶段开发

## 产品定位

ME Web Intelligence（WI）是面向高级客户的外部市场情报与竞争预警能力，不是单一的竞品网站定时抓取器。它的价值是把公开市场中分散、异步、不同可信度的信号，整理成有来源、有时间、有证据链、可人工复核的经营判断。

高级客户验收标准不是“抓到了多少页面”，而是：

- 能较早发现竞争对手的产品、市场、组织和传播动作；
- 能说明每个判断来自什么来源、何时观察、多久有效；
- 能区分事实、推断和未知，不用单一弱信号制造结论；
- 能把多个来源合并为同一个竞争事件；
- 只读、建议型、人工复核，不自动改价、投放、发布或联系外部对象。

## 管道范围

| 管道 | 公开信号 | 首期结果 |
|---|---|---|
| 竞品官网 | 产品、价格、促销、档期、余位、定位 | 页面快照、变化事实、影响分析 |
| 主流新闻媒体 | 融资、并购、高管、重大合作、危机、扩张 | 新闻事件、来源分级、影响窗口 |
| 行业新闻 | 政策、需求、供应链、市场格局、渠道变化 | 行业事件、受影响市场和竞品 |
| 行业杂志/专业出版物/行业网站 | 例如旅游行业的 Travel Today；产品趋势、专业观点、行业背书、渠道动向 | 主题信号、权威引用、趋势摘要 |
| 招聘信息（NZ） | SEEK、Indeed 上的新城市、新团队、销售扩张、技术投入、新业务方向 | 组织/战略领先信号，不等同于已发生业务事实 |
| Google SERP / SEO | 排名、搜索结果、竞品页面、SERP 特征 | 搜索可见度变化和竞争页面变化 |
| Google Ads / Meta Ad Library | 广告主张、素材、投放方向、落地页 | 公开广告动作和消息变化 |
| AI 可见度 / GEO | 竞品在 AI 查询中的出现、推荐和引用 | 查询级观测，不恢复已退役的 ai-tracker |
| 口碑与评论 | 评分、评论量、主题、情绪和异常反馈 | 口碑趋势与竞品对比 |

| Facebook Group 讨论 | 经客户授权的群组导出或 Meta 审批后的受控接入；话题、时间、来源链接 | 讨论信号与主题变化，不把单条发言当作经营事实 |

Facebook Group 不按普通公开网站批量抓取处理。首期只登记受控来源类型：客户可以提供已获授权的导出内容，或在 Meta 当前政策允许且完成应用审核、群组管理员授权后接入。不得使用个人登录 Cookie、绕过权限的浏览器抓取或隐式采集成员身份。作者身份默认不进入分析，正文中的个人信息需要脱敏。

群组讨论属于 C 级辅助证据，必须保留来源 URL、群组授权范围、观察时间和原始内容哈希；单一帖子不能直接生成客户经营建议，至少需要与官网、新闻、招聘或其他独立来源交叉验证。

其他社交公开内容先作为后续扩展，不在第一轮承诺稳定覆盖。

## 统一数据与分析契约

所有管道必须进入同一套外部情报记录，至少包含：

- `client_id`、竞争对象、来源类型、来源 URL；
- 原始观察时间、抓取时间、有效期和新鲜度状态；
- 原始内容哈希、标准化事实、证据摘录和来源可信度；
- 事件类型、涉及对象、影响市场、关联产品；
- `fact` / `inference` / `unknown` 区分；
- 前后证据关系、变化状态、分析状态和人工复核状态。

分析层必须先做来源和时间校验，再做变化判断。单一招聘启事、转载新闻或搜索结果不能直接升级为客户经营结论；跨来源一致时才提高置信度。

## Apify 采集实现登记

当前实现复用 `src/lib/apify/client.ts` 的 Actor 启动、轮询、dataset 读取和失败处理，并由 `src/lib/web-intelligence/apify-external.ts` 做统一字段转换。已核验的首批 Actor 配置如下：

| 用途 | Actor | 首批输入边界 | 输出处理 |
|---|---|---|---|
| RSS / Atom 新闻 | `ef12/rss-scraper` | 单 feed、最多 200 条 | 标题、链接、摘要、发布时间；缺 URL 或正文拒绝 |
| 行业网站 / 新闻网站 | `automation-lab/news-article-extractor` | 每站最多 50 篇，首期关闭图片 | 公开文章正文/摘要进入 observation，不保存作者身份作判断 |
| SEEK NZ 招聘 | `corvuslab/seek-scraper` | NZ、最多 100 条、近 7 日、带详情和增量字段 | 职位、公司、地点、薪资、职位描述、发布时间；作为组织领先信号 |
| 竞品网站流量方向信号 | `themineworks/similarweb-scraper` build `0.1.11` | 每次最多 20 个域名；默认按域名设置低额成本上限 | 总访问量区间、环比变化、跳出率、访问深度、平均停留、来源结构、主要国家；只作为低置信度公开估算 |

这些 Actor 都是 Apify Marketplace 的第三方 Actor，正式上线前必须完成一次小样本真实运行，记录 Actor run id、实际字段、费用和失败行为；Actor 页面或字段发生变化时不得静默继续写入。采集器不绕过登录、不读取求职者/群组成员私密数据，也不把完整受版权保护正文直接展示给客户。

流量方向信号有额外边界：Apify Actor 读取的是第三方公开估算，不是竞品 GA4/后台的一手访问数据；`total_visits` 只能作为趋势参考，不能据此推断订单、收入、客户流失或“直接冲击”。当前结果可以提供主要国家背景，但不承诺给出 NZ 单一市场的精确访问量；NZ 需求判断仍需结合 NZ SERP / Trends 等独立信号。客户自己的精确访问数据应优先接入其 GA4、GSC 或站点一方日志。

线上启用顺序固定为：生产 migration 单独批准 → 配置真实来源 URL/关键词 → 小样本验收 → 才能建立调度。未完成前，官网竞争监控旧路径保持不变。

## 分阶段开发

### ME-WI.0.2-A：多管道基础层

- [ ] 设计共享 source / observation / evidence / event 契约；
- [ ] 统一来源等级、发布时间、观察时间、有效期、转载去重和失效规则；
- [ ] 统一抓取运行状态、费用记录、失败原因和可重试边界；
- [ ] 统一结果页的当前判断、历史记录、来源和证据呈现；
- [ ] 保持现有客户隔离、只读和人工复核约束。

### ME-WI.0.2-B：新闻与行业出版物

- [ ] 建立允许来源清单和来源配置 UI；
- [ ] 抓取主流新闻、行业新闻和行业杂志的文章元数据与正文摘要；
- [ ] 为每个重点行业维护垂直媒体清单；旅游行业首批纳入 Travel Today 等行业杂志/网站，并与主流媒体分开标注；
- [ ] 识别公司、竞品、行业、市场、产品和事件类型；
- [ ] 处理转载、重复报道、付费墙、删除文章和无法验证的时间；
- [ ] 只把可追溯的文章事实送入分析，不把新闻观点当作事实。

### ME-WI.0.2-C：招聘情报

- [ ] 首期只接入新西兰主流招聘平台 SEEK 和 Indeed 的公开职位信息；
- [ ] 记录职位、地点、发布时间、公司和来源 URL，并尽可能保留职位详情页作为核验链接；
- [ ] 识别扩张城市、职能组合、团队规模线索和新能力方向；
- [ ] 明确招聘是领先信号，不等同于已上线产品或已完成扩张；
- [ ] 处理职位关闭、重复职位、跨平台重复和过期职位；
- [ ] 增加“组织信号”专用分析提示与人工复核状态。

### ME-WI.0.2-D：搜索、广告、AI 可见度与口碑

- [ ] 把 DataForSEO/SERP、公开广告库、AI 可见度和口碑快照接入统一事件模型；
- [ ] 接入 Apify 竞品网站流量方向信号，保留 Actor build、run id、dataset id、checked_at 和实际费用；以月度趋势为首期频率，先验证跨月稳定性再进入 AI 经营分析；
- [ ] 复用既有 provider 和数据表，不另建重复的客户/竞品名单；
- [ ] 为每种管道定义独立新鲜度、成本上限、证据完整度和降级文案；
- [ ] 明确“未测量”与“没有变化”，不把缺数据显示成零或负面结论；
- [ ] 为跨来源事件提供统一的来源列表和证据链。

### ME-WI.0.2-E：高级客户情报层

- [ ] 将同一竞品在新闻、招聘、官网、广告和搜索中的信号聚合为竞争事件；
- [ ] 形成重大动作、趋势变化和需要人工关注的预警等级；
- [ ] 提供按客户经营目标、产品范围和市场的筛选；
- [ ] 生成高级客户可读的周度情报摘要，但不替客户执行经营动作；
- [ ] 用真实 Customer Zero 证据验证时效、误报率、来源可追溯性和客户隔离。

## 不在本需求内

- 被动问答入口；
- 自动调价、改促销、改广告、发布 CMS 或联系外部对象；
- 恢复已退役的 `ai-tracker`；
- 没有来源凭证的网络搜索摘要；
- 为单一客户硬编码新闻源、竞品名单或私有事实。

## Reuse Statement

复用现有 Web Intelligence 的客户资格、预算闸门、Apify 抓取、快照/证据、来源 URL 校验、新鲜度判断、LLM 分析和人工复核边界。官网抓取属于共享能力；旅游路线对位属于 industry profile；客户名单、目标和产品事实仍来自客户配置与已批准证据。
