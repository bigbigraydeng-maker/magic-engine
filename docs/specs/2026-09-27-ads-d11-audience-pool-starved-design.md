## v2 改写说明（子牙 3 BLOCKER + 魏征 4 BLOCKER 后）
v1 的三条判据（池子平 + 再营销 CTR 跌 ≥15% + 频次 <3）在生产上**不成立或抓不到**：
- CTS 唯一用视频池的组含类似受众，被角色判成 `mixed`，v1 永远进不了判断（魏征 B1）；
- 「池子平」不等于「没人进」：365 天滚动池进出打平时本来就平；页面/表单池不该被开视频供血药（魏征 B2、子牙 B2）；
- CTR 复算：近 3 天 4.77% vs 前 14 天 5.06%，只降 5.8%，且主要是 9/12–13 尖峰回落 + 9/16 组自身改动，「断供→CTR 缓降」证据不足（魏征复算）；CTR 3 天合计噪声约 ±12%，15% 门槛只比噪声高 1.3 倍（魏征 C2）。
- 卫青审查窗口的方向（2026-09-27）：要比 CTR 下跌更早发现断供。
→ v2 把「断供」改成用**直接证据**判，CTR 与频次降为说明材料（不再是门槛）。这偏离了手册 §二十八 写的三条判据，已请卫青审查窗口同步修订手册；建议仍只进待办、花钱仍要 PM 点头，边界不变。

生产核对（2026-09-27 只读）：CTS「ThruPlay viewers 365d」「Video viewers 50% 365d」收人规则分别含 13 / 9 个视频；规则里视频的在投广告中，顶层 ThruPlay 组最后花钱 9/16；9/19–9/25 仍在花钱的只有冷启动留资组里 1 条广告（$20.76 / 7 天）和再营销组自己的 1 条（$2.71，自己喂自己不算）；用这两个池子的再营销组同期花费约 $258 → **供血不到消耗的一成**。

## 1. 判据（v2，三条同时成立才命中）
1. **视频类池子没长**：`audience_rule_events` 含 `video`（`video_view*` / `video_completed` 等）或 `audience_subtype = 'VIDEO'`；最新人数 > `D4_AUDIENCE_FLOOR`；近 7 天（账户时区日）至少 5 天有快照（每天取当天第一条，去掉「消失」行）；**末 3 天中位数 − 首 3 天中位数 ≤ max(`D11_POOL_FLAT_ABS = 500`, `D11_POOL_FLAT_PCT = 2%` × 人数)**（缩也算）。窗口内该池自己的规则有真改动（`realSettingChanges` 里有这个受众）→ 不判。门槛标「单客户证据候选值」。
2. **供血太少（直接证据）**：「供血广告」= 在投或近 7 天有花费、创意视频 id 落在该池 `audience_rule_object_ids` 里、挂客户登记主页、且所在广告组**不包含该池**（自己喂自己不算）的广告。近 7 天供血花费 ≤ `D11_MAX_FEED_SHARE = 10%` × 同期「消耗广告组」花费。池子规则里没有视频 id → 判不了（静默）。
3. **有人在消耗这个池子**：至少一个在投（`DELIVERING`）、不在实验中、`included_audience_ids` 含该池、组内至少一条在投广告挂客户主页的广告组（不限角色——含类似受众的 mixed 组也算，魏征 B1）；近 7 天花费 > 0。
- 说明材料（不作门槛）：每个消耗组的点击率近 3 天 vs 前 14 天（日中位数口径）、所在系列 7 天频次（缺失写「拿不到」）、池子 28 天内被刷透程度（消耗组 28 天曝光 ÷ 池子人数）、**池龄 vs 保留期**（`audience_created_at` / `audience_retention_days`：池龄 < 保留期 → 写「还没有人到期被移出，没长就是真没新人」；池龄 ≥ 保留期 → 写「没长也可能是进出打平，这条主要依据供血花费」；拿不到 → 写「以供血花费为准」。只改措辞不作门槛：判据 2 本来就用直接证据，不依赖池子为什么平）。措辞按材料分两档：点击率已在降且频次不高 →「已经开始影响再营销」；否则 →「还没明显影响，这是提前提醒」。
- 客户主页没登记（`clientPageId` null/undefined）或没有广告层数据 → 不跑。

## 2. 输出
- 新码 **D11**，**每个断供池一条**；`evidence.audience_id` 必填；单位 = 消耗组（按 id 排序，输出稳定）；`clientVisible: false`。
- 标题：「再营销受众池断供：「{池名}」7 天没长（{首}→{末} 人），给它供人的广告最近 7 天只花了 {供血花费}，用它的广告组花了 {消耗花费}」
- `reasons[0]` 建议：「开顶层视频广告给这个池子补新人（新增花费，要你点头才开，系统不会自动开）。开之前两件事：① 要投的视频必须先加进这个池子的收人规则（读回原规则 → 追加 → 写回 → 读回核对，别覆盖原有的）；② 另建独立系列，版位锁 Facebook/Instagram，开后按版位回读，Audience Network 花费应接近 0。正在跑的再营销组本身不动。挑供血素材看内容对不对、新不新，不看历史完播率。」+ 未证实提示：「改一个正在被在投组使用的受众的收人规则会不会让那个组重新学习，还没验证过。」
- 止损：「14 天后看：池子有没有开始长（首要）、视频是否确认已在收人规则里；再营销点击率只作辅助参考。」
- **不与 D2 去重**（子牙 B3、魏征 B4）：D2 照报；D11 文案加一句「如果这些广告组里有广告同时报了点击率下降，先补人、再判素材」。
- **PM 待办**：`ADS_RULE_CODES` 加 `D11`；`findingKey`：有广告单位 → 原逻辑；否则当 `code === 'D11'` 且 `evidence.audience_id` 是字符串 → `D11:${audience_id}`；其它 → null（不对所有码退回第一个单位）。Magic Bridge 不受影响（只取 `clientVisible === true` 且有广告单位的 D2/D10）。

## 6. 后续接执行时的硬约束（留给下一个窗口，本 PR 不实现）
把「发现 → 建议 → PM 批准 → 补池子收人规则 → 开顶层广告 → T+1 验版位和池子增长 → 回写效果」接成能力时，**必须走 Inngest 编排**（CLAUDE.md 铁律 3：跨步骤异步接力 + 外部副作用），不许靠日历提醒或人工记忆串联：
- 不新建「detected」事件：接现成的 `ads.diagnostics.completed_for_client`（`ads-d3-auto-pause.ts:50`）；后续阶段事件业务可读，如 `ads.audience_starved.supply_approved` / `ads.audience_starved.supply_verified`
- 照 D3：生成增长动作候选 → `validateGrowthActionCandidate` → 提交 Kernel（审批中心）→ action-submission 审批；幂等键按（客户, 池子）+ 冷却期，防止每天重复提
- 改池子收人规则单独留回执：改前规则 object id、改后、读回核对结果、怎么撤回
- 除 T+1 验版位外，补 T+7 效果检查事件（池子增长、再营销点击率），回写 Check/Tune；写清 PM 在哪里点批准
- 每阶段机器可读回执：request id、client_id、来源记录（`diagnostic_run_id` + 结论键）、受众 id、广告组 id、状态、花费影响与信封结果、授权状态、版位校验结果（audience_network 花费）、池子人数前后、批准人、provider 回执、created_at
- 照现成样板 `src/lib/inngest/functions/ads-d3-auto-pause.ts`（发现 → 事件 → 人批 → 执行），不另起一套
- 开广告是 `new_spend`：必须过自治信封日上限；改受众与花钱都 fail-closed——没有 PM 批准事件 + provider 回执，不许标完成
