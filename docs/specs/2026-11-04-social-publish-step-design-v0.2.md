## 1. 现状（2026-11-04 核实）
- 视频工厂点「通过」→ 发布程序每小时 :05 跑，把片发成 Facebook **草稿**（`FACTORY_PUBLISH_LIVE` 未设 = 只发草稿）。
- 草稿 → 公开只有一个系统入口：周卡上的「转公开」（`WeekPackApproval` → `/api/factory/work-orders/[id]/promote`）。周卡开关 `WEEKLY_PACK_APPROVAL_ENABLED` 与转公开开关 `WEEKLY_PACK_REEL_GO_PUBLIC` 都关着；视频工厂里原有的单条按钮 10-23 已撤（`7dac680c0`）。
- 转公开前现在只查：状态、两张清单、草稿文案与库一致、红线词、出镜授权（#3588）。**不核对团目录事实**——周卡排好到点公开之间，团目录若改了价格 / 团名 / 出发日，片照样能公开（v1.1 G7）。
- 每周闭环会算日期，但写库开关关着，不写 `publish_on`；到日自动公开（G11）等 PR #2817（「草稿不再记成已发布」，草稿中）。

## 2. 这一刀做什么
1. **发前事实复核（G7）**：转公开的「预览」和「确认」两步都在 `promote/context.ts buildContext` 里，紧跟红线检查之后，**用当前已发布团目录**重新跑一次 `checkFacts`（片里字幕 `output.caption`、正文 `buildReelPostCaption`、首评 `buildReelFirstComment`，与每周闭环完全同一套规则与取数 `loadSocialFactSource`）。
   - 只有 `pass` 才放行；`fail` → 422 列出对不上的那几项；`needs_human` → 409「要人核对」；团目录读不到 → 503 不放行（fail-closed，「查不到 ≠ 没问题」）。
   - 不写库（只读），结果放进预览返回给管理员看（目录版本号 + 逐项结论）。
2. **周卡演练**：不写新代码。用线上只读数据跑一次每周闭环（演练模式），把「下周哪几条、哪天、为什么能发 / 为什么刷掉、发前复核会不会过」做成一页给 PM 看；PM 看过再决定开哪几个开关（开关是 PM 的决定，开关本身可随时关回）。

## 3. 不做
- 到日自动公开（G11）：等 #2817。
- 改转公开的权限 / 一次性口令 / 指纹：不动。
- 口播事实核对：仍不做（成片入口设计 v0.2 §4）。

## 4. 开工十问
1. **IMPACT 哪一段**：Act（发布）的最后一道闸；外环指标仍是询价 / 合格客人（第七部，读回在下一刀）。
2. **确定 vs 模型**：全是确定性规则（`checkFacts`），不调模型、不花钱（第三部）。
3. **对外动作与授权级别**：转公开 = L3，只认全局管理员本人点；本刀只让闸更严，不放权（第六部）。
4. **完成证据**：预览里带目录版本 + 逐项结论；拦下时返回具体原因（第四部）。
5. **谁验证**：生产（视频工厂 / 苏东坡）≠ 质检（马良 + 事实核对）≠ 批准（PM）（第五部）。
6. **学习写哪**：本刀不新增学习；被拦下的条目进下一刀的「错题本」（第十部）。
7. **考卷**：用 11-04 手工核的 23 条练习题里的真实错例写成固定测试（合成数据，不放客户事实到共享测试）（第九部）。
8. **PM 纠正落到哪**：本刀无；下一刀做。
9. **读不到 / 判不了**：团目录读不到 = 拦，并说原因；`needs_human` 不当 pass（第十一部）。
10. **占 PM 多少注意力**：每次转公开多一行核对结果；不新增 agent、不新增待办（第十三、十六部）。

## 5. 验证
- 单测：pass 放行；fail / needs_human / 目录读不到各自拦且原因正确；目录改价后同一条片从放行变为拦下；预览带出目录版本。
- 变异：去掉复核调用、把 needs_human 当 pass、读不到当 pass，测试必须变红。
- 当场试跑：合并部署后，对已排期的一条 CTS 草稿片调一次「预览」（只预览，不确认、不公开），看返回里的核对结果；同时出演练卡给 PM。

## 6. v0.2：设计复审并入（子牙 + 魏征，各 4 条必改）
魏征用生产数据实测：CTS 现有 24 条 Facebook 草稿，按当前团目录（第 13 版）重核，**14 条放行、10 条拦下、0 条要人核、0 条读不到**；被拦的 10 条全是真过期（Natural China 旧片写 16 天 / $7,349 / 3 月 26 日出发，目录现为 19 天 / $7,999 且该团已取消；China Panorama 写 Victoria 游轮，目录为 Century；「4-5 星」对目录「5 星」；旧团名 Shanghai & Surroundings）。

1. **规则抽成一份共享函数**：把 `run.ts` 的单条核对（字幕 / 正文 / 首评 / 链接拆取）抽到 `weekly-loop/reel-facts.ts` 的 `checkReelFacts`，每周闭环和发布侧都调它，保证同一套规则。「今天」一律按新西兰日期（`isoDate(nzCalendar(now))`）。
2. **哪些客户要核**：团目录读取返回「这个客户没有已发布的团目录」= 不适用（预览里写一句，放行）；其余读不到（读取出错 / 目录为空 / 历史读失败）= 拦，不从「读不到」倒推「不需要核」。
3. **三处都核（同一个函数 `recheckReelFacts`）**：
   - 转公开（预览 + 确认，`buildContext`）：没过就拦。
   - 发布 worker 真发分支（`FACTORY_PUBLISH_LIVE=true` 时直接公开的那条路）：没过就终态失败，不排重试。
   - 补发首评（`resume.ts`）：只核首评这一串，没过就不发首评。
4. **已在 Facebook 上被人手动公开的片**（`view.published`，只同步记录）：照样核，但不拦同步，没过就发告警。
5. **「要人核对」的出口**写死：改片中文案或改团目录后重新预览；本刀不做人工放行（那是新的 A 级权限设计）。
6. **拦下原因**：纯文字短句、不带括号、最多列 3 项（周卡页面会吞掉带括号的报错）；预览数据加可选 `fact_check` 字段（目录版本、结论、最多 3 项、画面字幕是否核过），周卡与预览面板显示。
7. **目录版本进指纹**：预览后目录发了新版，确认时提示「预览之后内容变了」，要求重新预览。
8. **外部成片**（无 `output.caption`）：预览里写「画面字幕未核」，不因此拦。

不做（后续）：链接指向目录里不存在的团时改判「要人核」（会误伤通用页链接，先观察）；讲课片的发布路径（不写团价格，待核实后再说）。
