# 学习期（learning_stage_info）在源头读不到：核实结论与处理建议 · 119 号 · 2026-10-21

## 结论（一句话）
**不是 ME 解析错，是 Meta 对这两个账户的广告组根本不返回 `learning_stage_info`。** 所以内核的 `inLearningPhase(null)=true` 会长期成立，「对已存在广告组加预算（放大）」会被信封一律拒——放大目前只能出建议。

## 证据（只读，2026-10-21）
1. **ME 自己的连接器直读 Graph**（`fetchAdsetSettings`，请求里带 `learning_stage_info`，用 CTS 已存的令牌）：官方账户 16 个广告组（3 个 ACTIVE）、旧个人账户 29 个（3 个 ACTIVE），**带该字段的 0 个**。
2. **Meta 广告 MCP** 对官方账户的广告组请求该字段：在投的 3 个（今天 01:16 NZ 重建）与历史 PAUSED 的，**均无该字段**；其余字段正常返回。这 3 个组 `is_dynamic_creative=false`（排除了动态创意这个文档里的原因）。
3. **库里快照**：CTS 的 ad/adset/campaign 级 `learning_stage` 全是 NULL。
4. **官方文档**（`developers.facebook.com` 的 Ad Set / AdCampaignLearningStageInfo 页）：字段含义是「排序或投放系统是否仍在学习」，枚举 `LEARNING / SUCCESS / FAIL`；注明 **「只对在投（active）的广告组返回；使用动态创意优化的不返回；不是所有广告账户都有资格」**。文档没写「有资格」的判据。
5. **本次没能验证**：没有「已在投多日」的广告组可测——官方账户在投的 3 个都是今天才建的，旧账户的在投组也读不到；所以「在投多日后才返回」这一种可能没排除，但官方文档并未这样说。

## 现实含义
- 目前最可能的解释：**这两个账户（或其令牌/接口版本）没有该字段的资格**；这是 Meta 侧条件，ME 无法自行修好。
- **不要等这个字段**：数据驱动流程里「放大」不能依赖它。

## 处理建议（A 级，影响内核信封，留给总控/PM 决定）
给内核一个**「自己推导的学习期代理」**，并明文标注「推导值」：
- 学习中 = 广告组**激活不足 7 天**，**或** 最近 7 天内发生过**重大修改**（预算大改、受众/定向、优化目标变更——这些在我们的快照哈希里本来就能看到变化），**或** 7 天内优化事件数 < 50（用 `ad_daily_insights` 的开聊/留资累计）；否则不在学习期。
- 读不到推导所需数据时仍 fail-closed（拒加钱）。
- 这会让「放大」在新组满 7 天后可用，同时仍保护学习期；代价是改 `envelope-facts.ts` 的学习期取值，属 A 级内核改动，需子牙+魏征审。
- 在此之前：放大只出建议（与数据驱动稿 v0.3 §3 一致）。
