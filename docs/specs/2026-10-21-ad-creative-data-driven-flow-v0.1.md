# 素材流程改为「数据驱动」· 设计要点 v0.1 · 只设计，未写代码 · 119 号 · 2026-10-21

> 起因：PM 2026-10-21「按数据」——取消「PM 逐条批素材上广告」；视频工厂质检过的视频自动进待测试池，用小笔测试预算轮测，按数据排名，好的放大、差的自动停，好广告一直跑到疲劳再换。PM 只管两个数：**测试预算上限、放大总预算**。广告池与发动态是两条线（发哪条动态由社媒 Agent/97 号定）。风险级 A（碰钱、碰授权）。属于「④素材部」+「③预算与授权部」（见 departments-split）。

## 1. 新流程（对比旧流程）
| | 旧 | 新 |
|---|---|---|
| 入池 | PM 逐条点「批准」 | 工厂 + 苏东坡质检通过 → **自动进「待测试池」**（需带推广期，缺则不入池） |
| 测试 | 无 | 系统用**测试预算**给每条新素材一小笔轮测（同团同受众，公平分配） |
| 排名 | PM 感觉 | 按数据排名：看完率(ThruPlay/展示)、点进 WhatsApp/开聊人数、单次成本；样本不够不排名 |
| 放大 | PM 决定加预算 | 排名靠前且样本够 → 进「放大池」，在**放大总预算**内自动加（仍受 20% 单次幅度、72h 冷却等内核信封） |
| 淘汰 | 人工停 | 数据差（样本够仍低于线）→ **自动暂停**（收类，永远放行）；疲劳（频次/点击衰减，复用现有疲劳诊断）→ 退役并向视频 Agent 发 `creative_request` 要新片 |
| PM 管什么 | 每条素材 | **两个数**：测试预算上限、放大总预算（+ 批推广计划） |

## 2. 状态机（取代 candidate→approved）
`pending_qc`(工厂中) → **`test_queue`**(质检过、自动入池) → **`testing`**(在测) → **`scaling`**(放大) / **`rejected`**(数据差，自动停) → **`retired`**(疲劳/推广期到)。
- 现有 `candidate/approved` 迁移：`approved` ≈ 已在 `scaling` 或既有手批的；`candidate` ≈ `test_queue`。**迁移期保留手批通道**（PM 仍可手动把某条直接放进放大），两套并存到新流程跑稳。
- 推广期仍是硬条件：无推广期不得入 `test_queue`；到期自动 `retired`（沿用 2964 的断路器）。

## 3. 钱怎么管（与三道闸衔接，不另起一套）
1. **测试预算 / 放大总预算放进已批准的推广计划的广告步骤里**（`ads_campaign` 步骤新增两个数：`test_budget_cap_cents`、`scale_budget_cap_cents`）。PM 批计划 = 批这两个数。→ 复用 **PR3010 计划闸**：测试和放大的每一笔新增花费都必须落在已批计划某个步骤内、不超这两个数。
2. **2999 日预算闸**照常：任何启用/加预算先过客户日预算上限（含全部账户）。
3. **内核信封**：新建测试组 = `new_spend`；放大 = 加预算；暂停 = 收类。`autonomy_mode` 目前是 `observe`，**要让「系统自动开测试组 / 自动放大」生效，必须由 PM 本人把 CTS 切到 `bounded_auto`**（这是 PM 才能做的授权，我不替定）。切换前系统只出建议和草稿。
4. 超出放大总预算 → 不自动加，出待办请 PM 加预算（只认 PM 本人）。
5. 反向：停/降永远放行；读不到计划/数据时，加钱方向拦、停止方向放行（沿用 3010 v0.6 §1）。

## 4. 排名口径（防「数据好看是假的」）
- 指标：看完率、点进 WhatsApp 人数（有 utm/CRM 归因的）、单次成本；**样本门槛**（最低展示/花费，实现设计里定数）；对比必须同团、同受众、同时段，不跨团比。
- 反噪声：连续 N 天稳定在线上/线下才升降（防一天运气）；起量学习期不动（沿用内核学习期排除）。
- 看不到的不当零：数据缺失 = 「没测成」，不是差，不得据此自动停。
- 目标团的盈亏线（单次成本上限）来自计划步骤，不写进共享代码。

## 5. 与 2990（素材↔广告对应）的衔接
- 自动测试组建出来时，**ME 自己知道「哪个工单 → 哪个上传视频 → 哪个广告」**（从工厂上传到 Meta 全程是机器操作）。所以对**工厂出品**的素材，对应关系是机器事实，用新增的 `link_method='factory_upload'` 由「建广告处」窄函数写入，**不需要 PM 签字**。
- 2990 的「PM 签字 + 机器证据」只保留给**人工传到 Meta 素材库**的外部视频（如上海 v7 这类手传的）。上海视频 1136316685721299 当前是手传，等这套定了按「自动进测试」处理；传的时候要由 ME 代码做并记哈希（后续块）。
- 回报接口（手工建广告回报 ad_id）仍是事后登记，不是闸。

## 5b. 广告池 vs 发动态：两条线，不混
广告池只管「花钱投放哪条素材」；**发动态（Post/Reel/Story）发哪条由社媒 Agent（97 号统筹）综合定，不由广告池定**。工厂成片可以同时进两边，但两边各自的状态与授权互不借用（动态发布授权仍是 PM 的）。

## 6. 范围外 / 不做
不做自动发动态；不做跨团比较；不动 Meta 新建留资广告被案件挡住（1815089）的现状——测试广告目标先限定 ThruPlay/WhatsApp 类（实现设计里核实可用目标）；不新增内核层。

## 7. 未核实 / 实现前第一步
①样本门槛与各指标在现有 `ad_daily_insights` 里是否能取到（看完率、WhatsApp 点击是否按广告拆）；②计划步骤增加两个预算字段对 `plan_data.promo` 解析/内容指纹的影响（改 spec 会让已批计划指纹变——需兼容旧计划，可选字段）；③现有疲劳诊断能否直接触发 `retired`；④工厂→Meta 上传目前是谁在做（决定 `factory_upload` 写入点）；⑤`bounded_auto` 切换的前置检查（见内核信封设计）。
