# GitHub Actions 省钱设计稿（只出设计，不改 .github）

日期 2026-10-18 · 作者 118 号 · 依据：`gh api` 只读统计 10-01~10-18 的全部运行记录 + 抽样 60 次任务耗时 + 本地 git 历史。**未改任何文件；动 `.github/` 属 A 级，须子牙+魏征审、PM 本人回「合 N」。**

## 给 PM 的结论
1. **本月 1–18 日约 1,215 次 PR 推送，每次触发 8 个检查流程，估算约 21,000 计费分钟（按标价约 $168；账单实际 $215，估算偏低约 20%）。**
2. **最大的浪费：54% 的推送（658/1,215）是只改文档/台账的 PR，却跑了完整的类型检查、构建和测试。**
3. 最稳的省法是第 1 项（文档类 PR 跳过重检查），估计省 **25% 左右（约 5,300 分钟）**；其余都小，或要动主干规则。
4. 账单的钱不是代码问题：预算 $200 已满，是否加额度是 PM 的决定。

## 已经在省 / 不用做
- 所有 PR 检查都已有 `cancel-in-progress`：本月 PR 验证被取消 368 次。
- Codex 两个流程 10-14 之后已停，本月共花约 720 分钟（≈3%），之后不再产生。
- “Claude Code”流程 2,012 次全是 skipped，0 分钟。

## 数据怎么来的（不要把估算当账单）
- 次数：按天翻页拉全部运行记录，共 12,817 条；PR 验证 1,215 次。
- 分钟：每个流程随机抽 6 次，把每个任务时长向上取整到分钟（GitHub 就是这样计费）后求平均，再乘以次数（取消的按一半）；扣掉 10-18 因账单故障 3 秒即失败的运行。官方计费接口需要 `user` 权限，没拿到。
- 每次推送的平均计费：PR 验证 8.3、Ledger 3.2、Kernel 2.0、ai-orchestrator 1.5、ops-review-loop 1.5、fix-scope 1.0、风险闸 1.0、团目录边界 1.2 分钟。
- 文档类判据：PR 全部改动文件都在 `docs/` 下或以 `.md` 结尾（含 `docs/ledger/`）；本月 618 个 PR 里 302 个，对应 658 次推送。

## 没验证的
被 `if` 跳过的必过检查在本仓库主干规则里是否真算通过（第 1 项的前提，必须先实测）；第 2 项的命中率；第 3 项合并后各检查名在规则里的对应关系。
