## 1. 归属怎么判（纯函数 `diagnostics/ownership.ts`）

广告组名下的广告 = 当前快照 ∪ 近 35 天出现过的（`recentAds`）∪ 近 35 天**每一行**快照挂过的主页（新字段 `adPageHistory`）。已不在的广告只有在广告层日数据里花过钱才算（删掉前一分钱没花的别家广告不连累客户的组）。

| 名下广告（每条广告挂过的每个主页各算一行） | 归属 |
|---|---|
| 全部 = 客户登记主页 | `own` |
| 全部 ≠ 客户主页 | `other_page` |
| 两种都有（含同一条广告换过主页） | `mixed_pages` |
| 有读不到主页的 / 有花费却一条广告都没有 | `page_unknown` |
| 一条广告都没有、也从没花过钱（刚建的空组） | `empty`：不切、不列、不连坐 CBO |

**拿不准一律不算客户的**（fail-closed）。

系列：
- **CBO**：任一子组不是 `own`（`empty` 除外）→ 整个系列连同全部子组排除，排除清单只列系列一条。
- **ABO**：只排除不是 `own` 的子组；有子组被排除时，系列层日数据（含 7 天去重频次）一并切掉（里面混着别人的花费和人群，子牙）。

## 2. 在哪里切

`scopeAccountToClient(account, clientPageId, date)` 在 `buildAccountContext` 之前把 `AccountInput` 切成「只剩客户自己的」，**白名单**（子牙）：
- `snapshots`：只留客户的系列 / 广告组 / 广告组下的广告；受众、账户行保留。
- `daily`：广告组行只留 `own`/`empty`（快照里已经没有的被删广告组也按名下广告判，魏征）；系列行只留名下没有被切子组的。
- `hourly`：只留 `adset_id` 属于保留广告组的行。
- **不切** `adDaily` / `recentAds` / `adPageHistory` / `settingChanges` / `audienceHistory` / `latestCaptures`。
- 幂等：切过的再切一次结果不变（测试锁住）。

调用点与分工：
- `diagnostics/run.ts`：广告组/系列层（D1/D3/D4/D5/D7/D8/D9）用切过的上下文；**广告级 D2/D10/D11 与覆盖率用没切的上下文**——它们本来就逐条按主页过滤，切掉「混的」广告组会让客户自己挂在里面的广告静默漏检（子牙必改 4）。D9 挪到账户级闸之后。
- `opportunities/run.ts`：同一道切分。
- `loader.ts`：先读 `clientPageId`，D1 按小时预筛用切过的账户（run 再切一次，幂等）；新增 `adPageHistory`。
- 广告级命中挂在被切掉的（混主页）广告组上时，`flagDroppedAdsetUnits` 在证据和原因里标明「组层数字含别家，只看广告自己的数」（子牙第二轮：否则同一个组既「没参与诊断」又被报）。
- **豁免**：`meta/ai/live-rules.ts`（Magic Bridge 当场检查）直接建上下文、只跑 D2/D10，不经切分：它把花费占 ≥60% 的主页当客户主页（没有主页过这条线就不跑），规则再逐条按这个主页过滤广告，所以不需要切（子牙必改 3，第二轮更正措辞）。

不切 / 降级：
- `clientPageId === undefined`（没加载）/ 共用账户 → 原样。
- `clientPageId === null`（客户没登记主页）：账户里只有一个主页 → 原样跑（不让付费客户整段失明），归属未核实，自动暂停一律拦；**≥2 个主页 → 只做账户级**（同共用账户：D1/D7 + 「去登记主页」提醒；机会发现出一条 not_comparable），子牙建议 7。注意此时 D1 在整个账户上判，「日预算还剩」含别家的预算（跟共用账户同一口径）。

排除清单：新增原因 `other_page` / `mixed_pages` / `page_unknown`；只列评估日在投或近 7 天有花费的（含已删除的广告组）；detail 写主页 id，不写客户名。内部日报文案同改。

新增 D7「登记主页可能不对」：近 7 天名下广告全挂客户主页的广告组零花费、名下广告全挂别家主页的有花费 → 下发人工任务（魏征：否则客户所有广告组被静默切掉，日报只剩排除清单）。混主页 / CBO 连坐的花费不算「别家」（子牙第二轮）；广告层快照最近一轮没抓全时不出（原因是没抓到，魏征第二轮）。

## 3. 自动暂停第二道防线（`ads-d3-auto-pause.ts`）

`processD3Hit` 在「共用账户」闸之后、dry-run 之前加归属闸 `verifyAdsetOwnership`：
1. `clients.facebook_page_id` 为空 → 拦（`client_page_unknown`）。
2. 该账户**最近一轮广告层快照必须抓全、且不超过 24 小时**，否则 `capture_stale`（快照看不到新加进组的别家广告，魏征）。
3. 该广告组近 35 天**每一行**非「消失」广告快照都挂客户主页才放行；分页读完（每页 1000 行），读满 10 页视为可能截断，判不了（子牙第二轮：只读一页会让 25 条广告以上的大组永远核实不了）。
   - 闸比诊断严：诊断不算「已删掉、一分钱没花过」的别家广告，闸算。结果是诊断照报 D3、闸记 blocked——朝安全方向的不一致，保留。
4. 读失败 → `read_failed`。

记账：核实过不是 / 没登记主页 → `status='blocked'`；系统没法核实（`read_failed` / `capture_stale`）→ `status='failed'`（子牙：别让人以为「查过了、是别人的」）。放行时把归属依据（判定、广告条数、主页 id）写进 `flywheel_actions.payload.ownership` 和 Kernel `evidence.ownership`。D2/D10 的「客户没登记主页」提醒里加一句「自动暂停建议也一律拦下」。

## 4. 登记表要不要把这种账户标成「共用」？→ 不标

- `shared=true` = 整账户只做账户级、快照同步整个跳过四层。标上 = 该客户主账户 54 条自家广告的广告组层诊断和快照全停，只为挡 5 条已暂停的别家广告。
- 登记表表达的是「哪些客户登记了这个账户」；另一个客户根本没登记这个账户，没有第二行可判「共用」。按创意主页判是更细、更准的那层（归属按「≠ 客户主页」判，不要求别家主页已登记——魏征核实）。

- Kernel 执行器（批准那一刻）用 Meta 实时数据再核一次归属，并核对 `adset_id` 属于 `ad_account_id`（魏征）。
- 批准卡片展示 `evidence.ownership`（本 PR 只写进证据）。
- 客户只能登记一个主页（AU/NZ 各一个时第二个主页的广告组会被判别家）。
- D1「多半是账户单日花费上限」在切分后可能指错方向：证据补「整个账户同时段是否在花钱」（魏征）。
- D2/D11 用的系列层 7 天去重频次在 ABO 混主页系列里含别家人群（广告级规则仍在未切上下文上跑，沿用现状）。

- `flagDroppedAdsetUnits` 接线（run.ts 调用处）只有函数级测试，没有端到端变异覆盖（需要构造混主页组里的真实 D2/D10/D11 命中）。
