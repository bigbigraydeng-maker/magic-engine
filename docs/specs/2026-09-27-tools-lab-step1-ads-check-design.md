## 1. 9/27 实走正式站发现的断点（这一步要消掉的）

1. 官网中文首页没有任何入口；`/cn/meta-ads-ai/` 是「首批招募」页，17 项申请表 → 候补 → 人工邀请，而且写的是「中国外贸企业」一类人。
2. 示例报告 `/meta-ads-ai/demo` 是代管客户口吻，唯一下一步是写邮件。
3. 注册页 `/portal/register` 卖的是已荒废的「500 MTC 代币」，英文。
4. 新自助客户注册后先被送进多步 onboarding 向导（`resolveSelfServeLanding` 在 `onboarding_completed_at` 为空时一律改道），来做广告体检的人会被挡在向导里。
5. 注册后入口只是顶部一行小字「Meta 广告 AI 分析（只读测试）」。
6. 客户看得到的 5 处写着「Magic Bridge」。

## 2. 改什么

### A. 官网（`website/`，静态站，Cloudflare Pages）
- **新页 `/cn/lab/`「Magic Engine 工具实验室」**：一句话说明 + 两类人各一段（国内外贸 / 海外华人）+ 工具卡片。第一张「Facebook 广告体检」→ `/cn/meta-ads-ai/`；「网站免费诊断」「品牌健康打分」显示「即将上架」（第二、三步再接）。可被搜索引擎收录。
- **中文首页 `/cn/`** 导航加「工具实验室」，并加一张入口卡片。
- **重写 `/cn/meta-ads-ai/`** 为广告体检介绍页：删掉「首批招募 / 邀请测试」说法和 17 项申请表；两类人各一段；「先看示例」→ 示例页；主按钮「免费体检我的广告」→ `https://app.magicengine.com.au/meta-ads-ai/mine`；写明「Facebook 连接正在等 Meta 官方审核；现在注册，开放后第一时间通知你」（群发通知前单独问 PM）。保留只读 / 不改广告 / 删除数据说明和隐私页链接。原表单后端 `waitlist.js` 不动（只是页面不再用这个表单）；`pilot-wiring.test.ts` 按新页面改。
- 页面上的按钮按官网现有写法打点（`lead-event.js`，进 `website_lead_events`）。

### B. 应用（`src/`）
1. **固定入口 `/meta-ads-ai/mine`**（新页面，服务端跳转）：已登录的自助用户 → 自己的 `/meta-ads-ai/<客户>`；未登录 → `/portal/register?tool=ads-check`；其他身份（运维 / 付费客户）→ 他们原来的首页。只用登录会话里的身份，不接受网址里的客户编号。
2. **注册后直达**：`normalizeSelfServeTarget` 认 `/meta-ads-ai/mine` → 改写成本人的 `/meta-ads-ai/<客户>`（与已有「只认本人那一个」规则一致）；`resolveSelfServeLanding` 在目标是本人广告体检页时**跳过 onboarding 向导**（体检不需要向导里的资料；以后从后台首页进去照旧走向导）。邮件验证码和 Google 登录两条路都经过这里，一并生效。
3. **注册页中文版**：`?tool=ads-check` 时左侧和表单、验证码步骤全部中文，讲「免费体检你的 Facebook 广告」，`next` 固定为 `/meta-ads-ai/mine`；不带参数时英文原样不动（MTC 文案本步不改，免得影响别的入口）。
4. **记线索**：带 `tool=ads-check` 注册成功（新建了自助客户）时，写一条 `website_lead_events`（`cta_key='tool_signup'`，`destination='ads-check'`，`source='tools_lab'`，`metadata` 只放客户编号，不放邮箱）。两条注册路都记。不加表、不改表。
5. **示例页**：默认显示自助客户看到的样子（「值得你看一眼的广告」卡片、老板自己能试的建议）；上方一个切换「我们帮你管会看到什么」显示现在的代管版。两处按钮「免费体检我的广告」→ `/meta-ads-ai/mine`；保留「虚构数据」横幅。
6. **品牌**：客户看得到的「Magic Bridge」全部换掉——广告体检页头写「Magic Engine · Facebook / Instagram 广告体检」，错误提示写「广告体检」，示例页标题、删除数据说明页里的括注同改。内部代码、今日待办里的名字不动。
7. **后台入口**：客户后台顶上那行「Meta 广告 AI 分析（只读测试）」换成一张醒目的卡片「免费 Facebook 广告体检」，一句话说明 + 按钮。

## 3. 安全与边界

- `/meta-ads-ai/mine` 与注册跳转只用登录会话的身份，永远落到本人自己的客户；不认网址参数里的客户编号（沿用 P0-J 路径穿越修复的做法）。
- 跳过向导只针对「本人的广告体检页」这一个目标；其他目标照旧。
- 线索记录不存邮箱等联系方式（联系方式已在客户表里）；记录失败不影响注册。
- 不动额度、防刷、数据库结构、Meta 授权。

## 5. v2 修订（设计审一轮：子牙 1 BLOCKER、魏征 2 BLOCKER、板桥文案）

**拆成两个 PR**：PR-A 应用（先合，`/meta-ads-ai/mine` 要先在线上）；PR-B 官网（后合）。

**PR-A 应用**
1. `/meta-ads-ai/mine` 必须能处理**所有**已登录身份（子牙 BLOCKER）：自助 → 本人体检页；付费客户 / 运维 → 复用 `resolveRedirect` 的现有落点（不再写第三份挑客户逻辑）；已登录但名下没有客户 → 中文注册页。补「不会来回跳」测试。页面 `force-dynamic`，身份用 `getUser`。
2. **老用户回来进得去**（魏征 BLOCKER 1）：没登录时去中文「登录/注册合一」——注册页在 `next=/meta-ads-ai/mine` 时是中文；邮箱已存在就自动改发登录验证码，不报「已存在」。体检页登录过期不再跳员工登录页，改跳 `/meta-ads-ai/mine`（对运维仍走 1 的分流）。
3. **中文模式看 `next==='/meta-ads-ai/mine'`**（或 `tool=ads-check`），Google 登录失败回跳、登录注册互跳都带着它；服务端报错按错误码在前端换中文；注册页显示 `error=auth_failed` 的中文提示。
4. **线索只在「第一次验证成功」时记**（魏征 BLOCKER 2、子牙 SHOULD 1）：共用函数「每个客户只记一次」（先查同一客户有没有 `tool_signup`），调用两处——Google 回调 `ensured.created` 为真且目标是 mine；验证码通过且目标是 mine。`page_path` / `target_href` 填好。官网公开打点接口拒收 `tool_signup` 这个名字，防伪造。
5. **后台卡片只给自助客户、只放后台首页**；运维开的 / 付费客户 / 员工保留原来那行字，只去掉「只读测试」和内部代号。体检页「返回工作台」在向导没走完时指向向导。
6. **品牌清单补全**：`[clientId]/page.tsx`、`meta-ads-ai/page.tsx`（还指向旧入口）、`login/page.tsx`、`error-messages.ts` 三条、数据删除页中英两段、示例页；加一条测试扫描客户可见目录不再出现内部代号。
7. 等审核文案去掉「第一时间」：「开放后我们发邮件通知你」；同 PR 开台账卡 + 日历提醒「Meta 批下来后给已注册的人发通知」（名单 = 验证过邮箱、从 mine 进来的自助客户；群发前问 PM）。
8. 示例页顶部切换「自己用，你会看到」/「交给我们管，你会看到」；横幅「以下是虚构的示例店铺，数字不是真实客户的」；底部主按钮「免费体检我的广告」，次入口「想让我们帮你管？写邮件聊聊」。
9. 90 天免费期文案补「到期不会自动扣费」。
