## 2. 甲 · 现在就能做的代码

### PR-1 · 自助开通与防刷（A 级）
1. **谁能开通**：只有**自助注册的客户**（`clients.source='self_serve'`）的自助成员（`access_type='self_serve'`）能点「免费开通」；管理员 / 付费客户页面不显示这个按钮（魏征 S4：管理员误给代管客户开）。权限检查统一用 `requireOnboardingClientAccess`（子牙 NIT）。
2. **开通怎么写**：邀请表加一列「来源」（`ops` / `self_serve`），`approved_by_email` 写 `self_serve:<用户 id>`。写入只走一个 `service_role` 专用数据库函数，函数内复核：客户是自助客户、调用人是本客户自助成员、不在封禁名单。
   - 没有记录 → 新建（生效、90 天、开托管分析、每月上限用默认值）；
   - 已有、来源是自助、**只是到期** → 自己续 90 天（版本号自动换新，旧授权不复活——`read_grants.sql:74-82`）；
   - 已被停用 / 撤销、或来源是运维开的 → 拒绝，提示联系我们（子牙 S1、魏征 S3）。
   - 开通回执复用现有 `audit.ts`，不新建表。
3. **防刷与总开销**（全部写进现有扣预算数据库函数 `meta_ads_reserve_sponsored_analysis`，加锁判断 + 约束兜底，不在程序里先查后放——子牙 B3）：
   - 每客户每月上限（现有，默认 US$1）；
   - **同一个广告账户**、**同一个 Facebook 用户**跨客户每月合计上限（同 US$1）——堵「断开 → 新邮箱注册 → 重绑再领」（魏征 S2）；
   - **全平台每月总上限**（单行加锁，建议 US$30）；用满时给单独提示「本月免费名额已满，下个月 1 号恢复」，不说成「你的额度用完」。
   - **封禁名单**（按 Facebook 用户 id / 广告账户 id，运维维护）：开通、连接、生成三处都查（魏征 S3）。
4. **自助客户先关掉签发外部接口钥匙**（`route.ts:11,37`，子牙 S3）。
5. **登录跳转**：`normalizeSelfServeTarget` 精确放行 `/meta-ads-ai/<本客户 id>`（魏征 NIT）。
6. **Facebook 连接开关**：新环境变量 `META_ADS_AI_PUBLIC_CONNECT`（默认关）。关着时，只有运维名单里的客户（审核期间的测试者）看得到「连接 Facebook」；其他自助客户看到板桥文案：「Facebook 连接正在等 Meta 官方审核，通常要几周。审核一通过我们会发邮件通知你，不用再注册。」（注册时已有邮箱，不另收；等待中的客户数进 PM 今日待办）。
7. **对外文案**（板桥必改）：删掉全部「邀请测试」字眼（含错误提示）；连接按钮上方说明「接下来 Facebook 会弹出『Magic Engine』的授权页，这就是我们，只需要勾选『读取广告数据』」；开通页写明「免费期 90 天」；到期、额度用完、总名额用完各一句（不出现美元）；页头改为「Magic Bridge · Magic Engine 出品 / Facebook / Instagram 广告体检 / 免费 · 只看不改」；选账户时显示账户名；删掉页脚推销段。
8. 账户被自助客户先占、之后要登记给代管客户：补一条运维释放路径，并在冲突时下发人工任务（子牙 S2）。

### PR-2 · 自助客户现场算卡片 + 自助版文案（A 级，客户可见）
1. **只在一种情况现场算**：这个客户**完全不在巡检名单**（没有登记广告账户、`ads_growth_states` 没有任何记录）。代管客户的「共用账户 / 没登记主页」（巡检故意拒判）和「过期 / 读库失败」（巡检坏了）一律不覆盖，照旧显示原因（子牙 B2、魏征 S1）。
2. **补齐规则需要的全部数据**（子牙 B1、魏征 B1）：广告 / 广告组 / 系列设置（含 `ad_studies` 实验信息、`updated_time`）；**广告、广告组、系列三层**近 28 天按天数据；系列近 7 天频次。任何一项读不到 → 不现场算，第三部分如实写原因。
3. **单独时限**：现场算自己 15 秒、只拉有花费的广告、限制页数；超量**整段放弃**，不截断（截断会改变同组对照和多重比较——魏征 S5）；失败只影响第三部分。
4. **复用规则，不改默认行为**：写一个薄转换层把 Graph 数据转成巡检用的 `DailyRow`（`toInsightRow` 是写库用的，不直接复用——子牙 S6）；设置转换复用 `snapshot.ts` 的 `normalizeAd / normalizeAdset / normalizeCampaign`；跑同一个 `diagnoseAdLevelRules`。
   - 主页：上游算出近 28 天花费最多的**非空**主页、且占比 ≥ 60%，作为 `clientPageId` 传入（规则函数零改动）；不到 60% 就不现场算，第三部分写明（子牙 S4、魏征 S6）。
   - 结果口径：自助客户没有配置，按各广告组去向判（与 Magic Bridge 结果口径同一函数 `resolveCoreMetric`）；与巡检「没配置就跳过」的差异写进报告说明。
   - 连续两次：按**账户时区**的昨天、前天各判一次，两天都命中才出卡片；与巡检的差异（用今天的设置判前天、Meta 事后修正数据、改名也算修改）都偏向少报，写明并加测试（子牙 S7、魏征 S5）。
   - 「检查了 N 条」只数真正判得出结论的广告；只投播放 / 曝光的账户不写「没有正在投放的广告」（魏征 S5）。
5. **自助版文案，按「来源 + 客户类型」分两套**（魏征 B2，五处全改并逐句测试）：卡片标题「值得你看一眼的广告（N 条）」+ 开头「下面是从你账户数据看到的变化，改不改由你决定，我们不会动你的广告」；每条一句自己能做的建议（例：「打开这条广告用的表单，把不是非问不可的问题删掉，再看两三天」「换一张新图或新视频试试，文字和受众先不动」）；删掉「请告诉我们」「你不用动手」「团队复查」；`client-copy` 的「准备好会自动出现 / 登记好主页」只给代管客户；AI 提示词里「和广告团队商量」对自助客户改成「你可以自己试」；卡片区结尾只出现一次「不想每天自己盯？我们可以帮你看着，发现问题直接处理——点这里跟我们聊聊」。`buildRuleCards` 接受新来源 `live`。
6. Inngest：现场算是一次同步只读、无对外副作用，按 CLAUDE.md 例外豁免，PR 写明原因。

### 8.3 PR-1 调整
- **审核没过之前不让普通自助客户开通**（板桥必改 1、子牙 S1）：开关 `META_ADS_AI_PUBLIC_CONNECT` 关着时，只有 `source='ops'` 的客户（测试者）能走完整流程；其他自助客户看到等待文案 + 「先看看示例报告长什么样 →」（链到 `/meta-ads-ai/demo`），不显示开通按钮。测试者限制在服务端 `startAdsConsent` 拦截，不只靠隐藏按钮。
- **90 天从第一次连上 Facebook 开始算**；到期可自己再开 90 天（要重新连 Facebook，文案说清）；停用 / 撤销 / 运维开的不可自助恢复。
- **审核通过后的通知邮件**（板桥必改 2）：做成一个带「演练模式」的一次性任务，列出所有在等的自助客户；打开开关那天由 PM 在今日待办里点头后才真发（经 Gmail，发给客户属对外发送，必须 PM 授权）。
- 跨客户额度：同一 Facebook 用户合计上限可能误伤代理商——自助开放面向的是自己投广告的商家，接受；全平台总额用到 80% 进今日待办（魏征）。
- 崩掉的任务：结账函数与超时回收分支同步释放三本账（魏征 S2）。
- **文案按「在不在巡检名单」分，不按注册来源**（魏征 S4）：判据写死为 `clients.meta_ad_account_id` 非空；自助客户转代管后，以该账户第一条可用巡检记录为切换点，之前继续现场算、用自助口吻。
- 提示原文（板桥必改 3，「1 号」按**新西兰时间**）：到期「90 天免费期到了，点这里免费再开 90 天（需要重新连一次 Facebook）。」；个人额度「本月免费体检次数用完了，下个月 1 号自动恢复。」；账户额度「这个广告账户本月的免费次数已用完（可能在别的账号下用过），下个月 1 号恢复。」；全平台「本月免费名额已满，下个月 1 号恢复。」

## 7. v1 设计审结论（已在 v2 落地，逐条标了出处）
- **子牙 3 BLOCKER**：① 现场算缺广告组层按天数据、系列 7 天频次、`ad_studies`，几道防误报闸会变放行 → 补拉，缺任一项不现场算；② 触发条件太宽（共用账户 / 没登记主页是巡检故意拒判，过期 / 读库失败是巡检坏了）→ 只在「完全不在巡检名单」时现场算；③ 全平台总上限必须写进 `meta_ads_reserve_sponsored_analysis` 加锁判断，不能程序里先查后放。SHOULD：90 天到期续期规则（加「来源」列，自助到期可续、停用 / 撤销 / 运维开的不可）；账户抢占需运维释放路径；自助客户先关掉签发外部接口钥匙；主页用上游算出后当 `clientPageId` 传入并要求花费占比过阈值；结果口径与巡检一致；`toInsightRow` 不能直接复用；现场算单独时限（约 15 秒）；页面全中文 vs 澳新英语用户（PM 定）。数据删除回调单独拆 A 级 PR。
- **魏征 2 BLOCKER**：① 同子牙 ①；② 代管口吻不止一处（卡片标题「我们正在跟进」、承诺句、`client-copy` 的「准备好会自动出现 / 登记好主页」、`askSentence`「请告诉我们」、AI 提示词「和广告团队商量」），且 `validSection` 只认 `patrol` → 按「来源 + 客户类型」分两套文案并逐句测试。SHOULD：免费额度可换壳重领（断开 + 新邮箱注册）、注册无频率限制 → 按广告账户 / Facebook 用户各设月额度，总上限用满单独提示；封禁可换新客户绕过 → 按 Facebook 用户与广告账户做封禁名单；开通按钮只许自助客户点（管理员会误给代管客户开）；超量整段放弃不截断、「昨天」按账户时区、「检查了 N 条」口径、只投播放类的账户措辞；主页过滤排除空主页并写明只看了哪个主页。
- **板桥 5 必改**：审核前不给外部用户「连接 Facebook」按钮（改成等审核 + 留邮箱）；授权页显示「Magic Engine」要提前说明；90 天到期提示；删掉全部「邀请测试」字眼；额度用完提示「下个月 1 号自动恢复」、不出现美元。另给了自助版卡片文案与页头文案。
