# Magic Bridge 对新注册客户自助开放 · 设计稿 v1

- 日期：2026-09-27 · 作者：卫青规则窗口（Claude Code）· 来源：PM 9/27 经小秘书定方向「(A) 新注册的客户自己用」；PM 当面补充：**不接 MTC 自助计费**（那套现在基本荒废），报告费用沿用现有的「ME 承担 + 每客户每月上限」
- 风险级：**A**（对外开放产品能力；改邀请准入这道安全边界；客户数据隔离）→ 设计与实施都走 子牙 + 魏征 + 板桥，实施后加 狄仁杰（攻击验证）
- 按 §11：频率 中（每个新注册客户都会走）/ IMPACT 高（新客户拿到的第一份价值：Inspect → Prescribe）/ 收入 高（自助获客入口）→ 零个低、两个高 → **P0**
- 层级门（Inline）：
  > [跟班 · Tier] Magic Bridge = Meta Connector（L3）上的客户界面；本次把广告支柱既有的 L1 规则（D2/D10）从「只给代管客户的每日巡检」扩到「报告生成时现场算」，是既有能力的第二个调用方，不新增能力线，不登记候选。
  > [跟班 · 红线] 不写死任何客户：准入按客户参数化；规则阈值不变；自助文案与代管文案分开，不把「团队会处理」的代管承诺说给自助客户。

## 1. PR-1 · 自助开通（A 级）
1. **自助开通按钮**：客户页入口改为对所有已登录的本客户成员显示（不再要求先有邀请）；点进去是说明页 +「免费开通」按钮。点按钮 → 服务端为**本客户**写一行邀请：`status='active'`、`starts_at=now`、`expires_at=now+90 天`、`sponsored_analysis_enabled=true`、每月上限用表默认值。幂等（已有行不改，已被停用/撤销的**不能**自助恢复——只有运维能恢复，防止被封禁客户自己重开）。
   - 只允许本客户成员（沿用 `requireDashboardClientAccess`）；写入走一个带权限检查的数据库函数（`service_role` only，函数内复核成员关系与现状），不在路由里直接 upsert。
   - 审计：写一条开通回执（谁、何时、哪个客户、来源 self_serve）。
2. **登录跳转**：`normalizeSelfServeTarget` 放行 `/meta-ads-ai/<本客户 id>`（只放本客户，别的 id 仍改写回首页）。
3. **对外文案**：页头「免费广告分析邀请测试」→ 正式说法；「邀请测试资格」类提示改写；页面标题按品牌规则待板桥定（例如「Magic Bridge · Facebook / Instagram 广告分析」——连 Facebook 的步骤里仍需出现 Facebook 字样）。
4. **总开销保护**（钱，PM 可改默认）：每客户每月上限沿用 US$1（约 8 份报告以上）；新增**全平台每月总上限**（建议 US$30，超了新报告暂停并进 PM 今日待办），防止批量注册刷单。
5. 不做：MTC 扣费（PM 明确不接）；客户自助关闭/删除数据的新入口（页面已有「断开连接 / 移除账户」）。

## 2. PR-2 · 自助客户也能看到卡片：生成报告时现场算（A 级，客户可见）
1. **什么时候现场算**：报告生成时，若该广告账户**没有**可用的每日巡检结果（`loadRuleFindings` 返回 `source:'none'` 且原因是没接入 / 没数据），就现场算；有巡检的代管客户继续用巡检结果（不变）。
2. **怎么算（复用，不另写规则）**：
   - 用客户自己的只读授权多读两样：广告 / 广告组 / 系列设置（`id,status,effective_status,adset_id,campaign_id,creative{…},updated_time,optimization_goal,destination_type`），以及**广告层按天数据 28 天**（`level=ad, time_increment=1`，分页，按花费取前 N 条广告，超时 / 超量就放弃现场算、第三部分写「这次数据太多，没有逐条检查」）。
   - 设置 → 复用 `snapshot.ts` 的 `normalizeAd / normalizeAdset / normalizeCampaign`；按天数据 → 把 `daily-insights.ts` 私有的 `toInsightRow` 导出复用，转成巡检用的 `DailyRow`。
   - 跑**同一个** `diagnoseAdLevelRules`（D2/D10），阈值不变；**连续两天**的要求用「同一份数据分别按 昨天、前天 各判一次，两天都命中才算」来满足（与 PM 待办 / 客户报告的「连续 2 次」同口径）。
   - 「最近改过设置」：没有历史快照，用 Meta 返回的 `updated_time` 当变更时间（与巡检里「Meta 修改时间优先」同一原则）。
   - 主页过滤：巡检按「客户登记的主页」挡掉混在共用账户里的别家广告；自助客户没有登记主页，且账户是他自己授权给我们的——**只看这个账户里、创意主页是本账户最常用主页的广告**（取近 28 天花费最多的主页），避免把代理商账户里别家的广告讲给他听。规则函数加一个「主页从哪来」的参数，默认行为不变。
3. **自助客户的文案**（板桥审）：代管文案是「我们的广告团队已经看到，会复查处理，你不用动手」——**对自助客户不成立**。新增自助版：说清哪里变差 + 一条可以自己去试的建议（例如「先检查这条广告的表单问题是不是太多」）+ 「想让我们帮你盯，可以联系我们」。卡片与正文第三部分共用这套文案；复查日期那句去掉。
4. 结果存进报告证据的 `rule_section`（新来源 `source:'live'`），页面卡片与正文去重逻辑沿用包 C。
5. 不做：D11（内部建议，本来不给客户）；为自助客户开每日巡检（那是代管服务）。

## 3. 外部卡点 · Meta 审核（人工任务，按铁律 3 下发，不许烂尾）
- 要做：确认生产用的是哪个 Meta 应用（`FACEBOOK_APP_ID`）→ Meta 企业验证 → 提交 `ads_read` 高级权限审核（用途说明、操作录屏、隐私政策链接 `/privacy`、**数据删除链接**、应用图标等）→ 应用切到正式模式。
- 我这边能自动做的：写好审核用的用途说明和录屏脚本；补 Meta 要求的「数据删除」说明页和回调接口（放进 PR-1）；审核材料清单做成 PM 今日待办的人工任务（what / how / href 三件套）。
- 审核周期由 Meta 决定（通常数周）。**审核通过前**：只有在我们 Meta 应用上加为「测试者」的人能连账户——可以先邀请少量真实潜在客户当测试者走完整流程。
- PR-1 / PR-2 可以在审核期间先做完上线（外部用户暂时连不上 Facebook 这一步，其余都通）。

## 6. 设计审结论（2026-09-27，v1 → 待改 v2；方向待 PM 确认「A 与 B2 都做 / 只做 B2」，暂停中）
- **子牙 3 BLOCKER**：① 现场算缺广告组层按天数据、系列 7 天频次、`ad_studies`，几道防误报闸会变放行 → 补拉，缺任一项不现场算；② 触发条件太宽（共用账户 / 没登记主页是巡检故意拒判，过期 / 读库失败是巡检坏了）→ 只在「完全不在巡检名单」时现场算；③ 全平台总上限必须写进 `meta_ads_reserve_sponsored_analysis` 加锁判断，不能程序里先查后放。SHOULD：90 天到期续期规则（加「来源」列，自助到期可续、停用 / 撤销 / 运维开的不可）；账户抢占需运维释放路径；自助客户先关掉签发外部接口钥匙；主页用上游算出后当 `clientPageId` 传入并要求花费占比过阈值；结果口径与巡检一致；`toInsightRow` 不能直接复用；现场算单独时限（约 15 秒）；页面全中文 vs 澳新英语用户（PM 定）。数据删除回调单独拆 A 级 PR。
- **魏征 2 BLOCKER**：① 同子牙 ①；② 代管口吻不止一处（卡片标题「我们正在跟进」、承诺句、`client-copy` 的「准备好会自动出现 / 登记好主页」、`askSentence`「请告诉我们」、AI 提示词「和广告团队商量」），且 `validSection` 只认 `patrol` → 按「来源 + 客户类型」分两套文案并逐句测试。SHOULD：免费额度可换壳重领（断开 + 新邮箱注册）、注册无频率限制 → 按广告账户 / Facebook 用户各设月额度，总上限用满单独提示；封禁可换新客户绕过 → 按 Facebook 用户与广告账户做封禁名单；开通按钮只许自助客户点（管理员会误给代管客户开）；超量整段放弃不截断、「昨天」按账户时区、「检查了 N 条」口径、只投播放类的账户措辞；主页过滤排除空主页并写明只看了哪个主页。
- **板桥 5 必改**：审核前不给外部用户「连接 Facebook」按钮（改成等审核 + 留邮箱）；授权页显示「Magic Engine」要提前说明；90 天到期提示；删掉全部「邀请测试」字眼；额度用完提示「下个月 1 号自动恢复」、不出现美元。另给了自助版卡片文案与页头文案。
