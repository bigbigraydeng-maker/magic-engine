# CRM 手机外勤页（今天要联系 + 一键外呼）设计稿 v0

状态：草稿，等 PM 回「开始」才写代码。风险级：B 级（只新增一个页面，复用现有接口；不碰鉴权、数据库表、钱、发信闸）。
来源：PM 2026-11-15「能否开发一个手机移动版的 CRM 入口，尤其是电话外呼板块，方便工作人员在户外使用」；PM 回「各自」= 每位员工用自己的手机、自己的登录账号。

## 1. 要解决的事（一句话）

员工在户外，打开手机就能看到「今天先打谁」，点一下系统就打到自己手机并接通客人，挂断后一键记结果、一键约回电。

## 2. 做完 PM 能看到什么

1. 手机打开固定网址，登录一次后可「添加到主屏幕」，以后像 App 一样一点就开。
2. 页面只有一个列表：今天要联系的人。每行：名字、为什么今天要联系（一句话）、上次谁跟的、一个大「打电话」按钮。
3. 点「打电话」：手机先响，接起后自动接通客人，全程录音、记入 CRM（跟电脑上的点击外呼是同一条线）。
4. 挂断后回到这一行，点一个结果：没接 / 聊了（打字或语音输入一句）/ 约了回电（明天上午 10 点 / 明天下午 2 点 / 下周一上午 10 点，三选一）/ 号码打不通 / 别再联系。
5. 点名字进一页只读的小详情：最近几条记录和电话摘要，够户外看一眼，不能改资料。

## 3. 这次不做

报表、发信、批量操作、改客人资料、改阶段、日历页、私信/邮件回复。要用仍然回电脑。手机版也不做离线。

## 4. 复用什么（不新写）

| 要的能力 | 复用 | 位置 |
|---|---|---|
| 今天名单 | `GET /api/clients/[id]/crm/today`（分桶、排序、已处理变灰都现成） | `src/app/api/clients/[id]/crm/today/route.ts` |
| 点击外呼（先打员工手机再接客人，含别再联系 / 打不通 / 每日上限 / 国家白名单闸） | `POST .../contacts/[cid]/call` | `.../contacts/[cid]/call/route.ts` |
| 员工登记自己的手机号 | `POST .../crm/my-phone` + `CallButton` 里的就地填写 | `CallButton.tsx` |
| 记结果 / 没接一键 | `POST .../crm/touchpoints`（`outcome` 一键，不经 AI） | `touchpoints/route.ts`、`drawer-actions.ts` |
| 约回电三个预设 | `callbackPreset`（服务端按 CTS 时区算，校验 ≤60 天） | `callback-pick.ts`、`callback-presets.ts` |
| 登录与权限 | 现有员工登录和 `requirePaidClientAccess` | `src/app/login`、`src/lib/auth/client-access` |

新增的只有：手机页面外壳（一个新路由 + 窄屏组件）、主屏幕图标所需的清单文件（manifest）、少量窄屏样式。**不新增接口、不新增表。**

## 5. 页面与路由

- 路由：`/dashboard/clients/[id]/crm/field`（放在现有 CRM 目录下，沿用现有登录和客户隔离）。电脑端侧栏不加入口，只给手机网址；以后要不要放入口再议。
- 只用 `buckets` 里「要人做的」那一层（`layer`），「刚有动作的 / 先放着的」默认折叠。
- 点击目标不小于 44px，单列，无横向滚动，底部固定「刷新」。
- 打电话按钮点后立刻变「正在先打你的手机…」，60 秒内不可重复点（服务端本来就拦，页面同样禁用，避免户外网差时连点）。
- 网差处理：请求失败显示一句人话「没打出去，请重试」，不自动重试（外呼是有成本的副作用，宁可手点）。

## 6. 安全与规矩（照搬现有，不放宽）

- 员工只能看到、只能拨自己有权限的客户；联系人必须属于 path 上的客户（现有 IDOR 闸）。
- 「别再联系 / 只别打电话 / 号码已标打不通」继续由服务端拦，手机页只负责不显示按钮。
- 员工没登记手机号：页面就地填一次，沿用 `my-phone`（只能登记自己的）。
- 外呼开关 `TELEPHONY_OUTBOUND_ENABLED`、每日上限（客户 80 / 员工 40）不改。
- 主屏幕图标不缓存任何客人数据（不做 service worker 离线缓存），避免手机丢失后留有客户名单。
- 页面里不出现真实供应商名（Twilio 等），对员工只说「CTS 号码」。

## 7. 要先核实的坑（开工第一步，不是现在）

1. 现在登录后的 CRM 页面在手机宽度下的实际效果：我只读了代码，没登录实测。开工第一刀先用手机尺寸真打开「全部客人」和抽屉，记一条基线。
2. 手机浏览器的登录有效期：员工户外一天要不要反复登录？沿用现有登录，先量，不改鉴权。
3. 员工是否都已在系统里登记手机号：之前 7 个员工账号只有 1 个能打（`my-phone` 注释），要对每位员工核一遍，缺的在页面里就地补。
4. iOS「添加到主屏幕」后的登录保持，需要在一台真 iPhone 上试一次。

## 8. 切片（每刀开工前问 PM 点头）

- **第 1 刀**：只读手机页——今天名单 + 为什么 + 上次谁跟的，没有任何按钮。PM 在自己手机上看是否好用。
- **第 2 刀**：加「打电话」按钮和「登记手机号」就地填写。当场试跑：用 PM 自己的号码当「客人」（不打真实客人）。
- **第 3 刀**：打完一键记结果 + 约回电三预设 + 小详情页。
- **第 4 刀**：主屏幕图标 + 窄屏打磨 + Impeccable 检查（前后数字写进 PR）。

## 9. 平台层级（跟班 Inline）

- 层级：L4 客户配置之上的展示层，挂在既有 CRM 能力下；不新增能力线、不新增支柱，不登记候选。
- 换客户 / 换行业：页面只读 `today` 与 `call` 接口，没有写死 CTS 名称；换到其他客户能直接用，需要的只是该客户已接入电话。
- Reuse Statement：复用 today、call、my-phone、touchpoints、callback-pick；新增的是窄屏外壳；无客户私有事实进共享代码。

## 10. 要 PM 拍板的（业务问题，不是技术）

1. 户外员工一天大概会打多少个？（决定每日 40 次的员工上限够不够）
2. 手机页要不要给所有员工，还是先只给 1-2 位试用？
3. 「别再联系」这个结果要不要放在手机上？（建议放，但放在二级按钮，防误点）

## 11. 验收（做完怎么算成）

- 一位员工用自己的 iPhone / Android，登录后 10 秒内看到今天名单。
- 点「打电话」，自己手机响，接起后接通；CRM 里出现这通电话的记录和录音（挂断约 2 分钟后）。
- 挂断后一键记「没接」和一键约回电，各自在电脑端 CRM 里能看到。
- 说过别再联系的人，手机页上没有打电话按钮；强行调接口也被服务端拦。
