## 0. 给 PM 的一页

**一句话**：销售用模板发出的一对一邮件里，「目录下载」链接在发出的那一刻换成「这位客人专属」的链接（用 CTS 自己的域名）。客人一点，系统先记一笔「某某点了目录」，再立刻跳到真正的目录文件，客人几乎感觉不到。

- **客人看到的**：信里多了一条 `go.ctstours.co.nz` 开头的链接（域名最后定），点开和以前一样直接下载目录。
- **销售看到的**：客人时间线上出现「点了邮件里的『目录下载』链接」。系统里本来就有的「点了链接、之后没人跟」分组会把他排进待跟进名单。**刚发完信 24 小时内的点击只记录、显示在时间线上，但不参与「谁先联系」的判断**（否则销售刚打完电话处理完的客人马上又亮起来）；24 小时之后的第一次点击才会点亮。
- **为什么是点击不是打开**：苹果手机 / Mac 的邮件 App 会替客人提前下载图片，没看也显示「已打开」；有的邮件 App 默认不加载图片，看了也记不到；我们现在发的是纯文字信，做打开跟踪得改成网页格式，就不像私人来信了。我们自己 10-29 就踩过这个坑（台账 `2026-10-29-crm-email-open-counts-as-last-contact`）。点链接是客人亲手做的动作，准得多——但**也不是百分之百**：有些邮件安全软件会替客人点链接，所以报表只写「至少 N 位点击」。
- **v0 不做什么**：不做「是否打开」；不动群发邮件（Mailchimp 那边本来就有）；**不改销售自由写的信里的任何链接**，只换模板里明确写了专属链接占位符的地方；v0 只跟踪**目录下载这一个链接**，其它链接保持直连。
- **安全上多做的三件事**：①这个新域名**只做跳转**，网站其它页面（登录页、后台、接口）在这个域名下一律打不开；②给 Inngest（后台定时任务系统）固定回调地址，防止有人借任何一个域名改掉它（这是**早就存在**的风险，见台账 `2026-10-30-inngest-serve-host-unpinned`）；③发信前先探测跳转入口是否健康，不健康就**这一封**退回原始链接，客人照样能下载。
- **试跑只对 hello@ 生效**：设置里有一个「只对这些收件人换链接」的名单，试跑完立刻关；对 CTS 客人真正打开要等你回 `开`，而且要先满足 §3.8 的前置。
- **已标「别再联系」的客人点了链接，什么都不记。**
- **销售不许对客人说「我看到你点了 / 下载了目录」**：这类话会让人觉得被盯着。点击只用来决定「先联系谁」，我会把这条写进给销售的说明，也不让 AI 起草信时引用点击记录。
- **要你和别人做的事**（实现前）：①把最新版目录 PDF 放上官网，给我下载链接（**不要放在官网的 `/tours/` 目录下**，那里会被现有检查当成「下架团页」）；②CTS 域名管理员加一条域名解析记录；③Render 后台加域名并设两个环境变量；④CTS 隐私政策加一句（法务确认，**上线前**）。具体写法见 §6。
- **花钱**：不新增供应商，几乎为零。
- **最大的风险**：跳转入口出问题时，**已经发出去的信**里的目录链接会打不开（10-29 晚网站因欠费停机 4 小时 48 分就是例子）。v0 的应对：只跟踪目录一个链接、入口有环境变量兜底地址（建议配成目录文件本身）、发信前探测入口、写明「加固」的触发条件（§3.9）。
- **现在没有要你回答的问题**。你合设计稿之后，实现分两张改动单（先迁移后代码），都是 A 级，都要你回「合」。

## 1. 目标与不做

**目标**
1. 对「销售用模板发出的一对一邮件」里被登记的链接（v0 = 目录下载），知道**哪位客人在什么时候点了**。
2. 点击成为 CRM 里已有的「意向信号」（不是「联系过」），不新建一套读模型。
3. 机制平台通用：同一套「专属链接」将来给短信（发信设计 §4.14 / P3b）和其它客户用；CTS 专属的只有域名、目标链接、文案，放客户配置。

**不做（本设计）**
- 打开跟踪（像素）。理由见 §0 与 §8-F；若以后要做，只当「参考计数」，不写触点、不排序（与发信设计 §4.7 一致）。
- Mailchimp / Resend 群发的打开 / 点击（它们自带，已有或已规划）。
- 销售自由写信里的链接（不改写）；模板里没写 `{{link.x}}` 的链接（不改写）。
- 落地页 / 表单提交回传（属短信 P3b 设计）。
- 点击后自动派活（不加 Inngest 函数，理由见 §3.8）。
- 「同一封信多个链接几秒内同时被访问」规则、登记「全部团页面」为专属链接、进程内缓存、按来源 IP 判机房网段、触点延迟确认（v0 都先不做，见 §9）。

## 3. 方案

### 3.1 总体流程

```
销售在抽屉里选模板 → 预览（显示真实目录链接 + 「发送时换成专属链接：目录下载」）
   → 点发送 → 取锁之前：入口健康探测（1 秒上限，60 秒缓存）；不健康 = 这一封不跟踪
   → 现有全部闸（按真实链接检查）
   → 【新】在员工确认的原文里找模板 {{link.x}} 渲染出的那个链接（先匹配）
   → 【新】匹配上了才生成专属链接（幂等）并替换；匹配不上 / 任何异常 = 发原文并记「跳过」
   → 加页脚 → 建草稿 → 发出
客人点专属链接 → 【新】GET /r/{code}：查库（失败走环境变量兜底）→ 先 302 跳转
   → 之后（不等）：查客人是不是「别再联系」→ 判人 / 机器 → 记点击行 → （符合条件时）写一条客人触点
CRM：客人时间线出现「点了邮件里的『目录下载』链接」；已有的分组 / 排序读到它（刚发完 24 小时内的点击除外，§3.8）
```

### 3.2 设置：顶层可缺省键 `tracked_links`

放进现有「发信设置」（版本化、只增不改、仅全局管理员能改）。

```jsonc
"tracked_links": {                        // 整块可缺省；缺省 = 没有登记任何专属链接
  "enabled": false,                       // 只管「发送时换不换」；登记表不受它影响
  "only_for": ["hello@magicengine.cloud"],// 非空 = 只对这些收件人换；[] = 谁都不换；null = 对所有人（见下）
  "host": "go.ctstours.co.nz",            // 必须以 go. 开头，且是 allowedLinkHosts 里某个域名的子域
  "ttl_days": 400,                        // 链接多久后失效
  "grace_hours": 24,                      // 发信后多少小时内的点击不参与「谁先联系」的判断
  "fallback_url": "https://www.ctstours.co.nz/",
  "destinations": [
    { "label": "catalogue", "title_zh": "目录下载", "url": "https://www.ctstours.co.nz/…（待 PM 给）" }
  ]
}
```

保存校验：`label` 为 `^[a-z][a-z0-9_]{0,30}$` 且不重复；`url` / `fallback_url` 必须 https、主机在 `guardrails.allowedLinkHosts` 里，**且路径不能落在团页目录下**（对 `destinations` 跑与发信闸相同的检查，F4）；**同一个 `url` 不许登记两次**；最多 5 条；`ttl_days` 30–800；`grace_hours` 0–168；`host` 必须以 `go.` 开头（原因见 §3.6）。

- **`only_for` 的语义与现有灰度名单一致**：`[]` = 谁都不换（等于关）；非空 = 只换这些；`null` = 所有人。把 `enabled:true` 与 `only_for:null` 一起保存，必须带 `confirmUnrestricted:true`（沿用 `settings-input.ts:54` 的做法）；设置页不许因为清空输入框就悄悄存成 `null`。
- **改目标要确认**：对已存在的 `label` 改 `url`，保存必须带 `confirmDestinationChange:true`，设置页显示「已发出的 N 封信里的这个链接会一起指向新地址」（§3.5 第 3 步）。
- **放顶层而不是 `providers`**：要改解析器让它认识一个**可缺省**的键，旧的 6 个设置版本照常读；放 `providers` 下需要同样改解析器，没有好处。
- **设置页、解析、序列化、保存必须四处一起改**（F5）。加测试：「读出来 → 设置页往返 → 序列化 → 再解析」等于原值；设置页遇到自己不渲染的块要**原样带回**。
- **回滚两档**：①软回滚 = 保存新版本把 `enabled` 关掉（登记表还在，`{{link.x}}` 照常解析成真实链接，模板照常能发，只是不再换链接）；②硬回滚（回滚代码）= 先把模板里的 `{{link.*}}` 去掉（新模板版本）、再保存一个**没有这一块**的设置版本，最后才回滚代码；否则旧解析器会把带新块的版本判成「未知键」，发信功能按「读不出设置」拒发。**`/r/` 入口一旦有链接发出就是对外承诺，回滚代码不得删它。**

### 3.3 模板里怎么写：`{{link.<label>}}`

- 占位符新增一族 `link.<label>`（与 `input.*` 同形，F6）。只许出现在**正文**，不许出现在主题；三种选团方式（不选 / 选一个 / 选多个）都可用。
- **渲染时只解析成登记的真实链接**，与 `enabled` 无关；该 label 没登记 → 缺值，这封信发不出去，并提示「目录下载链接还没配置」。保存模板时也校验：引用了没登记的 label 就拒绝保存。
- 预览、`rendered_sha256`、`final_sha256`、闸门检查看到的**都是真实链接**（F3）。预览和发送闸两处渲染都要传入登记表，加测试防止后者漏传导致哈希静默变空。

### 3.4 发送时换链接（`sendUnderLock` 里，门全过之后、加页脚之前）

只在**同时满足**下面条件时才动正文：①这是模板发信（`input.template !== null`）；②该模板的正文含 `{{link.<label>}}`；③`tracked_links.enabled` 为真；④收件人在 `only_for` 里（`null` 则所有人）；⑤取锁之前的入口健康探测通过（结果缓存 60 秒）。

```
planInRawBody(...)         纯函数：在员工确认的**原文**里，用与抽链接相同的字符集和句末标点规则（F4）取出链接片段（带原文位置），
                           找出「整体等于该 label 登记链接」的片段；最多取 {{link.label}} 在模板里出现的次数
issueTrackedLinks(...)     只有「匹配上了」才执行：写库，每个 (客户, 联系人, 请求号, label) 一条，唯一键保证重试 / 孪生请求复用；1.5 秒上限
replaceRanges(...)         按位置把这些片段换成 https://{host}/r/{code}（句末的 . , ; : ! ? ) 原样留在链接外面）
```

- **先匹配、后生成**：员工把链接改了、删了，或匹配不上，就**不生成链接记录**，并在回执 `warnings` 里记 `tracked_links_skipped:no_match`——衡量时「带跟踪的封数」才不会虚高。
- **匹配用原文，不用归一化后的链接**（F4：抽链接返回的是归一化字符串，位置对不上原文）。需要归一化才对得上的写法（全角、HTML 实体、IDN 变体）一律不换，按「跳过」处理。自由写信、没写占位符的链接**一律不碰**。
- **码**：14 位密码学随机字符（约 83 位），不含联系人编号；同一请求号同一联系人同一 label 重试**复用同一条记录**。
- **fail-open**：任何一步出错或超时（探测失败、生成失败、替换后复查不一致）→ **发出原始真实链接**，并在回执的 `warnings` 数组里记 `tracked_links_skipped:<原因>`（F17：不新增回执列，不往审计行塞东西）。理由：跟踪是衡量功能，不该拦住一封销售信；衡量时用回执区分「没跟踪」和「没点击」。
- **替换后复查**：对「替换前正文 + 页脚」与「替换后正文 + 页脚」各跑一次标准抽链接，要求后者的链接集合 = 前者里被换的那些换成本次生成的专属链接。**不一致不拒发**——退回原始正文发出（替换只可能产生我们自己的专属链接，退回原文是安全的）。
- **专属域名不加进 `allowedLinkHosts`**：闸门在替换前只看真实链接；白名单是精确匹配（`content-gates.ts:235`），不动。
- **审计行存实际发出的正文**（含专属链接）；**时间线消息和触点原文存「员工确认的原文」**（真实链接，F15），这样同事在 CRM 里点这个链接不会被算成客人点击。邮箱同步回读同一消息编号时不覆盖（F15）。`final_sha256` 仍是员工确认的文字（F3）。
- **预览**多返回 `trackedLinks: [{label, titleZh}]`，面板显示「这些链接发送时会换成专属链接：目录下载」。

### 3.5 跳转入口：`GET /r/[code]`（免登录）

1. **先清洗再校验**：路径里的码先剥掉末尾的 `.,;:!?)`（客人邮件客户端有时把句末标点算进链接，F4），再要求是 14 位字母数字；不合格 → 302 到该域名的环境变量兜底地址（不是纯文字 404，客人看到的应是网站而不是报错）。`HEAD` 单独导出：返回 302、**不记录**（Next 14 不单独写 `HEAD` 会拿 `GET` 代跑并记成点击）。所有响应带 `Cache-Control: no-store`、`X-Robots-Tag: noindex`、`Referrer-Policy: no-referrer`。
2. **查链接**（无进程内缓存）：按码查库（1.5 秒上限）。
   - 找不到 / 请求的域名与链接记录的域名不符 → 302 到该域名的环境变量兜底地址（`TRACKED_LINK_FALLBACKS`，JSON：域名 → 地址；**不依赖库**，也**不去反查客户设置**；域名不在这张表里才返回纯文字 404）；
   - 已过期 → 302 到该链接记录里的 `fallback_url`；
   - 库不通 / 超时 → 302 到环境变量兜底地址。**建议把兜底地址配成目录文件本身**，这样 v0（只有一个登记链接）在库故障时客人仍直接拿到目录。
3. **目标解析**：优先用当前设置里同 label 的登记链接，**条件是它与链接记录里快照的目标在同一个主机上**（只许换路径，不许换主机）并且通过 §3.2 的保存校验；否则用快照目标。这样官网换了目录文件的地址，旧信里的链接自动指向最新版；而一次设置保存也不能把 400 天内的旧链接改指到别的网站。
4. **先跳转**：给客人返回 `302`；**目标只来自库里那一行 / 当前设置**，不接受地址栏参数，所以不是开放跳转。**不读不写任何 cookie。**
5. **之后（不等）记录**，出错只记日志、不影响客人（Next 14 没有「响应之后继续执行」的接口，服务重启时这一步会丢，所以点击数是「至少」）：
   - 查客人是不是已标「别再联系」：是 → **什么都不记**（与隐私政策「用于跟进」的用途一致）；
   - 判人 / 机器（**不完美，结果只是「大概率真人」**）：`Purpose` / `Sec-Purpose` / `X-Purpose` / `X-Moz` 头里带 `prefetch` 或 `preview` → `prefetch`；UA 命中扫描器 / 爬虫 / 预览抓取名单（`bot`、`crawler`、`spider`、`Proofpoint`、`Mimecast`、`Barracuda`、`Slackbot`、`facebookexternalhit`、`WhatsApp`、`Teams`、`curl`、`python-requests` 等，名单在代码里带测试）→ `bot`；距链接**生成**不到 10 秒 → `suspected_bot`（重试复用旧链接记录时这个时间点会偏早，已知局限）；都不命中 → `human`。**分类用完整 UA，库里只存粗分类**（设备：手机 / 电脑 / 其它；系统与浏览器大类）和**命中的是哪条规则**（`matched_rule`），不存原始 UA、不存 IP。另存 `Sec-Fetch-User` 是否为真（只记录，v0 不拿它判定）。
   - 写一行点击（只增不改）。**每条链接最多记 50 行**，超出只跳转不记。
   - 符合条件时写客人触点（§3.8）。
6. **限流**：进程内存里的令牌桶（每个来源 IP 每分钟 60 次，IP 取 `X-Forwarded-For` **最右一项**——平台追加的那项，左边的可以被客人伪造；IP 只在内存里、不入库）；表最多 5000 项（超出丢最旧的），302 之后的后台写入队列最多 100 个（超出丢弃并记日志）。超限直接 302 到兜底地址，不碰库。入口与后台、Inngest 在同一个 Render 进程里，所以处理函数必须便宜：一次带索引的查询加一次设置读取。
7. 已知局限：企业邮件网关（Safe Links、Proofpoint、Mimecast 等）常用普通浏览器标识、在投递后几分钟或客人点击的瞬间抓取，UA 规则抓不到，会落进 `human`；同事在已发送箱里点、客人转发给别人、客人回信的引用里被点，都会记在原客人名下。所以对外报数只写「至少 N 位点击」，上线后用「`human` 点击距发出的时间分布」（大量集中在发出后几分钟内 = 疑似网关）而不是 `matched_rule` 占比来判断名单该不该补。

### 3.6 域名隔离与 Inngest 加固（F13、F14）

- **中间件加一条最先执行的规则**，写成「新增一条带域名条件的匹配 + 函数最上面的早返回」，**不要**把现有匹配范围放宽到全站（函数体默认把其余路径当 `/dashboard`，放宽后主站的 `/api/*` 含 webhook、Inngest、定时任务会全被导去 `/login`，F13）：
  - 匹配用 `has: [{ type: 'host', value: 'go\\..+' }]`；
  - 判断域名**读请求的 `Host` 头**（转小写、去掉端口）；**不要用 `nextUrl.hostname`**（Next 14.2 里它可能是 localhost，单元测试会假绿）、**不要复用 `public-origin.ts` 里先读 `X-Forwarded-Host` 的取法**；
  - 域名以 `go.` 开头时，只放行路径正好是 `/r/<14 位字母数字>`（后面可带至多 3 个句末标点）或 `/r/healthz` 的请求，**其余一切路径**（首页、`/login`、`/report/*`、`/api/*` 包括 `/api/inngest`、`robots.txt`、`/r/a/b`）直接返回**空响应体的 404**，在任何登录检查之前；不能落到 Next 的 404 页（那个页面会在 CTS 域名下加载 ME 自己的 GA 和 Meta Pixel）；不读不写 cookie（CTS 官网在整个 ctstours.co.nz 下可能有 `_ga`、`_fbp`，每次点击浏览器都会一并发来，不能让它们进入任何日志或存储）。
  - 实现时对「大小写、端口、`X-Forwarded-Host` 伪造、`/r/` 的路径变体（尾斜杠、双斜杠、`/r/../`）、`HEAD`/`OPTIONS`/`POST`」逐一写测试。
- **Inngest 固定回调地址**（独立于本功能的**既有**风险，已另记台账 `2026-10-30-inngest-serve-host-unpinned`，本功能新增域名使它更值得堵）：在 Render 设环境变量 `INNGEST_SERVE_HOST=https://app.magicengine.com.au`（SDK 已支持，不用改代码；两种登记路径都会用它，SDK 源码 `:1016`、`:1033`、`:1236-1241`），并在 Inngest 云端核对 App 当前登记地址就是它。改完要**手动重新部署一次**，部署时间晚于改变量。不做的话，任何人对服务的任一域名发一个匿名 `PUT /api/inngest`，Inngest 的回调地址就会被改登记到那个域名，之后域名解析一坏，所有客户的定时任务和事件任务一起停。
- 码只在登记它的域名上有效（链接行存域名快照），在 onrender 域名或 ME 自己的域名上一律走兜底 / 404。

### 3.8 客人触点与 CRM 读模型

**写入规则**（在 §3.5 第 5 步，客人不是「别再联系」且分类为 `human` 时）：

```
contact_touchpoints: channel='email', direction='inbound', source='me_link',
  occurred_at=点击时间, summary='点了邮件里的「{title_zh}」链接',
  metadata={ email_clicked: true, tracked_link: <label>, tracked_link_id, request_id,
             recent_send_response: <点击时间 − 链接生成时间 < grace_hours> }
  source_ref = <link.id>          （宽限期内的第一次真人点击）
             = <link.id>:late     （宽限期之后的第一次真人点击）
```

- 每条链接**最多两条触点**：宽限期内第一次真人点击一条（`recent_send_response=true`），宽限期之后第一次真人点击另写一条（`recent_send_response=false`）。靠既有唯一键 `(client_id, source, source_ref)` 幂等（F7）。这样「第一次点击就在 24 小时内」不会永久压掉几天后客人真正回头看的那次。
- 形状与群发邮件的点击行一致（F7），所以 `engagementFromMetadata` **保持不变**、仍把它读成 `click`（F8、F18 的 `revive.ts:75`：抹掉标记会让它被当成「真消息」）。
- **宽限期内的点击（`recent_send_response=true`）**是客人对我们刚发的这封信的即时反应：**时间线照常显示，但下面四个「谁先联系」的判断必须跳过它**（读模型把触点转成内存结构时带上 `recentSendResponse`，这四处排除它；若存在共用的取数函数，优先在那里统一排除）：
  1. `day-list.ts:354-357`（`customerActed`：否则已变灰的卡片重新亮起，F9）；
  2. `segments.ts:693-698`（`lastClick` / `clickPending`：否则说过「以后才走」的人被拉回名单、或进「点了链接」分组）；
  3. `returning-lead.ts:165-179`（`isTheirsActive` 与 `theirs.clicks`）；
  4. `returning-journey.ts:243-250`。
  它**不能**靠让 `engagementFromMetadata` 返回「无」来实现：没有行为标记的入站触点会被 `segments.ts` 当成「客户回话了」排进最高优先档、被 `day-list.ts:356` 当成客人动作重新点亮、被 `revive.ts:75` 当成真消息（F9、F18）。
- 超过宽限期的点击照现有规则处理（这是产品已定的规则：「几周前说的话，抵不过他现在正在看这件事」，`segments.ts:826-845`）。
- **不承诺「不改排序」**：全部客人页的排序由数据库函数按「最新触点」排、不看 metadata（F11），宽限期内的点击会让他在「最近动静」排序里靠前，这是正常的；「最近联系」文字由 F11 那张卡的修复决定。
- 不进「7 天最多几封」的计数（入站，F10）。
- **硬前置**（对 CTS 打开本功能之前必须全部做完并上线，实现里每一条都配一个用 `me_link` 点击行的测试，断言：宽限期内的行**不**让段位变成 `replied`、**不**让卡片重新亮起、**不**进「点了链接」分组、**不**当回头客）：
  1. 台账卡 `2026-10-29-crm-email-open-counts-as-last-contact`（F11）的修复上线，且**覆盖**：「最近联系」文字、「今天已处理」、**全部客人页的排序数据库函数**。
  2. 上面四处读模型的「宽限期点击」排除已上线。

### 3.9 失败时怎么办

| 情况 | 影响 | v0 做法 |
|---|---|---|
| 跳转入口整体不可用（服务挂、欠费停机、域名没解析、证书出问题） | **已经发出去的信**里的目录链接打不开；新发的信不受影响 | ①v0 **只跟踪目录一个链接**，其它链接直连；②**发信前探测入口健康**（`/r/healthz`，走一遍真实域名，1 秒上限、60 秒缓存），不健康就这一封发原始链接并记跳过——覆盖「域名没解析 / 证书过期」；③加存活监控；④服务整体停机时发信本身也停了；停机前已发出的信里的链接会失效——**已知残余风险**。加固选项（后续）：把跳转放到边缘节点（如 Cloudflare Worker + KV）。**触发条件**：任何一次因入口不可用被客人反馈，或单封信覆盖人数明显变大 |
| 数据库慢 / 挂 | 点击可能漏记 | 查库 1.5 秒超时后 302 到环境变量兜底地址（建议配成目录文件本身）；记录失败只记日志 |
| 生成专属链接失败 / 超时 / 匹配不上 / 复查不一致 | 这封信没有跟踪 | fail-open：发原始链接，回执 `warnings` 记 `tracked_links_skipped:<原因>` |
| 扫描器 / 杀毒软件 / 企业邮件网关预点链接 | 个别误报为真人点击 | 分类降级 + 24 小时内只记录不点亮；报表一律写「至少 N 位点击」，样本 <20 不下结论 |
| 链接过期 | 客人点到旧信 | 302 到链接记录里的 `fallback_url`，不报错页。**v0 没有撤销单条链接的手段**（删掉 label 只会让它落回快照目标） |
| 有人灌入口 | 拖慢同进程的后台 | 内存令牌桶（有表上限）+ 每条链接最多记 50 行 + 后台写入队列上限 + 处理函数只做一次带索引查询加一次设置读取 |

### 3.10 隐私与合规（不是法律意见）

- **收集什么**：点击时间、哪条链接、哪位客人（由专属链接对应）、设备粗分类。**ME 的库不存 IP、不放 cookie**；Render 等平台自己的访问日志可能记录 IP，按其保留期限（未查，见 §7）。
- **用途**：判断客人对目录是否有兴趣、决定谁先联系，以及汇总后改进邮件模板；不出售、不共享。
- **披露**：F22——隐私政策目前没写邮件点击跟踪。上线前在「Cookies and tracking technologies」下加一句，**建议英文**：*"Our emails may include links that let us see whether a link was clicked (for example, our catalogue download). We use this to follow up on information you have asked for and to improve our emails."* 措辞与是否需要法务意见由 PM 转法务（NZ Privacy Act 2020 的收集透明要求；我不替你做法律判断）。**隐私政策已上线是对 CTS 打开本功能的前置条件。**
- **只对咨询过的客人**：发信闸本来就只允许发给咨询过、且未标「别再联系」的人，本功能不放宽任何一条。已标「别再联系」的客人若点了旧链接：照常跳转，**什么都不记**（§3.5 第 5 步）。
- **删除与撤回**：见 §3.7 擦除通道。
- **一对一跟进信是否需要退订方式**（NZ 未经请求电子信息法）不属于本设计，但相关，列入 §7 交法务。

### 3.11 衡量（IMPACT）

Measure = 点击行；Check = 每份模板「带跟踪且真发出的封数（连回执 outcome=sent，排除 `warnings` 里有 `tracked_links_skipped` 的）」对「真人点击的客人数」；Tune = 目录放哪句、措辞、通话后信 vs 未接通信谁的点击多。样本 <20 不下结论。v0 先用只读 SQL / 脚本出数，面板后做。

### 3.12 与短信（P3b）、与发信设计的关系

- 共用：两张表、码的做法、跳转入口、真人判断、触点写入、设置块。**不在本设计里**：短信同意依据、退订词、落地页 / 表单回传（P3b 可以选「跳转入口」或「官网落地页回调同一个 `recordClick`」，写入形状一致）。短信渠道的触点标记键（对应 `email_clicked`）由 P3b 设计时补。
- **与发信设计 §4.4 / §4.7 的口径差异（要在批准本稿时同步修订那份文档）**：发信设计规定供应商（Resend）回报的打开 / 点击「只累计计数、不写触点」，因为那类事件是供应商判的、含苹果预读；本设计里的点击是 **ME 自己发的专属链接**，ME 自己判真人、绑定到具体链接，所以**真人点击写触点**（仍是意向信号，不算联系，且 24 小时内即时反应不参与「谁先联系」）。若某封 Resend 发出的信里放了 ME 专属链接，要**关掉 Resend 自己对这封信的点击跟踪**，避免链接被二次包装。

## 4. 复用声明与归属（平台化原则）

- **归属**：平台共享的「邮件 / 短信互动测量」基础设施（IMPACT 的 Measure / Check），不是新支柱、不是新能力线。
- **复用了什么**：触点表与它的幂等键（F7）、CRM 读模型与分组（F8）、发信闸的链接检查与句末标点规则（F4）、版本化发信设置（F5）、占位符体系（F6）、只增不改表与服务端角色 RLS 的做法（F25）、发信设计里已规划的「客户自己的域名 + 每人一个令牌」方向（F19）。
- **新增且平台共享**：两张表、跳转入口、域名隔离规则、真人判断、`link.*` 占位符、`planInRawBody / issueTrackedLinks / replaceRanges`、擦除函数。
- **行业层**：无。
- **客户层（CTS）**：域名 `go.ctstours.co.nz`、目录文件地址、`fallback_url`、`only_for`、隐私政策那句话——全部在设置 / 客户配置里，不进共享代码。
- **换客户测试**：换成地产客户（楼盘册子下载）、物流客户（报价单链接），共享代码不用改，只配 `host` 和 `destinations`；「目录下载」是 `title_zh` 配置，没有任何默认行为只对 CTS 成立。
- **换行业测试**：同上；真人判断名单是技术性的，与行业无关。
- **没有把客户名 / 客户 ID / 行业判断写进共享代码**。
