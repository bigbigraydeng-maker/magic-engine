## 0. 给 PM 的一页

**一句话**：销售发出的一对一邮件里，「目录下载」链接在发出的那一刻换成「这位客人专属」的链接（用 CTS 自己的域名）。客人一点，系统先记一笔「某某点了目录」，再立刻跳到真正的目录文件，客人几乎感觉不到。

- **客人看到的**：信里多了一条 `go.ctstours.co.nz` 开头的链接（域名最后定），点开和以前一样直接下载目录。
- **销售看到的**：客人的时间线上出现「点了《邮件主题》里的『目录下载』链接」。系统里本来就有的「点了链接、之后没人跟」客人分组会把他排进待跟进名单（目前由群发邮件的点击喂数据）。
- **为什么是点击不是打开**：苹果手机 / Mac 的邮件 App 会替客人提前下载图片，没看也显示「已打开」；有的邮件 App 默认不加载图片，看了也记不到。我们现在发的还是纯文字信，做打开跟踪得改成网页格式，不像一对一的私人来信。我们自己 10-29 就踩过这个坑（见台账 `2026-10-29-crm-email-open-counts-as-last-contact`）。点链接是客人亲手做的动作，准得多。
- **v0 不做什么**：不做「是否打开」；不动群发邮件（Mailchimp 那边本来就能看到打开 / 点击）；不改销售自己写的信里的任何链接；v0 只跟踪**目录下载这一个链接**，其它链接（全部团页面、团详情页）保持直连。
- **要你和别人做的事**（实现前）：①把最新版目录 PDF 放上官网，把下载链接给我；②CTS 域名管理员加一条域名解析记录；③Render 后台给服务加这个域名；④CTS 隐私政策加一句（法务确认）。三件套写法见 §6。
- **花钱**：不新增供应商，几乎为零（用我们自己的服务器）。
- **最大的风险**：跳转入口一旦打不开，客人点目录链接就下载不了（10-29 晚网站因欠费停了 4 小时 48 分就是例子）。所以 v0 只跟踪目录一个链接、监控入口、并写明「加固」的触发条件（§3.8）。
- **现在没有要你回答的问题**。你合设计稿之后，实现分两张改动单（先迁移后代码），都是 A 级，都要你回「合」。

## 1. 目标与不做

**目标**
1. 对「销售一对一发出的邮件」里被登记的链接（v0 = 目录下载），知道**哪位客人在什么时候点了**。
2. 点击成为 CRM 里已有的「意向信号」（不是「联系过」），不新建一套读模型。
3. 机制平台通用：同一套「专属链接」将来给短信（发信设计 §4.14 / P3b）和其它客户用；CTS 专属的只有域名、目标链接、文案，放客户配置。

**不做（本设计）**
- 打开跟踪（像素）。理由见 §0 与 §8-F；若以后要做，只当「参考计数」，不写触点、不排序（与发信设计 §4.7 一致）。
- Mailchimp / Resend 群发的打开 / 点击（它们自带，已有或已规划）。
- 销售自由写信里手敲的链接（不静默改写）。
- 落地页 / 表单提交回传（属短信 P3b 设计）。
- 点击后自动派活（不加 Inngest 函数，理由见 §3.6）。

## 3. 方案

### 3.1 总体流程

```
销售在抽屉里选模板 → 预览（显示真实目录链接 + 提示「发送时换成专属链接」）
   → 点发送 → 现有全部闸（含链接检查，按真实链接检查）
   → 【新】按设置里登记的目录链接，为这封信 + 这位客人生成专属链接（幂等）
   → 【新】把正文里等于「登记链接」的链接整体替换成专属链接 → 加页脚 → 建草稿 → 发出
客人点专属链接 → 【新】跳转入口 GET /r/{code}：
   判是不是真人 → 记一行点击 →（第一次真人点击）写一条客人触点 → 302 跳到目录文件
CRM：客人时间线出现「点了《主题》里的『目录下载』链接」；已有的分组 / 排序照常读
```

### 3.2 设置：`providers.tracked_links`（可缺省）

放进现有「发信设置」（版本化、只增不改、仅全局管理员能改）：

```jsonc
"providers": {
  "published_tours": { "...": "..." },
  "tracked_links": {                       // 整块可缺省；缺省 = 不跟踪
    "enabled": true,
    "host": "go.ctstours.co.nz",           // 专属链接用的域名，必须在 CTS 自己的域名下
    "ttl_days": 400,                       // 链接多久后失效
    "fallback_url": "https://www.ctstours.co.nz/tours",   // 链接失效 / 查不到时跳去哪
    "destinations": [
      { "label": "catalogue", "title_zh": "目录下载", "url": "https://www.ctstours.co.nz/…（待 PM 给）" }
    ]
  }
}
```

保存时的校验：`label` 为 `^[a-z][a-z0-9_]{0,30}$` 且不重复；`url` 与 `fallback_url` 必须 https 且主机在 `guardrails.allowedLinkHosts` 里；`host` 必须是 `allowedLinkHosts` 中某个域名的子域；最多 5 个登记链接；`ttl_days` 在 30–800。

> **借位说明**：`providers` 本意是「事实来源」，这里借它放链接配置。原因是 F5：顶层键是「一个不少一个不多」，往顶层加键要改写所有旧版本，而设置表是只增不改的，做不到；`providers` 是现有唯一「可缺省」的扩展点。
> **上线顺序要点**：必须先让解析器认识这一块（旧版本照常读），再保存带这一块的新设置版本。回滚时先保存一个**去掉这一块**的新设置版本，再回滚代码；否则旧代码会把带新块的版本判成「未知键」，整个发信功能按「读不出设置」拒发（安全但会停摆）。

### 3.3 模板里怎么写：`{{link.<label>}}`

- 占位符新增一族 `link.<label>`（与 `input.*` 同形，F6）。只许出现在**正文**，不许出现在主题；在三种选团方式（不选 / 选一个 / 选多个）里都可用。
- 渲染时解析成**登记的真实链接**；该 label 没登记或整块没开 → 当作「缺值」，这封信发不出去，并提示「目录下载链接还没配置」（宁可发不出，不发一封缺链接的信）。
- 顺带解决一个现存限制：`{{all_tours_url}}` 只能在选团的模板里用（`facts/published-tours.ts:275`），「不选团」的通用信目前只能手写链接；以后同样可以登记一个 `all_tours` label 来用。
- 预览、`rendered_sha256`、`final_sha256`、闸门检查看到的**都是真实链接**（F3）。

### 3.4 发送时换链接（`sendUnderLock` 里，门全过之后、加页脚之前）

```
planTrackedLinks(body, settings)        纯函数：用与链接检查相同的抽链接 / 归一化逻辑（F4），
                                         找出「整体等于某个登记链接」的链接（不是子串匹配：/tours 不会误伤 /tours/china/…）
issueTrackedLinks(...)                  写库：每个 (客户, 请求号, label) 一条，唯一键保证重试 / 孪生请求复用同一条
replaceLinks(body, issued)              把这些链接替换成 https://{host}/r/{code}
```

- **码**：14 位随机字符（密码学随机数，约 83 位），不含联系人编号、不含任何可推出信息；同一请求号同一 label 重试**复用同一条记录**，所以重发 / 孪生请求得到同一个链接。
- **失败策略（fail-open）**：生成专属链接出错时，**照常发出原始真实链接**，并在回执 / 审计的 meta 里记 `tracked_links: skipped(issue_failed)`。理由：跟踪是衡量功能，不该因它拦住一封销售信；但衡量时「没点击」必须能区分「没跟踪」。审查官可否决（§7-8）。
- **替换后不变量**：最终正文里的链接集合必须等于「替换前的链接集合，其中登记链接换成本次生成的专属链接」；多出任何别的链接就**拒发**（防实现错误凭空造链接）。
- **预览**：多返回一个 `trackedLinks: [{label, titleZh}]`，面板显示「这些链接发送时会换成专属链接：目录下载」。
- **审计与回执**：审计行存的是实际发出的正文（含专属链接，F2）；回执 meta 加 `tracked_link_ids`。`final_sha256` 仍是员工确认的文字（F3）。

### 3.5 跳转入口：`GET /r/[code]`（免登录，F12）

1. 码格式不对（不是 14 位字母数字）→ 302 到回退地址。
2. `HEAD` → 同样返回 302（让扫描器认为链接有效），**不记录**。
3. 查链接：找不到 / 已过期 → 302 到回退地址（按请求域名找到对应客户设置里的 `fallback_url`；域名不认识 → 纯文字 404），并计一次「未知码」日志。
4. 判断是不是真人（**不完美，结果只是「大概率真人」**）：
   - `Purpose` / `Sec-Purpose` / `X-Purpose` / `X-Moz` 头里带 `prefetch` 或 `preview` → `prefetch`；
   - UA 命中扫描器 / 爬虫名单（`bot`、`crawler`、`spider`、`Proofpoint`、`Mimecast`、`Barracuda`、`Slackbot`、`facebookexternalhit`、`curl`、`python-requests` 等；名单放代码里带测试，上线后按 `suspected_bot` 占比增补）→ `bot`；
   - 距专属链接生成不到 10 秒 → `suspected_bot`（人来不及点开邮件，扫描器通常在投递瞬间就取）；
   - 同一封信的多个链接在 3 秒内被同时访问 → `suspected_bot`（v0 只有一个链接，这条先休眠）；
   - 都不命中 → `human`。
5. 写一行点击（只增不改）：时间、分类、方法、UA 前 80 个字符、距生成的秒数。**不存 IP、不放 cookie。**
6. 仅当 `human` 且这个链接**还没有**真人点击记录时，写一条客人触点（§3.7）；客人已标「别再联系」则**照常跳转、照常记点击行、但不写触点**（不把他重新排回跟进名单）。
7. 302 跳到该链接登记的目标，`Cache-Control: no-store`。**目标只来自库里那一行**，不接受地址栏参数，所以不是开放跳转。
8. 第 5–6 步任何出错都**不挡跳转**（记日志、照跳）；整个入口给库的每次调用设 1.5 秒上限，超时就直接跳转（查不到目标则走回退）。

### 3.6 为什么 v0 不上 Inngest

CLAUDE.md §3 要求「跨步骤异步接力或外部副作用」默认上 Inngest。本设计的点击记录是**单次同步写库、无外部副作用**，下游（客人分组 / 排序）是**读时计算**，没有异步接力，所以按规则属例外。**替代回执**：点击表本身（每次访问一行，只增不改）。**恢复条件**：以后要在点击后自动做事（例如给销售发提醒、建待办），再加业务可读事件 `crm.email_link.clicked` 并走 Inngest，同时评估 Inngest 额度（10-30 为 41,992 / 50,000，见 F17 旁证）。

| `method` text、`seconds_since_issue` int、`ua_head` text（≤80 字） | 不存 IP |
| 索引 `(link_id, occurred_at)` | |

**客人触点（第一次真人点击写一条）**

```
contact_touchpoints: channel='email', direction='inbound', source='me_link', source_ref=<link.id>,
  occurred_at=点击时间, summary='点了《{email_subject}》里的「{title_zh}」链接',
  metadata={ email_clicked: true, tracked_link: <label>, tracked_link_id, request_id }
```

- 形状与群发邮件的点击行一致（F7），所以 `engagementFromMetadata` 与「点了链接、之后没人跟」分组（F8）**无需改动读模型**就能读到；`source_ref = link.id` + 既有唯一键（F7）保证「每个链接只记第一次真人点击」，后续点击只进点击表。
- 不进「7 天最多几封」的计数（入站，F9）。
- **硬前置**：F10 那张卡（「最近联系」把打开 / 点击算成联系）必须先修好并上线，再对 CTS 打开本功能；否则点了目录的客人会被算成「今天已处理」，反而从待跟进里消失。实现里加测试：一条 `me_link` 点击不改变「最近联系」和「今天已处理」。

### 3.8 失败时怎么办

| 情况 | 影响 | v0 做法 |
|---|---|---|
| 跳转入口整体不可用（服务挂、欠费停机、域名没解析、证书出问题） | 停机期间点目录链接的客人下载不了 | ①v0 **只跟踪目录一个链接**，其它链接直连不受影响；②给入口加存活监控（`/r/healthz` 一类，实现时定）；③**加固选项**（后续）：把跳转放到边缘节点（如 Cloudflare Worker + KV），ME 挂了也能跳，点击事后补记。**触发条件**：任何一次因入口不可用被客人反馈，或单封信覆盖人数明显变大。 |
| 数据库慢 / 挂 | 点击可能漏记 | 入口尽力跳转（查不到目标走回退），漏记只是少记，不影响客人 |
| 生成专属链接失败 | 这封信没有跟踪 | fail-open：发原始链接并在回执里记 `skipped` |
| 扫描器 / 杀毒软件预点链接 | 个别误报为真人点击 | 分类降级；报表一律写「至少 N 位点击」，样本 <20 不下结论（沿用发信设计 §4.14 的做法） |
| 链接过期 / 被撤销 | 客人点到旧信 | 回退到 `fallback_url`，不报错页 |

### 3.9 隐私与合规（不是法律意见）

- **收集什么**：点击时间、哪条链接、哪位客人（由专属链接对应）、设备粗略类型（UA 前 80 字）。**不存 IP、不放 cookie。**
- **用途**：判断客人对目录是否有兴趣、决定谁先联系；不出售、不共享。
- **披露**：F16——隐私政策目前没写邮件点击跟踪。上线前建议在「Cookies and tracking technologies」下加一句，**建议英文**：*"Our emails may include links that let us see whether a link was clicked (for example, our catalogue download). We use this only to follow up on information you have asked for."* 措辞与是否需要法务意见由 PM 转法务（NZ Privacy Act 2020 的收集透明要求，我不替你做法律判断）。
- **只对咨询过的客人**：发信闸本来就只允许发给咨询过、且未标「别再联系」的人，本功能不放宽任何一条。
- **保存期限**：v0 不自动删，满 12 个月复审（点击行很小）。

### 3.10 衡量（IMPACT）

Measure = 点击行；Check = 每份模板「带跟踪的发出封数」对「真人点击的客人数」（跳过 `skipped` 的）；Tune = 目录放哪句、措辞、通话后信 vs 未接通信谁的点击多。样本 <20 不下结论。v0 先用只读 SQL / 脚本出数，面板后做。

### 3.11 与短信（P3b）共用什么

共用：两张表、码的做法、跳转入口、真人判断、触点写入、设置块。**不在本设计里**：短信同意依据、退订词、落地页 / 表单回传（P3b 可以选「跳转入口」或「官网落地页回调同一个 `recordClick`」，两条路写入形状一致）。短信渠道的触点标记键（对应 `email_clicked`）由 P3b 设计时补，`engagementFromMetadata` 到时再扩。

## 4. 复用声明与归属（平台化原则）

- **归属**：平台共享的「邮件 / 短信互动测量」基础设施（IMPACT 的 Measure / Check），不是新支柱、不是新能力线。
- **复用了什么**：触点表与它的幂等键（F7）、CRM 读模型与分组（F8）、发信闸的链接检查与抽链接逻辑（F4）、版本化发信设置（F5）、占位符体系（F6）、只增不改表与服务端角色 RLS 模板、发信设计里已规划的「客户自己的域名 + 每人一个令牌」方向（F13）。
- **新增且平台共享**：两张表、跳转入口、真人判断、`link.*` 占位符、`planTrackedLinks / issueTrackedLinks`。
- **行业层**：无。
- **客户层（CTS）**：域名 `go.ctstours.co.nz`、目录文件地址、`fallback_url`、隐私政策那句话——全部在设置 / 客户配置里，不进共享代码。
- **换客户测试**：换成地产客户（楼盘册子下载）、物流客户（报价单链接），共享代码不用改，只配 `host` 和 `destinations`；没有任何一条默认行为只对 CTS 成立（「目录下载」是 `title_zh` 配置）。
- **换行业测试**：同上；真人判断名单是技术性的，与行业无关。
- **没有把客户名 / 客户 ID / 行业判断写进共享代码**。

6. 隐私政策措辞、是否需要法务意见。
7. 设置块借 `providers` 的位置（§3.2）是否可接受；备选「新建一张客户设置表」代价更大。
8. fail-open（生成失败照发原始链接）是否合适，还是应当拒发。
