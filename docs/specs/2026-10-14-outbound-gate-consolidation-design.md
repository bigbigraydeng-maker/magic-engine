## 0. 先说结论（PM 读这段就够）

1. **你说的那个口子还在，而且比想的更宽。** 9 月 16 日那条中文文案走的是「真人在门户里手打发送」这个入口：它**完全不过任何内容检查**，只要是登录的付费账号就能发任何字，「是不是 AI 写的」这个标记还是**发送方自己在请求里填**的（填 false 就是 false）。那次没发出去，只因为当时拿不到主页令牌。今天 CTS 的私信令牌是好的，同样的请求现在会发出去。
2. **不止这一个口。** 我逐个渠道查了 14 条能真发消息的路径，**没有一条在「发送函数里面」检查内容**；检查全在调用方，调用方自觉才有。其中 **CTS 评论自动回复现在就是开着的**（每小时跑一次，近三个月已自动发出 40 条公开回复，全是英文、没有中文），它的检查只认阿拉伯数字，中文写的「三千八」「保证出签」查不到。
3. **中文闸今天是空的。** 数字闸只认 `$3,880` 和 `2026-10-14`；禁谈话题和品牌红线是纯英文词表；唯一懂中文的那层只标记、不拦。
4. **修法一句话：让「发送函数」自己拒绝没有合法来路的内容。** 每次发送必须带「来路证明」——要么是一份已批准、过闸、正文没被改过的草稿；要么是代码里登记的固定模板；要么是真人账号当场发的（含价格/日期要二次确认）。三者都不是，发送函数直接拒，写不了审计、调不了平台接口。再加一个能识别中文价格、日期、承诺的扫描器，AI 写的话命中就**拦下**，不是只标记。
5. **分四步，每步合并前都要你回「合」。** 第一步先做中文扫描器（只会多拦，不会多发，最安全）。**修好之前新开关一个都不开；另有一个已开着的评论回复要你定关不关（§8 第 1 问）。**

## 3. 收口方案：发送函数自己验「来路」，fail-closed

### 3.1 原则

不改「谁在调」，改「**发送函数肯不肯发**」。三个会话发送函数（`sendReply` / `sendWhatsApp` / `sendMailReply`）和两个评论函数（`replyToComment` / `sendPrivateReply`）各自在**第一行**调用同一个 `assertOutboundAllowed(...)`；它抛错或返回拒绝，就既不写审计，也不碰平台接口。**默认拒绝，只有三种来路放行。**

### 3.2 来路（origin）三种，类型上必填

```ts
// src/lib/messenger/outbound-gate.ts  （新文件，平台共享）
export type OutboundOrigin =
  | { kind: 'approved_draft'; draftId: string }          // AI 草稿，已批准
  | { kind: 'fixed_template'; templateId: 'autoack_v1' } // 代码里登记的固定模板
  | { kind: 'human'; actor: HumanActor }                  // 真人在门户当场发
```

调用方**必须**传 `origin`（类型必填，漏传编译不过）。发送函数**不再接受调用方自报的 `usedAiDraft`**——审计里的这一列改成由 `origin.kind` 推出来。

| 来路 | 发送函数里怎么验（都是自己查库，不信传进来的东西） | 不满足就 |
|---|---|---|
| `approved_draft` | ① 按 `draftId` 读草稿行：属于该客户该会话、状态=已批准、是「线上模式创建」的草稿（见 PR 2568 §5.2 第 2 条的不可变演练标记）；② **要发的正文必须与草稿行里的最终正文逐字相同**（比对 SHA-256，不信「已批准」三个字就够）；③ **对最终正文重跑一遍确定性内容闸**（§4 的扫描器 + 该客户 policy 的已确认事实比对）；④ 用「已批准 → 发送中」的原子更新占住，防止重复发 | 拒绝；草稿标 `send_failed`，发待办（what/how/href） |
| `fixed_template` | 正文必须**等于**代码内登记的模板常量（精确相等）；登记表里的模板不得含数字、链接（由测试保证）；发送审计标明模板编号 | 拒绝 |
| `human` | 必须带 `HumanActor`：只能由 `requirePaidClientAccess` 签出（该函数返回里加一个模块私有的凭证对象，脚本拿不到）；正文过扫描器，**命中价格/日期/期限/承诺/签证形状 → 返回 `需要确认`**，调用方带上「我确认过：价格、日期」的显式确认后才放行；确认内容与命中的种类写进审计 | 没有 actor：拒；命中且没确认：返回 409 `claims_need_confirm` 并列出命中的种类 |

### 3.3 为什么真人这一档不直接拦死

员工回「团费 NZ$3,880，10 月 28 日出发」本来就是正常工作，拦死等于逼他们回 Business Suite 手打（那条路我们看不见）。所以：**命中就必须弹一次确认**，确认动作留痕（审计里有「确认了哪几类」「正文哈希」「谁」）。这一档的剩余风险是「拿着 PM 登录会话的脚本替他点确认」——代码拦不住，只能靠流程（记忆里已有「窗口不替 PM 点网页」）+ 事后对账（§3.5）。**PM 已答（2026-10-14）：`确认`，按本节办。**

### 3.4 审计表加三列（数据库改动，A 级，要 PM 点头）

`conversation_outbound_log` 加：`origin_kind text`（`approved_draft` / `fixed_template` / `human`）、`draft_id uuid null`、`body_sha256 text`；并让 `used_ai_draft` 改为由 `origin_kind` 生成（旧行保持原值，不回填）。`conversation_reply_drafts` 需要 `body_sha256` 与创建时阶段标记——**与 PR 2568 §5.2 第 2、4 条合成同一次改动**，不开两次。迁移走服务角色模板，写法照 CLAUDE.md §7（`FOR ALL TO service_role`）。

## 4. 中文价格/日期/承诺闸（识别并「拦下」）

### 4.1 放在哪、怎么接

一个**纯函数**扫描器 `scanOutboundClaims(text): ClaimHit[]`，放在 `comment-guardrails.ts` 里与现有英文扫描器并列，并让 `detectUnverifiableClaims`（评论渠道用）调用它，这样评论渠道自动拿到中文能力。三个接入点，**都用同一个函数**：

1. **F2 草稿生成时**：作为**通用闸**挂进 `runVerifierGates` 的列表（`id: 'content_claims'`），所有客户的 policy 自动带上，不用每个客户抄一份。命中且在该客户「已确认事实」里找不到匹配 → **blocked**（今天的语义闸只写 `semantic_flags`，不改结果，本闸改 `ok`）。
2. **发送函数里**（§3.2）：对 `approved_draft` 的**最终正文**再跑一遍；对 `human` 来路命中就要求确认。
3. **评论渠道**：`isPraiseReplySafe` 保留「不含任何数字」，再叠加「不含任何中文价格/日期/期限/承诺形状」；命中改用写死的安全话术（现有 `safePraiseReply`），不发 LLM 那句。

### 4.2 识别哪几类（每类都输出归一化后的值，便于和事实比对）

| 类 | 识别什么 | 归一化 | 处置（AI 来路） |
|---|---|---|---|
| **价格** | 数字（阿拉伯/全角/汉字/大写/混合）靠近币种或价格词：币种 `纽币 纽元 新西兰元 新币 新元 NZD NZ$ 刀 块 块钱 蚊 元 澳币 澳元 AUD 美金 美元 USD 镑 人民币 RMB ¥ ￥`；价格词 `价格 价钱 团费 费用 售价 报价 起价 起 每人 人均 单人 双人 单房差 定金 订金 押金 总价 优惠价 特价 立减 折`；另有 `3.8k`、`三千八`、`3千8` 这类口语 | 转成「数值 + 币种」 | 数值能在已确认价格集合里找到 → 放行；找不到或集合为空 → **blocked** |
| **日期** | `2026年12月31日`、`12月31日/号`、`3月18号出发`、`十二月三十一日`、`2026/12/31`、`12.31`、`下周三/下个月/这周末/国庆/春节/圣诞前`、`有效期至/截止/之前报名/前下单`、`周三出发` | 转成「（年）月日」或「相对表述」 | 绝对日期在已确认班期里 → 放行；其它（含所有相对日期）→ **blocked** |
| **期限/时效** | `15天14晚`、`十五日游`、`三个工作日内回复`、`24小时内` | 数值 + 单位 | **blocked**（第一版不放行，因为「回复时限」本身也是承诺；安全兜底话术里不含数字） |
| **承诺** | `保证 包过 包签 包出签 一定能 肯定能 百分百 100% 绝对 稳过 无条件 确保 承诺 全额退款 必定` | 词命中 | **无条件 blocked**（不看事实） |
| **签证/政策** | `签证 免签 落地签 NZeTA eTA` 与 `免/无需/不需要/可以/通过/拒签/出签/费用/办理` 同句共现 | 词共现 | **blocked**（第一版不核事实，一律转人工；已确认的政策事实回放留二期） |
| **名额** | `余位 余票 仅剩 剩N位 名额有限 满团 还有位置` | 词命中 | **blocked** |
| **最低价/优惠** | `最低价 最便宜 全网最低 免费升级 赠送 立减 优惠 折扣` | 词命中 | **blocked** |

**blocked 的含义**：这份 AI 草稿状态记为 `blocked`（今天已有这个状态），**不进待批准队列**，转人工待办，**不附一键发送的兜底话术（PM 已答 `只转人工`）**：待办只写客人说了什么、为什么被拦、直达会话链接，由员工自己回。**不是只加一个标记再放过去。**

### 4.3 归一化（先把「写法」折平，再识别）

1. NFKC：全角数字/字母/符号折成半角（`３８８０`→`3880`，`①`→`1`，`ＮＺ＄`→`NZ$`）；这一步现有代码已有。
2. 去掉零宽字符、软连字符、emoji 键帽修饰（`3️⃣8️⃣`→`38`）、数字之间的空白。
3. 汉字数字 → 数值：`零〇一二两三四五六七八九十百千万` 与大写 `壹贰叁肆伍陆柒捌玖拾佰仟`；支持「三千八百八十」「三八八零」「3千8」「三千八」（口语省略单位按「个位到千」补全，宁大勿小——不确定就当命中）。
4. `k/K/千/万/w` 乘数；千分位 `3,880` `3 880`。
5. **先剥掉链接**（链接另有白名单闸）再扫，避免追踪参数里的数字误杀。
6. 扫描器自身抛异常 → **按命中处理（拦下）**，不是放行（防「安全检查本身失败等于放行」）。

**威胁模型**：这是防**模型写错/人手滑**，不是防蓄意绕过。故意用拼音、图片、拆字绕过的不在范围；那一类由「发送函数验来路」（§3）和对账（§3.5）兜底。

### 4.4 误杀代价与降级

- **代价**：今天 CTS 知识库里可对客的事实是零条（PR 2568 §1.2），所以**第一阶段几乎所有带数字/日期的 AI 草稿都会被拦**，转人工，员工看到的是转人工待办（不带一键发送）。按近 30 天约每天 11 条私信估算，会多出来的人工量就是「含数字的那几条」，预期单日个位数。这是故意的：宁可让人回，也不让模型自己报价。
- **降级阶梯**（任何一档都不放宽「承诺/签证/名额」三类）：
  1. 每个客户的「已确认事实」补齐后，价格/日期两类能放行匹配项（这是主要的「变松」路径，靠补事实，不靠调正则）。
  2. 误杀过多时，只能收窄「期限/时效」一类（例如放行「24 小时内」这类**写在模板里**的固定句），**不接受**「调低灵敏度」「只标不拦」。
  3. 任何放宽都要重跑 §4.5 的全套反例，并写进该客户配置的变更记录。
- **校准办法（不发给任何人）**：把历史上员工真人发出的中文回复在本地跑一遍扫描器，**只输出计数**（命中几条、哪类），不输出正文，估计误杀率；再用 PR 2568 里将产生的演练草稿复核。
