# 客户内容底座·瘦身版范围（PM 2026-10-05 回「瘦身」，以本文件为准，覆盖 v0.3 里更大的部分）

起因：PM 问「是否没有过度开发」。自查：设计阶段偏重（约 200 万 token、零行代码落地），方案范围超出当前真实用量（CTS 工厂总共真发过 3 条 Reel；9 月 122 条社媒草稿、状态为已发布 0 条，状态字段是否被用未细查）；统一发布的「通行证+指纹」防不住 9/28 事故那类脚本直调接口。

## 现在做（小而有证据）
- 内容生成接口登录校验（已开窗口）；价格/日期识别补 NZD、元、中文日期（已开窗口）；客户资料包只读函数，不切换渠道（已开窗口）。
- Reels 品牌色读不存在的列（修）；Reels 发布路由 `caption` 覆盖与 `account_id` 归属校验（几十行）。
- 发布闸：**只把现有价格检查（`judgeOutgoingPost`）接进发出函数入口**，不做通行证/注册表/反向扫描。

## 缩小
- 产品价格团期：**只做 CTS**，官网抓取 + 核实日期 + 状态四态（正常/过期/抓取失败/没测成，只有正常放行）；**不做**快照写入审计、改价双人确认、新建表。
- 统一事实检查：**只接视频、广告、社媒三个真在发的渠道**，先 `dry_run` 统计再开硬闸。
- Remotion：**只做 CTS 的一两个模板接入出片机**，外部成片入口已砍；其余模板先不迁。
