# Reel 按日公开（批卡授权 → 到日自动转公开）设计 v0.2

- 日期：2026-11-04 · 窗口：97 号 · 风险级别：A（对外发布执行者、授权、定时函数）
- 上游：每周闭环设计 v1.1 §3 G11；发布这一环第一刀 `2026-11-04-social-publish-step-design-v0.2.md`（公开前事实复核，已合 #3597）
- 触发：PM 11-04「做按日公开」。读了：藏经阁第一、二、四、六、十三部经 + 第 55 号讲稿笔记。

## 1. 现状（11-04 核实）
- 每周闭环把下周 Reel 排好日子（`brief.weekly_pack.publish_on`），周卡把它们列出来给 PM 批。
- 周卡的「批」对 Reel 只有一个开关 `WEEKLY_PACK_REEL_GO_PUBLIC`：打开后，**批卡那一刻**用 PM 在卡上逐条预览得到的一次性口令，把整周 Reel **同时**转公开（`week-pack/lines.ts runReelLines` → `promoteReel`）；不按日期。口令 5 分钟过期，所以也没法「批了以后到日再用」。
- 转公开动作（`factory/publish/promote/`）本身齐全：前置检查、出镜授权、团目录复核、读回、抢占、三本账、首评、收尾。只是它要「管理员 + 预览口令」。
- Story 已有「批 = 发出授权（带内容指纹），到点由程序发」的成熟做法（`social/story-publish/`）。

## 2. 要做的（一句话）
**批卡时，按 PM 预览看到的每条 Reel 的内容指纹，记下一份「到日可公开」的授权；每天到点，程序只对「今天该发、授权还有效、内容没变、所有闸都过」的那几条，走现有转公开动作公开，并留回执；任何一项不满足就不发，并下发待办。**

## 3. 授权：批卡时写什么（不新增表）
- 写在每条 Reel 的流量记录 `payload` 里（转公开已经用这一行存预览槽和授权状态），新键 `scheduled_go_public`：
  `{ status: 'armed', publish_on, fingerprint, card_run_id, card_decision_id, authorized_by, authorized_at, expires_at }`
  - `fingerprint` = PM 在卡上预览这一条时预览槽里的指纹（`computeFingerprint`：视频、草稿文案、首评、审片时间、**团目录版本**）。没预览过的那条不授权（与现在一样要求先看）。
  - `expires_at` = `publish_on` 当天结束（新西兰时间）+ 1 天宽限；过期不再发。
  - 写入用现有乐观锁（`casPayload`），写不上就该条显示「没记下授权」，其他条不受影响。
- 只有新开关 `WEEKLY_PACK_REEL_SCHEDULED_PUBLIC='true'` 时批卡才写授权；与旧的「批卡即公开」开关互斥（两个都开 → 只按日，不立即公开）。
- 撤回：周卡已有「停掉没发的」入口（Story 用），Reel 同一入口把 `armed` 改 `revoked`。

## 4. 执行：每天到点做什么
- 新 Inngest 定时函数 `cloud-reel-scheduled-go-public`：每天新西兰 **18:00**（行业配方晚间时段；客户配置可改）醒一次，开关 `WEEKLY_PACK_REEL_SCHEDULED_PUBLIC` 不是 `'true'` 只写一行 disabled 回执。
- 找「`publish_on` = 今天（新西兰）且授权 `armed`、未过期」的 Reel，**每条一个步骤**，不重试：
  1. 重新跑转公开的全部前置（`buildContext`：状态、两张清单、草稿文案一致、红线、出镜授权、**团目录复核**）。
  2. 当场算出的指纹 ≠ 授权里的指纹 → 不发，授权改 `stale`，待办：「这条批过之后内容或团目录变了，请在周卡重新预览并批」。
  3. 全过 → 用**系统身份**（`system:week-card:<card_run_id>`）走转公开确认那一套（抢占 → 调平台 → 先流量记录后工单 → 三本账 → 首评 → 收尾），授权改 `consumed`，回执记请求号、视频号、公开时间、首评状态。
  4. 已经被人手动公开 → 只同步记录（同现有 sync_only），授权 `consumed`。
- 失败（平台报错 / 读回不一致）：授权 `failed`，不自动重试，下发待办（what / how / href 齐）。

## 5. 不做
- 不改转公开动作的规则，只给它加一个「系统身份 + 批卡授权」的入口（替代「管理员 + 5 分钟口令」）。
- 不做多平台（只 Facebook）；不做按小时排（每天一个时点）。
- #2817（草稿不记成已发布）是另一条线，与本设计不冲突；开开关前确认它已合并，避免三本账口径打架。

## 6. 开工十问
1. **IMPACT 段**：Act（按批准执行）；外环看 Story 晚间邀约后的私信与询价（下一刀读回）。
2. **确定 vs 模型**：全确定性；不调模型、不花钱。
3. **授权级别**：公开 = L3，**只认 PM 本人在周卡上逐条预览后的批**；程序只是到点执行，不扩权。内容或目录一变，授权自动失效。关 / 撤回永远人点。
4. **完成证据**：流量记录里的授权状态 + 转公开回执（请求号、平台视频号、读回的公开状态、首评）。
5. **谁验证**：生产（视频工厂）≠ 质检（马良 + 事实复核）≠ 批准（PM）≠ 执行（定时函数）；执行前全部闸重跑。
6. **学习写哪**：本刀不学习；`stale` / `failed` 的条目进下一刀错题本。
7. **考卷**：合成数据测试 + 变异（授权缺失 / 过期 / 撤回 / 指纹变 / 目录换版 / 授权被复用 / 两次执行并发）。
8. **PM 纠正落到哪**：撤回或重批都写进流量记录，台账卡记一笔。
9. **读不到 / 判不了**：读不到授权、读不到目录、读不到平台状态 → 不发、下发待办，不当成可以发。
10. **占 PM 注意力**：每周还是只批一次卡；只有「内容变了 / 发失败」才出待办。

## 7. 验证与试跑
- 单测 + 变异（见第 7 问）；集成：内存版库 + 假平台，从批卡写授权到定时执行公开走完整链路。
- 当场试跑：开关保持关；手动发一次执行事件（演练模式：全部检查照跑、到「调平台」前停下），对 CTS 下周第一条（11/9）出回执给 PM 看；开开关是 PM 的决定。

## 8. v0.2：设计复审并入（子牙 + 魏征，各 5 条必改，结论一致）
以下条款**替代** §3–§4、§7 中与之冲突的写法。

### 8.1 批卡时怎么写授权
- 每条 Reel 都走转公开现有的口令校验 `checkToken`（同一管理员邮箱的预览槽、口令哈希对得上、没过期、没用过、是这张工单），批卡的人必须过全局管理员检查（`promoteReelGated`；设计稿说的「PM 本人」在代码里 = 全局管理员名单，写明）。
- 校验、标口令已用、写 `scheduled_go_public`，在**同一次**乐观锁写入（`mutatePayload`）里完成。
- `authorized_by` 记批卡管理员邮箱；执行时另记 `executed_by: system:week-card:<run>`，不覆盖。
- **授权指纹不含团目录版本号**（CTS 近 14 天发过 13 版目录，含版本会让几乎每条授权失效）；批准时与执行时的目录版本都记进回执。执行前照样当场重跑团目录复核，必须通过——闸不放松。
- **授权绑定发布日**：`scheduled_go_public.publish_on` = 批卡时 `brief.weekly_pack.publish_on`；没有发布日或日子无效的 Reel **不授权**，卡上直说「没排日子，不会按日发」。

### 8.2 到点怎么执行
- 定时函数每 30 分钟醒一次（`TZ=Pacific/Auckland`，`retries: 0`，同一客户串行），按客户配置的发布时点（缺省 18:00 新西兰）判断「到点没有」；登记进定时任务登记表。
- 找「`publish_on` = 今天且已到点、授权 `armed`」的条目；同一天里多次醒来，所以碰上部署窗口也能在当天补上。
- **`publish_on` 早于今天仍是 `armed` → 改 `missed` 并下发待办**（不在 PM 没批过的日子补发）。
- 每条一个步骤，步骤里自己兜住错误，一条出错不影响其他条。
- **核授权、抢占、改状态在同一次乐观锁写入里**（新纯函数 `checkGrant(最新 payload)`：`armed`、指纹 = 当场算的、授权日 = 工单当前发布日 = 今天、未过期、`authorized_by` 现在仍是全局管理员）→ 同时写 `claimed` + `attempt_id`。撤回与执行抢的是同一行同一把锁，先到先得。失败释放时同一次把授权改 `failed`。
- 系统入口 `runScheduledPromote` 是单独导出的函数，**不接网页接口**；转公开接口仍只收 `confirm` / `preview_token`。触发事件只许带客户、日期、是否演练，不许带工单号或「强制」字段。
- 抢占后没收尾（`claimed` 超过租约）→ 读回平台：已公开走「只同步记录」，未公开标「结果不明」并下发待办。
- 有人已在 ME 里手动转了公开（`promote_authorization` 已 `consumed`）→ 授权标 `consumed_manual`，不出待办；有人在 Facebook 上手动公开 → 只同步记录，不比指纹。

### 8.3 撤回与重批
- 撤回按客户查所有 `armed` / `stale` 的授权，**与哪一周、Story 读不读得到无关**。
- 周卡页面加一块「已授权、还没公开」：每条显示发布日、谁批的、状态；可单条撤回；`stale` 的可单条「重新预览并授权」（走同一套口令校验）。
- 周卡文案：按日公开开关打开时，卡上写「批了之后按每条的日子在新西兰 18:00 公开」，不再写「批了立即公开」；两个开关同时开时只按日。

### 8.4 演练与试跑
- 演练只跑 `buildContext` + `checkGrant`，除运行记录外不写任何东西（不留抢占、不盖调用时间）。
- 前提：每周闭环写库已于 11-04 打开，11-05 08:30 首次真实排期写入 `publish_on`；试跑在那之后对 CTS 11/9 那条做演练并出回执。11-04 前生产库 26 条已过审 Reel 都没有 `publish_on`。
