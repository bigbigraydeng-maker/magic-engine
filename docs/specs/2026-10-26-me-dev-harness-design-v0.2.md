# ME 开发总控台（harness）设计稿 v0.2

> 状态：只设计，没写代码。来源：PM 2026-10-26 看了 NextLoop 截图，要一套 ME 自己的版本。
> 台账：`docs/ledger/2026-10-26-me-dev-harness-design.md`
> 前作：`docs/specs/2026-09-24-harness-ledger-v0.md`（台账本身）。本稿是它的「一屏汇总」层，不改台账规则。
> v0.1 → v0.2：子牙（架构）+ 魏征（挑刺）各审一轮，必改项全部吸收，见 §8。

## 0. 一句话

**一张每天自动刷新的总控页：只列最近 3 天在干活的窗口，每个窗口三个点（开了 PR / 合进去了 / 台账验过没），外加一栏机器真能抓出来的撞车——两个开着的 PR 在改同一个文件。不新造领卡、不改台账规则、不碰 GitHub 检查。**

## 1. 为什么要做（现状数字，2026-10-26 实查）

| 现状 | 数字 | 后果 |
|---|---|---|
| 窗口契约（`~/.claude/window-discipline/briefs/`） | 610 张（593 张按会话命名 + 17 张旧格式）；最近 3 天动过的只有 21 张 | 只在开窗口那一刻读一下，没有地方汇总；绝大多数早已不活跃 |
| 侧栏窗口 | 14 个分组合计 400+ 个 | 已合并 PR 的窗口大量没归档；无编号窗口混在里面 |
| 窗口编号计数器 `spawn-counter.txt` | 停在 92 | 实际编号已用到 122，编号靠人记 |
| 台账卡 | 1091 张：decided 651 / done 384 / verified 51 / failed 5 | 不到 5% 验过；651 张「决定了没做」里 573 张是 10 月的 |
| 唯一写入者 | 只写在 CLAUDE.md §5 | 没有程序检查两个窗口是不是在改同一批文件 |

前作的结论仍然成立：**变成程序的防护起效了，写成文字的没起效。** 所以 v0.2 只保留程序真能判断的东西，砍掉只能「提醒」的部分。

## 3. 设计

### 3.1 窗口列表：只列活跃的

- 数据来源：桌面应用的会话列表和侧栏分组。**这两样本机脚本读不到**，只有 Claude 会话里的工具能读，所以由每天的定时任务（§3.5）去取，存成一份 JSON 交给汇总脚本。
- 只列：最近 3 天有活动、而且分支不是 `main` 的窗口。其余在页底写一行总数（「另有 N 个不活跃窗口」）。
- 每行：编号（没有就写「无编号」）· 侧栏分组 · 风险级 · 三个点 · 最后活动时间。

### 3.2 三个点：全部读现成数据

| 点 | 含义 | 从哪读 | 判定 |
|---|---|---|---|
| ① 开了 PR | 窗口分支上有 PR | 会话列表自带的 PR 号和状态 | 有 = ●；检查项 `Risk gate` 红 = ◐ |
| ② 合进去了 | PR 已合并 | 同上 | 已合 = ● |
| ③ 验过了 | 这个 PR 写的台账卡验没验 | PR 改动里的卡（`docs/ledger/*.md`）→ 卡的 `status` | 全部 verified = ●；有 failed = ×；done 过了 `verify_by` = ◐ |

- 判级读 `Risk gate` 这一检查项的结果，不读评论；要读评论里的 `me-dev-gate` 标记，必须只认 `github-actions[bot]` 写的，且绑定当前 head。
- 一个 PR 写了多张卡时，按最差的那张算。没写卡（调研窗口、纯文档）显示「—」，不算红。
- 窗口没有 PR：三个点都画「—」，不当成问题。

### 3.3 撞车检查：两个开着的 PR 改了同一个文件

这是 v0.2 唯一的新判断，也是唯一能真正抓到「唯一写入者」被违反的办法：

- 列出所有开着的 PR 和它们改动的文件，同一个文件出现在两个以上 PR 里就列出来：文件 · 哪几个 PR · 各自属于哪个窗口。
- 排除公共台账目录 `docs/ledger/`（每张卡一个文件，不会撞）和锁文件这类必然共改的生成物（排除清单写在脚本里，带测试）。
- 只显示在页面上，不进今日待办，不拦合并。跑两周后看真实撞车次数，再决定要不要做成必过检查（那要改 `.github/`，属于 A 级）。

### 3.4 建议归档

PR 已合并 + 3 天没动的窗口列成一栏。只建议，不自动归档。

### 3.5 刷新和发布

- **汇总脚本** `scripts/harness/snapshot.mjs`：纯只读，不调大模型。输入是定时任务给的会话 JSON，加上 `gh` 查开着的 PR 和改动文件、读 `docs/ledger/`。输出一份 JSON 和一页 HTML。
- **只由定时任务触发，不挂在开窗口的报到脚本上。** 报到脚本今天触发了 876 次，最多一小时 161 次，挂上去会把 GitHub 查询限额打穿。脚本自带单实例锁，10 分钟内重复调用直接返回上一份结果。
- **定时任务**：先每天一次（新西兰时间早上 8:30），任务里做三件事：读会话列表和侧栏分组 → 跑汇总脚本 → 发页面。建好立即手动跑一次，实测这一次花多少钱，写进台账卡；超过 1 美元一次就改成两天一次。
- **不往 GitHub 推任何东西**：只读，不提交，不触发 Actions 检查费。
- **页面放哪、带不带客户信息**：
  - 全量版（含窗口完整标题）只存本机文件，在 PM 这台 Mac 上打开。
  - 手机版发到 PM 自己的私有 claude.ai 页面，**只放编号、侧栏分组、风险级、点、时间**，不放窗口标题、契约原文和金额。实测 610 张契约里 270 张写着客户名或金额，标题里也常有，所以手机版一律不带。分组名（如「CTS」）本来就是 PM 自己起的侧栏名，保留。

## 4. 分刀

| 刀 | 做什么 | 风险级 | 文件 | 谁写 |
|---|---|---|---|---|
| 1 | `snapshot.mjs`：三个点、撞车检查、建议归档、两种 HTML（全量 / 手机版）+ 测试 | C | `scripts/harness/` 新目录 | DeepSeek |
| 2 | 定时任务：取会话和分组 → 跑脚本 → 发手机版页面；当场跑一次并记花费 | C | 本机定时任务 | Claude Code（要用桌面应用的工具，DeepSeek 用不了） |
| 3 | 修编号发号器：抢不到锁时报错退出，不再照写；计数器校准到当前最大编号 | C | `~/.claude/window-discipline/next-window-no.sh`（不在仓库） | Claude Code |

当场试跑：刀 1 用真实数据跑一次，截图给 PM；刀 2 建好立即手动运行一次，打开手机版页面核对窗口数和侧栏对得上；刀 3 同时开两个进程领号，确认拿到不同号码。

## 5. 不做

- 不做领卡字段 `holder`（§8 第 1–3 条）。
- 不做 GitHub 必过检查（等撞车数据）。
- 不另做台账看板（已有「开发欠账」栏）。
- 不改今日待办邮件。
- 不做 ME 后台页面（数据在 PM 这台 Mac 上，服务器读不到）。
- 不自动给窗口编号、不自动改标题（报到脚本做不到，见 §8 第 6 条）。
- 不接 Grok：页面是资料，不是指令。

## 7. 资源优先级（ENGINEERING_QUALITY_GATES §11）

按 §11：频率 高（PM 每天在 400 多个窗口里找活）/ IMPACT 中（开发自己的「检查」环节，只有不到 5% 的卡验过）/ 收入 低（客户看不到）→ **P2**。P0 仍是社媒 + 广告 + CRM，本设计排在它们后面。

## 9. 复用声明（Reuse Statement）

- **复用**：桌面应用的会话列表和侧栏分组、`Risk gate` 检查结果、台账格式和夜巡、「开发欠账」栏、编号发号器、PR 3157 切换层（刀 2）。
- **新增、平台共享**：`scripts/harness/snapshot.mjs`（ME 内部开发工具，不是产品能力）。
- **行业专属**：无。**客户专属**：无。共享代码里不出现客户名或客户编号；手机版页面不带窗口标题。
- **层级判定**：内部工程治理工具，挂在已有的台账 + 合并闸底座上，不新增能力线，不登记平台候选。实现落点与判定一致。
