## 1. 先查了什么（不重造）

- 「每条广告」标签（`entity-tree-panel.tsx` + `entity-tree/build.ts`）**已经**列出 系列 → 广告组 → 每条广告 的近 7 天花费、留资、每条成本、链接点击率、开关状态。所以这一刀是**在这张现有表上补缺**，不另做新表。
- 缺的 5 样（对照方案第 5 刀原文）：
  1. 结果列写死「留资」。NAL 三个在投组全是 WhatsApp 开聊组，表上一律显示「留资 0」——错。要按**广告组自己的结果种类**（`rules/core-metric.ts`，跟第 1 刀成绩单同一口径）。
  2. 没有「还不能比」：没有按点击数的门槛。手册 E-02③ 说门槛按点击数、由行业层给；旅游 ⑧ = 每条至少 150 次点击（PM 10-28，候选）。其他行业没给 → 显示「门槛未定」，不编数字。
  3. 没有「参考，不是因果」（C-19）。
  4. 没有「前后不全可比」：广告组每日快照里存了受众（`included_audience_ids` / `excluded_audience_ids` / `targeting_summary` / `advantage_audience`），窗口内变过就标出来。**表单中途换**：广告快照里没有表单编号，查不出来，页面上明说。
  5. 旅游「同团、同出发档期才比」：库里**没有**「这条广告推哪个团」的结构化记录（查过：没有任何广告/系列表带团字段）。只按 CTS 广告名的写法去拆 = 把单客户习惯写进共享代码，不做。改为旅游行业显示一句提醒，请人看广告名。
- 真数据例子（CTS 近 7 天，组 C 素材测试）：4 条素材链接点击 65 / 18 / 7 / 3，只有第一条接近门槛。今天的表会让人以为后三条「不行」。

## 2. 改什么

| 文件 | 改动 | 层级 |
|---|---|---|
| `playbooks/types.ts` + 5 份剧本 | 加两个**参数**：`creativeCompareMinLinkClicks: number \| null`（旅游 150，其余 null）、`creativeOfferNoun: string \| null`（旅游「团和出发档期」，其余 null） | L2 参数（剧本只收参数和词，这两个都是） |
| `entity-tree/creative-compare.ts`（新，纯函数） | 每条广告：按组的结果种类取结果数、算单价、判「能不能比」；广告组：窗口内受众有没有变、哪天变的 | 共享 |
| `entity-tree/build.ts` | 快照行多带目的地 / 优化目标 / 受众签名；广告组节点多带结果种类、受众变动日；广告节点多带素材判定 | 共享 |
| `entity-tree/load.ts` | 多读这几列；快照回看天数至少覆盖整个窗口；读客户行业和主结果（只读） | 共享 |
| `entity-tree-panel.tsx` | 表头按结果种类写「留资 / 开聊」；加「链接点击」「投放天数」「能不能比」三列；每个组上面几行说明 | 共享 UI |

「能不能比」按顺序判，先中先停：

1. 这个组不按留资 / 开聊投（播放量、触达等）→「不比单价」
2. 组里有花费的广告不到 2 条 →「组里只有这一条」
3. 行业没给门槛 →「门槛未定」
4. 这条广告的数据没存链接点击 →「点击没记，判不了」
5. 链接点击 < 门槛 →「还不能比（18/150）」
6. 否则 →「够数了」（**不写「赢了」**，只是可以拿来看）

点击用**链接点击**（Ads Manager 上的 Link clicks），不用「全部点击」：后者含点赞、展开，数量约是链接点击的 2.5 倍，用它会让样本看起来比实际够。这是更保守的选法。
