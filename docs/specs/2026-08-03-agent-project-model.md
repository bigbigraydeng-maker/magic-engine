# 中介 · 楼盘 · 开发商 三者怎么建档（2026-08-03 PM 拍板）

## PM 的原话

> 我觉得我们的客户就是 Roman Hu，开发商出发要做品牌 branding，否则楼盘销售都应该归属到 Agent 下面的，
> 然后在这里我们为 agent 创立单独的楼盘 master brief、广告等策略。
>
> 但是这个功能仅针对地产中介，中旅的 ME 后台不应该出现任何和地产有关的按钮和 page（现在是有的）。
>
> 这两单都是我们对 Roman 负责，但是 invoice 是我们和楼盘开发商直接发。

---

## 定下来的模型

**客户 = 中介（Roman Hu）。楼盘不是客户，是中介名下的项目。**

| | 是什么 | 建档层级 |
|---|---|---|
| **Roman Hu** | 我们服务的对象，我们对他负责 | **客户** |
| 30 Kiteroa | 他手上的一个楼盘 | Roman 名下的**项目** |
| Parkhomes | 他代理的一个开发商项目 | Roman 名下的**项目** |
| 楼盘开发商 | **开票对象**，不是服务对象 | 项目上的一个字段 |

**唯一的例外**：开发商自己要做品牌 branding（不只是卖房），那它就是独立客户 —— 因为那时要服务的是
开发商的品牌资产，不是中介的销售业绩。

**每个楼盘各有一份 master brief、广告策略、素材** —— 楼盘之间的卖点、目标人群、价格带完全不同，
共用一份 brief 出来的内容必然含糊。

---

## 为什么不是「每个楼盘一个客户档」

因为那样会把**服务关系**和**资产隔离**混成一件事：

- 服务关系上，我们只对 Roman 负责一个人，报告、沟通、续费都是他
- 资产隔离上，Kiteroa 的实拍绝不能进 Parkhomes 的广告（两个开发商是竞品）

拆成两层就都成立：**客户层管服务与账，项目层管资产与隔离。**

## 已做：行业专属功能不再串台

PM 点名的 bug —— 中旅后台出现地产按钮。真实缺陷是导航把「房子」和「行程单」挂给**每一个客户**，
所以旅行社有地产工具、建材客户有旅游行程单，**两个方向都错**。

修法（`lib/clients/industry-features.ts`）：

- 按行业决定可见性，**默认隐藏**。行业字段目前 15 个客户是空的、还有一批是自由文本
  （`Travel — Tour Operator`、`SPC/hybrid flooring wholesale (B2B trade)`），
  默认显示的话任何没填行业的客户都会看到全部行业功能 —— 正是这个 bug 的形态
- 归一化下划线/长破折号：库里存的是 `real_estate`，而现成的行业字典按空格匹配 `real estate`，
  直接用**匹配不上**
- 按钮和页面**两边都挡**：藏掉导航但网址还能敲进去，不算修好

挡下时的提示写的是「这个功能不适用于你的业务」+ 怎么打开（去设置里填行业），
不是「无权访问」—— 那会让人以为是权限出问题了。
