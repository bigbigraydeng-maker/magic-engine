## 1. 现状（我 10-15 读代码核的，不是凭记忆）

同一个「社媒日常」，现在散在客户页「内容生产」栏的 **至少 8 张卡**（`src/app/dashboard/clients/[id]/page.tsx` 约 640–660 行）：推广计划、社媒矩阵、推广活动、每日计划、Story 自动发布、视频工厂、内容工厂、Launch Hub、内容生产包，另有 `ContentHub.tsx` 里两个快捷入口。PM 要看「这周社媒发什么、卡在哪」，得点开至少三个页面再自己拼。

**一个已经踩过的坑，设计必须避开**：库里的状态可能和平台上真实状态对不上（10-13 两条 Reel 人工从草稿转公开，库里仍写「草稿」）。总览页如果只读库里状态，会重复这个误导——所以总览格子的状态要标明「库里状态」，平台核对结果另列（见 3.2）。

## 2. 目标与不做

**目标**：PM 打开一个页，10 秒内回答三件事——①这周每天 Post / Reel / Story 排没排、过没过审、授权没授权、发没发；②现在谁卡在哪、该我点什么；③点一下去对应的老页面干活。

**不做**（本稿明确排除）：
- 不新建、不改发布 / 授权 / 开关能力；所有「动手」按钮仍在老页面。
- 不新建表、不迁移、不新增 cron。
- 不替代每日计划页、Story 页、视频工厂页、推广计划页；它们保留，入口页只是一扇门。
- 不展开成每日计划编辑器（115 推广计划里「社媒展开成每日计划」是它那边的事，不在这页）。
- BGM / 内容配比体检，**第 1 版不做**（只在文档里人工核，见 `docs/clients/cts/2026-10-15-feed-variety-rules-and-reorder.md`），第 3 步再评是否值得做成页面。

## 3. 设计

路径：`/dashboard/clients/[id]/social`，标题「社媒日常」。客户页「内容生产」栏里的 8 张卡**不删**，在最前面加一张「社媒日常」主卡（其余卡片保留，等入口页稳定后再讨论收纳）。

### 3.1 页面结构（从上到下）

1. **头条一句话**：本周（周一到周日，客户本地时间）排了 X 条、已发 Y 条、卡住 Z 条；Z>0 时变橙色。读不到数据时写「本周看不清：<谁来补、点哪里>」，沿用推广计划页同一写法。
2. **「待你动手」栏**（最多 5 条，每条带 what / how / href 三件套，沿用 `src/lib/pm-todo/manual-items.ts` 做法）：
   - Story 授权将在 48 小时内到期 / 已到期；
   - Reel 在审 N 张，点这里去视频工厂（按客户过滤）；
   - 每日计划最近一份已覆盖到的日期 < 今天 + 3 天（「计划没排」）；
   - Meta 主页发布授权缺失 / 已过期；
   - 库里状态与平台对不上（3.2 的第二步）。
3. **本周 7 天格子**：行 = Post / Reel / Story，列 = 周一到周日。格子里是**库里状态**的一个小标签：未排 / 已排 / 已审 / 已授权 / 已发 / 错过 / 被拦；点格子跳到对应老页面的对应条目。
4. **四张入口卡**：每日计划（Post / Reel）、Story 周包、视频工厂（带 `?client=`）、推广计划（社媒栏）；每张卡上一行数字（待办 N）。
5. **规则提示栏**（只读文字）：该客户当前生效的发布规则（人工 / 自动、对客自动发送安全前置状态、无紧迫话术、BGM 与配比规则链接）。第 1 版是静态文字 + 链接。

### 3.2 数据从哪来（全部是既有的只读来源）

| 页面块 | 数据 | 现有来源 | 新增 |
|---|---|---|---|
| Post 格子 | 每日计划槽位与审核 / 授权 / 回执 | `social_plans` + `daily_plan_auto_publish_*`，读取函数已在 `src/lib/campaign/` | 一个**只读汇总**函数 |
| Story 格子 | 周包条目状态 | `story_packs` / `story_items`，读取函数 `src/lib/social/story-lite/list.ts` | 复用，不新增 |

### 3.3 与 115 推广计划页的对接

推广计划里的「社媒栏」不展开社媒细节，只放一个按钮「去社媒日常」，链接 `/dashboard/clients/[id]/social?week=<该计划那一周>`。入口页读 `week` 参数定位周；115 不用知道社媒内部。**约定**：115 只依赖这个 URL 约定，不 import 入口页代码。

## 5. 风险与反例（给审查者）

1. **「库里状态」误导**：已在 1 节与 3.2 写明，第 2 步前所有格子标注「库里状态」。
2. **谁看得到**：Story 页仅全局管理员，入口页同级别；不对付费客户开放（客户侧页面另议，本稿不涉及）。
3. **与老页面重复**：入口页只读 + 跳转，老页面是唯一的「动手」处；不会出现两处授权。
4. **多客户**：页面按 `clientId` 取数；East Inter / NAL 没有每日计划或 Story 时，对应格子显示「这个客户没有这条线」，不报错。
5. **不新增能力线的证明**：没有新表、没有新 cron、没有新发布路径；接口是只读聚合。若审查认为聚合函数应属某个已有模块，放进该模块，不放新目录。
