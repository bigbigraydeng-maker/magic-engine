## 2. 目标与不做

**目标**：PM 打开一个页，10 秒内回答三件事——①这周 Post / Story / Reel 各是什么情况（**按线分别报，不求总和**）；②现在谁卡在哪、该我去哪里点；③点一下去对应的老页面干活。

**不做**：不新建 / 改发布、授权、开关；不新建表、迁移、cron；不新建 `/social` 路径、不新建第二个汇总接口；不替代老页面（「动手」按钮只在老页面）；不做 BGM / 配比的自动「拦截」，只做**只读提示**。

## 3. 设计

### 3.1 入口：改名 + 主卡
- 每日计划页 `?tab=overview` 的标签名和客户页新增主卡都叫「**社媒日常**」；点主卡直达该标签。
- 客户页其余 8 张卡**不删**，等稳定后另议收纳。
- 115 推广计划页社媒栏的按钮链接到 `/dashboard/clients/[id]/daily-plan?tab=overview`；第 2 步补上 `week=` 后再带周参数（115 只依赖这个 URL 约定，不 import 页面代码）。

### 3.2 页面块（在 `WeekOverviewPanel` 之上 / 之下增加，不另造数据）

1. **头条：按线分别报，不求总和**：`Post a/b · Story c/d · Reel 在审 n`。每个词的定义写死：
   - 「排了」= Post：每日计划槽位有内容；Story：周包里有该条目；Reel：**没有计划日**，只报「在审 n / 库里记为已发 m」，单独一行，**不进周格子**。
   - 「库里记为已发」= Post：`publish_meta` 有回执；Story：`LiteItemStatus` 为 SENT；Reel：`published_ref` 有值。**页面文字一律带「库里记为」，不出现裸的「已发」**；Reel 有回执但没平台核对时写「平台状态未核」。
   - 「卡住」= Story：被拦 / 已过时间仍待发；Reel：在审超过 3 天；Post：未接入 / 没授权。
   - Story 当天时间已过但仍是待发，**当场本地算出**显示为「已过点，没发出（库里仍是待发）」。
2. **本周格子**：Post / Story 沿用 PR 2548 面板；**周的定义**：周一到周日，**按新西兰日期**（`page-text.ts` 现有函数）；第 1 版注明，不承诺客户本地时间；跨周界要有测试用例。
3. **「去哪里点」栏（导航，不叫待办，不进 `manual-items`）**：**只读**今日待办里已有的条目，按客户过滤（`src/lib/pm-todo/story-lite-items.ts`、`meta-token-health-items.ts`、`platform-connection-items.ts` 已有 Story 没发出去 / 不确定、Meta 令牌与连接健康），另加两条本地算出的：Reel 在审 n 张、每日计划最近一份覆盖到哪天。**不另造判据**；「库里与平台对不上」第 2 步前算不出，**不挂空条目**。
4. **只读提示行（回答 PM 的原始诉求「刷起来重复」）**：本周 Reel 里同一首 BGM 出现 N 次（读 `brief.remotion.props.musicFile`）、价格屏 Reel 占几条。只提示，不拦；规则全文见 `docs/clients/cts/2026-10-15-feed-variety-rules-and-reorder.md`。
5. **开关状态栏（只读）**：Story 发布「真发 / 演练」、Reel 全局开关「真发 / 草稿模式」。读不到就写「读不到」，不省略（PM 看到「已授权」不能把演练当真发）。

### 3.3 没有这条线的客户
「有没有这条线」必须来自**显式配置**：Story 是否有过授权包、每日计划是否绑了推广活动、客户是否有视频工厂工单。查不到 ≠ 没有这条线，更不能推成「没排」。没有这条线的客户，该线显示「这个客户没有这条线」，头条**不亮橙色**；配置了名额但没配时显示「名额未配置」，不算成 0。

### 3.4 权限与数据
接口沿用 PR 2548：`requireGlobalAdmin`，`clientId` 取自路径，先过 `isUuid` 与客户访问检查；**加一条测试：非全局管理员调用返回 403**。不新增表。**第 2 步接入 Post 时，数据只能经这同一个鉴权入口读，不得走每日计划页那条「登录管理员」的低权限路径**，以免偷偷降级权限。

### 3.5 补充约定（魏征第二轮）
- 「去哪里点」栏每一类先判「这个客户是否启用了这条线」，**没启用整条不出现**；只有「启用但没排」才算卡住。
- 名额沿用 PR 2548：「用了 a/b」，未配置写「名额未配置」，不写 0。
- Story 视频的 BGM 曲目目前库里没有字段（先记在周包文档 / 出片单里）；入口页**不查** Story 视频 BGM 重复，字段补上之前列为前置，不是第 1 版内容。
- 平台核对列（第 3 步）依赖的 88 号核对回执已随它收尾；第 3 步要么改读 Meta 读接口（需另评令牌读取），要么由例行任务写回执，**不在本稿承诺**。

## 8. 发布前清单（YouTube Shorts / Facebook / Instagram）——PM 10-16 要求，并入本入口一起做

**起因**：有窗口发 YouTube Shorts 时漏了上传自定义封面（本地生成了封面帧但没上传，平台自动选帧，煎饼封面食物不突出）；三条封面也没统一小标识 / 字体 / 配色。PM 问「AI 真的记住不犯同样错误吗」——**不能靠记，要靠强制清单**：能机器检查的做成发布前闸，不能机器检查的做成勾选清单，不勾不让点发布。

### 8.1 先说清楚：YouTube 这条线现在是谁在发、授权怎么走
- **ME 仓库里没有任何 YouTube 发布代码、没有频道连接、没有授权记录**（我 10-16 搜过 `src` 与 `scripts`：只有抓爆款参考的 YouTube 读取，没有上传 / 封面接口）。
- 台账 `2026-10-14-cts-oct-channels-and-budget-split-pm-direction` 写的是「YouTube 和 TikTok 的社媒内容 Codex 窗口在做」。所以 **YouTube Shorts 现在是在 ME 之外、由 Codex 窗口人工 / 浏览器操作上传的**，没有 ME 里的授权记录、发布回执，也没有被入口页看见。
- 授权现在只存在于聊天里（PM 的话经统筹转达），**没有机器可查的授权**。这是个洞：YouTube 线现在既无闸、也无回执。
- TikTok 有 ME 内代码（PR 2540，私密发布测试，正式应用仍是草稿），YouTube 没有。

**处置（97 号定）**：①YouTube Shorts 在没有 ME 内发布路径前，**一律人工发布 + 本节清单全勾 + 发布后把「视频编号、频道、时间、授权来源、封面是否上传」写进一张台账回执**；②清单做成页面勾选（8.3），先让 YouTube 有闸；③是否在 ME 里建 YouTube 连接器（Connect 优先，YouTube Data API 现成）属于新能力，另做 Tier 判定后再提，**不在本稿**。

### 8.3 怎么做（分三阶段，代码交 DeepSeek，禁 Codex）

| 阶段 | 内容 | 风险级 |
|---|---|---|
| P1 | 清单库：一个纯函数模块 `src/lib/social/prepublish-checklist/`（条目定义 + 各平台适用 + 机器检查函数：第 0 帧 / 占位符、首评链接与隐形字符、BGM 近 7 天、紧迫词与红线词、授权状态读取）；入口页「去哪里点」栏旁加「发布前清单」只读状态（「9 项里机器过 6 项、需勾选 3 项」）；**不写库、不拦任何按钮** | B |
| P2 | 勾选存储：每条内容的勾选结果（谁、何时、证据链接）存进**现有回执位置**——Post 放 `plan_data` 的 `prepublish_meta`（与 `review_meta` 同做法），Reel 放工单 `output`，Story 放周包文档，YouTube 放台账回执；**不新建表**；页面上勾选框 | B（Post 部分碰每日计划写入，单独评）|
| P3 | **闸接入发布按钮 / 发布 worker**：不勾不让点（Post 发布路由、Reel 工厂发布 worker、Story 发送前）。**这一步碰发布路径 = A 级**，要子牙 + 魏征 + 狄仁杰审、PM 本人点头，**不在本稿批准范围**；P1、P2 先行，P3 在 P1 数据证明清单本身稳定后再申请 | **A** |

> **和 PM 要求的差别**：PM 要的是「不勾不让点发布」，这是 P3；P1、P2 先让清单**看得见、查得出**，YouTube 线有勾选与回执，先填补「现在没有任何闸」的洞。请 PM 知道：真正「拦住发布」那一步是 A 级，不是 B 级。

### 8.4 反例与风险
1. **清单变成「点一下就过」的形式主义**：每项勾选必须填「谁 + 何时 + 证据」，证据为空视为未勾；机器能查的不让人勾（机器结果为准）。
2. **YouTube 勾选没人读**：P2 之前由 97 号每天核对 YouTube 台账回执，缺了就报统筹。
3. **平台未核**：第 3 阶段之前，机器查「第 0 帧」看的是本地 / 存储成片，不等于平台上最终显示的封面。
4. **换客户**：词表、封面规范来自客户配置（VI / 红线词配置），不写进共享代码；East Inter、NAL 没有的平台，该平台整列不出现。
