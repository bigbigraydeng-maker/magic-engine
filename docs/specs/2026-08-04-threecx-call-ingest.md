# 电话接进 CRM（3CX）

**状态**：判断层已完成并上线；取数层等对方开分机
**DAPE**：E 执行（回流）· **支柱**：口碑 / 广告归因（电话是 CTS 最主要的成交渠道）
**轨**：FDE

---

## 为什么要做

CTS 的生意大部分在电话上成交，而电话现在**在系统里完全不存在**：

- 客人打进来没人接 —— 这是「有人想订、我们错过了」的直接证据，今天没有任何地方记录
- 销售打出去聊了什么 —— 只在他自己脑子里
- 广告 / SEO 带来的电话 —— 归因链在响铃那一刻断掉，投放效果被系统性低估

## 架构：取数 / 判断分成两半

跟邮件那条线同一个分法（`src/lib/microsoft/mail-graph.ts` ↔ `mail-ingest.ts`）：

| 层 | 文件 | 职责 | 依赖 3CX 吗 |
|---|---|---|---|
| 判断 | `src/lib/threecx/call-plan.ts` | 一通电话在 CRM 里意味着什么 | **不依赖** |
| 取数 | 待建 `src/lib/threecx/xapi.ts` | 拿令牌、读通话记录、翻译成 `CallRecord` | 依赖 |
| 落库 | 待建 `src/lib/threecx/call-ingest.ts` | 认人、写对话、写触点 | 间接 |
| 调度 | 待建 `/api/cron/call-sync` + `render.yaml` | 每小时跑一次 | 间接 |

**这样分的理由**：判断错了会安静地毁掉销售的名单，所以判断必须能被单测一条条钉住、
不能跟网络调用绑在一起。而且判断层不依赖接口长什么样，对方那边还没开通也照样能先做完、
先审完 —— 事实上就是这么做的。

接口版本变了、甚至将来换一家电话供应商，脏活都只发生在翻译那一层。

## 判断层的六条（已实现，`call-plan.ts`）

| # | 判断 | 在防什么 |
|---|---|---|
| ① | 内部通话整条丢 | 同事互打分机变成客人 —— 客户 8/4 刚在邮件那边反馈过一次 |
| ② | 号码认不出来就丢，绝不猜 | 存错号 → 将来销售照着它打给陌生人 |
| ③ | 未接来电必须建人 | 「有人想订而我们错过了」，等同于邮件的「客人自己开过口」 |
| ④ | 纯外呼不建人 | 打给供应商 / 同行 / 打错号，不配变成一张「今天该联系谁」的卡 |
| ⑤ | 没接通 / 秒挂的外呼不算「跟过」 | 一片灰卡，而那些人一个电话都没接到（`automated-touch.ts` 踩过两次的不对称） |
| ⑥ | 一通电话只算一次，哪怕转接过 | 逐段记 → 一通电话在时间线上变成三次联系，时长还被重复计算 |

录音**只存编号，绝不存能直接打开的链接** —— 那是客人的通话内容，链接落库等于把它
复制到一个没人管权限的地方。要听的时候拿编号带凭证去换。

## 还没做（按顺序）

1. **取数层**：`/connect/token`（client_credentials）→ 通话记录列表 → 翻译成 `CallRecord`
2. **凭证怎么存**：每个客户一套 PBX 地址 + 密钥。存哪、谁能读，是安全决策，动手前要单独审
3. **落库层**：复用 `resolveContact`（电话身份）+ `contact_touchpoints`（`channel: 'phone'`、
   `source: 'threecx'`、`source_ref` = 通话编号）。`countsAsReached=false` 写成
   `metadata.automated = true` —— 那是读路径（今天该联系谁）现有的「这一笔不算有人跟过他」标记
4. **录音**：按需换取，带鉴权，不落公开链接
5. **归因**：来电号码接上已有的人 → 电话计入原本的首次来源
