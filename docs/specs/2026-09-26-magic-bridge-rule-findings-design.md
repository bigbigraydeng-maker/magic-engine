## PR-A · 修失败 + 按实扣费（B 级）
1. `maxOutputTokens` 2000 → 4000（最坏多约 1 美分）。
2. 模型一返回就记 `knownCost`。之后任何失败（截断、空文本、授权刚好变了、写库失败）按 `safeCharge(knownCost, reserve)` 扣：**是有限正数才用，截到 `[0, reserve]`；否则（缺失/NaN）按预留扣**——防止空值写进额度导致额度闸失效（魏征 C9）。模型调用本身抛错（拿不到用量）仍按预留扣（保守）。
3. 仍然不保存半份报告。
4. 测试：截断按真实成本；成本缺失/NaN/超预留/负数的四种兜底；模型抛错仍扣预留；成功照旧。
5. 不做：数据库扣费函数加空值拒绝（改库，另批）；按错误类型退 0（对方拒绝的请求不计费——判定依赖 SDK 错误分类，本轮保守不动）。

## PR-B · 结果按去向 + 巡检结论进报告（客户可见，自报 A 级）
### B1 结果按广告去向，按广告组加总（修 M4、M6）
- 多读一次 **广告组层投放数据**（`insights level=adset`，同窗口 + 上一窗口，字段加 `adset_id, campaign_id`），只保留窗口里有花费的组；再按 ID 批量读这些组的 `destination_type, optimization_goal`（`?ids=` 一次，含已归档的组；读不到的记「去向未知」）。
- 每个组用 `resolveCoreMetric`（与巡检同一函数；两可组合用该客户配置的主结果，没配就开聊）。
- 汇总（系列 / 账户 / 上一窗口同理）：**留资 = 各「留资组」的留资之和；开聊 = 各「开聊组」的开聊之和**（每组内部用 `pickAction` 按优先级取一个、不相加）。去向为空/未知的组（播放、互动、网站转化）**不进结果口径**，单独列「其它目标花费」，不许被写成「缺乏转化数据」。
- 系列/账户只有一种结果 → 给 `results` 和 `cost_per_result`；两种都有 → 分别给留资和开聊（各自成本），**永不相加**（手册 §13）。
- 塞进给模型的数据只加在 `totals / comparison / campaigns / previous_campaigns` 上；compact 去掉跟 leads 重复的 `conversions / cost_per_conversion`；`normaliseInsight` 与 `read.ts` 不动。
- 广告组读取失败 → 降级为老口径并在 coverage 里写明，不拖垮整份报告。

### B2 巡检结论：先确认「这个账户真检查过」，再用跟 PM 待办同样的门槛（修 M7、M8）
- 巡检按账户写覆盖标记：`DiagnosisRun.adLevelCoverage: [{ adAccountId, ran, reason, adsChecked }]`（`ran=false` 的原因：共享账户 / 主页没登记 / 没有广告层数据），`patrol.ts` 写进 `ads_growth_states.payload`。
- 共享门槛从 `pm-todo` 挪到 `src/lib/ads-strategy/rules/patrol-findings.ts`（`ruleHits / findingKey / streakFor / 最新一行够新且数据齐`），PM 待办和 Magic Bridge 共用一份（`meta/ai` 不反向引用 `pm-todo`）。
- Magic Bridge 取结论：最新一行不超过 3 天、非 partial、覆盖标记里本账户 `ran=true`，才算 `source='patrol'`；只取 D2/D10 命中、第一个单位是本账户、连续 ≥2 次命中；再用本次现读的广告状态剔掉客户已停掉的广告。否则 `source='none'` + 原因。
- 巡检 D2/D10 命中改标 `clientVisible: true`，Magic Bridge 按 `clientVisible && code∈{D2,D10}` 筛（目前没人读这个标记，改了不影响现有行为）。
- **本轮不做「没接巡检的账户现算疲劳」**：零用户（只 CTS 在用且有巡检），且会成第三套疲劳判断、17 天数据可能把报告拖垮（子牙 B-4、魏征 C10）。老的 `fatigueCandidates` 和 `dailyAds` 那次读取一并删掉。

### B3 规则那一段由程序写，AI 不碰（修 M5）
- 新纯函数（放 `src/lib/ads-strategy/rules/client-copy.ts`，广告支柱知识）：巡检命中 → 客户可读句子。报告**第三部分「需要留意的广告」由程序按模板拼接**，插进 AI 正文里；AI 收到的数据里**没有**任何疲劳/规则字段，提示词写明「第三部分由系统写好，不要写，也不要自己判断素材疲劳或受众饱和」。
- 出报告后兜底检查：AI 正文里出现「疲劳 / 饱和 / 老化 / 看腻」的句子删掉并记日志。
- 提示词顺带：对客户用大白话（点击率、每个客户花多少钱、平均每人看到几次），不写英文缩写；删掉会被模型无视的「700 字即失败」硬话术，改成「控制在 900 字左右」并由 4000 输出上限兜底；禁止出现：巡检、规则、D2、D10、显著、p 值、手册、PM、FDE、模型/供应商名。
- `PROMPT_VERSION` → v2（同一天可再生成一份，会再扣一份预留——CTS 本月额度见退款方案）。

### B4 客户文案（按板桥 v1 必改 + 魏征 C1–C3 改写）
- **有巡检的客户都是 Magic Engine 在代管广告**（巡检只对代管客户开）。所以建议一律用团队口吻，不叫客户自己去改账户（避免两边同时改、也避开「另建广告组要不要加钱」的 ABO/CBO 问题）：
  - 每条：标题 + 数据说明 + 「我们的广告团队已经看到这个情况，会在 {M月D日} 前后复查并处理，你不用动手。如果你最近自己改过这条广告的表单、欢迎语或图片，请告诉我们。」
- 标题与说明（「之前两周」代替「平时」；「留下联系方式 / 发私信咨询」代替「留资 / 开聊」；比例 1 位小数、金额带币种 2 位小数；每条标「数据截至 {M月D日}」；日期一律写绝对日期）：
  - D10 自身对照：「「{广告名}」最近 3 天，点进来的人里{留下联系方式/发私信咨询}的比例从之前两周的 {b}% 降到 {r}%」；说明：「每位{…}的客户成本从 {B} 涨到 {R}。问题多半出在点进去之后（{表单问题太多或网页 / 欢迎语和快捷问题}），不是广告图片本身。」
  - D10 同组对照：「「{广告名}」最近 3 天，点进来的人里{…}的比例只有 {r}%，同组其它广告是 {b}%」；说明：「它每带来一位{…}的客户要花 {R}，同组其它广告只要 {B}。」
  - D2：「「{广告名}」最近 3 天，看到广告后点进来的人变少了：点击率从之前两周的 {b}% 降到 {r}%」；说明按三种：素材变旧（「每人一周平均只看到约 {f} 次，不是看腻了，更可能是图片或视频不够吸引人了」）/ 看腻了（「同一批人一周平均已经看到约 {f} 次，看多了就不太会再点」）/ 次数拿不到（「这次拿不到每人看了几次，分不清是图片不够吸引人还是看腻了」）。频次优先用巡检值，缺了用本次现读的系列 7 天频次补（魏征 C3）。
  - 比例为 0：「最近 3 天还没有人{…}（之前两周是 {b}%）」。
- 空结果按三种：`patrol` 且没命中 →「这次没有发现哪条广告明显变差（检查了 {n} 条正在投放的广告）」；`none` →「这个广告账户这次没有做单条广告检查（{原因：还没接入每日检查 / 没有正在投放的广告 / 数据还不够}）」；旧报告没有该字段 → 不显示。
