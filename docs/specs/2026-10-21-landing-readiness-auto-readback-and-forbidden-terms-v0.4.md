## 1. 表只是缓存，真正的防线是闸现场重读（改写 v0.3 §1 措辞）
- **开投闸只用「现场重读结果」判定**；`landing_readiness_current` 只用于**展示和待办**，不作放行依据（v0.2 §1.2/§1.3、v0.3 §1 里任何「闸读库里行重算」的说法一律作废）。
- 现场重读**失败/超时一律拦**。
- 写入函数 `landing_readiness_upsert_v1`：`SECURITY DEFINER`，**`REVOKE ALL ON FUNCTION … FROM PUBLIC`**，只授给唯一服务身份，**`SET search_path` 钉死**；常驻断言覆盖：函数 EXECUTE 权限、表上 INSERT/UPDATE/DELETE/TRUNCATE 对 service_role 与 PUBLIC 均无、search_path 已钉。

## 2. 落地 URL 核对：域名+路径，且核全部链接
- 比 **域名 + 路径**（`evil.example/shanghai` 不再因路径一致放行）；跟随跳转的**每一跳与终点都必须在客户登记的域名内**。
- 一个创意里**所有**链接都要核：`asset_feed_spec.link_urls`、`link_data`、`video_data.call_to_action` 等各形态；**任一条解析不出来或不在登记页 → 拦（不是跳过）**。
- `reactivate_campaign` / `approveDraft` 一次打开多条广告：**每条广告都核**，任一不过整批拦。

## 3. 现场重读的限流与回执
- v0.2 §1.4「每页每小时≤1 次、并发 1」只管**定时读回**；**闸的现场重读单独限流、设超时**（建议单页 ≤10 秒、全客户总预算内），不占用定时读回配额，也不卡死该客户所有启用。
- **闸现场读到的字段与 `checked_at` 写进启用回执**（出事后可查当时看到了什么）。

## 4. 如实写限度（cloaking 与范围）
- 官网可以对 ME 的探测特征（UA/IP/请求头）返回与真实访客不同的内容；**现场重读只能证明「官网愿意对 ME 这么说」**，不能证明所有访客所见。缓解：用与真实浏览器一致的请求特征 + 官网侧承诺不做按探测者区分（写入对接约定）；仍作为已知限度。
- `ready` 必须带范围标注：**`copy_clean_scope: "ssr_only"`**（只覆盖服务端渲染 HTML，不含 JS 渲染内容）；待办界面写「服务端渲染文案已检查」，**不写成「文案全部合格」**。
