# 新建/重建广告组「零消耗不干等」· 设计 v0.2（增量，仅供讨论）· 只设计，未写代码 · 119 号 · 2026-10-21

> 在 v0.1 之上：冲突处以本稿为准。吸收子牙+魏征对 v0.1 的审查（经 74 转）。风险级 A。**本稿不构成对 `bounded_auto` 或任何自动花钱的授权**；「重做有效」只是 74 提供的**单次样本观察**（10-21 01:16 NZ 重做的三个组随后在消耗），不是已证明的因果。

## 1. 克隆的幂等（最重）
`ads.add_retargeting_adset` 的 `providerIdempotency='unsupported'`、`maxAttempts=1`（`registry-ads.ts:315-350`），克隆建组同样没有 Meta 侧幂等。所以：
- **幂等键 `(旧 adset_id, rebuild_seq)`**，`rebuild_seq` 上限 1（见 §5）；复用内核已有的 `action_runs` 幂等机制作「**意图行**」（**不新建表**）：调 Meta **之前**先落意图行；同一旧组只能有一条未了结意图（幂等键唯一保证）。
- **结果未知**（超时/崩溃/网络断）→ 进「待核实」，**禁止盲重试**：先按名称（`…rebuild1` 后缀 + 名称里的 `rebuild_of=<旧id>`）去 Meta **查有没有已建出的新组**，查到就接管（补回执、走后续步骤），查不到且确认失败才允许一次受控重试。名称后缀只是辅助，幂等的根是意图行。

## 2. 步骤顺序（写死，每步回读）
1. 暂停旧组 → **回读确认 PAUSED**（未确认不得继续）；
2. 新组 **以 PAUSED 创建**（`create_paused`）→ 回读核对设置 → **过闸**（3010 计划闸 / 2999 日预算闸 / 客户日上限 / 内核信封）；
3. **activate 之前再回读旧组仍是 PAUSED**，并在 `rebuild_seq` 上互斥（防止两个重建并行）；
4. 激活新组 → 回读；写回执。
- 「旧组停成功、新组建失败」时：**保持已停**——这是**偏保守的选择**，后果是该组**断投**，出红色待办（what/how/href），不自动回滚去重开旧组。新建被拒/失败**不留在投的半成品**：已建出的残留对象一律保持 PAUSED、命名带 `rebuild_failed`、列入待办，绝不 ACTIVE。

## 3. 触发判据（⑥诊断部，只读，实时读 Graph）
- **激活时刻锚点**：从**激活时刻**起算（创建后暂停、晚上才激活，按激活时刻算，不按创建时间）。
- **排除排队态**：`delivery_sub_status` / `effective_status` 为 `PENDING_REVIEW`、`IN_PROCESS`、学习期(`LEARNING`)等 → **不触发**；审核中**超过 24 小时**才算问题（出待办）。读不到这些状态 → 出「读不到」待办，**不触发重建**。
- **账户内同类对照（同时是账户级判据）**：同账户同期别的组**有消耗**、**独此一个为 0** 才触发；若同账户新组**全部**为 0 → 判账户级问题，不克隆，出红色待办。
- **有效投放小时数**：夜间/投放时段排程按**有效投放小时数**算，不按挂钟小时；2 小时指有效投放小时。
- **曝光阈值不固定为 20**：按「该组日预算 × 账户近期 CPM」算**预期曝光**，实际 < 预期的 10%（且预期值足够大才有意义）才算「近乎零」；**日预算过小**（预期曝光本就很少）→ 走待办，**不进可重建**。
- 阈值（2h/3h、10%、N）放 `ad_strategy_configs`（客户配置，**不进计划指纹**）。

## 4. 为什么克隆会不同（只在有理由时才克隆）
- 克隆与原组的差别：**重新提交审核 / 清掉卡住的投放状态 / 可换受众种子**。其余设置相同。
- **可重建的原因只限定一类**：「重复激活后卡在 preparing」（见 §1 证据）。其他原因（审核被拒、受众过小、预算过低、付款/账户状态）一律**只出待办**，不克隆。
- **根因不明、同受众同创意的克隆 = 赌运气**：自检结论里必须明说「根因不明，克隆是赌运气」，且**不提供「一键重建」按钮**，只给「人工决定是否重建」。
- **默认不重建手批的素材**（如 A2/B3）：除非所属计划步骤显式标记 `allow_rebuild`。

## 5. 账户级限制与上限（改松为收紧）
- 命中 **Meta 案件 961007739837851 / 错误 1815089** 任一 → **当天对该账户全面停止重建**。
- 同账户当天**已出现 1 次重建后仍零消耗** → 停止该账户当天后续重建。
- **受限账户上限 0 次；正常账户起步 1 次/天**（v0.1 的「每账户 3 次」作废）。同一旧组谱系最多重建 1 次（`rebuild_seq ≤ 1`）。

## 6. 信封事实口径（新增一节，fail-closed）
`new_spend` 在内核信封里的现状会踩雷：`beforeCents=0`、`hoursSinceLastChange` 为 `null` 会被拒「读不到上次变动」；跨账户合计只对 `ads.scale_unit_budget` 加载，`new_spend` 同样被拒；学习期读不到按学习期拒。重建动作（暂名 `ads.rebuild_adset`，**A 级内核改动**）必须明文规定：
| 事实 | 新建类取值 |
|---|---|
| 学习期 | **不适用**（`learningApplicable=false`，对象是新建的）；但对**旧组**的暂停本身是收类，不受学习期限制 |
| 冷却期（72h） | 对新建对象**不适用**（无历史）；旧组暂停属收类，不受冷却 |
| `before` | 新组 `before=0`，但**跨账户/客户合计必须加载**（不允许因「读不到合计」而误拒或误放） |
| 读不到任何必需事实 | **一律 fail-closed（拒）**——仅限「加钱/新建」方向；暂停方向读不到仍放行 |
- **预算口径二选一，写死选甲**：甲）**暂停回读通过后**，才把旧组日预算从合计里扣除，再把新组作为新建重新读预算过闸；乙）新组日预算**不抵扣**旧组，直接过日上限（更保守）。**采用甲**，并保留乙作为回退。
- **CBO**（预算在系列层）时：新组无自己的日预算（继承系列预算），语义不同——**不增加总预算**，但同系列下仍需确认新组不使系列预算被双重计算；ABO 才有「新组日预算 ≤ 旧组日预算」的约束。两种形态在设计与测试里分开写。

## 7. `ad_creative_links` 写入
- 表里**没有** `rebuild_of`；PR 3002 已把写入收口到受保护窄函数，且**新增列 service_role 无写授权**。决定：**`rebuild_of_ad_id` 是新列**（再一次 **A 级迁移**，随后续块排期），**复用 3002 的建广告/登记函数写入**，**不另开写口**；`AdCreationPath` 新增 `rebuild_adset`。
- 旧行保留；新行**可共用旧行的签字**（同一素材同一成片，签字对素材而非对广告）。
- **先后一致**：意图行先于 Meta 调用；关联行写入必须在「新组创建成功回读后」同一流程完成，且有对账（「新组存在但无关联行」= 孤儿，每日扫描列入待办），防「广告建了关联行没写进」。

## 8. 建议项落实
- **2 小时只出自检待办（不含重建按钮）；3 小时才升级为带「一键重建」的待批准请求**。
- **回执分两类**：「自检结论」与「克隆动作」；克隆类 fail-closed。
- **每个旧组同一时刻只有一个自检/重建状态机**：以 `action_runs` 按旧 adset_id 的最新一条为准（读时取最新，不靠事件顺序）。
- **读不到状态**：有去重键（旧 adset_id + 日期）和升级路径（连续 2 天读不到升级给 PM）；停止方向读不到保持放行。
- 红色待办必带 what / how / href。根因统计**复用既有回执/复盘表，不新建表**。
- **开关**：`zero_spend_rebuild_enabled` 放 `ad_strategy_configs`（客户级，默认 false），写权限与审计同数据驱动稿 v0.6 §4（只经专用 PM 路由，通用 PATCH 拒收，service_role 列级 REVOKE）。**注意 `autopilot_dry_run` 不是刹车**（内核不读它，见记忆与 `ads.*` 权限实情），所以需要这个独立开关；CTS 现为 `observe`，本规则只出待批准请求与待办。

**本稿不构成对 `bounded_auto` 或任何自动花钱的授权。**
