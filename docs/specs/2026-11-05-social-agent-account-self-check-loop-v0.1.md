|---|---|

| 改版 | 大量 v1/v2/v3「只换一样」的广告测试改版，被当成社媒内容排进账号 |
| 缺的形式 | 真人出镜、客人说话、导游、幕后、干货问答、轻松类：**0 条** |
| 行业爆款对照 | 素材库旅游类播放前 60 条的高频标签：快剪、幽默、旅行 vlog、干货、像用户自拍；CTS 41 条一条都不对上 |
| 排期 | 每周 / 每日排期只核事实、授权、出镜、同团不连发，**不看形式和音乐** |
| 账号层面 | **没有任何一步看「账号整体」**：每条单看都合格，合在一起千篇一律 |

根因：社媒 Agent 只有「单条内容」的闸（事实、马良、出镜），没有「账号整体」的环。生产（工厂）按广告测试思路出改版，排期不管形式，回看（72h 读回）还没做——**没有一个步骤会对「账号最近长什么样」负责**。

## 1. 一句话

**给社媒 Agent 加一个账号自检环：每次排期前和每周一次，按行业配方给「账号最近 N 条」量多样性和外环结果；超线的自动在排期里纠正（只调顺序、不新增外发），缺的形式自动下单或派人工任务，PM 每次指出新问题就变成一条新的检查和考题。**

## 2. 环的六段（对齐 IMPACT）

| 段 | 做什么 | 谁 / 在哪 |
|---|---|---|
| **Inspect** | 取账号「最近 30 天已发 + 未来 14 天已排」的全部 Reel，带每条的模板、BGM、镜头数、改版组、内容柱、形式标签 | 代码（工单 `brief.remotion.template / props.musicFile / variant_of`、流量记录） |
| **Measure** | 算多样性指标（§3）和外环指标（72h 私信 / 询价，按形式归集） | 代码；外环读回没做好之前写「没测成」，**不写 0** |
| **Prescribe** | 指标对照行业配方阈值（L2）与客户覆盖（L4），出「发现 + 处方」清单 | 代码规则；不交模型 |
| **Act** | 按 §4 三档：排期自动纠偏 / 缺形式自动下单 / 要人的派任务 | 排期器、工厂、今日待办 |
| **Check** | 下一次自检看这条发现消没消；外环按形式比 | 自检回执对比 |
| **Tune** | 阈值、配比的调整只出「建议」；PM 纠正落到 §6 | 候选 → PM 批 → 进配方 |

## 3. 量什么（第一版，全部代码可算）

| 编号 | 指标 | 默认阈值（旅游行业配方，候选） | 读不到时 |
|---|---|---|---|
| D1 模板集中度 | 最近 10 条里占比最高的模板 | ≤ 50%；同一模板不连发 3 条 | 工单没有模板字段 → 标「没测成」 |
| D2 BGM 重复 | 同一首曲子间隔；30 天最高占比 | 同曲 7 天内不重复；单曲 ≤ 30% | 同上 |
| D3 改版扎堆 | 同一改版组（`variant_of` 链 / 同底稿）7 天内上账号条数 | ≤ 1（改版是广告测试用的，账号只放一个） | — |
| D4 形式覆盖 | 30 天内出现过的形式 ⊇ 配方最低集合 | 旅游：风景 / 团介绍、客人故事或真人、干货问答，各 ≥ 1 | 形式标签缺 → 「没测成」并出「补标签」任务 |
| D5 内容柱配比 | 30 天内容柱占比 vs 配方 35/25/20/15/5 | 任一柱偏离 > 15 个百分点 | 工单没有内容柱 → 「没测成」 |
| D6 视觉单一 | 品牌色 / 镜头数 / 开场类型的分布 | 同一开场类型 ≤ 60% | — |
| O1 外环 | 每种形式 72h 带来的新私信、表单询价；CRM 合格客人 | 不设硬阈值；n < 5 不下结论（SO-09） | 读回没跑 → 「没测成」 |

阈值放 **L2 行业配方**（`src/lib/social/recipe/`）；客户可在配置里覆盖（L4）。共享代码只写「怎么算、怎么比」，不写 CTS 的数字。

## 4. 发现之后怎么动（放权按风险，第六部）

| 档 | 动作 | 级别 | 例子 |
|---|---|---|---|
| A 排期自动纠偏 | 排期选片时把 D1/D2/D3/D6 当硬约束：违反的候选往后排或这次不排，写原因 | **L2 自动**（只改未授权条目的排序，不新增外发；PM 仍在清单上逐条批） | 下一条不能又是明信片 + 同一首曲子 |
| B 缺形式自动补货 | 内容池里缺 D4 某形式 → 按配方给工厂下单（受每日 3 张 / 5 美元护栏）；只能用工厂已有的模板与素材 | **L2 自动**（计划 §4 已批「出片下单自动」） | 缺干货问答 → 下一张清单模板的「签证要点」单 |
| C 要人或要开发 | 工厂没有该形式的模板 / 需要客户素材（真人、客人）/ 阈值本身要改 | **L3 人做**：进今日待办（what / how / href）；开发欠账进台账 | 「要做轻松类新模板」→ 开发卡；「请 CTS 提供导游出镜素材」→ 客户侧任务 |

**永远不做**：自动删帖、自动改已授权条目的日子、自动加发布量。

## 5. 完成证据（第四部）

每次自检写一行回执（`cron_run_logs`，job `social-account-audit`）：每个指标的值 / 阈值 / 结论（过 / 超线 / 没测成）、发现清单、每条发现的处方与执行结果（已纠偏 / 已下单 / 已派任务）、上次发现是否已消。周报只写「消了几条发现、外环有没有变」，不写「做了多少动作」（第十四部）。

## 6. PM 纠正怎么落地（第十部）

PM 每指出一次「账号哪里不对」，必须落到三处之一，并写台账卡：
1. **新检查项**（§3 加一行指标 + 阈值候选）；
2. **考卷新题**（`src/lib/social/account-audit/__tests__/exam.test.ts`：输入 = 当时的真实条目快照，期望 = 这些发现）；
3. **规则表候选**（社媒 Agent 规则表新增一条 SO-xx）。

本次（2026-11-05）三处都落：D1/D2/D3/D4/D6 检查项；考卷第 1 题 =「CTS 近 60 天 41 条」快照，期望命中 D1、D2、D3、D4；规则表新增 SO-13。

## 7. 记忆分层（第八部）

## 9. 开工十问

1. IMPACT 的 Check + Tune；外环 = 按形式归集的 72h 私信 / 询价、CRM 合格客人。
2. 取数、算指标、比阈值、出处方全是代码；模型只用于以后「给新形式写脚本」，不判对错。
3. 无新增对外动作；排期纠偏与自动下单都在已批的 L2 内；新模板 / 客户素材 / 改阈值都是 L3。
4. 自检回执逐指标逐发现；下一次自检核「发现消没消」。
5. 生产 = 工厂 + 排期；验证 = 自检环（独立代码）+ PM 看清单。
6. 见 §7。
7. 考卷 = §6 的回放题，第 1 题即今天这 41 条。
8. 见 §6。
9. 字段缺失写「没测成」并派「补标签」任务，不当 0、不当通过。
10. PM 注意力：每周一条「账号自检」摘要（消了几条 / 还剩几条 / 要你做什么），只有 C 档进待办。不新增 agent：是社媒 Agent（苏东坡）的一个环。

## 10. 不做

自动删帖、改已授权日子、加发布量、自动买 BGM、对外承诺播放量。
