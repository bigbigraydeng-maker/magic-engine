# 功能地图与人机分工 · 定稿 v1 · 116 号窗口 · 2026-10-16

**来由**：PM 要先梳理清楚 Goal / Marketing Plan / 推广计划 / 看板 今后怎么配合，并在 10-16 定了一条总原则（原话要点）：
> Magic Engine 后台软件的大部分工作是给 AI Agent 设计的。①几百条的任务清单不是给人看的，记录在那里，让 AI 自己去查；②界面按钮少则少；③真人只负责资金预算审核、授权，其余全部交给 AI Agent。

这条原则高于本稿所有细节；冲突时以它为准。

## 1. 一张图（各管哪一层）

| 层 | 是什么 | 谁用 | 去留 |
|---|---|---|---|
| **Goal（目标）** | 要什么结果、到哪天（例：CTS 圣诞团招募、NAL 每月 300 个开聊，月度自动续建） | AI（广告自治、诊断、处方、对账都拿它当尺子） | **保留，是核心**。真人只在定目标时参与 |
| **Marketing Plan（计划壳）** | 一轮活动的一条记录：标题、起止、草稿 / 已批准 | 系统 | **保留壳**。「AI 生成一堆任务写进看板」那一半 6-8 之后没再用过，**停用** |
| **推广计划**（壳里的 `promo`） | 这一轮分阶段怎么打：广告、社媒、邮件，并每周对 Goal | AI 起草、AI 每天自查；真人只看一句话和批准 | **保留，是 Marketing Plan 的内容层**，不是第二个功能 |
| **每日计划** | 社媒每天排什么（归 97 号） | 社媒代理 | 保留；推广计划只核对条数 |
| **任务清单（原看板的底表 `execution_items`）** | AI 自己的工作队列：诸葛亮 30 天写 211 条、诊断 35 条、自动写博客读它 | **只给 AI 查，不给人看** | **表保留；看板页面不再作为人的入口。** 几百条不进今日待办 |
| **今日待办** | 真人唯一的入口 | 真人 | **只放：资金 / 预算审核、授权**（五类里的 decide / one_click）；其余折进开发欠账或周报 |

**更正（我之前说错的一点）**：我曾把「诸葛亮 / 诊断的 200 多条没人处理」当成缺口、想让它们进今日待办。按 PM 原则这是错的：那是 AI 的队列，由 AI 自己查；进今日待办的只能是需要真人授权 / 批预算的那一小撮。

## 2. 人机分工（落到推广计划）

| 事 | 谁做 |
|---|---|
| 起草阶段、广告预算 / 受众 / 素材建议（带依据） | AI（已上线） |
| 每天对账、查检查清单、查每日计划条数够不够 | AI（已上线，每天 07:10） |
| 排期、社媒草稿 | AI（每日计划代理，97 号） |
| **批准计划**（含预算数字） | **真人（只认 Magic Lab 内部账号）** |
| **开投 / 加预算 / 换已投受众** | **真人本人**（`spend-activation`，不动） |
| 对外发布 | 真人授权（现有审核→授权→发布链，不动） |
| 「落地页是否真实存在」「素材是否合规」这类**核实** | **应由 AI 自查**；AI 查不了的才进今日待办（现在是人点「已核实」，与原则冲突，见 §4） |

## 3. 界面按钮原则（推广计划页）
默认只留：**一句话头条 + 批准计划（当它真的可批时）+ 让系统起草建议**。其余（手填表、阶段 / 步骤增删、看示例、高级文本）已折叠进「想自己改？展开」。还要继续收：
1. **「按计划继续」每周按钮：移除。** 每天自动查已经取代它；它是「看过、没意见」的人工签字，和原则相反。
2. **「已核实」按钮：随 §4 的 AI 自查上线而移除。** 在此之前不能删（删了硬检查永远变不绿，计划批不了）。
3. 页面不再新增任何需要真人点的确认类按钮。

## 4. 接下来的开发（先后，由 AI 自己拍；每项 A 级走两审 + 当场试跑）
1. **（小）移除「按计划继续」按钮与对应流程**，保留检查与每日待办。
2. **AI 自查替代「已核实」**：先做能机器核实的（要推的东西在落地页上是否真实存在：读客户官网 / 团目录，对日期、价格；读不到或对不上才进今日待办）。「客户是否同意措辞」属于授权，保留为真人授权项。
3. **目标选择**：推广计划选目标时可选草稿目标 / 直接新建（现在只列进行中的，CTS 上海团的目标是草稿选不到）。
4. **老 Marketing Plan「生成任务」功能停用并标注**（保留历史数据）。
5. **「诸葛亮 / 诊断写的任务」由 AI 自己消费**：确认有 agent 在读并关闭这些队列；只有需要真人授权的才升级到今日待办（已有分流表 `five-kinds`，不新增入口）。
6. 取消：S4b「批准后把计划变成看板任务」（与原则冲突）；邮件监控 P3 暂缓（见 §5）。

## 5. 优先级（按 §11 三维打分）
- 邮件监控：频率 低 / 闭环关键度 中 / 收入关联 低 → **P3**，暂缓（现在线上没有一份带推广结构的计划，且邮件节奏归 102 号）。
- 把一份真计划录进去跑起来（CTS 3–5 月）：频率 高 / 闭环关键度 高 / 收入关联 高 → **P0**，需要 PM 点头（要往正式库写一份草稿）。

## 6. 不做
不删 `execution_items` 表；不碰 97 号的每日计划文件；不新增人工确认类按钮；不让 AI 自动开投或加预算。
