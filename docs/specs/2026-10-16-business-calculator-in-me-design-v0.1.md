## 1. 它是什么
CTS 客户页里的「经营测算」页：手填参数 → 浏览器里立刻算出结果；可保存多个命名场景，对比任意两个。**不读真实数据，不写 Meta，不改任何计划/预算/授权**。结果卡与对比表**各自带一行**「内部模拟 · 不构成预算依据」；结果标题叫「按这组假设算出的年度利润」，不叫「预计」。场景名输入框旁提示「别写批准、承诺类字样」。

## 2. 公式（逐项搬自公开脚本 `cts-business-calculator.pages.dev/assets/index-BK1a3pRZ.js` 的 `_a`，2026-10-16 读取；魏征另用 Python 重写核验过）
**夹逼（前端与服务端用同一套范围，被夹逼时在输入框旁显示「已按 X 计算」）**：CPL ≥ 0.01；广告 ≥ 0；转化率、Tour 占比、毛利率夹 0–100；每单人数 ≥ 0.1；服务费、人工 ≥ 0；佣金率取 min(毛利率, 佣金率)；额外 Sales 取 ⌊x⌋ 且 ≥ 0。**价格脚本不夹逼**（负价照算），本设计在输入层限制为 ≥ 0 并提示。CPL < 0.5 或线索 > 10 万条时红字提示「参数可能不现实」。
**计算**：线索 H = 广告 ÷ CPL；订单 = H × 转化率；加权每单人数 R = 占比×Tour每单人数 + (1−占比)×定制每单人数；游客 = 订单 × R；加权每位人均价 k =（占比×Tour每单人数×Tour价 + (1−占比)×定制每单人数×定制价）÷ R；销售额 = 游客 × k；毛利 = 销售额 × 毛利率；佣金池 = 销售额 × 实际佣金率；**公司留存 = 销售额 ×（毛利率 − 实际佣金率）**；固定成本 = 人工 + CTS 服务费（**不含广告**）；年度总成本 = 广告 + 固定成本；**利润 = 公司留存 − 年度总成本**。
**每位游客**：留存 St = k ×（毛利率 − 实际佣金率）；广告成本 wl = 转化率 > 0 ? CPL ÷（转化率×R）: ∞；净贡献 Tl = St − wl。
**打平**：打平游客 = 固定成本 ≤ 0 ? **0**（哪怕转化率 0）: Tl > 0 ? ⌈固定成本 ÷ Tl⌉ : **无法计算**；打平线索 = 转化率 > 0 ? 打平游客 ÷ (R×转化率) : (打平游客 > 0 ? ∞ : 0)；打平广告费 = 打平线索 × CPL；打平利润 = 打平游客有限 ? 打平游客×Tl − 固定成本 : ∞。
**Sales**：每人处理线索基准 6000 条/年（25 条/天 × 240 天，**计算器预设，来源未证实，不当建议显示**）；需求人数 = ⌈H ÷ 6000⌉，折合 FTE = H ÷ 6000；**「额外增加 Sales」只影响人均指标**（每位 Sales 的线索/订单/游客/销售额/佣金 与产能利用率 = H ÷ (6000 × 总人数)），**不加任何成本，不进利润**，页面写明这一句。显示：金额除零/无穷显示「无法计算」，数量显示「—」。
**黄金测试**（默认值：广告 60000、CPL 7、转化 5%、人工 100000、服务费 60000、佣金 10%、Tour 80%、1.6 人×3500、定制 2 人×4000、毛利 20%）：利润 40,571、销售额 2,605,714、游客 720、订单 429（428.57）、线索 8,571、打平 575 人、Sales 需求 2（8571÷6000 取整）；另补 12 组边界（转化率 0、CPL 0.001、佣金 30% > 毛利 20%、转化率 150%、Tour 占比 0 与 100、固定成本 0、每位留存 < 每位广告成本、广告 0 等），期望值取自原脚本，**测试里注明「2026-10-16 读自线上脚本」**。
**默认值**＝原计算器初始值，**不代表 CTS 实测**，每个默认旁固定标「公开计算器初始值」。毛利按成交渠道不同（直接 20% / Agent 或 Sales 10%）由用户自己填两格，不预设。

## 3. 保存与对比（唯一的新数据）
- **表** `public.me_calculator_scenarios`（迁移 `supabase/migrations/20261016100000_business_calculator_scenarios.sql`，头注「service-role only; apply only after explicit PM approval」）：`id uuid pk`；`client_id uuid not null references public.clients(id)`；`name text not null` trim 后长度 **1–60**（与原计算器一致）；`inputs jsonb not null`，检查为 object 且 `pg_column_size` ≤ 8KB；`formula_version smallint not null default 1`；`created_by text not null`；`created_at/updated_at timestamptz not null default now()`；`unique (client_id, name)`。**每客户 50 个用插入前触发器强制**（防并发 51 个）；接口把「重名」「超限」映射成不同错误码；`updated_at` 由接口每次显式写，乐观锁用它（不匹配回 409）。RLS 抄 `crm_booking_members`：`FOR ALL TO service_role USING (true) WITH CHECK (true)` + `revoke all … from anon, authenticated`。
- **语义**：「保存当前」遇同名 → 提示「同名场景已存在，覆盖吗」，确认后带 `updated_at` 覆盖（过期回 409）；改名撞名回 409；DELETE 不带锁，页面对 404 显示「该场景已被别人删除」并从对比里移除；对比时**现取两个场景并校验 `updated_at`**，不用载入时的快照；对比差值**先取整再相减**；浏览器里有未保存修改时点「载入/切换」弹确认。
- **接口**（不新增定时任务，不碰 `render.yaml` 与 `cron/registry.ts`；纯手填无外部副作用，不需要 Inngest）：`GET/POST /api/clients/[id]/business-calculator/scenarios`，`PATCH/DELETE …/scenarios/[scenarioId]`。鉴权 **`requirePlanApproverAccess(clientId)`**（`client-access.ts:161`，内部账号，客户员工 403）；另校验 clientId 为真实客户，且 `industryFeatureFlags(industry).business_calculator` 为真。
- **入口与页面**：客户页「经营工具」区入口卡（`src/app/dashboard/clients/[id]/page.tsx`），**只对旅游行业客户显示**，在 `src/lib/clients/industry-features.ts` 加行业开关 `business_calculator`（沿用 `TRAVEL_KEYWORDS`）；页面**服务端也判内部账号**（不能只靠接口 403，也不能只用 `ServerFeatureLock`，它放行付费客户员工）。公式模块 `src/lib/crm/industry/travel-business-calculator.ts`（纯函数，旁边是 `travel-booking-rule.ts`），校验器白名单字段，**缺字段用默认、多余字段拒绝**。
- **公式版本**：每个场景存 `formula_version`；将来公式升级，载入旧场景带「按 v1 公式算」标记，可手动「用新公式重算」，不静默改旧数。
- **计算只在浏览器里**，服务端只存取参数；按钮只有保存/载入/删除/对比，无导出、无自动保存。
- 复用：仓库没有「一客户多条、用户自起名」的表，场景表是新建；复用 `crm_booking_tracker` 迁移结构与 RLS 写法、`requirePlanApproverAccess`、行业开关机制。
