# CRM「今天先联系」改为流水线面板 + 大模型排轻重缓急 —— 设计稿 v0（2026-10-29）

- **作者**：76 号窗口（CRM 页面）· **状态**：设计稿 v0，只出方案；落地各刀另走流程
- **风险级**：设计稿本身 C（纯文档）；落地会改变销售每天看到的名单、引入模型判断 → 按 A 级（设计两审 + 代码两审 + PM「合」）
- **承接 / 不重复**：[129 号跟进流程 AI 升级设计 v0](./2026-10-28-crm-followup-ai-upgrade-design-v0.md)（已合并）的「账本 → 状态（球在谁手里）→ 下一步」。**本稿不另建状态模型，复用它的 §2.3 状态派生**；本稿只补两样它没有的：①面板长什么样（流水线列）；②**列内排序和「我们欠他什么」由大模型读对话给出**（129 第一期写的是「规则选、不用模型打分」——PM 2026-10-29 改口要模型，见 §1）。

---

## 0. 给 PM 的一页

- **问题**：现在的「今天先联系」按固定规则分两组（今天要联系 / 先放着），读不懂对话内容。打完电话、答应了发方案的人会被归成「聊过一轮就断了」掉进先放着（Mercurio，10-29）；而「球在我们手里」的人有约 500 位，规则分不出谁更急。
- **做法**：一块 4 列的流水线面板。**谁进哪一列由事实决定**（谁最后说话、我们答应了什么、客人说过什么时候），**同一列里谁排前面由大模型决定**，每张卡写一句理由和下一步。硬规则（别再联系 / 同行 / 非咨询）不交给模型。
- **上线顺序**：先影子跑 1 周（只记录不显示）→ PM 抽查对不对 → PM 说「开」才换面板。

---

## 1. PM 要什么（原话要点）

2026-10-29：「我们的业务是一个长尾、需要种草的业务。打完电话直接归类到『先放着』明显有问题。」
「传统 CRM 通过标签可以判断谁报价了、谁需要 follow up，但判断不出轻重缓急。我们希望通过大模型，根据我们发的内容、收到的内容、用户回复的时间以及语气语义，来综合判断客户的轻重缓急。」
「比如要做一个方案，等同事做，两三天才能给客户回复——今天不用回复，但不代表三天后不联系他，它依旧是一个有效的 hot list。」
「把它做成 Pipeline（流水线）的效果。」

## 4. 面板：4 列

| 列 | 进入条件（事实，确定性） | 列内排序（模型） | 出列 |
|---|---|---|---|
| **① 现在处理** | 欠他回复（客人最后一条真话晚于我们最后一次人工联系）· 约好的回电到期 · 刚通完电话 3 天内没记下一步（已上线 3393）· 「我欠他」的承诺到期 · 回头客重新留资 | 轻重缓急 高 / 中 / 低 + 一句理由 | 我们真人出手了（回信 / 通话 / 记了下一步） |
| **② 我欠他东西** | 有一条**未完成的承诺**（我们答应发方案 / 报价 / 资料），带到期日 | 按到期日；模型只给「到期前要不要提前提醒」 | 承诺完成（发出对应邮件 / 人工勾掉）→ 进 ③；到期未完成 → 升到 ① |
| **③ 等他回** | 我们最后出手、客人还没回、没有未完成承诺 | 模型判断「该不该催、什么时候催」（读回复间隔、语气） | 客人回话 → ①；超过行业剧本的等待期 → ④ 或 ① |
| **④ 种草唤醒** | 长尾：说过「以后再走」、多次没回、行程窗口还远 | 只显示**今天被唤醒的**：出行窗口前约 90 天、团目录新出发日 / 价格变化、点了团页链接 | 被唤醒 → ①；其余交给自动邮件按节奏养，不占面板 |

- **不在面板上**：别再联系、非咨询、同行（同行在邮件里跟，PM 10-29）、终态（已付定金 / 全款 / 已出行归来）——它们在「全部客人」里照样能找到。
- **「挽留」**不单独成列，做成卡片上的标签（曾经热、近期沉默）。
- **产能切线**：每列默认亮出前 N 张（CTS 配置，建议 ① 列 20），其余折叠「还有 X 位排队」，**不消失**（2026-08-02 教训）。
- **阶段（已联系 / 已报价…）不上主面板**：留在卡片详情里，避免同一个人两套说法（PM 10-10「只留一个统一概念」）。

## 5. 大模型做什么、不做什么

**做（两件）**
1. **抽承诺**：从简报 `promises_made`、通话分析 `next_step`、我们发出的邮件里，抽出「我们答应了什么 + 到期日 + 原话出处」。**原话必须逐字在原文里**（沿用 enquiry-screen `acceptNonEnquiry` 的引文校验），对不上就不抽。抽出的承诺第一版需要人点一下确认才进 ② 列（和通话分析复核同一个按钮）。
2. **列内排轻重缓急**：输入 = 这个人最近 N 条往来（我们发的 + 他回的 + 时间间隔）+ 已确认的事实；输出 = `urgency`（high / medium / low）、`why`（一句话，带一条原话出处）、`next_step`（一句话）、`recheck_at`（什么时候再看）。

**不做**
- 不决定谁进不进面板、不决定「排除」（只降不升 / 硬规则在前，模型在后）。
- 不改阶段、不发任何消息、不写客人资料。
- 模型失败 / 超时 / 余额没了 → 列内回退到确定性排序（等得最久的在前），并在面板顶部写一行「今天的排序没有用到 AI（原因）」。

**什么时候跑**：只在这个人**有新动静**时重判（新入站、新出站、承诺到期、唤醒日到），不是每天全量读 1000 多人。复用每小时的简报周期（`brief-cycle`）挂一段，单独 step、单独时间预算（3377 / 3382 两审的教训）。

**花多少钱**（估算，未对账单核实）：每次重判约 1–2k 词元进 / 150 出；按 CTS 每天约 100 人有新动静，Haiku 价约每天 0.1–0.3 美元。

## 6. 怎么知道排得对（Check）

- **影子期 1 周**：模型照常算，结果只写进一张记录表，不改面板。每天把「模型排的 ① 列前 20」和「销售实际联系了谁、客人实际回了谁」对照，周末给 PM 一页：命中率、模型说高但没人联系的、模型说低但客人主动回的。
- **上线门槛**：PM 抽查 20 张卡，理由写得对、没有明显错排 → PM 说「开」。
- **持续**：每周一页对照，模型和销售判断不一致的样本留作校准集（只在客户私有记忆里，不进跨客户经验）。

## 7. 隐私与安全

- 只把「最近 N 条往来」的必要文本发给模型（与现有简报同一外发边界，不新增数据类型）。
- 原话出处必须逐字可查；模型编的引文一律不认。
- 「别再联系 / 退订 / 同行 / 非咨询」硬规则在模型之前判，模型看不到这些人。

## 8. 不做（本稿范围外）

- 自动发信（仍走 127 号的发信通道、人点发送）。
- 7 天 2 封上限闸（另卡）。
- 「每条通话事实可修改」（另卡 `2026-10-29-crm-call-analysis-edit-facts`，A 级）——但 ② 列的承诺确认会复用同一个复核入口，两者一起设计。
- NAL / Oztop 等其它客户（剧本与配置就绪后再开）。

## 9. 拆分（各自判级、各自两审）

| 刀 | 内容 | 级别 |
|---|---|---|
| WP-1 | 只读影子：每次有新动静时跑「承诺抽取 + 列内排序」，结果写进记录表（新表 → 迁移，PM 亲手合）；不改面板 | A（新表 + 模型外发） |
| WP-2 | 列划分（确定性）：把现有 hot/cold 两组换成 4 列的数据形状（接口返回列 + 每列切线），面板仍按旧样式显示，便于对照 | B |
