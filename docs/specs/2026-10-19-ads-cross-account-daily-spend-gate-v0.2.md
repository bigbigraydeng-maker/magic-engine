## 0. v0.1 → v0.2 改了什么（一句话）

**v0.1 提议「在现有判据上乘一个超投余量系数 1.25」。实测之后这个做法被推翻了：乘系数不是第一步，让判据认得出系列级预算才是。**

v0.1 自己在 §5 第 1 条写明「1.25 没有一手证据，实现前必须先用生产数据跑分布」。本稿就是那次实测的结果。

## 1. 实测怎么做的

生产库只读查询，30 天窗口，两处口径都与现有判据对齐：

- 分子（实际花费）：`ad_daily_insights`，`level='campaign'`，与 `circuit-spend-window.ts:63-72` 同口径
- 分母（预算设置）：`ad_entity_snapshots`，**每天只取当天最后一次快照**（快照一天抓 4–5 次，第一次查询把同一天累加了 4–5 倍，已作废重算）
  - 广告组级：`level='adset'` 且 `budget_level='abo'`
  - 系列级：`level='campaign'`

## 2. 实测结果（两条，第二条更要紧）

### 2.1 Meta 确实会超投，实测上限约 1.3 倍

某客户多天出现实际花费高于当天预算设置：1.09 / 1.12 / 1.15 / 1.18 / 1.23 / 1.26 / **1.31**（最高）。
所以「预算设置合计 ≤ 总闸」**不等于**「实际花费 ≤ 总闸」，v0.1 识别的那个差别是真的。

**但 1.3 这个数不能直接写进代码**，三条理由：
1. 样本小：两个客户、三个账户、30 天
2. 分母不可靠：有一天算出 7.7 倍，查下去是那天快照只抓到一个很小的广告组，大部分花费对应的对象没进快照。**用快照当分母本身就有缺口**
3. 这个倍数与投放方式、预算改动频率相关，不是一个固定常数

### 2.2 ~~主要客户的预算全在系列级，而判据只认广告组级~~ —— **这条我写错了，已更正**

**原先写的（错的）**：某客户预算全在系列级（CBO），而 `envelope-facts.ts` 只认广告组级（ABO），所以跨账户闸对它永远返回「判不了」。

**错在哪**（魏征复审指出，本窗口已自行核实原文）：
- `envelope-facts.ts:227-235` 对在投的 **CBO 系列把系列预算计入账户合计**，`:242` 还把 CBO 系列下的广告组跳过以免重复计
- 我引的那句 `budget_level !== 'abo'`（`:244`）在**广告组循环**里，只管「不属于任何 CBO 系列的裸广告组」
- CBO 支持 2026-10-02 就进主干了

**所以**：这道闸**认得出系列级预算**，不存在「对 CBO 客户永远判不了」这回事；原先据此提出的「第一步是放宽钱闸、必须 PM 签字」也站不住，**已撤回**。

实测里那个客户广告组级为 0、系列级 50–117，在真闸下是算得出来的。

**还不知道的**：这道闸至今**一次都没被真正执行过**（`action_runs` 里 `ads.*` 为 0 条），所以它在真实数据上到底判得出还是判不出，没有证据。要查的候选（魏征列、本窗口未查）：`campaign_id` 为空的广告组、CBO 系列那行快照缺失或不在投放状态、账户级币种行缺失、快照新鲜度不够。

## 3. 所以第一步改成什么（已按更正重排）

**第一步不是放宽、也不是加系数，而是先拿到证据：** 让这道闸在真实数据上真的算一次，看它判得出还是判不出。

- 现状：它一次都没被执行过，所以"它会不会误拦"纯属推测
- 怎么拿证据：不需要动判据——写一个只读脚本，用生产数据调一次事实组装那段，把每个客户的结论和原因码打出来。与本窗口今天对熔断探针做的试跑同一个做法，零写入、零 Meta 请求
- 判得出 → 再谈第二步；判不出 → 按它给的原因码逐条修，那些修法大多不是"放宽"，而是补数据

**第二步（有证据之后）：超投余量。** 做法不变，仍然不写死常数；前提仍是先解决 §2.1 第 2 条那个分母缺口。
