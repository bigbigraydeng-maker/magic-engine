# 广告素材补链 · 实现设计 第一节（写死状态定义）· 119 号 · 2026-10-21

> 设计阶段（v0.2–v0.6）已过审；本节把魏征终验的 3 个状态矛盾写死，作为实现的前提。风险级 A：PR 保持草稿，签字钉 SHA，合并问 PM。写代码派 DeepSeek，我审；PR 写轮数与花费。

## 1. 「有效签字」唯一定义（一处定义，所有读取方复用）
- **有效 = 签字哈希 == 工单此刻文件哈希 ∧ `retracted_at` 为空**。已撤回的签字不得被引用，也不会因哈希回到旧值而复活。
- 只在一个读取函数 `creative_binding_is_valid(attestation_id)`（SQL 函数）里实现；所有读取方（核验、启用闸、台账观察、页面展示）只调它，**禁止各自再写一遍**（加一条架构测试：全仓搜不到第二处比较工单哈希与签字哈希的代码）。
- 读取函数读工单哈希时 **`SELECT … FOR SHARE`** 锁工单行，防读到一半被重渲改写。
- 唯一键只约束**未撤回**行：`UNIQUE (work_order_id, final_mp4_sha256) WHERE retracted_at IS NULL`（部分索引条件只引用本行固定列，可行）。撤回后对同哈希重签 = 新建一条带新序号的签字（旧撤回行保留）。
- 撤回只经 `link_retract_v1`；触发器放行 `retracted_*` 的受审写入，其余列一律拒。

## 2. 角色隔离：凭据做不到分离就如实降级
- 六个数据库角色（v0.6 §2 矩阵）**凭据分离的前提**：签字凭据**只存在于独立服务/进程**（管理员会话签字路由所在的进程），与自动登记、回填代码**不在同一个运行环境变量集合里**；若自动登记与签字同属一个 Render 服务且共享环境变量 = 名义隔离，**不得声称数据库层强制**。
- 实现前必须核实并记录：①各角色凭据实际放在哪（服务/变量名）；②Oztop 插件与任何客户站点读不到任何角色凭据；③轮换步骤。**三项里任一项做不到 → 文档与 PR 描述如实降级为「生产方≠验收方只靠流程」，不写成数据库强制。**
- 函数拥有者 = **不可登录专用角色**，函数 `SET search_path` 钉死；签字函数的**操作人身份来自受信会话校验**（路由在管理员会话里取邮箱，函数再对管理员名单校验），不接受调用方自报。
- 常驻权限断言：「**多出的授权 = 红**」，覆盖表权限、函数 EXECUTE、**函数拥有者**、`link_stale_reasons` 表的写入者。
- 新表 RLS 按仓库规则 `FOR ALL TO service_role USING (true)`。与「service_role 无 EXECUTE/无直写」共存方式：RLS 只是行级兜底；**列级/表级 `REVOKE INSERT, UPDATE, DELETE, TRUNCATE … FROM service_role` 在 RLS 之上生效**，service_role 只保留 SELECT；写只能经 DEFINER 函数（函数拥有者绕过 RLS）。迁移里同时写 RLS 策略与 REVOKE，并加断言测试证明两者并存时直写被拒。

## 3. 换创意：意图独立成表，状态机写死
- **意图拆成独立表 `link_swap_intents`**（追加式，不置 `stale_at`）。**只有换创意被确认成功才置关联行 `stale_at`**；因此「明确失败清除意图」不需要把 `stale_at` 清回去，矛盾消失。
- `link_stale_reasons` 追加表只增不改，**只有 `link_mark_stale_v1` 能写**，列入权限矩阵断言。

| 状态 | 触发 | 读取方行为 |
|---|---|---|
| `swap_pending` | 先写意图，调 Meta 之前 | **一律不采信并带原因「换创意进行中」，不得回落到旧创意** |
| 已确认成功 | Meta 明确成功 | 旧行 stale（置 `stale_at`），新关联行生效，采信新行 |
| 明确失败 | Meta 返回错误 ∧ **读 Meta 当前创意编号确认仍是旧创意** | 意图标「作废」（追加记录），采信旧行 |
| 结果未知 | 超时/崩溃/网络断；**「明确失败后读 Meta 当前创意」这一步超时也落入此状态** | 保持 `swap_pending` 的读取行为（不采信+待办） |
| 对账命中旧 | 每日扫描读到线上创意编号 == 旧 | 意图作废，采信旧行 |
| 对账命中新 | 线上创意编号 == 新 | 补写新关联行、旧行 stale，采信新行 |
| 对账命中第三者 | 线上编号既非旧也非新 | 不采信 + 出红色待办（人工看） |
- 手在 Meta 后台/MCP 换创意：不经本路径，靠启用/核验时实时读 + 每日扫描兜底，窗口最长到下一次扫描（如实写入限度）。
