## 1. 现状（9/27 读代码 + 查正式库）

- 入口：`magicengine.com.au/discover`、`/cn/discover`（官网静态页 + `website/functions/api/scout.js` + `report.js`）。填网址 → 抓首页 → 调一次 AI（失败重试一次）→ 屏幕上给 3 条，留邮箱后邮件发全部 5–7 条。
- 正式库 `discovery_leads` 最近 30 天只有 **1** 条——几乎没人在用。
- **问题一（红线）：会出假结果。** AI 调用两次都失败时，`getDemoFindings(market)` 把一套写死的「示例发现」当成这个网站的诊断结果展示，并存进这条线索（之后邮件也会发）。抓不到首页时，提示词里只有「Domain: x. No homepage text available.」，AI 仍会编出几条「发现」。这违反「绝不凭空注入客户业务数据」。
- **问题二：没有任何防刷。** 每次提交都调用付费 AI，没有次数上限、没有月度上限。
- **问题三：结果只有英文，且写死澳新语境**（澳新 GST、财年、本地平台、澳新英语拼写）。国内外贸企业的网站面向海外市场，这套语境不对。
- `/cn/discover` 页面本身是中文，但结果和邮件是英文。

## 2. 改什么（只动官网 `website/`，不动应用、不改数据库）

1. **不出假结果**
   - 删掉「AI 失败就展示示例发现」：两次都失败 → 返回「这次没诊断成功，请稍后再试」，不存线索、不给结果。
   - 抓不到首页文字（且用户没有填「没有网站」那三项）→ 返回「我们打不开你的网站（可能被防火墙挡住），换个网址或稍后再试」，**不调用 AI**。
   - 用户填了「没有网站」三项时照旧诊断，但结果开头标明「以下根据你填写的信息，不是看了网站」。
   - 前端 `app.js` 里「接口失败就展示示例」的兜底一并去掉，改成同样的失败提示。
2. **防刷与花费上限**（记在现有 `discovery_leads.attribution` 里，不加表）
   - 每个访问者 IP（取 Cloudflare 自带、访问者改不了的 `CF-Connecting-IP`，存哈希不存原文）每天最多 3 次。
   - 全站每月最多 1500 次（按本月 `discovery_leads` 行数算；约 US$25–30 / 月）；用到 80% 在今日待办提醒——**今日待办在应用里，这一条本步不做，只在台账卡写上限**（见 §4）。
   - 超限返回中文 / 英文提示「今天的免费次数用完了，明天再来」/「本月免费名额已满」。
   - 同一网址 24 小时内重复提交直接返回上次结果，不再调用 AI。
3. **中文结果与市场语境**
   - `/cn/discover` 提交时带 `lang: 'zh'`：提示词要求全部输出简体中文，邮件（`report.js`）也发中文版（标题、正文、按钮）。
   - 市场语境按网址判断：`.au` / `.nz` 保持现在的澳新语境；其他（`.com`、`.cn` 等）改用「出海 / 外贸」通用语境——不写死任何国家的税率、财年、本地平台，只看网站本身能不能让海外买家看懂、信任、找到联系方式。
4. **接进实验室**：`/cn/lab/` 的「网站免费诊断」卡片从「下一个上线」改成「可以用 · 免费」，按钮「去诊断」→ `/cn/discover`；`/cn/discover` 页头导航与品牌对齐 Magic Engine 工具实验室（不出现「张骞」等内部名）。
5. **线索**：沿用 `discovery_leads`；`entry_page` 已有来源记录，另在 `attribution` 里写 `tool: 'site-check'`，以后和广告体检的线索一起汇总。

## 6. v2 修订（设计审：子牙 4 BLOCKER、魏征 4 BLOCKER、板桥文案）

第二步比预想大：现在线上这个诊断本身有几处漏洞，要一起补齐才能放进实验室。

**A. 不出假结果（补全）**
1. AI 两次失败 → 失败提示，不给结果、不存结果（原 §2.1）。
2. **抓首页必须像一个真网页**：返回 2xx、`text/html`、正文 ≥ 300 字、不是防火墙 / 验证页（特征照搬 `src/lib/site-audit/antibot-detector.ts`）、跳转后仍是同一个网站；否则一律按「打不开」，**不调 AI**。
3. 抓取安全：只许 http/https、80/443 端口，拒绝 IP 直连，最多跟 3 次跳转，最多读 1MB。
4. **前端的假结论一起删**：`app.js` 里按严重程度算出来的「100 分可见度」、写死的「AI 现在没在推荐你」、进度条里「检查 Google / AI 助手 / 社媒」（实际只读首页）、页面简介里的同类说法、「24 小时内送达 / 稍后补发」（没有补发机制）。进度改成「正在读取你的网站首页 → 正在分析」。
5. 提示词：只能写首页上真实看到的内容并说明在哪里看到；没看到写「没找到」；澳新版去掉「至少一条提 EOFY/GST」的强制要求。

**B. 防刷与花费上限（改用已有的原子计数）**
1. 复用数据库现有函数 `zhangqian_rate_limit_consume(类型, 键, 窗口起点, 上限)`（只有服务端能调，一步完成「查 + 扣」）：`site_check_ip` 每访问者每天 3 次、`site_check_month` 全站每月 1500 次，**调 AI 之前先扣**；数据库出错一律拒绝，不放行。不改数据库。
2. 访问者键：Cloudflare 的 `CF-Connecting-IP`（访问者改不了），IPv6 取前 64 位；用带密钥的哈希（密钥由现有服务端密钥派生，不新增环境变量）加当天日期，只存哈希不存 IP；取不到 IP 直接拒绝。
3. 只有真正调 AI 才扣次数：打不开的网站、24 小时内复用都不扣（魏征：误伤主要来自打错网址重试）。
4. 同源检查：只接受官网和 Cloudflare 预览站发来的请求。
5. 输入长度：网址 ≤ 500 字，「没有网站」三项各 ≤ 200 字。
6. 24 小时复用：键 = 统一格式的主机名 + 语言 + 语境；命中时**新建一行**、复制诊断结果并标记复用，绝不把上一个人的线索编号给新访客。

**C. 报告邮件（`report.js`，原设计漏了）**
1. 一条线索只能发一次；每访问者每天最多发 5 封（同一计数函数，类型 `site_report_ip`）。
2. 邮件里所有来自网址和 AI 的内容先转义再拼；不放任何来自网站内容的链接。
3. 语言与语境存进这条线索的 `findings` 里（`lang`、`context`），发邮件时读存下的值；中文邮件（板桥文案）；去掉「张骞」和写死的财年 / GST 句子（只在澳新语境出现）。

**D. 中文与语境**：只有中文页（带 `lang:'zh'`）用「出海通用」语境；英文页保持澳新语境（子牙：按后缀判断会误伤用 `.com` 的澳洲商家）。`app.js` 与 `cn/discover.html` 的按钮、报错、结果区、等待文字、占位符、「🇦🇺 专为澳新」、页脚全部给中文页出中文（板桥文案）。

**E. 隐私说明**：写明「为防止滥用，我们记录访问者网络地址的不可逆编码，最多保留 2 天」——计数表按天窗口，另加清理：过期窗口在下次写入时顺带删除（本步做）。

**留作后续**：Cloudflare Turnstile 人机验证（要在 Cloudflare 后台建站点密钥）；全站月度名额用到 80% 的今日待办提醒（应用侧）；`report.js` 走 Resend 与「发信只走 Gmail」的规矩不一致（记一笔，不在本步改）。

**风险级别改为 B+**：动的是会花钱、会以我们名义发邮件的公开接口——实施后加请狄仁杰做一次攻击验证。

## 7. 检查点（2026-09-27，实施后审 + 预览站试跑之后）

- 代码与测试：分支 `feat/tools-lab-site-check`（PR 2126，草稿），HEAD 731992c4；实施后审 子牙 + 魏征 2 BLOCKER、狄仁杰 2 高 3 中——全部已修；故意改坏 26 处关键判断全被测试抓住。
- **新发现（阻塞上线）**：官网（Cloudflare Pages）的服务端函数很可能**没有配数据库的地址和钥匙**。证据：正式库 60 天内没有任何一条来自官网函数的记录——`discovery_leads` 里没有 `scouted` 行（诊断从没存下过线索），`website_lead_events` 里没有任何官网打点（`lead-event.js` 回 `tracked:false`），只有经应用转发的 `contact_submit`。预览站调用返回 `no_visitor`（取不到数据库钥匙派生的访问者键）。
- 影响：①第二步依赖数据库计数，照现在上线会对所有人返回「暂时用不了」；②第一步官网按钮的点击打点（`lab_*`）一直没记下来，「每周四个数」里的访问 / 点击缺数据。
- 决定（技术，Claude Code 拍板）：**不把数据库总钥匙再放一份到 Cloudflare**（钥匙散落越多越危险）。改为把诊断和发报告的服务端逻辑搬进应用（`app.magicengine.com.au`，钥匙本来就在），官网页面直接跨域调用应用的公开接口；访问者地址用 Render 转发的地址。官网打点同样改为发到应用。现有 JS 守卫逻辑原样移植成 TypeScript，测试一并迁移。
- 下一步：在同一分支上改；PR 2126 保持草稿，改完重新请 子牙 + 魏征 复核与狄仁杰补测。
- **搬迁完成（同日）**：服务端逻辑在 `src/lib/tools-lab/site-check/`（guards / diagnose / leads / report-email）+ `src/app/api/public/site-check/route.ts`、`report/route.ts`；官网 `app.js` 改调 `https://app.magicengine.com.au/api/public/site-check`；`website/functions/api/scout.js`、`report.js` 改为 410，`_shared/site-check.js` 删除。全站日 / 月上限返回「本月免费名额已满」而不是「明天再来」。测试 54 条，故意改坏 30 处关键判断全部被抓住。
- **搬迁后复审（子牙 2 BLOCKER、魏征 1 BLOCKER、狄仁杰 1 高 5 中）全部已修**（同日）：

  2. 访问者地址可伪造 → 只在「转发地址最右边那个非内网地址是 Cloudflare 的地址」时才信 `cf-connecting-ip`，否则拒绝（`visitor.ts`）；IPv6 按前 48 位算一个人；日志记下转发链形状（不含原地址），上线后据此确认。
  3. 抓网页改用平台现成的 `safeFetchText`（`src/lib/net/safe-fetch.ts`：连接锁定到检查过的地址、每跳重新检查、DNS 超时、按网段判断），自写的抓取循环删掉（`homepage.ts`）。
  4. 24 小时复用只认真诊断出来的那一行（复用出来的副本不再被复用），并加全站每天 300 次的复用上限。
  5. 邮件：收件人先归一化（去掉 + 后缀、Gmail 去掉点号）再算「每个邮箱每天 1 封」；全站每天发信上限 100 → 30；任何「x.y」形状的片段一律拆断（含 bit.ly、t.me、中文域名）；防重复标识按「线索 + 邮箱」；认领出错回「暂时用不了」而不是「已发过」；释放失败写日志。
