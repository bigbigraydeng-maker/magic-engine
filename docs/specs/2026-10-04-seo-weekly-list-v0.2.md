# SEO 每周清单 v0.2（缩小版，CTS 先行）

> 状态：设计稿 v0.2。**取代 v0.1 的实现范围**（PM 2026-10-04 回「缩」，要求不过度开发）。
> [v0.1](./2026-10-04-seo-goal-plan-daily-loop-v0.1.md) 作为"将来扩展的完整设计"保留，里面的复审意见、现状审计、数据口径仍然有效；v0.1 里标 A 级的部分（枚举迁移、预算账本、Inngest 日派发、警报升级、降级机制、缺口词、自相残杀体检、拒稿原因、泛化）**本版全部不做**。
> 依据：我查看了 ME 的 SEO Intelligence 页面代码与同一批数据表——页面已具备关键词排名（带谷歌真实曝光/点击）、品牌/非品牌拆分与内容优先级排序、对手缺口（FDE 已填 17 个对手）、逐页 7 天对比。**缺的只是"把这些变成本周几件事，并记下做没做"。**

## PM 版摘要
- **要做的 3 样**：①一个 SEO 目标（谷歌 28 天点击 ≈1,070 → **1,340**，到 2027-01-03，PM 已选进取档）；②每周一自动出一份 3～5 件事的清单；③每周核对"事情真做了没"，写进周报一行进度。
- **不做**：新建表/改数据库结构、花数据费、定时工作流、自动改客户网站、每日拆活。全部由人做，系统只出清单和核对。
- **风险级 B**（无迁移、无付费调用、无对外写）。若实现中需要改 `kernel/boundaries.ts` 名单则升 A 并停。
- **诚实边界**：CTS 14 天只有约 3 万曝光，**不能证明某件事带来多少点击**。只报三样：做了没（核对）、目标词排名动没动、整站点击趋势（不归因）。

## 一、每周清单怎么出（零新发现代码、零付费）
每周一（`Pacific/Auckland`）为 CTS 挑 **≤5 件**，来源全部是页面已有的数据与函数：
| 来源 | 判据 | 清单项类型 | 谁做 |
|---|---|---|---|
| 排名第 4～30 且月搜 ≥100 的非品牌词（`keyword_snapshots` 最新周快照；复用 `prioritizeContentKeywords` 的意图排序与品牌别名过滤） | 按"搜索量 × 距上一档差几名"排序；同词 90 天内已出过不再出；品牌词/竞品品牌词排除 | `加强某页`（补小节/加内链/往主页面汇链）或 `写新文章`（走现有周博客管线，人审后发布） | **人**（系统只给 what/how/href） |
| 逐页对比里曝光高、排名≤10、点击率偏低的页（`page-health` 同源 `gsc_page_daily`，近 28 天，跳过最近 3 天，曝光≥300） | 点击率低于排名曲线 0.6 倍 | `加强某页`（先看标题是否 >60 字符被截断、是否被自家另一页分食） | **人** |
- 只有这**两种**清单项类型，不做"机器自做诊断"（那需要付费查询）。每项写清：**what**（哪个词/哪页、现在第几名、月搜多少，数字来自快照并带取数日期）、**how**（具体怎么改）、**href**（直达页面/后台），并按[能力图谱](./2026-10-04-seo-specialist-capability-map-v0.1.md) §3 加三栏（借鉴自高星开源 SEO skill 的通用做法，不是新系统）：
  - **证据与置信度**：每个数字标来源与取数日；结论标 `确认`（来自快照/GSC/DataForSEO 的数）/ `很可能` / `假设`（例如"哪个自家页在排这个词"没查就写假设，**不当事实**）。
  - **固定诊断顺序**（写进 how 的第一步）：①这个词/页收录了吗 → ②是不是被自家另一页分食 → ③标题是否 >60 字符被截断 → ④内容是否覆盖该词意图。前一步没通过就不谈后一步。
  - **失败判据**：写明"28 天后该词排名没上移≥3 名，判没起效"，对应下面第三节的排名口径；**不写点击归因**。
- 同主题的多个说法（如签证 3 个近义说法）**合并成一项**（按搜索意图相同判断），不拆成多项占名额。
- **不碰**：`seo-meta/cycle/`（标题描述自动改）管的页和保护名单（`seo_config.meta_cycle_protected_slugs`、近 30 天 `seo_meta_log` 改过的页）本周不派；`seo_config` 只读。
- 缺数据（量/难度/排名缺任一项）→ 该词跳过并在回执写原因，**不当 0 放行**。
- 清单上限与阈值（5 项、≥100、≥300、0.6、在途 ≤8）放在代码默认值里，可被 `clients.seo_config.loop.*` 覆盖（缺省即默认；**写覆盖值是另一次 PM 点头的生产写，本版不写**）。

## 二、清单落在哪（复用现有表，不新建）
- **目标**：`goals` 里建一条 active SEO 目标。需要给 `PRIMARY_METRIC_CATALOG` / `autoFetchMetricValue` 补指标 `seo_gsc_clicks_28d`（取 `gsc_page_daily` 近 28 天全部页点击求和，跳过最近 3 天；基线 1,070 用**同一函数重算后**写入）。已有 GEO 新指标先例。
- **清单项**：`execution_items`（`source='zhuge'`，`steps_json.loop='seo_goal_v1'`，`initiative_id` 挂该目标下 1 条计划项，`due_date` 周一到周五错开）。写库只通过 `zhuge/action-persister.ts` 新增导出函数（该文件已在 Kernel 架构测试的历史写入名单里，**不新建写 `execution_items` 的文件**）。
- **三处旧机制必须避开（v0.1 §6.3-6，均为具体条件）**：①清单项**顶层**写 `keyword`/`url`（旧去重键只读顶层，否则互相 supersede）；②`card-expiry.ts` 的 14 天自动作废排除 `steps_json.loop` 非空；③周上限只数带 `rule_id` 的巡检卡，清单项不占额度。各配一条专测。
- **调度**：新增 `/api/cron/seo-weekly-list`（周一）+ **同一个 PR 里**加 `render.yaml` 条目 + 登记 `cron/registry.ts`。**不用 Inngest**，理由（CLAUDE §3 例外须写明）：无对外副作用、无跨步骤异步，只读自家表并写自家表；替代回执 = `cron_run_logs`（任务名 `seo-weekly-list`，含出了几项/跳过几项及原因/取数日期）。
- 路由支持 `?dry_run=1`（只返回将出的清单，不写表）。

## 三、核对（每周，随清单任务一起跑，零新抓取）
| 清单项 | 怎么核对 | 结论 |
|---|---|---|
| 写新文章 | `blog_posts` 出现 `primary_keyword/keyword_volume/keyword_kd`（现有列名）与清单一致且 `published`，网址 HEAD 返回 200 | 通过 / 不过 / 没测成（网址不通） |
| 加强某页 | 取每周站点抓取（`site-audit-weekly` 已存的 `client_site_pages` 正文）对比，清单指定的链接/小节是否出现；抓取早于人报完成时间则"没测成" | 通过 / 不过 / 没测成 |
- 结论**四态不混**：通过 / 不过 / 没测成 / 过期放弃。人点"完成"**不拦截**（不改执行卡接口），但周报里分开写"人报完成 N / 系统核对通过 N"，**只有核对通过才算完成**。（已知遗留：门户的完成统计可能含"人报完成"，实现窗口要在 PR 里写明；不为此改接口。）
- 14 天仍未动 → 置 `skipped`（`steps_json.skip_reason='expired_no_action'`，并写一条 `execution_logs` status_change，作者用 `system`——该表 author 只允许 `system/luban/fde`），进周报"放弃清单"，每行带 what/how/href。
- **目标词排名**（三态：移动≥3名 / 没动 / 没测成）：只对"写新文章/加强某页"且已核对通过的词，**清单项创建当天记基线**（取最新周快照排名并写明取数日期，**不做现场付费查询**），T+28 天对比下一次周快照；快照里查不到该词（只存当前有排名的词）→ 记"超出快照范围"，不当"掉出榜"也不当"没测成"。

## 三·五、速度：怎么比"传统一周一周磨"更快（不放松任何闸门）
**传统节奏的慢点不在分析，在"人从零开始写、写完再等人看、做完很久才知道有没有做成"。** 本版把能提速的地方放在这三处，**都不新增系统**：
1. **周一清单秒出，且已带好诊断**：数据全在库里，清单在周一早上自动生成，固定诊断顺序的前两步（收录、被自家别页分食）的结论一并写好，人不用再花半天"查是什么问题"。
2. **人只批、不从头写（下一步 S3，本包不做）**：对"加强某页 / 写新文章"，由系统用已有的内容引擎先**预写好改动稿**（补哪一小节的文字、加哪几处内链的锚文字、标题备选），人只做"看一眼、点头"。预写必须过现有闸：内容先对官网原文核对、不编价格日期（CLAUDE §8）、事实核对硬规则复用 `hard-fact-check`；改线上页仍走现有授权，**不因为快而放松**。
3. **做完当周就核对**：核对随下周一清单任务一起跑（不等 14 天）；"页面真改了 / 文章真上线了"周内就知道。**排名有没有动要 28 天才能判，这个提速不了**，不假装。
**怎么证明变快了**（零成本、可查）：记分牌加一个数——**"从出清单到核对通过的中位天数"**。目标是第一个月把它压到 ≤7 天（这是目标，不是已测得的数；传统对照没有实测数据，不编）。若数字不降，说明卡在人这一步，再决定要不要做 S3。

## 四、周报与提醒（不新建面）
- 周报（`weekly-seo-report` 既有）新增一栏：本周清单 N 项 / 人报完成 / 核对通过 / 没测成 / 过期放弃 / **出清单到核对通过的中位天数**（逐条带 what/how/href），目标进度（28 天点击 vs 1,340，周环比，**仅趋势、不归因**）。
- 今日待办：**不新增**（沿用"只留五类"：清单走周报；只有目标偏离或清单没出，才由既有 `pm-daily-todo` 的开发欠账栏提示"本周 SEO 清单没生成"）。

## 六、Reuse / 换客户 / 不做
- **复用**：`keyword_snapshots`、`gsc_page_daily`、`prioritizeContentKeywords` 与品牌别名、`clients.brand_aliases`/`competitor_domains`（本版不用对手，留作后续）、`goals`/`initiatives`/`execution_items`/`execution_logs`、周博客管线、`site-audit-weekly` 抓取、`weekly-seo-report`、`pm-daily-todo` 欠账栏、`cron_run_logs`。
- **platform-shared 新增**：周清单挑选与核对逻辑、一个目标指标。**client-specific**：目标值、阈值覆盖、保护页（均走配置/`goals`）。共享代码里无 CTS 名字或 ID。
- **换客户 / 换行业测试**：换成地产客户——判据只用量/排名/曝光/点击率，无行业语义；近机会词月搜门槛 ≥100 对本地长尾偏高，故做成可覆盖默认值而非常量。
- **不做**：新表/迁移、付费调用、Inngest、自动写客户网站、每日拆活、缺口词、自相残杀体检、预算账本、警报升级与降级、拒稿原因、第二个客户、对 `seo-meta/cycle/` 与 `seo_config` 的任何改动、承诺"SEO 动作带来流量"。
