## 0. 给 PM 的一页话

- **做完你会看到**：员工在**新线索**资料里记一笔，备注里写了「目录 / catalogue」，保存框下面会**自动勾上**「30 分钟后自动发 2027 目录」。员工不动就照发；觉得不对可以取消勾选，或者在 30 分钟内点「先别发」。信从 info@ 发出，跟 11-10 那 22 封一样，客人回信直接回到销售收件箱。发出后客人挂上「AI 跟进中」。
- **夜里不发**：晚上 9 点到早上 8 点（客户所在时区）记的，等到早上 8 点再发。
- **不会发的**：别再联系的、阶段不在名单里的（CTS 只发「新线索」）、**这一版目录已经发过的**、本周已收满 2 封系统邮件的、标了「不自动发目录」的人。不发的都会记下原因。
- **要注意的一点**：挂上「AI 跟进中」之后，客人第二天起会从「今天先联系」名单里挪到「交给系统跟」。所以误发不只是多一封信，还可能让人少打一个电话。上线头两周，每天的汇总里会列出每一条「命中的原话」，方便你和员工看有没有误判。
- **授权只认你本人**：跟欢迎信同一套「授权」页，只有你能批，带有效期；模板改了，授权自动作废，要你重批；随时能撤销，撤销后立刻停。每天最多发几封由你定。
- **每天早上**：名单邮件改成「昨天自动发了几位、几位没发、为什么」；每封都能在「发信统计」页看到，标明「自动发」。
- **要你亲手做的事**：发信记录表要改结构（加「是不是自动发的、凭哪份授权、哪条备注触发」），按规矩这一刀要你亲手合。

## 1. 路线：发件走现有「一键发目录」，授权复用 ME 自己发信的常设授权

| 比较 | 现有一键发目录 | ME 自己发信（triggered-send） |
|---|---|---|
| 发件箱 | info@（Microsoft 邮箱，回信进销售收件箱） | Resend 新域名，Reply-To 指回现有邮箱 |
| 每周 2 封上限 | 跟员工手发同一张记录表 | 写出站触点，员工手发那条路也计入（口径一致） |
| 授权 | 只有「人点的发送」，没有常设授权 | 有现成的常设授权：PM 本人批、有效期、模板指纹、可撤销、每日名额在数据库里锁着数 |
| 现在能不能对客人发 | 能 | 不能：正式名单卡在三件事上（台账卡 `2026-11-10-me-send-gate-formal-sending-prerequisites`，12-01） |
| 要改数据库 | 发信记录表要改（见 §4，不是一行约束） | 触发名白名单要改 |

结论：**发信用现有一键发目录**（马上能对真客人发、发件箱不变），**授权复用** `src/lib/messaging/triggered-send/standing-authorization.ts` 的判定（PM 本人批、有效期、模板指纹、可撤销），而不是在「发信设置」里加一个任何全局管理员都能打开的开关。

## 2. 规则（全部是客户配置，共享代码不写客户名、不写阶段名）

授权提案里写死一份规则快照（批准后不能改，改了要重批）：

| 字段 | 含义 | CTS 初始值 |
|---|---|---|
| `stageKeys` | 只对这些阶段 key 发（营销动作只作额外加严：不是 `nurture` 一律不发） | `['new']` |
| `hintKeywords` | 备注里出现这些词，保存框**预先勾上**（只是提示，最终由员工这一次保存决定） | `catalog`、`catalogue`、`目录` |
| `delayMinutes` | 保存后等多久才发 | 30 |
| `quietHours` | 不发的时段，客户时区 | 21:00–08:00 |
| `dailyMax` | 每天最多自动发几封（数据库里锁着数，「结果不明」也算） | 待 PM 定 |
| `pilotRecipients` | 试跑期只发这些地址（只管自动发，不影响员工手发） | `hello@magicengine.cloud` |

不自动发目录的人：联系人上的标记「不自动发目录」（页面能看见、能撤），不放在配置里的名单。现在那 3 位迁过去。

## 3. 怎么跑（Inngest，CLAUDE.md §3）

1. **记一笔接口**（`src/app/api/clients/[id]/crm/touchpoints/route.ts`）新增可选字段 `autoCatalogue: true`。只在这次真的新建了备注（`result.created === true`）时，发事件 `crm.catalogue_auto.requested`，**事件 id 固定为 `crm_catalogue_auto:<备注编号>`**（Inngest 去重）。事件里快照：客户、客人、备注编号、员工邮箱（取 `logged_by`，为空则不发并写原因）、**当时的收件地址**、授权编号、规则快照指纹。
2. **函数** `crm-catalogue-auto-send`，按客户并发 1（`concurrency: { key: client_id, limit: 1 }`）：
   - `sleep` 到 `delayMinutes`，再顺延出夜间免打扰时段；
   - 醒来逐项重读，任一读不到 = 不发：授权仍有效且模板指纹没变；备注还在、没被「先别发」；客人仍在名单阶段、没有「不自动发目录」标记；**收件地址跟事件里快照的一样**；**这一版目录对这位客人（和这个地址）没发过、没有结果不明的**（新关口，见 §5）；数据库里抢到今天的名额；
   - 调 `sendCatalogueAndTakeOver`：`requestId` = 固定命名空间的 UUIDv5(备注编号)；`actorEmail` = 记备注的员工；`expectedRecipient` = 快照地址；另外带上「自动发 + 授权编号 + 备注编号」写进回执。
3. **兜底扫描**（每小时）：只扫保存时间早于「等待时间 + 15 分钟」、勾了自动发、却既没有回执也没有跳过记录的备注，补发同一个固定 id 的事件。按仓库惯例这是新增定时函数，改定时任务登记表，按 A 级走；同一单当场试跑（只发试跑名单）。
4. **跳过和撤回也有记录**：在发送前就被拒的（资格、已发过、名额满、撤回、地址变了、授权失效）写进新的「自动目录记录」表（客户、客人、备注、结果、原因、时间），每天汇总读它。

**额度**：自动发的信记在记备注那位员工名下，会占用他自己手发的每小时 30 封 / 每天 100 封额度，也占邮箱每天总量。`dailyMax` 设在这之下，汇总里写明。

## 4. 发信记录表要改的不止一处约束（A 级，Ray 亲手合）

同一单里一起改，读的一侧必须同时改，否则一条自动回执会让这位客人之后所有模板信都失败：

- 库：`auth_basis` 放开 `standing_rule`；加 `authorization_id`、`source_touchpoint_id` 两列（自动发必填，人点的为空）。
- 写：`toInsertRow` 明写 `auth_basis`；`SendTemplateEmailArgs` / `SendCatalogueArgs` 带上来源。
- 读：`receipt-store.ts` 的行解析认新取值；`findSentTemplateReceiptsSince`、`listRecentReceipts`、`listReceiptsSince`、`findReceiptByRequest` 全部回归测试。
- 类型和事件：`types.ts` 的 `authBasis`、`crm-email-events.ts` 的事件内容不再写死 `human_click`。
- 统计页：「发信统计」每行标「自动发」。

## 5. 新关口：同一版目录对同一位客人只发一次

现有链路没有这道关（资格只看别再联系 / 阶段 / 先放一放；「AI 跟进中」员工收回后就不挡了）。新关口按客人和地址查「这一版目录发过或结果不明」，有就跳过。员工手点按钮也走这道关（手点时给出提示并允许确认后再发，具体做法在那一刀再问 PM）。

## 6. 风险

- **A 级**：对客人发信 + 改数据库 + 新的自动发信路径 + 新定时函数。
- **误判**：关键词只用来预先勾选，最终由员工这次保存决定，所以否定词不再是唯一防线。头两周每天列出命中原话，记下「员工取消勾选」「先别发」「客人回复说已经有了」的次数，算误判率。
- **部署顺序**：设置 / 授权新字段先部署代码再写配置，避免旧代码读不懂新配置（`settings.ts` 遇到不认识的字段直接拒）。
