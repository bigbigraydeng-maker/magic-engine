# 写了「跟进目录」备注就自动发目录 · 设计稿 v0（2026-11-12，待审，未开工）

> 窗口：76（CRM）。起因：PM 11-12 问「为什么今天（11-11）写了要发目录的人没发出去」。查实不是程序出错：
> 备注本身不触发发信；11-11 那 7 条备注、11-10 剩下的 10 位新线索都还没发。PM 回「做自动」→「开始」。
> 本稿只是方案，代码一行没写。按规矩：每一刀开工前先跟 PM 讲清「做完你看到什么变化」，PM 点头才做。

## 0. 给 PM 的一页话

- **做完你会看到**：员工在**新线索**的资料里记一笔「跟进目录 / follow up catalogue」，系统**30 分钟后**自动从 info@ 发出 2027 目录（跟 11-10 那 22 封一样的信、一样的发件箱），发出后客人挂上「AI 跟进中」。这 30 分钟里员工可以在资料页点「先别发」撤回。
- **不会发的**：别再联系的、阶段不是新线索的、已经发过目录的、本周已收满 2 封系统邮件的、你说过不发的人（现在 3 位）、过了「先放一放」日期还没到的。不发的会写明原因。
- **每天早上**：名单邮件不再让你挑编号，改成「昨天自动发了几位、几位没发、为什么」。发出的每一封都能在「发信统计」页看到。
- **开关在你手里**：只有你本人在「发信设置」里打开才会开始发；随时能关，关了立刻停。每天最多发多少封也由你定。
- **要你亲手做的一件事**：有一处要改数据库的发信记录表（现在它只认「人亲手点的发送」），按规矩这一单要你亲手合。

## 1. 为什么不走「ME 自己发信」那套（更正 11-12 上午的说法）

上午我说要走发信窗口在做的「ME 自己发信」（triggered-send）。细查后改走现有的「一键发目录」那条路，理由：

| 比较 | 现有一键发目录（本稿选这条） | ME 自己发信（triggered-send） |
|---|---|---|
| 发件箱 | info@（销售的邮箱，客人回信直接回到销售收件箱，跟 11-10 那批一致） | Resend 新域名发件，回信要另配 |
| 每周 2 封上限、退订、别再联系、链接点击统计 | 已有，和员工手发同一套 | 已有，但和员工手发是两套账 |
| 要改数据库 | 发信记录表放开一个「常设规则」的取值（一行约束） | 触发名白名单也要放开（同样要改库） |
| 能不能马上对客人发 | 能（这条路本来就在对真客人发） | 不能：正式名单还卡在「旧群发退场、账号绑客户」三件事上（台账卡 `2026-11-10-me-send-gate-formal-sending-prerequisites`，verify_by 12-01） |

两条路都要改一处数据库约束；选现有这条是因为发件箱、回信和每周上限都跟员工手发同一套，而且不用等另一套正式开放。

### 1.1 复用常设授权的硬约束（发信窗口 11-12 回复，按此执行）

- **能直接用**：授权页的门和授权人（`requireTriggeredSendAdmin` + `isTriggeredSendApprover`，名单只放 PM 本人）；授权表「一份生效 / 一份待批」唯一索引按 `(client_id, trigger_key, channel)` 分，加新触发不跟欢迎信抢位；`live-switch.ts` 的写法。
- **要改**：
  1. `judgeStandingAuthorization` 现在用欢迎信的规则解析器和关口版本，目录规则进去一律判无效。拆成两层：通用层只管撤销 / 没批 / 没武装 / 过期 / 规则指纹 / 模板指纹；规则解析和关口版本由各触发自己传入；欢迎信那层原样包一层、行为不变（它的授权测试、真库 46 项、28 处变异原样全绿）。**这一小刀由发信窗口来拆**（他提出可以做），76 不碰。
  2. 授权表 `trigger_key` 只许 `welcome`、`channel` 只许 `email`：加 `catalogue` 要迁移（A 级，Ray 亲手合）。`account` 列现在是 Resend 账号名；目录走 info@，这一列对目录写成发件邮箱的连接标签，或另加字段（第 2 刀定，跟发信窗口对）。
  3. 授权事件 `crm.triggered_send.authorization_changed` 的 `trigger_key` 类型写死 `welcome`，要放开，消费方按触发分。
  4. 授权页和四个命令（propose / authorize / revoke / status）现在只认欢迎信。按触发拆开前，**先跟发信窗口对文件归属**（`authorization-*.ts`、`welcome-letter/` 组件他正在写），不两边同时改。
- **不做**：
  - 目录信**不记进** `triggered_sends` 账本：它是「同一触发同一地址终身一次」，下一版目录就发不出；回执和退订是 Resend 那套；而且每周上限按地址读这张表，目录信又记在 CRM 发信记录表里，会被算两次，白白吃掉客人「7 天 2 封」的一个名额。每日名额照 §3 在 CRM 自己的表里锁着数。
  - 不复用欢迎信的总开关 `TRIGGERED_SEND_LIVE / TRIGGERED_SEND_CLIENTS`（开欢迎信试跑就等于开了自动目录）。另起一对 `CATALOGUE_AUTO_LIVE / CATALOGUE_AUTO_CLIENTS`。
- **退订（合规）**：自动发的目录是营销邮件，新西兰《垃圾邮件法》要求带能用的退订。info@ 这条路现在只在发信前**查**客人有没有退订，信里**没有**一键退订链接。第 3 刀要给自动目录信加退订链接（复用 ME 一键退订入口的做法，但令牌指向 CRM 发信记录，不指向 `triggered_sends`）；没有退订链接就不开自动发。员工手发的目录信要不要也加，另问 PM。

## 2. 规则（全部是客户配置，共享代码里不写 CTS）

放进现有的「发信设置」（版本化、只有全局管理员能改）新增一块 `autoCatalogue`：

| 字段 | 含义 | CTS 初始值（PM 定） |
|---|---|---|
| `enabled` | 总开关 | false（PM 授权时打开） |
| `noteKeywords` | 备注里命中哪些词算「要目录」（不分大小写） | `catalog`、`catalogue`、`目录` |
| `noteNegations` | 同一条备注里出现就不算（防「已经发了目录」「不要目录」） | `已发`、`发过`、`sent`、`不要`、`don't`、`do not` |
| `stages` | 哪些阶段才自动发 | 只有新线索（按阶段的营销动作判，不按阶段名字） |
| `delayMinutes` | 记完备注后等多久才发（给员工撤回） | 30 |
| `dailyMax` | 每天最多自动发几封 | 待 PM 定（建议 30） |
| `excludedContactIds` | 永久不自动发的人 | 现在那 3 位（原来写在每日名单任务里） |

之后照跑现有一键发目录的全部关口：发信设置有效、目录没过期、资格（别再联系 / 阶段 / 先放一放）、模板、渲染、每周上限、冷却、白名单、链接检查、目录关口。任何一步读不到数据 = 不发。

## 3. 怎么跑（Inngest，CLAUDE.md §3）

1. **记一笔接口**写完员工备注后，如果命中关键词，发事件 `crm.catalogue_auto.requested`（客户、客人、备注编号、记的人、时间）。只发事件，不在接口里发信。
2. **函数** `crm-catalogue-auto-send`：先 `sleep` 到 `delayMinutes`；醒来重读：开关还开着？这条备注还在、没被撤回？客人还符合规则？今天还没到 `dailyMax`？然后调现有 `sendCatalogueAndTakeOver`，请求号用备注编号推出来（同一条备注重放只发一次），发件人记成「常设规则 · 由 <记备注的员工> 触发」。
3. **兜底扫描**：每小时扫一次「过去 24 小时命中关键词、但没有任何发送记录或跳过记录」的备注，补发事件（防事件丢失）。新增定时任务时同一单加 `render.yaml` 条目，当场试跑。
4. **回执**：每封自动目录都有发送记录（现有表，`auth_basis='standing_rule'`）；不发的写一条跳过记录（原因、备注编号）。每天早上的名单邮件改成读这些记录出汇总。

**撤回**：资料页那条备注旁边显示「30 分钟后自动发目录 · 先别发」，点了写一条撤回记录，函数醒来看到就跳过。

## 4. 风险与要人决定的事

- **风险级 A**：对客人发信（不可逆外发）+ 改数据库约束 + 新的自动发信路径。数据库那一处：Ray 亲手合。代码单：两位审查员（Opus）审，PM 本人回「合 <单号>」。
- **误发的主要来源是备注写法**：例如员工写「客人说已经有目录了」。关键词 + 否定词只能挡住常见写法。上线头两周每天的汇总里列出「命中的原话」，PM / 员工发现误判就加否定词；误判率记下来（PM 11-03 原则：AI / 规则判不准就量准确率、拿人纠正改它）。
- **待 PM 定（一次问一件）**：① 每天最多自动发几封；② 30 分钟够不够；③ 那 16 位还没发的，是等上线还是先手动发。

## 6. 层级判定（Inline）与 Reuse

- 层级：现有 CRM「一键发目录」能力的自动触发，L1 能力扩展，不新增支柱；规则全部进客户配置（L4）。
