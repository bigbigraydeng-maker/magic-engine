# 新建/重建广告组「零消耗不干等」规则 · 设计要点 v0.1 · 只设计，未写代码 · 119 号 · 2026-10-21

> 来源：PM 2026-10-21 经 74 转述——「新建/重建的广告组投出约 2–3 小时仍零消耗 = 有问题，不要干等（business cannot wait）」。并入部门草案（`ad-agent-departments-split-v0.1.md`）：**⑥诊断部**发现、**①总控**出请求、**③预算与授权部**过闸、**⑤投放部**执行、**⑦追踪与回执部**记回执与根因。风险级 A（新建类花钱动作、碰内核）。**本稿不构成对 `bounded_auto` 或任何自动花钱的授权。**
> 事实依据（74 提供，未由我独立复核）：10-21 01:16 NZ 重做的 v2 三个组都在正常消耗（WA名单相似 $21.19/558 曝光、WA看过视频 $5.61/183 曝光、播放量 $5.39/973 曝光），说明「重做」能解决那批 preparing 零消耗。

## 1. 触发（⑥诊断部，只读）
- 条件：广告组 `effective_status=ACTIVE` 且 `delivery` 正常，**创建/激活后 ≥ 2 小时**，且**花费 = 0 且曝光 ≈ 0**（初值：曝光 < 20）。
- **必须实时读**（经连接器直读 Graph，别用 6 小时同步的快照表，否则最坏晚 6 小时才发现）；读不到 → 出「读不到」待办，不当作正常。
- 窗口：**2 小时**起先自检并出待办；**3 小时**仍零消耗才进入「可重建」（PM 说「约 2–3 小时」，两个数做成配置，不写死）。

## 2. 先自检一轮（⑥，只读，约 1 分钟内完成）
逐项取证并写进回执：①审核状态/被拒原因（`effective_status` 如 `WITH_ISSUES`、`delivery_sub_status`）；②受众规模是否过小；③日预算是否低于该目标的最小花费；④付款/账户状态（`account_status`，如 3）；⑤是否因**重复激活**卡在 preparing；⑥Meta 案件限制（如 1815089 类）。
- **有明确可修原因** → 出对应待办（一句话 what/how/href），**不克隆**。
- **账户级原因**（同账户所有新组都零消耗，或账户状态异常）→ 不克隆（克隆不会好），出红色待办。

## 3. 无明确可修原因 → 一次性「克隆重建」（⑤执行，属 `new_spend` 类）
- 新建同配置广告组（新 ID）+ 新广告，**旧的先暂停**（旧的本来零消耗，先停不损失，也保证总额不增加），再建新的；新建失败则旧的保持已停，出红色待办。
- **同一广告组谱系最多重建 1 次**；重建后 2 小时仍零 → **不再重建**，出红色待办并记「根因候选」。
- **每个账户每天最多重建 N 次（初值 3）**，防止账户级问题引发循环克隆。
- 新对象带来的连带事项：**新 `ad_id` 要写进 `ad_creative_links`**（`link_source`/`rebuild_of` 指向旧行）；沿用同一帖子/素材（不重新传素材）；命名带 `rebuild1` 后缀；utm 保持一致。

## 4. 与现有闸/内核的衔接（不另起一套）
- 重建是 **`new_spend`**，且现有内核**没有「克隆广告组」动作**（唯一新建类是 `ads.add_retargeting_adset`，不能借用）→ **需新注册动作**（暂名 `ads.rebuild_adset`），属 **A 级内核改动**，走子牙+魏征，列入实现前第一步。
- 必须过：3010 计划闸（落在已批步骤内）、2999 日预算闸（旧的先停，合计不增加）、客户日上限（含内核信封）。**暂停旧组属收类，永远放行。**
- **按现状（CTS 为 `observe` / `require_approval`）：这条规则只会产生「待批准」请求 + 红色待办，不会自动重建。**「不要干等」在 `observe` 下落地为：**2 小时就出一键批准的待办**（带自检结果和「一键重建」入口，PM 点一下就执行），而不是等人发现。**自动重建只在 `bounded_auto` 客户且开关打开时生效**，开关与切换仍只由 PM 本人决定。

## 5. 回执与根因统计（⑦）
每次重建写机器可读回执：旧 id → 新 id、触发时间、自检结果（逐项）、是否账户级、判定人（自动/PM 点击）、重建后 2 小时结果。**用这些回执长期统计零消耗根因**（审核卡住/预算过低/重复激活/账户状态/不明），数据足够后把「不明」的找出规律，目标是减少克隆、找到根本原因。事件名建议 `adset.zero_spend.detected` / `adset.zero_spend.self_check` / `adset.rebuilt`，走 Inngest。

## 6. 未核实 / 实现前第一步
①各自检项在 Graph 上对应哪些字段（`delivery_sub_status`、拒审原因、最小花费规则）；②「重复激活卡 preparing」的判据；③克隆需复制哪些设置（受众、版位、出价、学习期）才算「同配置」；④内核新动作与信封口径；⑤曝光≈0 的阈值与创建时间的取数来源（`created_time`/激活时间）；⑥2h/3h/N 的配置位置（计划步骤 or 客户配置）。
