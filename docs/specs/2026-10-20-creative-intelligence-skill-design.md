# 广告 Agent 的「素材智能」技能（creative intelligence）· 设计稿 v0.1（只设计，未写代码）

- 日期：2026-10-20　窗口：119　风险级：**A**（会影响「哪条素材被投」→ 碰钱；本稿只出建议，不执行，真要做按 A 走）
- 来源：PM 10-20 夜：视频 Agent 现在属于广告 Agent 的一个技能——去了解、整理好看/好用/流量高的视频，并不断训练。
- 状态：草稿，待 74 号带去过平台层级门，再送子牙+魏征审。

## 0. 先说结论（查了现有，不是从零设计）

1. **这不是新能力线，是广告支柱里「素材」这一段的补全。** 仓库里已经有一份 **Creative Lifecycle Engine v0.2 设计稿**（`docs/specs/2026-07-11-creative-lifecycle-engine.md`，子牙起草，三视角评审过：发布入池 → 证据够了判生死 → 晋升 → 疲劳退役 → 尸检反哺生产）。**它只有设计稿，代码里没有实现**（我 grep `creative_lifecycle` 零命中；现存的只是分发端试点 `winner-reel-sync`）。本稿的建议是：**素材智能 = 把 Lifecycle 稿里「判生死 + 尸检反哺」这一半落成只读建议技能**，不另起一套。
2. **最大的真缺口不是算法，是「广告 ↔ 片子」对不上。** 生产库 `ad_creative_links`（建广告那一刻记下「这条广告投的是哪条片」）**只有 4 行**。没有它，就算算出「哪条广告好」，也没法说「所以该再做哪种片子」，更学不出「哪种内容带来真买家」。第一刀必须先补这一环。
3. **数据面其实比想象的好**：`ad_daily_insights` 的 `level='ad'` 行已带 `video_3s_views / video_thruplays / video_p25…p100 / video_avg_watch_seconds / ctr / frequency / cpm`（CTS 近 618 行）。**但最新数据日停在 10/10**（回填没跑到新户，与作战地图修的是同一个问题）——**数据不新，任何榜单都不能写成「现在」**。

## 1. 平台层级判定（Inline）

- 层级：**L1 能力扩展，挂在既有「广告」支柱下**（素材/创意这一段）；不新增支柱、不新增能力线。行业差异（旅游的好片长什么样）进 **L2 行业 Playbook**；CTS 私有结论进 **L4 客户私有记忆**。
- 红线 1（禁包装升级）：叫「素材智能」可以，但它**只读、只出建议**，不是「执行手」，也不是独立能力线；对外文案用大白话「看哪条视频好用」。
- 红线 3：单客户（CTS）需求默认落 L4/L2，**登记为 L1 候选**（Low bar）；升 L1 要 ≥2 个付费客户分属不同行业提同一需求，或同一逻辑在 ≥3 客户处复制。眼下只有 CTS 一个，所以**第一刀的共享代码只做「纯函数+通用数据结构」，不写旅游/CTS 的判断规则进共享代码**。
- 换客户测试：把 CTS 换成 NAL（物流），「视频×受众的好用榜」「疲劳预警」代码不用改；「什么算好片」的阈值要换（物流看消息数不看留资，见广告行业手册）→ 阈值必须是 Playbook/配置，不是常量。
- 待 PM/74 拍板项：是否把本技能作为「广告支柱下的素材能力」登记进 `platform-candidates.md`（建议是）。

## 3. ② 输出什么、给谁

**原则：给 AI 查、不给人看；人只管预算与授权（PM 10-16 总原则）。** 输出是**机器可读的建议记录**（含证据与新鲜度），人看到的只有已经收敛的待办项。

每天（只读，数据新鲜才出）：
1. **好用视频榜**：「视频 × 团/主题 × 受众」维度，综合 完播率(thruplay/展示)、均看时长、CTR、单次结果成本、最低样本量。样本不够标「样本不足」，不排名。→ 写入广告健康页的一块（给 74/105 看）。
2. **疲劳预警**：沿用现有频率红线（`FATIGUE_FREQUENCY_HIGH`）+ 完播下滑；**只预警，不换素材**。→ 今日待办（dev/广告车道），含 what/how/href。
3. **「该补哪种素材」清单**：对比「好用榜的共性变量」与「素材池现状」→ 缺口任务，**走现成的 `POST /api/clients/[id]/execution` + `promo_ref`**（105 号 10-18 设计稿已确认这条路是开着、带闸、不建生产包的），不新写入通道。
4. **候选素材建议**：创意池里 candidate 状态但自然表现好的 → 建议送审批（**只是建议进 approved 队列，不自动批**）。

每周：
5. **推荐下一条要测的变量**（一次只改一个变量）：例如「同团同受众，只换开场」。写成一条实验建议卡，交 74/PM 点头后由工厂生产；**本技能不下生产单**。
6. **复盘摘要**：上周的建议哪些被采纳、结果如何（喂训练，见 ③）。

## 4. ③ 怎么「训练」：只用已验证结果，三层分开

- **训练 = 更新规则与权重，不是微调模型。** 现成可复用：`memory-extractor`（投放结果 → proven/failed/preferences，三张记忆表）、Agent 学习库（专家视频 → 能力点 → 用自己数据验证 → 才写进规则手册，10-19 的 120 号设计）。**不另造学习框架。**
- 一条建议要进入「规则」，必须：有结果回流（采纳后 N 天的实际表现）→ 与预测对账 → 样本达到阈值 → 才升格。**没验证的只是「假设」，不改权重。**
- **三层**（对齐 10-10 PM 定的「平台-行业-客户」）：
  - 平台通用：判分框架、样本量规则、数据新鲜度闸（纯函数，不含任何客户/行业事实）；
  - 行业（旅游）：什么变量在旅游里有效（先标「候选，单客户证据」，与现有手册口径一致）；
  - 客户（CTS 私有）：具体哪条片、哪个受众、价格点、受众年龄偏大需要慢字幕（已有记忆）。**客户私有事实只进 client private memory，不进共享代码。**
- 反例防护：不拿样本不足的差异学规则；不拿「数据已停更」的窗口学规则；归因对不上（一对多）就留空不猜（`creative-link.ts` 同口径）。

## 5. ④ 与视频工厂 Agent、苏东坡质检的边界

| 角色 | 做什么 | 素材智能能不能做 |
|---|---|---|
| 视频工厂（`src/lib/factory/`） | **生产**：配方对账、分镜自检、出片 | ❌ 不生产，不调任何生成接口 |
| 苏东坡 / 马良审查 | **质检放行**（生产方≠质检方，PM 9-28 红线） | ❌ 不放行，不替代质检 |
| PM / 授权 | 批准进入创意池、批准发布 | ❌ 不批准 |
| **素材智能** | **只读 + 出建议**：榜单、疲劳预警、缺口清单、下一个实验建议 | ✅ 唯一职责 |

它的所有输出都是「建议记录」，下游动作各走各的闸：缺口 → 105 的任务写入；生产 → 工厂；质检 → 苏东坡；入池 → PM 授权。

## 6. ⑤ 红线

- **不烧未批准素材**：「可投」列表只含 `creative_pool` 里 `approved` 的；candidate 只能出现在「建议送审」里（RL-05）。
- **不自动换素材**（C-10）：疲劳预警只提醒；`ads.swap_creative` 这类动作**本技能不提交**。
- **动作都走内核**：任何会改广告的后续动作由既有 `ads.*` 能力经内核授权；本技能的代码路径里**不得 import 任何 Meta 写接口**（测试里断言）。
- **数据不新不下结论**：数据日落后 >2 天，榜单位置写「判不了：数据停在 M/D」。
- **归因不确定不猜**：广告 ↔ 片子对不上就空着。
- **客户私有事实不进共享代码**；写入记忆按层。
- 对外（客户可见）文案不出供应商名（见 CLAUDE.md 封装名规则）。
- 触及「放行」或「发布」的一切不归本技能。

## 7. ⑥ 最小第一刀，两周内能验证什么

**第一刀（只读，不执行，B 级偏 A 的设计前提已满足）：**
1. **补「广告 ↔ 片子」链路**：从 `ad_creative_links` 现状（4 行）出发，查清为什么稀少（建广告那一刻没写？还是走了别的建广告路径？）；补写入点或补回填。这是前置，且本身有价值（CRM 归因 `attr_creative_ref` 也卡在这）。
2. **一个纯函数 + 一个只读接口**：`rankCreatives(adRows, links, now)` → 「视频 × 受众」榜，带样本量与新鲜度；先只在广告健康页展示给 74/105，**不进待办、不触发任何动作**。
3. **修数据新鲜度**（与作战地图同源：回填没覆盖新户 → 榜单只会是「判不了」）。

**两周后能验证什么（写进台账 verify_how）：**
- 榜单是否把「花钱多、完播低」的和「花钱少、完播高」的排对（对账 74 手里已有的人工判断，10 条以内抽查）；
- 疲劳预警是否早于人工发现至少一次（有则记，没有也如实记）；
- `ad_creative_links` 新增覆盖率（新建广告 100% 写入为目标）；
- **不验证**：能不能带来更多留资（两周内样本不够，不拿它当判据）。

**后续（不在第一刀）：** 缺口任务自动写入；每周实验建议卡；与 Agent 学习库的验证闭环；行业 Playbook 沉淀；自然流量先验。
