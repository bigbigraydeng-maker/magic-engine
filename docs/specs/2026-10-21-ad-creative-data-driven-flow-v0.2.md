# 素材流程改为「数据驱动」· 设计 v0.2（增量）· 只设计，未写代码 · 119 号 · 2026-10-21

> 在 v0.1 之上：冲突处以本稿为准。吸收魏征对 v0.1 的 8 条必改 + 5 条建议。风险级 A。**花钱授权 = 已批计划里的两个数 + PM 本人切 `bounded_auto`；入池本身不是花钱授权。**

## 1. 排名指标改版（前置，魏征8）
- **排名首选「开聊」**（与 D3 的 `target_cost_per_primary` 同口径，即 CTS 的 primary result），不用 WhatsApp「点击」（点击≠开聊≠咨询）。看完率（ThruPlay/展示）只作先行信号，**单独不足以放大**，也不用来自动停。
- `attr_ad_id` 是否按广告拆分、开聊是否按广告拆分**未核实**：核实前整条排名只出建议，不触发任何自动停/放大。
- **回传健康度挂起**：CAPI 只回传 Lead、有丢数/重复；近 7 天回传失败/缺失率超阈值（初值 20%，写进计划步骤可调更严、不可调松）→ **整个排名挂起**，不据此放大或停，出待办。

## 2. 状态机补完（魏征1、11、12）
`pending_qc` → `test_queue` → `testing` → { `scaling` | `rejected`(数据差，自动停) | **`inconclusive`**(没测成) } → `retired`。
- **`inconclusive` 出口**：测试窗口 **N=7 天**，或该素材累计测试花费达上限仍无结论（样本不够）→ 按「没测成」退出：暂停该测试组、**释放测试名额**、出待办（不是差，不据此惩罚素材，可再排队一次，最多 2 次）。避免「缺数据≠差」把测试预算占住。
- **并发名额**：同一计划步骤同时在测的素材数 ≤ 3（初值）。
- **迁移兼容（建议11）**：先发一个**只改解析的小 PR**——`config.ts` 的 `CreativePoolStatus`/`parseCreativePool` 先容忍新状态值（现在遇到不认识的状态会整条丢掉），**上线并验证后才允许写入新状态**。
- **旧 `approved`（建议12）**：不直接当 `scaling`。已在手批在跑的（A2/B3）标为 `manual_approved`，**保持原样、不被任何自动停动**；它们要进自动放大，需先作为 `testing` 用数据重新证明。手批通道到新流程跑稳前保留。

## 3. 样本与时段偏差（魏征2）——具体初值（计划步骤里可调，只许更严）
- 样本门槛：**≥ 2,000 展示 且 花费 ≥ 2× `target_cost_per_primary` 且 ≥ 3 个不同日期有数据**，三条都满足才出排名结论。
- **同批同时启动**：同一轮测试的素材同一时刻、同受众、同版位、同预算启动，避免时段偏差；晚入池的进下一批，不与上一批直接比。
- 稳定性：结论需连续 2 天同向，防一天运气。
- **放大第一步只给小幅、可撤回加预算**：单次 ≤ 20%（内核已有）、之后冷却 72h，复核仍达标才走第二步；达不到立即回到原预算（撤回）。

## 4. 三道闸与两个预算数的边界表（魏征3）
| 对象 | 口径 | 谁判 |
|---|---|---|
| 测试预算上限（计划步骤 `test_budget_cap_cents`） | **累计已花**（本轮测试窗口内累计花费，不是当日承诺） | 计划闸（3010） |
| 放大总预算（`scale_budget_cap_cents`） | **当日承诺日预算合计**（在投的放大组日预算之和） | 计划闸（3010） |
| 客户日预算上限 | 当日承诺日预算合计（所有账户） | 日预算闸（2999）+ 内核信封（含 20% 缓冲） |
- 一次动作的**有效上限 = 以上取最严（min）**，代码不得自行借用别处额度；回执写明是哪一道拦的。
- **测试省下的钱不转放大**（默认）；若 PM 想合并成一个共用额度，必须在计划步骤里**明写一个共用数**，不是代码自行转。
- 单条素材测试花费上限（数字）= `min(测试预算上限 ÷ 并发名额, 3 × target_cost_per_primary)`，取自计划，不写进共享代码。

## 5. 授权边界（魏征7）
- **入池 ≠ 花钱授权**：入池只是「可被测试」。花钱授权 = 已批计划的两个数 + `autonomy_mode='bounded_auto'`（PM 本人切）。
- **切 `bounded_auto` 之前，整条流程只产出建议和暂停的草稿**，不开测试组、不放大、不自动停。
- 对外文案合规：测试广告的文案**只用已审核模板**（不由广告 Agent 现写）；价格/日期数字由工厂现有闸（配方对账、官网可溯、苏东坡质检）把关；本流程不新增文案生产。

## 6. 自动停的边界（魏征6）
- 自动停**只用于系统自己开的 `testing` 组**；`manual_approved` 与 `scaling` 里的素材，数据差**只降级为「复核待办」，不自动停**。
- 同一素材 24 小时内自动停至多 **1 次**，7 天内至多 2 次，超过转人工。
- **疲劳判据**：新素材没有基线时不适用疲劳规则（满 7 天且 ≥ 5,000 展示后才适用）。**自动停的判据复用 D3 的同一个函数，不另写第二套**（避免与 D3 自动暂停重复/打架）。
- **读不到数据**：不自动停（停止方向没有证据就不动），同时不加钱（增加方向拒）。

已被 3002 覆盖：①`ad_creative_links` 对 service_role 无写权限，旧策略 `service_role_full` 已改成 `TO service_role`（匿名读口子已收）；②写入只经各写入者窄函数，已解析行不可改/删。**仍需新做（后续块）**：
- `link_method='factory_upload'` 当前不在函数词表内；新增**一个**窄函数 `link_ad_factory_upload_v1`，**仅「建广告处」角色有 EXECUTE**，要求 `work_order_id` + `final_mp4_sha256` + `meta_video_id` 三者互核（哈希必须等于 `content_work_order_hash_history` 里该工单此刻的哈希；`meta_video_id` 必须是 ME 自己上传记录里的编号）。

- **哈希复核（魏征5）**：入池时和建广告时**各校验一次**工单哈希；不一致 → 状态回退 `pending_qc`，并**停该素材对应的在投广告**（收类，自动放行），出待办。

## 8. 回执与 Inngest（建议13）
每次自动开测试组/放大/停都写机器可读回执（request id、client id、素材、动作、金额、判据版本、证据数字、是否 `no_publish`、created_at）。事件名：`creative.test.opened` / `creative.test.concluded` / `creative.scaled` / `creative.auto_stopped` / `creative.inconclusive`；走 Inngest 跨步骤接力（质检→入池→开测→读数→结论→放大/停）。回执落 flywheel_actions/授权回执，验证 PM 待办可见。若某步暂时不上 Inngest，PR 必须写明原因与恢复条件。

## 9. 写入者与仲裁（建议9）
每个广告对象（campaign/adset/ad）同一时刻**只有一个写入部门 = ⑤ 投放部**；③ 只判定，⑥ 只诊断，④ 只管池内状态与对应关系，① 总控仲裁冲突。⑤ 与 ⑦ 的边界：⑤ 执行并产生执行结果，⑦ 记录回执与对账，**不互相代写**。

## 11. 待验收的反向用例
①没测成：7 天或花满上限无结论→退出并释放名额；②回传失败率超阈值→排名挂起不放大不停；③读不到数据→不停不加钱；④哈希变→回退+停广告；⑤手批在跑的 A2/B3 在数据差时只出复核待办、不被自动停；⑥单次放大≤20% 且可撤回；⑦切 `bounded_auto` 前零写动作。
