# CRM：AI 起草的信加标记（设计稿 v0）

PM 2026-11-28 原话：「ai 写的信一定要有标记，做跟踪和学习，分析」。

## 做什么（这一刀）

- 新表 `crm_ai_letters`：AI 每起草一封给客人的信记一行——在哪一页起草（客人抽屉 / 跟进信页 / 第 7 天跟进信页）、第一封还是跟进信、AI 原稿、起草时的检查结果、谁让它写的。
- 起草接口（`…/email/compose/draft`）写完就记，返回 `aiLetterId`；**记不上就不给稿子**（503）。
- 两条发送路（`…/email/compose`、`…/followup-letters/release`）收到 `aiLetterId` 时，**在发信之前**把这次发送记到那封 AI 稿子上：这次发送的 request id、终稿、改没改、谁放行；**记不上就不发**。别的客人的稿子、已经用过的稿子，一律拒发。
- 三个页面把 `aiLetterId` 带上：客人抽屉的写信框、跟进信页、第 7 天跟进信页。
- 发信核心（`sendMailNew` 和它的所有闸）一行没改。

## 已知限制（独立审查 2026-11-28 指出，写明不修）

- 「不带标记发不出去」只对三个会起草的页面成立：服务器分不出一段文字是不是 AI 写的。员工把 AI 稿子复制到模板写信框再发，就没有标记。模板信和目录信本来就不是 AI 写的，不受影响。
- `released_at` 和终稿在发送**之前**写入，发送可能随后被拦：分析时「发出去了」一律按 request id 去回执表查，不能看 `released_at`。

## 不在这一刀

- 时间线上「AI 起草」的小标、AI 信效果页（写了几封、员工改了多少、客人回了几封、之后有几位走到报价或订团）：表里有数后下一张改动单做。
- 发没发成、客人回没回、后来报价订团：**不存进这张表**，按 request id 去发信回执（`crm_email_send_receipts`）和客人往来、阶段、订单里查，只有一份真相。

## 层级判定（me-platform-tier-gate，Inline）

挂在既有 L1「CRM 邮件发送 + Verification / Memory」下，按 `client_id` 隔离；不新增能力线、不写任何客户或行业事实；不用登记候选。

## 开工十问（藏经阁；读了第三、四、五、六、八、十、十一、十四部经）

1. **IMPACT 哪一段、外环指标？** Act（发信）→ Check（客人回没回）。外环看「AI 信发出后 14 天内客人回信 / 走到已报价及以后 / 订团」，不看「AI 写了几封」（第七、十四部）。
2. **确定的 / 交给模型的？** 写信交给模型；记录、比对改没改、绑定发送、拒发全是代码（第三部）。
3. **对外动作、授权级？** 发信仍是 L1「AI 出草稿、人点才发」，这一刀不升级；记录本身不对外（第六部）。
4. **完成证据？** 三层分开：起草有行（本表）→ 发送前绑定 request id（本表）→ 发没发成看回执表的 outcome（第四部）。
5. **谁验证？** 写信的是 AI，放行的是人；这一刀的代码由独立审查员复审（第五部）。
6. **学到的写哪层？** 只在客户私有数据里（本表按客户隔离）；「员工常改哪类句子」这类结论要等效果页出来、有数后才谈升到写信规则，升级要 PM 点头（第八部）。
7. **考卷？** 表里攒下的「AI 原稿 vs 员工终稿」就是以后写信规则的考题来源；这一刀先攒数据，不改写信规则（第九部）。
8. **PM 纠正落哪？** 员工改稿自动留痕（edited + 终稿）；PM 的纠正落到写信检查（`follow-up-checks.ts`）的固定测试里，跟 11-28 那三类错一样（第十部）。
9. **读不到 / 记不上时说什么？** 记不上不发，写明「标记没记上，这封没有发」；绝不把「没记上」当成「不是 AI 写的」（第十一部）。
10. **占 PM 多少注意力？** 零：不新增待办、不新增 agent，只在现有写信流程里加一笔记录（第十三、十六部）。

## 上线顺序（必须照做，否则所有 AI 起草都会被拒）

1. PM 同意后，先在线上数据库建表（`supabase/migrations/20261128120000_crm_ai_letters.sql`）。
2. 表建好再由 PM 亲手合并改动单（碰数据库结构，留给 PM 亲手合）。
3. 上线后当场试一次：在客人抽屉让 AI 起草一封（不发），查表里多了一行。
