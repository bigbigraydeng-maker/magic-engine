# SEO「提前写好的改动草稿」v0.1（最小 MVP）

日期 2026-10-06 · 状态：设计稿，待两审（子牙 + 魏征）· PM 2026-10-06 回复"做草稿"
层级判定（me-platform-tier-gate · Inline）：L1·SEO 支柱既有「处方」环节的扩展；复用周循环的生成与事实核对；受保护页名单、品牌语气来自客户配置（L4）；不新增能力线、不登记候选。

## 1. 要解决什么
每周清单只告诉人"这页点击率偏低"，改成什么字还得有人想、写、核对、提交，这一步慢。系统里其实已有全部零件：生成新标题描述（`ai-meta.ts`）、硬事实核对（价格、出发城市、Auckland 不许丢，`hard-fact-check.ts`）、只预演不写的开关。
**最缺的是受保护页**（签证指南、免签文章、/tours、/about）：周循环按设计永远不碰它们，每周清单也把它们整个排除了（`isExcludedUrl`），所以 PM 根本看不到这几页的机会（近 28 天合计约 227 次点击的潜力，其中签证指南一页就约 126）。

## 2. 最小 MVP（只做这一刀）
每周清单里，**受保护页**如果出现"点击率偏低"或"流量下滑"，就生成一条**带草稿的任务**：
- 草稿 = 当前线上标题/描述 + 建议的新标题/描述 + 事实核对结论 + 写这条草稿所依据的页面自己的搜索词；
- **只出草稿，不自动改**（受保护页永远要人点头）；
- 每周最多 2 条，另占名额，不挤掉现有的 5 条；
- 草稿没过硬事实核对就**不展示文字**，只写"为什么没写成"。

**不在 MVP 内（明确不做）**：审批后的自动提交（先由我手工按草稿提 PR，第二阶段再做受控入口）；非受保护页的草稿（周循环自己会处理，做了是重复）；正文 / 内链草稿；多客户。

## 3. 复用地图（不新造）
| 需要 | 复用 | 位置 |
|---|---|---|
| 页面自己的搜索词（选目标词） | 点击率诊断已读的 `fetchGscQueriesForPage` 结果 | `seo-weekly-list/ctr-diagnosis.ts` |
| 线上当前标题 / 描述 | `fetchLiveSnippet`（只认线上真实 `<title>`） | `seo-weekly-list/live-snippet.ts` |
| 生成新标题 / 描述 | `generateMetaCycleTitle` + 客户的 `brandVoice` | `seo-meta/cycle/ai-meta.ts` |
| 硬事实核对（价格 / 城市 / Auckland 等不许丢） | `checkHardFactsPreserved` | `seo-meta/cycle/hard-fact-check.ts` |
| 受保护页名单 | `clients.seo_config.meta_cycle_protected_slugs` | 客户配置 |
| 任务落库 / 去重 / 过期 / 核对 | 现有清单的 `writeSeoPlanItems`、`verifyPlanItem` | `seo-weekly-list/*` |

## 4. 数据流
1. 清单构建候选时，受保护页不再被丢掉，而是进入单独的 `protectedCandidates`（仍排除"近期被自动改过"的页）。
2. 取前 2 个（按潜力）：读该页自己的搜索词 → 选目标词（沿用周循环的"至少含 slug 里 2 个有区分度的词"规则，选不出就说明"没有可靠的目标词"，不硬写）；读线上标题 / 描述。
3. 调生成器写草稿 → 过硬事实核对 + 长度 ≤60/≤160 + 与线上标题不重复；任何一条不过 → 任务里写"没写成及原因"，不展示草稿文字。
4. 落成任务：类型 `seo.plan.review_draft`，`steps_json.kind = 'protected_draft'`，`steps_json.draft = {keyword, oldTitle, oldDesc, newTitle, newDesc, checks, queries}`，证据行带置信度；说明里写清"回复「合 <页面>」我来提 PR，不回就 14 天后自动过期"。
5. 核对：沿用 `page_changed`（线上标题 / 描述与草稿一致，或字数变化，视为已处理）；过期规则不变（14 天，无动作 → skipped 并写原因）。

## 5. 花费与限制
- 每周最多 2 次 AI 生成，约几美分；不调 SERP（受保护页无需竞品标题，避免付费调用）；谷歌页面搜索词读取免费。
- 失败不拖垮清单：读搜索词 / 线上标题 / 生成任一失败，只让该条草稿写"没写成"，其余照常。
- 全程不写客户网站、不写 `seo_meta_log`。

## 6. 风险与如实声明
- 生成的文字仍可能不好（硬事实核对只保证价格 / 城市 / 关键事实不丢，不保证好读）——所以只出草稿，由人决定。
- 目标词选择依赖页面自己的搜索词；样本很小的页面（曝光 <30）会选不出，直接说明。
- 受保护页多半带"| CTS | CTS Tours"之类品牌尾巴，草稿需保留品牌尾巴，否则会与现状不一致（核对项）。
- 第二阶段（审批后自动提交）会改客户网站，属 A 级，单独设计、单独两审。

## 7. 构建与验证计划
- 第 1 轮：`draft.ts`（纯函数 + 注入的生成 / 核对函数）+ 单测；第 2 轮：清单接线（受保护候选、名额、任务落库）+ 端到端假库测试；第 3 轮：文案与周报区块。
- 变异：核对不过仍展示文字、受保护页被自动应用、名额溢出、读搜索词失败拖垮整张清单。
- 当场试跑：线上 `seo-weekly-list` 只读演练，预览里能看到受保护页的草稿条目（或"没写成及原因"）；演练零写入。
- 关闭条件：PM 看到 ≥1 条能直接批的草稿，或看到一条清楚的"为什么写不出"。

## 8. 要 PM 定的一件事
草稿放在哪里给你看：直接放在每周清单任务里（本方案），还是同时在周报里列一块。建议先只放任务里，周报下一步再加。
