术语一次说清（后文直接用）：

- **护栏**：不管模型怎么判都必须遵守的规则（别再联系、同行、7 天最多 2 封邮件、不编价格）。
- **影子期**：模型照常判、结果只显示在旁边对照，**不改名单顺序**。
- **金标准题库**：PM 认过答案的一批真实客人（第一版 = 实验里那 40 位），用来考模型。
- **Inngest**：ME 现有的「事件接力」工作流工具，用来在「有新往来」时自动触发重判。

## 0. 给 PM 的一页

**第一件事：CRM 的核心改成「每位客人一张 AI 判断卡」，「今天要联系」按它排。**
现在的名单按「最近有动静」排，读不懂话：客人追问了没人回的被埋到一百多名，昨天打过去其实是语音信箱的却排第一。实验里，读完往来的 AI 前 25 名有 12 人要挪 10 位以上，挪的方向你看过说「基本都对」。

**第二件事：分工是「程序算事实、模型读内容、规则只当护栏」。**
谁在等谁、连续几通没接、上封邮件几天没回、是不是新线索 / 回头客、7 天发了几封——这些程序算，算得准（对上你的答案 80%）。态度、今天做什么、用什么渠道、理由——模型读原文判。别再联系 / 同行 / 7 天 2 封 / 不编价格——规则管，模型改不了。模型出错或没钱了，人照样留在名单上，标「需要人看」，**谁都不会被悄悄藏起来**。

**第三件事：用 Claude Haiku 5.5，CTS 一家每天大约 0.2–0.25 美元。**
五个模型同题比过，它最准（三项全对 21/40，排序相关 0.71）、零编造；线上现在用的 gpt-4o-mini 只对 10/40，不能用。价格是按开发工具缓存的价目算的，**上线前必须对官网价目核一遍**；另设每天 1 美元硬上限。

**第四件事：能做成会学习的 agent，但「学习」= 改提示词、例题和阈值，不是训练模型。**
同事在卡片上点「判断不对」并选原因 → 存成这家客户自己的纠错样本 → 每周拿金标准题库离线考一次新版本，**考得不比旧版差才允许上线**，上线要你点头。客人后来回没回、订没订，也会自动回填，用来判断哪类建议真的有用。客户的样本只给这家客户用；要变成旅游行业通用经验，得有多家客户的证据。

**第五件事：先修 5 个数据错误，再上 AI。**
语音信箱被记成「通话成功」、票务同事的邮件被当成客人来信、「已报价」被误判、同一个人两张卡、机器人自动回复被当成我们真人联系过。这些不修，AI 读的就是错的材料。

**第六件事：分 7 刀，先影子期两周（AI 判断并排显示、不改顺序），你抽查说「开」才换排序。**
需要你拍板的业务问题只有两个，见 §14。

## 1. PM 要什么（意图，2026-10-29 / 10-30）

- CRM 的核心对象是**每位客人的 AI 判断**：谁在等谁、态度、下一步、渠道、什么时候、为什么（带日期证据）。「今天要联系」按它排。
- PM 给的常识（全部要能判出来）：
  1. 我们邮件回复后客人又追问 → 必须跟进；
  2. 连续两通没接 → 别再打，换渠道；
  3. 我们群发了一批（例如某个团的咨询客人），5–7 天没回 → 换渠道跟进；
  4. 客人说还没准备好 → 等；
  5. 我们答应过的事 → 去兑现；
  6. 回头客再次留资 → 强信号；
  7. 同行 / 供应商 → 不是线索。
- 新问题（10-30）：**这套业务判断能不能变成一个会不断学习、越来越准的 agent？** → §10。

## 2. 证据（三次只读实验，2026-10-30，CTS；全程没写库、没发消息）

| 实验 | 做法 | 结论 |
|---|---|---|
| ① 参考答案 | Claude Opus 读完 40 位客人的全部往来，逐个判断 | PM 看后「基本都对」→ 成为**金标准题库 v1**。真正在等我们回话的 16 人，现在前 10 名只覆盖 5 人；4 人根本不该在名单上（书面拒绝过 / 说准备好会联系 / 两三个月无回应） |
| ② 线上模型 | 同样材料喂给 CRM 现在的 AI 通道（gpt-4o-mini） | 四项全对 3/40；45 人里 33 人判「客人在等我们」；把我们发的跟进信当成客人提问；理由里出现编造（写了一个当天根本没有记录的「客人表现出兴趣」） |
| ③ 五模型同题 | 程序先算好硬事实，五个模型吃同一份材料 | Haiku 5.5：态度 33/40、渠道 30/40、紧急度差 ≤1 级 35/40、三项全对 21/40、排序相关 0.71、零编造、约 0.0008 美元/人。Sonnet 5.5 同样准但贵 15 倍；gpt-4o-mini 仍然不行（相关 0.45，45 人里 33 人判最急） |

实验③还说明三件对设计重要的事：
- **程序算「谁在等谁」对上 80%（32/40）**，而且这一步做了之后，「把我们的信当客人提问」这类错误五家全部消失。注意：算法对着这 40 人调过三轮，80% 偏乐观。
- 没对上的 8 人里 5 人要读懂内容才能判（「不去了」「我准备好会联系你们」、机器人答应过发资料）——这部分本来就该交给模型。
- 五家共同的难点：「很久以前问过一句、机器人回过、之后再没真人动静」该不该今天追。这正是学习闭环要攒纠错样本的地方。

实验顺带发现的数据错误（§9 全部纳入范围）：语音信箱记成通话成功（4 人）、机器读聊天误判「已报价」（3 人）、票务同事发给客人的报价被记成客人来信、同一个人两张卡（一张私信一张邮件，模型看不到另一张卡上的回信）、机器人自动回复当成我们联系过。另有一个邮件模板把出发年份写错（已另行报告，不在本稿范围）。

实验脚本（未提交，在 focused-yalow 工作区）：`scripts/crm-ai-judgment-dryrun.ts`。它「先算事实再交给模型」的写法、输出字段和只读护栏是本稿 WP-2 / WP-3 的原型；客户数据不进仓库。

## 4. 核心对象：判断卡

每位客人一张，存在新表 `crm_contact_judgments`（客户私有，按 `client_id` 隔离），**每次重判写一行新的，不覆盖**——便于回看「当时为什么这么判」，也是学习闭环的原料。

| 字段 | 谁给 | 说明 |
|---|---|---|
| `who_waits` | 程序 | 客人等我们 / 我们等客人 / 都没在等 |
| `waiting_since`、`waiting_days` | 程序 | |
| `facts` | 程序 | 硬事实快照（§5.1 全部），原样存，方便事后对账 |
| `stance` | 模型 | 热 / 温 / 暂不 / 不感兴趣 / 不是线索 / 已成交 |
| `next_action` | 模型 | 打电话 / 邮件 / 短信 / WhatsApp / Messenger / 只记一笔 / 等 / 不联系 |
| `wait_until` | 模型 | 「等」时写到哪天（客人自己说过的日期优先） |
| `urgency` | 模型 | 1–5（5 = 今天最先做；1 = 今天不做） |
| `why` | 模型 | 一句中文，带日期证据；日期必须在材料里出现过（程序校验，§5.3） |
| `channel_reason` | 模型 | 为什么选这个渠道（短） |
| `guardrail_overrides` | 程序 | 护栏改了模型哪一项、为什么（例如「7 天已 2 封，邮件改成短信」） |
| `status` | 程序 | `ok` / `needs_human`（模型失败或校验不过）/ `skipped_guardrail`（别再联系等，没送模型） |
| `prompt_version`、`model`、`input_hash`、`trigger`、`cost_usd`、`latency_ms` | 程序 | 版本、花费、为什么重判（新往来 / 晨扫 / 手动） |

判断卡**不改**客人阶段、不发任何消息、不写客人资料。它只决定「今天名单上怎么排、卡片上写什么」。现有 AI 简报（`conversation_briefs.intent_level`、`next_action`）继续生成、继续在抽屉里显示，但**不再是排序依据**；判断卡可以把简报当作一条补充材料读。

## 5. 分工：程序算事实 · 模型判内容 · 规则当护栏 · 失败要保守

### 5.1 程序算的硬事实（确定性，有单测）

把实验脚本 `computeFacts` 的口径搬进共享代码（`src/lib/crm/judgment/facts.ts`），复用现有判据，不另写一套：

| 硬事实 | 口径 / 复用 |
|---|---|
| 谁在等谁 + 从哪天起 | 客人真发来的话（消息、打来的电话含未接）晚于我们最后一次**真人**回应 → 客人等我们；填表本身不算「客人在等回答」（另有「新线索」事实）；我们在通话里答应了要发东西且之后没发 → 客人等我们；我们最后一次伸手在 30 天内 → 我们等客人；否则都没在等。真人 / 机器用 `automated-touch.ts`、`human-actor.ts` |
| 上次真正聊上之后，我们连续几通没接 / 语音信箱 / 秒挂 | `isUnansweredCall` + §9.1 修好的语音信箱判据 |
| 我们最后一封真人邮件是哪天、几天了、客人之后回没回 | |
| 7 天内发了几封邮件（含群发） | 复用 `email-compose/quota.ts` 的同一份计数（127 号已定口径），不另算 |
| 新线索：从没有真人联系、也没打过 | |
| 回头客：联系过之后又填表，或多次填表间隔 > 3 天 | 复用 `returning-lead.ts` |
| 通话表态（不感兴趣 / 改天再说） | 复用 `call-stance.ts`，只认已核验、客人本人说的 |
| 别再联系 / 同行 / 非咨询 / 已成交阶段 | 复用 `dnc.ts`、`segments.ts` 的排除判据、`contact-list-view.ts` 的降级 |

时间线每一行都标清「客人 → 我们」「我们的人 → 客人」「我们的机器 → 客人」「内部备注（客人没看到）」。这一步是实验③消灭方向错误的关键。

### 5.2 模型判的（读内容）

态度、今天做什么、渠道、等到哪天、紧急度、一句理由。提示词里的「常识规则」= PM 那 7 条 + 实验里补的几条（语音信箱不算聊过、用客人用的渠道回、客人说了要哪个渠道就用哪个、表单选项「还在挑团」不等于没准备好、不写截止日催单等）。**规则措辞写在行业剧本里，不写死在共享代码里**（§11）。

### 5.3 护栏（模型之后再过一遍，模型改不了）

1. **别再联系 / 退订 / 同行 / 非咨询 / 已成交** —— 在模型**之前**判，这些人不送模型（省钱，也不外发他们的对话）；`status = skipped_guardrail`，卡片写明原因。
2. **7 天最多 2 封邮件** —— 模型选了邮件而计数已满 → 改成电话 / 短信（有号码时）或「等」，写进 `guardrail_overrides`。
3. **不编事实** —— `why` 里每个日期必须出现在材料或硬事实里；引号里的原文必须逐字在材料里（沿用 enquiry-screen 的引文校验）。不过 → `needs_human`，理由换成程序写的硬事实句。
4. **不写截止日 / 倒计时 / 「名额有限」**（CTS 规则，进客户配置）。
5. **不说价格**：判断卡只说「要报价 / 回答价格问题」，不写金额。
6. **渠道必须真能联系到**：选了打电话但没号码 / 号码坏 → 降级，复用 `reachableChannel`。
7. **「最急」必须有一条硬事实撑着**（#3396 §11.7 保留）：客人等我们、新线索、回头客、约好回电到期四者之一；否则紧急度最高压到 4。

### 5.4 失败时：保守，谁都不消失

| 情况 | 行为 |
|---|---|
| 模型超时 / 报错 / 余额没了 / 返回格式不对（重试 1 次后） | `needs_human`，人留在名单，按现在的规则顺序排，卡片写「AI 这次没判出来，按规则排，需要人看一眼」 |
| 当天预算用完 | 剩下的人沿用上一张卡（标「X 天前的判断」）；从没判过的按规则排 |
| 功能关掉 | 名单完全回到现在的规则排序（开关在客户配置） |
| 模型判「不联系 / 等」 | 人移到「先放着」或种草唤醒列，**仍可翻到**，卡片写原因和「到哪天自动回来」 |

## 6. 「今天要联系」怎么排

### 6.1 谁进名单
沿用现在的分段 + 4 列映射（#3396 §11.2），再加一条：判断卡说「不联系 / 等到某天」的人从「今天要联系」挪到对应折叠区；判断卡说「今天要做」、而分段把他放在「先放着」的人（例如追问了 48 天没回、被规则沉下去），**拉回今天要联系**。拉回和挪走都写在卡片上，影子期统计这两类各多少人。

### 6.2 顺序（从高到低）
1. 置顶 ⭐（人手动）
2. 约好今天回电到期（我们答应过的时间）
3. 判断卡 `urgency` 高的在前；同级里「客人等我们」在前，再按 `waiting_days` 多的在前
4. `needs_human` 的卡按现有 `compareNextAction` 插在 urgency 3 那一档（不沉底、不置顶）
5. 兜底：`compareNextAction`

每天早上（新西兰时间）冻结一次顺序（#3396 §11.5）；当天只有客人的新消息能触发重判并插队；我们打完电话卡片原位变灰。

### 6.3 卡片上显示什么
沿用 10-29 定的「每行三样」：名字 / **一句话原因（= 判断卡 `why`）** / **一个渠道（= `next_action`）**。点开看：谁在等谁、等了几天、态度、护栏改了什么、判断时间和版本、「判断不对」按钮（§10.2）。

## 7. 什么时候判、花多少、怎么防超支

### 7.1 触发
- **有新往来时（事件）**：新增 Inngest 事件 `crm.contact.touched`（客户 id、客人 id、触点 id、方向、是否机器发的）。**在写触点的地方统一发**（触点写入入口 + 消息同步 + 通话入库），不只挂在「新消息到达」事件上——10 月已有教训：消息大多走同步通道进来，只挂「到达」事件会漏掉绝大多数。群发 / 自动信 / 打开邮件不触发（否则一封群发触发几百次重判）。
- **每天早上 6:30（新西兰时间）晨扫**：把「今天名单候选池」（今天要联系 + 先放着里 30 天内有过往来的）过一遍；输入没变（`input_hash` 相同）且上张卡不到 3 天的跳过。晨扫兜底事件漏掉的人，也负责「等到某天」到期的人。
- **手动**：卡片上「重新判断」（每人每 10 分钟最多一次，沿用 AI 起草的冷却写法）。

### 7.2 怎么跑（照已有坑写）
- 一个人一次判断 = 一个独立 `step.run`，自带时间预算；**先占位再调模型**：唯一键 `(client_id, contact_id, input_hash, prompt_version)`，重试撞到已有记录就跳过（照抄 `crm/facts/infer.ts` 的占位写法）。
- 同一客人 5 分钟内的多个事件合并成一次（Inngest debounce）。
- 每家客户每天一个预算上限（CTS 初始 1 美元/天），用 `agent-learning/budget/reserve.ts` 的「先预留、后结算、账本不可用就零外呼」写法，新增用途 `crm_judgment`。超了按 §5.4 走。
- 回执：每次判断写一行（就是判断卡本身，含状态、花费、耗时、失败原因），满足 CLAUDE.md §3 的 Inngest 回执要求。本功能**没有外发副作用**（不发消息、不扣费），不需要授权事件。

### 7.3 每天花多少（CTS，粗估；单价按实验③实测计费单位 × 缓存价目）

## 8. 模型怎么选：平台 AI 通道加「按功能选型」

现状：CRM 的 AI 调用走 `src/lib/ai/failover.ts` 的 `askJson`，顺序写死为 gpt-4o-mini → Claude Haiku 4.5 → DeepSeek（DeepSeek 由开关控制）。它只允许改 OpenAI 的型号（`openaiModel`），Claude 型号是常量。实验证明 gpt-4o-mini 不能做这件事。

设计（WP-3，技术决定，不需 PM 选）：
- `askJson` 增加可选参数「功能档案」`profile`。档案集中登记在一个文件（`src/lib/ai/feature-profiles.ts`）：首选哪家哪个型号、备用顺序、是否允许 DeepSeek、单次最多输出多少。**不传档案的调用方行为完全不变**（简报、AI 起草等继续用现在的顺序）。
- `crm_judgment` 档案：首选 Claude Haiku 5.5（用强制格式的接法，避免实验里 Sonnet 那种一次出两份答案）→ 备用 gpt-4o（实验排序相关 0.70，第二准）→ **不用 gpt-4o-mini；DeepSeek 默认不用**（客人对话原文会发给中国公司；PM 10-26 为简报开过，本功能沿用「默认关」，要开由 PM 决定）。
- 备用模型判出的卡带 `model` 标记，影子期分型号统计准确率；档案里一个开关「备用模型判出的卡一律标需要人看」，备用明显差时打开。
- Haiku 5.5 的确切型号名在 WP-3 对 Anthropic 官方模型列表核实后再写进档案，不凭记忆写。

## 9. 数据地基：5 个必须先修的错误（都在范围内）

|---|---|---|---|---|

## 10. 学习闭环：让它越用越准（IMPACT 的 Check → Tune）

### 10.1 先说清「学习」是什么
- **是**：根据同事纠错和真实结果，改**提示词里的常识规则、例题（few-shot，即放进提示词里给模型参考的几道已纠正的真实例子）、程序里的阈值**（例如「我们等客人」超过几天算没在等、几天没回算该换渠道）。
- **不是**：训练或微调模型。不需要、也不打算。
- **算 agent**：它自己发现「哪类判断老被纠正」、自己起草改进版本、自己去考试；**但新版本上线永远要过闸**（§10.5）。

### 10.2 信号从哪来（三种）
1. **同事纠错（最直接）**：卡片详情一个按钮「判断不对」，点开单选原因（可加一句话）：
   - 他其实没在等我们 / 他其实在等我们
   - 不该今天联系 / 应该今天联系
   - 渠道不对（选正确渠道）
   - 态度不对（选正确态度）
   - 他不是客人（同行 / 供应商 / 同事）
   - 依据写错了（日期 / 事实不对）
   - 我们其实在系统外回过了
   - 其他
   **隐性信号**也记：同事没照卡片做、做了别的（卡片说发短信，他打了电话且打通了）——只记录，不自动算纠错，每周汇总看。
2. **结果回填（自动，7 天后）**：卡片建议的动作做了之后 7 天内，客人有没有**主动**回话 / 约时间 / 填订单 / 付定金。按「当天是否被联系」分层统计（#3396 §11.9：不能拿「被打了才回」自我印证）。CTS 成交量小（每周几十个表单客人、成交约 1%），所以**结果只作参考，不单独驱动改动**；主驱动是纠错和抽查。
3. **PM 抽查**：每周一页，随机 10 张卡 + 被纠错最多的 5 张，PM 回「对 / 不对」。PM 的答案直接进金标准题库。

### 10.3 存在哪（默认客户私有）
- 新表 `crm_judgment_feedback`：一条纠错 / 抽查 / 结果回填一行，指向当时那张判断卡——永远知道「当时模型看到了什么、判了什么、人说应该是什么」。`client_id` 隔离，权限只许 service_role（CLAUDE.md §7 模板）。
- 这就是**带标签的样本**，只属于这家客户。客人原文不复制进这张表，只存判断卡 id；删客人时跟着删。
- 不塞进 `client_learned_preferences`：那张表存的是「风格 / 话题偏好」这类一句话偏好，不是「一次判断 + 正确答案」的成对样本，硬塞会混淆语义。

### 10.4 每周离线考试（复用 agent-learning 的对照试验做法）
- **金标准题库**：v1 = 实验那 40 位（PM 已认）+ 5 位同团客人。冻结成「材料快照（时间线 + 硬事实）+ PM 认可的答案」。材料快照是客户私有数据，**存客户私有的存储，不进仓库**；仓库里只放题库结构和打分程序。之后每月从 PM 抽查和纠错里补新题（PM 认过才入库）。
- **打分**：沿用实验③口径——态度对、渠道大类对、紧急度差 ≤1 级、三项全对、排序相关、编造数（日期 / 引号校验）、格式错误数。打分程序进仓库（`src/lib/crm/judgment/eval.ts`）。
- **每周日晚跑一次**（Inngest 定时）：当前上线版本 vs 候选版本，同一份题库。结果进周报；只有「候选比现在好」才出现「要不要换」的问题。
- **复用**：`agent-learning/lesson-trial` 的「同题、有 / 没有这条改动各跑一次」对照写法和日预算账本（先预留后结算）；`agent-learning/lesson-verify` 的结论三档（支持 / 反对 / 证据不足）；`/api/admin/agent-learning/trial` 的「只读、限流、花费走日账本」接口形状，新增一个 CRM 考试入口供手动触发。**说清边界**：agent-learning 现有的回测只会读广告日数据，不能直接跑 CRM——复用的是写法、账本和接口形状，打分程序是新写的。

### 10.5 候选版本从哪来、谁能改什么
**agent 自己可做（不需批准）**：
- 汇总纠错，找出「同一类错误本周 ≥3 次」的模式；
- 起草候选版本（改规则措辞 / 换例题 / 调阈值），存成**未启用**候选（照 `global_learned_lessons` 的 `is_active=false`、人点了才采纳的做法）；
- 跑离线考试、写报告；
- **例题的日常轮换**：每次判断时，从**这家客户自己**的纠错样本里，按情形取最多 3 道相似的（例如「很久以前问过一句、机器人回过、之后没动静」这一类），连同纠正后的答案放进提示词。新纠错样本要先在每周考试里证明「放进去不降分」才进入可取池。

**需要 PM 批准**：
- 新提示词版本 / 新阈值上线（看了周报回「换」）；
- 任何影响护栏的改动（护栏只能人改代码，agent 碰不到）；
- 把一条经验升级成行业剧本（§10.6）。

**任何时候都禁止**：
- 不经考试在生产换版本；
- 考试降分、或编造数 > 0、或格式错误率上升 → 自动拒绝该候选，不送 PM；
- 拿题库里的客人当例题（等于泄题，分数虚高）——取样程序强制排除。

**版本**：每个提示词版本有编号（`crm-judgment-vN`），判断卡记录用的哪版；上线 / 回退只改客户配置里「当前版本」一个值，回退立即生效。

### 10.6 从客户私有升级到行业经验（只在有证据时）
- 默认全部留在客户私有。
- 升级成「旅游行业跟进经验」（进 L2 行业剧本）要同时满足：≥2 家同行业客户的纠错指向同一规则；在两家各自题库上都不降分；文字过 `memory/lesson-shareability.ts` 脱敏闸（无客户名、人名、金额）并走 `memory/write-lesson.ts` 唯一入口；PM 批准。
- 现在只有 CTS 一家，**第一期不会发生升级**；这是给 NAL 等接入后用的车道。

## 11. 平台层级判定（me-platform-tier-gate · Full）

**被判定对象**：CRM「每位客人 AI 判断卡」+ 按功能选模型 + 判断的学习闭环

**建议层级**：既有能力的扩展，分三层落：
- **L1（平台共享）**：判断卡的数据形状、硬事实计算、护栏框架、失败兜底、触发与预算、按功能选模型、离线考试与版本闸、纠错样本存储。归属 = 平台基础设施里的 **Next Best Action + Verification / Learning（Memory）机制**，作用在已存在的 CRM 名单引擎上。不新增支柱、不新增能力名。
- **L2（旅游行业剧本）**：常识规则措辞（出行时间、跟团游决策周期、「还在挑团」不等于没准备好）、阈值默认值（几天没回换渠道、多久算没在等）。挂在现有 `IndustryPlaybook` 接口上扩字段，不另起结构。
- **L4（CTS 配置）**：7 天 2 封、不写倒计时、我方员工邮箱名单、每日预算、当前提示词版本、开关、CTS 自己的纠错样本和题库。

**归属**：平台基础设施（Next Best Action / Verification / Memory），不是 6 支柱之一的新能力。

**和产品定义的边界**：产品定义 §3.2 写明 ME 不自建「CRM 系统本体」。本稿不扩充 CRM 记账功能（阶段、订单、联系人管理不新增），新增的是 §3.1 明确属于 ME 的 **Next Best Action、Check / Outcome、Learning**。§9 的数据修复是让证据可信的必要前提，不是扩 CRM 范围。

**换客户测试**：✓（有条件）
- 换 NAL（物流）：硬事实、护栏框架、判断卡、考试闸不用改；常识规则措辞要换（没有「出行时间」，有「货期」）→ 进 L2；邮件上限等进 L4。
- 换悉尼地产客户（只要线索的那类）：同上；「回头客」口径若不同，走剧本覆盖 `returning-lead` 判据。
- 前提：WP-2 / WP-3 **不把实验脚本里的旅游措辞原样搬进 `src/lib/crm/judgment/`**——这是审查重点。

**换行业测试**：✓（有条件）——行业差异全部经 `IndustryPlaybook` 进来；没有剧本的行业 → 中性默认规则 + 功能默认关，不吃旅游默认（顺带修 #3396 §11.10 指出的「三处调用一律吃旅游默认」）。

**智能层 or 执行手**：智能层（判断与学习），不执行任何对客动作。

**红线检查**：
- 红线 1（禁包装升级）✓：不叫「CRM 智能层」「新能力线」，就是名单引擎 + 学习机制的扩展。
- 红线 2（客户 / 行业事实不进共享代码）✓：护栏数值、员工邮箱、规则措辞全在 L2 / L4。
- 红线 3（禁直建 L1）✓：不是单客户新能力；平台部分是既有能力扩展。
- 红线 4 / 5 ✓：见上。
- 红线 6：不新增 L1 能力；五道 Build Gate 由各刀 PR 照常过。
- 红线 7 ✓：L2 只放行业规则措辞与默认阈值，CTS 事实全在 L4。

**PM 待拍板**：无（不涉及新支柱、新版本、收费）。**登记候选**：不登记。
**结论**：原本想法层级 = 既有能力扩展；判定一致；按 §12 分刀继续。

## 12. 工作包（按顺序，每刀独立 PR、独立判级）

按 [质量闸 §11](../ENGINEERING_QUALITY_GATES.md) 资源优先级：**频率 高**（销售每天打开名单）/ **IMPACT 关键度 高**（Prescribe 给的是错误信号，并直接卡住 Act：该回的没回）/ **收入 高**（离成交一步的客人等了 8 天没人回）→ **P0**。各刀共享这个优先级，顺序按依赖排。

写代码按 CLAUDE.md §5：默认 Claude Code 出指令、DeepSeek 写；A 级安全核心（迁移、批量纠正生产数据、模型外发边界）由 Claude Code 自写并在 PR 写明原因。每刀都要写台账卡（CLAUDE.md §9.6）。

### WP-1 数据地基：只读核数 + 9.2 规则 / 9.3 / 9.5 修复（B）
- **做**：三类错误的判据修正 + 单测；只读核出 9.1–9.5 各类受影响人数；不改历史数据。
- **验收**：单测覆盖实验里每类的真实形态（脱敏成假数据）；PR 写修复前后各类人数（只读 SQL 算）；名单引擎现有测试全过。
- **当场试跑**：本机用线上只读数据跑一遍分段，对比修前修后「客人等我们」人数，变化名单只给 PM、不进仓库。

### WP-1b 语音信箱纠正 + 历史数据纠正（A，批量改生产数据 → Ray 亲手合）
- **做**：9.1 全部 + 9.2 的历史方向纠正。纠正脚本默认演练（只出清单）；PM 看清单回「改」才真改，且只改系统推进 / 系统入库的。
- **验收**：演练清单人数与 WP-1 核数一致；真改后抽 5 人在抽屉里核对阶段和留痕；人手改过的 0 人被碰。
- **当场试跑**：演练模式跑一次，贴人数和 3 个脱敏样例。

### WP-2 硬事实计算进共享代码（B）
- **做**：`src/lib/crm/judgment/facts.ts`（从实验脚本搬口径，复用 §5.1 列的现有判据）+ 时间线渲染（标方向、真人 / 机器 / 内部）；不调模型、不建表。
- **验收**：在金标准题库 v1 材料上「谁在等谁」≥ 32/40；单测钉住实验里调过的三条口径（填表不算在等回答、没接通不算回应、AI 客服接管期间的话算机器发的）；共享目录 grep 不到旅游词 / 客户名。
- **当场试跑**：本机对 CTS 今天名单只读跑一次，贴各类人数。

### WP-3 按功能选模型 + 判断函数（A：改平台 AI 通道 + 客人对话发给新型号）
- **做**：§8 功能档案；`judgeContact()`（材料 → 模型 → 校验 → 护栏 → 判断卡对象）；提示词 v1 = 实验③版本，规则措辞放进旅游剧本。核实 Haiku 5.5 官方型号名与价格，写进 PR。
- **验收**：不传档案的现有调用方行为不变（现有测试全过）；题库上达到实验水平（三项全对 ≥ 19/40、排序相关 ≥ 0.65、编造 0、格式错 0）；护栏单测（7 天 2 封、没号码、别再联系不送模型、最急必须有硬事实）。
- **当场试跑**：对题库 45 人真调一次模型（预计 < 0.1 美元），贴打分表。

### WP-4 判断卡表 + 触发 + 影子期（A：新表迁移 → Ray 亲手合；新定时函数也按 A）
- **做**：`crm_contact_judgments` 表；`crm.contact.touched` 事件（在写触点处统一发）；晨扫定时；先占位 / 唯一键 / 预算账本；卡片详情**并排显示** AI 判断（灰字「AI 建议：…」），**名单顺序不变**；功能开关默认关，只给 CTS 开。
- **验收**：一条新入站消息 → 5 分钟内出卡；晨扫回执写人数、花费、失败数；预算超了按 §5.4；开关开 / 关下名单人数相同（测试钉住）。

### WP-5「判断不对」按钮 + 纠错表 + 结果回填（A：新表）
- **做**：§10.2 按钮和原因；`crm_judgment_feedback` 表；7 天结果回填（每日定时，只读算）。
- **验收**：点一次 → 表里一行、指向当时那张卡；回填按「当天是否被联系」分层；同事两步内完成。
- **当场试跑**：在 CTS 一张卡上点一次「判断不对」再撤回；回填定时手动跑一次，贴处理人数。

**影子期（WP-4 上线后 14 天）**：每天看三个数——AI 与规则排序的分歧人数、AI 拉回 / 挪走各多少人、`needs_human` 比例（目标 < 5%）。第 7 天和第 14 天各给 PM 一页抽查（10 张随机卡 + 分歧最大的 10 张）。PM 两次都回「对」、且同事纠错率 < 20%，才进 WP-6。

### WP-6 切换排序（A：改变销售每天看到的名单 → PM 说「开」）
- **做**：§6.2 顺序生效；§6.1 拉回 / 挪走生效；旧规则排序保留为一键回退。
- **验收**：开关一开，名单按判断卡排；回退开关一关，回到旧排序；名单人数前后一致。
- **当场试跑**：开前 / 开后 / 回退后各截一张给 PM。

### WP-7 每周离线考试 + 候选版本闸 + 例题取样（A：新定时 + 会改变线上提示词的流程）
- **做**：§10.4 / §10.5 全部；题库存客户私有存储；周报一页。

- **当场试跑**：手动触发一次考试（当前版本 vs 改了一条规则的候选），贴分数对比和花费。

## 15. 风险

| 风险 | 怎么防 |
|---|---|
| 模型自信地排错，销售照着做 | 影子期两周 + 两次抽查；「最急」必须有硬事实撑；纠错一键 |
| 系统外的沟通（同事在没同步的邮箱回过）看不到 → 误判「客人在等我们」 | 卡片写明「依据：ME 里没有回复记录」；纠错原因里有「其实在系统外回过了」，累计多了说明同步有缺口 |
| 题库只有 45 人，且算法对着它调过 → 分数虚高 | 每月补新题；考试同时报「新题」上的分数；例题池排除题库客人 |
| 价格和估算不符 | WP-3 核官网价；每天 1 美元硬上限 |
| 客人对话发给新型号 | 与简报同一外发边界（Anthropic 已在现有备用链路里）；DeepSeek 默认关 |
| 学习闭环变成「自己改自己」 | 新版本上线必须过考试 + PM 回「换」；护栏只能人改代码 |
