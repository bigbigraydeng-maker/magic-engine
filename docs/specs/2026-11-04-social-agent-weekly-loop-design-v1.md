## 0. 一句话

**社媒 Agent = 每周一次、按客户跑：备稿 → 对事实（程序）→ 审片（马良）→ 排期 → 出卡给 PM 批 → 发 → 读回 → 记错题。**
PM 每周批一张卡。第一阶段只做 CTS 的 Facebook；行业与阶段规则（四层方子）一并写成代码（PM 11-04 明确要求，魏征建议延后，按 PM 范围保留、排在第一阶段最后）。

## 2. 每周流水线

触发：新的每周定时函数 `cloud-social-weekly-draft`（改 cron 登记表，机器判 A），在客户出稿日发 `social/week_pack.draft_due`（并发键 client_id）。

| 步 | 做什么 | 关键规则 |
|---|---|---|
| ① 备稿 | 取审过、仍是草稿的 Reel；**按 `brief.variant_of.base_work_order_id`、`reopened_from` 和「片里字幕 + 产品键」归组，每组只留最新**；判不出是否同组的，报出来，不悄悄两条都放 | 不能只靠 `superseded` 状态（库里 78 条是库外写入）；30 条上限被截断要报 |
| ② 对事实 | 拆「最终三串字」：片里字幕 `output.caption`、正文 `buildReelPostCaption`、首评 `buildReelFirstComment`；比对客户事实来源 | 见 §2.1 |
| ③ 审片 | **扩展马良** `maliang_check` 到 v2：按镜头切点抽帧、声音转文字、可辨认人脸标记；**没有马良记录 = 未审，不进卡** | 花模型钱：失败不重跑，单客户每周花费上限 |
| ④ 排期 | 按名额排日子，同一「产品键」不连发；写 `brief.weekly_pack.publish_on` | 见 §2.3 写入闸 |
| ⑤ 出卡 | 复用 week-pack（v0.4）；指纹加入「事实核对结论 + 目录版本号」，目录改了卡自动作废 | — |
| ⑥ 发 | 第一阶段：PM 批卡后，仍按现有单条转公开发；**发前事实复核放进 `promote/context.ts` 的 `checkDraftContent`**，与红线扫描并排，对不上就拦 | A 级 |
| ⑦ 读回 | 现有读回链；判定逻辑第二阶段 | — |
| ⑧ 记错题 | PM 打回、②③刷掉的进考卷（§2.4） | 不自动改手册 |

**硬规则（写进代码与测试）**
- 任何程序都不许写人工审片清单 `checklist_human`；机器核过 ≠ 授权。
- 「没东西可发」不是成功：符合条件为 0、全被刷掉、开关关着、马良没审，四种都下发今日待办人工任务（what / how / href），复用 `pm-todo/manual-items.ts`、`week-pack-items.ts`。（实现偏差，2026-11-04 定：「开关关着」刻意**不**下发今日待办——开关默认关、只有 PM 自己会去改，每天出一条等于噪音；其余三种照上面下发。）
- 演练模式：只算不写库（不写 `publish_on`、不写核对结果），输出一张预览卡给 PM。

### 2.1 对事实（G2）
- **复用**：比对器 `messenger-agent/verifier/content-claims-gate.ts` 的 `evaluateClaims`；事实接口 `crm/email-templates/facts/types.ts` 的 `FactProvider`（提到共享层，邮件 / 私信 / 社媒共用）；取数 `tour-catalog/store-publish.ts` 的 `loadPublishedTourFacts`。
- **补识别**：英文天数（「14 Days」）、星级（「5-star」「4–5 star」）、游轮名、团名；已知 `NZ$7,3XX` 会被认成 7，要修。
- **认不出 = 不过**：凡提到团或卖点却对不上目录里唯一一个在售团的，判「不通过，待人核」，不许判过。团名有歧义（如两个 Natural China）→ 待人核。
- **旧团名**：要有正式的改名记录作依据（存客户事实来源），不在代码里写死字符串。
- **价格**：先比该出发日自己的价格，再比团「起价」；已取消 / 已关闭的出发日当错误。
- **星级、游轮**：目录没有独立字段，按「包含项」原文比对；目录没写的说法 → 待人核。
- 结果写工单 `output.fact_check`（目录版本、核对时间、逐项结果）。

### 2.3 排期写入闸（G1）
`publish_on` 在周卡指纹里（`manifest.ts`、`load.ts`），改一次日期，未点的卡作废。写入只在：这一周没有待批或已确认的卡；工单未公开、无转公开授权记录；审过且仍是草稿；带 `updated_at` 条件写（读到的版本没变才写）。另外**变体复制（`variant-order.ts`）和打回重开（`review-apply.ts`）都要剥掉 `weekly_pack`**，否则新版本继承旧日期。

### 2.4 考卷与准确率
- **练习题**：11-04 手工核对的 23 条（实际约 9 种情况）。只存「工单号 + 期望结论」，放客户私有文档 `docs/clients/cts/`；共享测试只用合成数据。
- **正式考试**：现在等审的 15 条 + 以后新出的，由 PM 在看不到机器结论的情况下先给答案。写代码的不接触正式考题。
- **算分**：该拦的拦住了没有（要求一条不漏）+ 好内容被错拦几条。
- 马良现有判法先拿练习题打底分（已知两条和人工结论不一致：f868fb79、f4bdd5f6）。

### 2.4a 马良补审接线（G3 实现，2026-11-04 补）
11-04 试跑：23 条候选里 16 条没有马良记录——它们是马良上线前出的片，出片那一刻的自检（只在 `in_review` 时跑）永远不会再补。所以每周编排里补一步：
- **补谁**：先空跑一遍循环，只挑「唯一原因是马良没审」的条目（`excluded_reason = unreviewed` 且事实核对 `pass`）。事实没过的不花钱审。
- **怎么审**：复用 `runReviewCheckV2`（v2 九宫格 + 镜头表 + 声音 + 人脸）、`remotionNineGridInput`、`remotionPublicVideoUrl(output.video_path)`、`runCheckWithTimeout`（180 秒）；每条一个 Inngest 步骤，不重试。
- **花钱上限**：单客户每周 `weekly_loop.maliang_weekly_cap_usd`（缺省 0.5 美元，上限 5），每次最多 6 条；已花的钱从近 7 天本任务回执 `summary.maliang_backfill.spent_usd` 累加——读不到就当没额度（不审）。每次调模型前**先把本次累计金额记到本次运行那行日志上**并当场重查额度（中途断掉或两次运行撞上也不会漏记、超花），记不上就不调；每次调用按 0.05 美元记，没配模型钥匙不开审。马良「没看成」（超时 / 下载失败 / 解析失败）的结论不写库，下周继续当未审重补。
- **什么时候花**：只有写库模式自动补审；演练模式只报「要补几条、估计多少钱」，除非手动事件明确带 `maliang_review: true`（当场试跑用）。
- **写回**：写库模式下，把 v2 结论盖到最新 `output.maliang_check`（`toWorkOrderSnapshotV2`），带 `updated_at` 条件写；没写上的不算审过。演练模式只在内存里叠加，用来算这张卡会排几条。
- **回执**：`maliang_backfill` 段写清：开没开 / 为什么没开、挑中几条、逐条结论、写上几条、跳过原因（没片 / 额度 / 单次上限）、花前花后金额。
