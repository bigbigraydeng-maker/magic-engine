## 0. 一句话

**社媒 Agent = 每周一次、按客户跑的一条流水线：备稿 → 对事实 → 独立审片 → 排期 → PM 批一张卡 → 发 → 读回 → 记错题。**
PM 只做一件事：每周批一张卡。今天 11-04 我手工做的挑片、对团目录、看画面、排日期，就是这条流水线前四步要自动做的事；那 23 条的结论是它的第一份考卷。

## 2. 每周流水线（每个客户一条，Inngest 编排）

触发：客户的出稿日（CTS 周四，新西兰时间），事件 `social/week_pack.draft_due`（并发键 client_id）。

| 步 | 谁 | 做什么 | 输出 | 不做什么 |
|---|---|---|---|---|
| ① 备稿 | 苏东坡（程序） | 取「审过、仍是草稿、没被取代」的 Reel；同一条片子多个版本只留最新；数够不够本周名额 | 候选清单 + 缺口数 | 不足时**不编**，下发人工任务「本周还差 N 条，去工厂下单」（三件套 what/how/href） |
| ② 对事实 | 程序（不用大模型） | 把**最终会发出去的三串字**——片里字幕（`output.caption`）、正文（`buildReelPostCaption`）、首评（`buildReelFirstComment`）——拆出天数、价格、星级、团名、游轮名、景点、出发日，逐项对客户的「事实来源」 | 每条：通过 / 不通过（列出哪一项、目录里是什么） | 对不上一律刷掉，不改写 |
| ③ 审片 | 审片员（独立 AI，马良角色） | 每个镜头抽帧（按镜头切换点，不是固定 9 帧）；声音转文字；标出可辨认人脸；看 logo / 字幕 / 地点 | 审片记录：通过 / 有疑问（附截图时间点） | **不代替 PM 批准**，不填 `checklist_human` |
| ④ 排期 | 苏东坡（程序） | 按名额和节奏给通过的片子排日子，同一个团不连发；写 `brief.weekly_pack.publish_on` | 本周排期 | 不碰已公开的 |
| ⑤ 出卡 | 现有 week-pack | 今日待办出一张卡（v0.4 已做好） | PM 批 / 不批 | — |
| ⑥ 发 | 现有转公开 | 到日子发；**发前最后一刻再跑一次②**（目录可能这周改了） | 平台回执 | 回执不全不算发出 |
| ⑦ 读回 | 现有读回链 | 发后 4h / 72h 读，判好 / 不好 / 还说不清 | 判定表 | — |
| ⑧ 记错题 | 程序 | PM 打回的、②③刷掉的，连原因进「考卷」；先存客户私有层 | 考卷新增 | 不自动改手册 |

### 2.0 「这周发什么」从哪来：四层方子（v1 补，PM 11-04 追问后加）

第①步备稿之前，先算「本周方子」，照 IMPACT v1.5 §3.3.1（PM 11-02 已定）四层叠：

```
平台规则（写死）→ 行业模板（默认）→ 阶段调整（按这个客户、这个平台自己的数现算）→ 客户配置（人填过的永远优先）
= 本周每个平台：发几条、什么形式、内容比例、哪些话题要人回
```

- **行业**：首批旅游、物流两份模板（冷启动 v0.2，只在文档里，**没写成代码**）。其它行业没有模板时，只用平台规则 + 客户配置，不套旅游的数。
- **阶段**：起步 / 成长 / 成熟 / 暂停四档，判据已定（v1.5 §3.3.1），**按客户、按平台各算各的，阶段函数没写**。
- **平台差异**（每个平台一套硬规则 + 自己的阶段）：

| | Facebook | Instagram | TikTok |
|---|---|---|---|
| 手册 | FB 运营思路 v0.2（3479） | IG 手册 v0.1 | **没有运营手册**，只有接入 / 审核 / 发布测试记录 |
| 怎么发 | 工厂草稿 → 转公开；Story 周包 | 原生发布设计 10-20；能否直接发**未核实** | 工厂有 TikTok 发布适配器（讲课片在用）；社媒线**没接** |
| 形式重点 | Reel + Story（晚上邀私信）；链接放首评 | Reel 为主，图文轮播；链接只能放主页 | 只有短视频；开头 1–2 秒决定去留；不能放链接 |
| 读回 | 互动 + 私信（缺观看数权限） | 待接 | 待接 |
| CTS 现在 | 已连、在用 | 走 Meta 连接，未核实发布权限 | 授权有效（另有 1 条已撤销），没发过社媒内容 |

**v1 只跑 Facebook**（与 v1.5「阶段层现在只算 Facebook」一致）。IG、TikTok 先补手册和读回，再逐个接；同一条片子跨平台发，要按平台改开头、文字和链接位置，不原样转发。

### 2.1 事实来源按行业换（平台层级门）
- 共享：②的拆字和比对规则、③审片员、④排期、整条编排。
- 行业：「事实来源适配器」。旅游 = `tour_catalog_published` 最新一版；其它行业以后接各自的产品目录。
- 客户：名额、节奏、禁用词（倒计时、余位）、人脸规则，放客户配置，不写进共享代码。

### 2.2 考卷与准确率
- 第一份考卷：11-04 手工核对的 23 条（14 刷 / 8 过 / 1 待定，见 start-plan §3.1）。②③上线前必须把这 23 条判对。
- 之后每周：PM 批 / 打回的结果自动进考卷；审片员的「有疑问」和 PM 结论对不上，计一次错。准确率写在卡上。

## 4. 明确不做
- 不做绕过 PM 的自动发布；不开 `FACTORY_PUBLISH_LIVE`。
- 不做图文、RSS 热点、视频模板库、发布名额按周写法。
- 不同时上多个客户：CTS 跑满两周再接 East。
- 大模型不判数字：②全程程序比对。

## 5. 复审与交付
- 设计复审：子牙（架构）+ 魏征（挑刺），通过后开工。
- 写代码：DeepSeek（aider），我出逐轮指令、审 diff、跑测试。
- 交付前当场试跑：用 CTS 真数据跑一遍①–⑤，不打开开关、不发布，把出来的卡给 PM 看；考卷 23 条要全对。

## 6. Reuse Statement
- 复用：视频工厂、week-pack（v0.4）、单条转公开、读回链（3492/3512/3517）、`outbound-claims`、`reel-media-checks`、`face-frame`、团目录。
- 新增（平台共享）：排期函数、事实比对 + 适配器接口、审片员、每周编排。
- 行业：旅游事实适配器（团目录）。
- 客户：CTS 名额、节奏、禁用词，留在客户配置。
- 层级门：社媒既有支柱上的环节，不新增能力线。
