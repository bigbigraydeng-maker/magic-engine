# 广告素材补链（ad_creative_links）· 设计 v0.4（增量稿）· 只设计，未写代码 · 119 号 · 2026-10-21

> 在 v0.2 + v0.3 之上的增量：**冲突处以本稿为准**。吸收子牙+魏征第三轮。风险级 A。

## 1. 签字记录不可伪造：撤直接写权限，只开受保护函数
v0.3 只拦了 UPDATE/DELETE/TRUNCATE，没拦 INSERT，且 service_role（Oztop 插件存着总钥匙）能直接插入伪造签字。照 2998 的做法：
- 对 `creative_binding_attestations` 与 `ad_creative_links` **撤销 service_role 的 INSERT/UPDATE/DELETE/TRUNCATE**；
- 只开一个受保护函数 `creative_binding_attest_v1(...)`（`SECURITY DEFINER`，`REVOKE ALL ON FUNCTION … FROM PUBLIC`，只授给唯一服务身份，`SET search_path` 钉死）；
- **`signed_by` 由管理员会话派生**（路由从会话取邮箱传入，函数内再校验在管理员名单），客户端传值一概忽略；
- 常驻权限断言（迁移后 CI + 每日审计）：表上无 service_role 写权限、函数 EXECUTE 只有指定身份、search_path 已钉。

## 2. 关联行 ↔ 签字记录 ↔ 同一个视频
- 关联行新增 **`source_video_id`**（原始库视频 id）；触发器要求 `source_video_id = attestation.video_id`；一条签字只能被「源视频相同」的关联行引用，V1 的广告不能引用 V2 的签字。
- **`work_order_id` 加唯一约束**（一个工单只能签给一个视频）；换绑走 §3 的重签路径，不是 409 死路。
- 函数内校验 **素材池条目、工单、签字三者 `client_id` 一致**，不一致拒绝。

## 3. 机器证据补强 + 重签路径
- 证据不止时长：页面给 PM 看的预览**带 `final_mp4_sha256`**，提交签字时把这个哈希回传，**服务端比对「此刻工单文件哈希」与页面哈希，不一致拒签**（防止工单重渲后签在没人看过的文件上）。
- **`meta_video_length_s` 与 `final_mp4_sha256` 都由服务端在签字请求内读取**，不接受页面传值（页面哈希只用于比对）。
- 如实写限度：Meta 会重编码，**哈希/时长证明不了「Meta 上的视频就是这个文件」**，只能证明「PM 看过的文件=此刻工单文件」且时长在容差内；对应关系的根仍是 PM 签字（记为 `pm_attested`，证据强度低于 post_id）。
- **重签路径**：工单文件哈希变化（重渲）→ 既有签字自动标 `stale`（§4）→ 允许同一视频在新哈希上**新增一条签字**（旧签字保留不改），关联行指向新签字；不再有「只能签一次、换绑 409、只能走迁移」的死路。

## 4. stale 标记单向，且不能只看列
- 触发器：`stale_at` **只能从空变为有值**；清除只能走经 PM 授权的迁移。
- **台账核验/启用时实时读 Meta 比对创意编号**，不只看 `stale_at` 列（换创意到被发现之间有空档）。
- `ads.swap_creative` 执行成功的同一路径**立刻**把旧关联行标 stale（同一事务内，失败则不算换成功）。

## 5. 未核实
- 工单文件哈希在服务端读取的成本（文件大小/存储位置）；重签后旧关联行的展示口径（沿用 v0.3 的「已失效」徽标）。
