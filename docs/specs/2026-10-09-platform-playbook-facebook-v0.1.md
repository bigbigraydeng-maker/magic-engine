# 平台剧本 · Facebook v0.1（社媒运营按平台拆解的第一份）

> 日期：2026-10-09 · 性质：**设计 + 事实盘点，不含业务代码** · 风险级：C（只加文档）
> 起因：PM 2026-10-09「社媒运营要拆开来看：Facebook 怎么发 post / story / reels、什么时候发；TikTok、Instagram 各是另一套逻辑。我们要像有经验的专业运营。」
> 关系：上一份 [调研文档](./2026-10-09-social-agent-skill-gap-and-oss-survey.md) 讲「学谁」；本文讲「运营这件事本身怎么拆，并先写 Facebook」。IG / TikTok 沿用同一个格式另写。

## 0. 结论

1. 专业社媒运营 = **一条平台无关的每周工作流（6 步）+ 每个平台一份「平台剧本」**。工作流是骨架，剧本是每个平台的参数与规矩，代码读剧本，Agent 按工作流跑。
2. Facebook 现状：**post、Reel、首评、评论回复、回看**都有；**Story 没有、发布时间没有依据、成绩没回灌**。
3. 本文的每一条平台事实都标了**来源档位**；第三方文章里的「最佳时间」互相矛盾，**只当冷启动候选，不当结论**，运行两周后用客户自己账号的数据替换。

## 1. 工作流骨架（6 步，所有平台相同）

| 步骤 | 做什么 | 谁来干（Agent / 代码） | Facebook 现状 |
|---|---|---|---|
| ① 定调 | 客户声线、受众、红线，读 `master_briefs` + 官网 | 诸葛亮 / 李白 | 有（靠临时读，缺固化的「品牌套件」） |
| ② 排日历 | 本月主题、各格式配比、每条的发布时间 | **排期师（缺）** | 每日计划有；**无按平台的配比与时间依据** |
| ③ 制作 | 写文案、出片、配图，过护栏与自检 | 视频工厂 + 李白 + 马良 | Reel 有；post 有；**Story 无** |
| ④ 发布 | 选格式、选时间、人点头后执行 | 苏东坡 → Publer / Graph API（人授权） | post、Reel 有；Story 无 |
| ⑤ 互动 | 首评放链接、回评论、回私信、转线索 | 苏东坡 | 有；提问只接住不转线索 |
| ⑥ 复盘 | 4h / 72h 回看、对比、写回记忆、改下周日历 | 苏东坡 + 诸葛亮 | 回看有；**不落库、不回灌** |

## 2. 平台剧本的结构（给代码读的 5 栏）

每个平台一份，字段固定，以后加平台只加一份，不改流程：

| 栏 | 含义 | 值的来源 |
|---|---|---|
| `formats` | 该平台有哪些格式，各自规格与限制 | 官方文档为准 |
| `cadence` | 一周发几条、各格式配比、候选发布时间窗 | 冷启动用候选，之后被客户自己的数据覆盖 |
| `hook_and_length` | 开头钩子、时长、字幕与安全区 | 我们的手册 + 配方库 |
| `engagement` | 链接放哪、回评规则、私信规则、转线索规则 | 我们的手册 + 护栏代码 |
| `metrics` | 能读到哪些数字、各代表什么、哪些读不到 | 官方文档 + 本客户的权限实况 |

剧本里**不放客户名和客户业务数字**；行业差异进行业剧本、客户差异进客户配置。

## 3. Facebook 剧本事实表

> 来源档位：**官方**（Meta 开发者文档，2026-10-09 取）｜**ME 实战**（我们手册里的拍板或事故）｜**第三方·候选**（博客 / 工具商文章，未验证）｜**待验证**。

### 3.1 formats（格式）

| 事实 | 档位 | 备注 |
|---|---|---|
| Page Story 支持图片与视频；视频 9:16、推荐 1080×1920（最小 540×960）、Story 上限 60 秒；媒体**不能复用已发过的内容** | **官方**（[Page Stories API](https://developers.facebook.com/docs/page-stories-api)） | 发 Story 需 `pages_manage_posts`、`pages_read_engagement`、`pages_show_list` 三个权限 |
| Story 里能不能放链接 / 贴纸 | **待验证** | 官方文档没写；不能假设 |
| Reel 推荐 9:16、1080×1920、H.264 + AAC、24–60 帧 | 第三方·候选 | 与我们工厂现有输出一致，无冲突 |
| 「2025 年 6 月起 Facebook 所有视频都按 Reel 处理，不再区分长短」 | 第三方·候选 | **待用官方来源核实**；与我们「一律发 Reel」的决定同向，但不能当依据 |
| 普通 post（图文 / 链接）仍可发 | ME 实战 | 现有 `publishToFacebook` |

### 3.2 cadence（节奏与时间）

| 事实 | 档位 | 备注 |
|---|---|---|
| 澳洲：工作日早 7–9、午 12–2、晚 7–10，周二到周四最强 | 第三方·候选 | 来源是工具商博客，口径不明 |
| 另一篇同样写澳洲：工作日 16–21 点，早上周中有小峰 | 第三方·候选 | **与上一条不一致** |
| 新西兰：晚 22–24 点 | 第三方·候选 | 来源是时间工具站，**与澳洲结论差距大，可信度低** |
| 一周发几条、各格式配比 | **待验证** | 受客户真实素材供给约束（手册 §5：客户不会每天投喂素材）。冷启动不拍数字 |

**处理规则**：以上时间窗只当「冷启动要试的几个格子」。三篇互相矛盾，本身就说明「别人的最佳时间」不可靠。真正的依据只能是**这个客户自己主页的粉丝活跃时间**（需要洞察权限，见 3.5）和**自己历史帖的成绩**。

### 3.3 hook_and_length（钩子、时长、字幕）

| 事实 | 档位 | 来源 |
|---|---|---|
| 第一帧不用纯风景空镜；文字钩子（问题 / 数字 / 反差）、UGC 感、快切更好 | ME 实战 | 手册第一条（配方库统计） |
| 关键文字落在 y=270~1248、水平居中不贴右；第三方说「底部 300px、右 120px 被盖」 | ME 实战 + 第三方·候选 | **保持我们更保守的安全区**，不改 |
| 字幕短句大字（一行 ≤6 词），长句进 caption | ME 实战 | 手册第三条 |
| 所有成片带客户 logo 水印 | ME 实战 | 手册第四条 |
| 「15–30 秒留存最好」 | 第三方·候选 | 不采用，由配方库与客户数据定 |

### 3.4 engagement（互动）

| 事实 | 档位 | 来源 |
|---|---|---|
| Reel 正文里的链接点不了，带链接的正文还会被压触达；**CTA 链接放首评，带追踪参数** | ME 实战（拍板 + 踩坑） | 手册第八条；`first-comment.ts` |
| 评论：LLM 只写夸赞；提问走安全模板转人工；夸赞过护栏且置信度 ≥ 0.85 才用；先私信后公开 | ME 实战 | 评论自动回复 spec；`comment-guardrails.ts` |
| 评论自动回复每小时跑一次 | ME 实战 | `render.yaml`：`0 * * * *` |
| 发帖后最初一小段时间的评论回复最值钱 | 第三方·候选 | 来自开源技能库 `engagement-routine`，未验证；现有节奏是每小时，是否需要加密待数据 |

### 3.5 metrics（衡量）

| 事实 | 档位 | 来源 |
|---|---|---|
| 2025-11-15 起 Page Insights 的 `impressions`、`page fans` 被废弃，`impressions` 由 `views` 取代；再调用会报「无效指标」 | **官方**（[Meta 开发者博客](https://developers.facebook.com/blog/post/2025/08/15/page-insights-api-updates/)） | **我们读成绩的代码只取点赞 / 评论 / 分享，没取 `impressions`**（查了 `getFacebookPostMetrics`，其它文件未全量扫），暂不受影响 |
| 2026-06-15 另有一批指标变动 | 第三方·候选 | 官方博客该页没写，**待核实后再设计**；动 Insights 前必须先查官方变更日志 |
| 基础权限只能拿点赞 / 评论 / 分享；播放、触达、观看时长需要洞察权限 | ME 实战 | 手册第十条 |
| 判断一条视频好不好：开头留存、进度曲线有无跳水点、完播比例 | ME 实战 | 手册第十条；**前提是拿到洞察权限** |

## 4. 要补的缺口（按剧本栏位归类）

1. **Story 能力**：官方已提供发布接口，我们现在完全没有。需要先确认 Story 对 Facebook 获客是否有价值，再决定做不做，**不预设要做**。
2. **排期师**：负责「每周配比 + 每条发布时间」。设计提案：冷启动在候选时间窗里**轮换着发**，每个时间格子攒到足够条数（暂定每格 ≥3 条，参照「数字带样本量」）后，用本客户自己的 4h / 72h 成绩排序，**覆盖掉候选**。样本不够就明说「数据不够」，不装有结论。
3. **洞察权限**：不拿到，就看不到播放与触达，时间和钩子都只能靠猜。这是前置条件，不是优化项。
4. **成绩落库并回灌**：同上一份调研的第 ② 项（Gate B/4 为 A 级，需要 PM 单独授权，本文不碰）。
5. **提问转线索**：同上一份调研的第 ① 项。

## 5. 平台层级判定（Inline）

- **层级**：L1 社媒支柱里新增一个「平台剧本」维度；它是**数据（剧本表）+ 共用流程**，不是新支柱、不是 Connector。IG、TikTok 沿用同一格式。
- **换客户**：旅游、地产、物流的 post / Reel 配比与评论高频问题不同，所以**配比与时间不进共享代码**，只能由剧本默认值 + 客户配置覆盖。
- **换行业**：同上；本文不含任何客户事实。
- **Reuse Statement**：复用 `facebook-publisher`、`reel-publishing`、`first-comment`、评论引擎、`social-post-evaluator`；新增的是一份剧本格式与 Facebook 一份实例，全部 platform-shared，外部事实一律标档位，未经验证的不入手册正文。

## 6. 验证与下一步

- 本剧本是 **v0.1 候选**。要升正文：第三方·候选的条目须经官方核实或在一个真实客户上跑出证据（CTS 为 Customer Zero），并经子牙签字。
- 下一步建议（待 PM 点头）：先做**拿洞察权限的核查**（现有客户的主页令牌有没有 `read_insights`）——这一步决定时间与钩子能不能被数据驱动，不涉及改代码，只读核查。
- 其后再定：IG 剧本、TikTok 剧本，用同一格式。
