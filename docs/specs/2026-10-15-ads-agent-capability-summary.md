- 日期：2026-10-15 ｜ 窗口：74（CTS 广告总控）｜ 风险级别：C（纯文档）
- 口径：**只写当天在代码与生产库里核实过的事实**，不写设计稿里的意图。每一行都标了依据。
- 为什么有这份：PM 问「广告 agent 现在拥有的 capability 和 playbook 都齐全吗」。答案是不齐，而且不齐的方式跟直觉不一样——**不是功能少，是没人调用、也没有数据喂进去**。

## 一、一句话结论

**能刹车，不能换方向；而且到今天为止，一次都没真跑过。**

- 八个动作里五个有真实实现，全是「停」和「减」，加预算算半个（手册已把它收窄成必须 PM 本人批）。
- 三个不能自动做：换素材（已写完但封存）、挪预算（设计明文走人工）、新建再营销广告组（判 P2 未做）。
- **生产库 `action_runs` 全表只有 2 条记录**（2026-08-21，都是 `page.*`）——广告动作**零执行**。

## 四、行业手册（playbook）有壳没肉

`src/lib/ads-strategy/playbooks/` 有 5 本：`default` / `travel` / `logistics` / `real_estate` / `retail`。
**每本只有 3 个字段**，全是叫法用词（旅游把结果叫「咨询」、地产叫「房源」）。真正的打法参数——什么时候该停、频次多高算疲劳、预算一次能动多少——是所有行业**共用一套写死在代码里**的。

对照 PM 2026-10-10 定的「所有支柱 agent 一律平台-行业-客户三层」：广告有这一层，但几乎是空的。按 §11 打分（频率低 / IMPACT 中 / 收入中）判 **P2**，记入待认领，不是现在要做的事。

---

## 五、所以真正的卡点不是「功能缺」

三件按顺序：

1. **没有调用方。** 诊断按设计只发现不出动作，没有任何地方发起 run。这是「八个动作都没跑过」的根因。
2. **没有数据喂。** 全库素材池 `approved` 0 条（CTS 3 条全待批），所以换素材这条即使上线也不会触发。
3. **权限已收窄。** 加预算、挪预算、改受众、关整个系列都要 PM 本人批（手册 RL-01/02/04/17），所以「自动增长」这条路本来就不许自己走。

**下一刀该做哪一件由统筹与 PM 定**；本窗口当天的判断是：先把「诊断出结论 → 变成一条待 PM 批的建议」这条路接通（手册 §11 A1 的第②项），比再补任何一个动作都值钱——否则动作越全，没人调用的动作就越多。
