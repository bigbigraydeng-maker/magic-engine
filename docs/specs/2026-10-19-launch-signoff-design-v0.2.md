# 「重大功能上线签字」最小版设计稿 v0.2（只设计，不写代码）

日期 2026-10-19 · 作者 118 号 · 依据：PM 10-19 规矩（统筹 18 号转述）；`docs/specs/2026-10-19-ads-agent-test-checklist.md`（T1–T7）。读过的现有零件：内核授权审计表 `authorization_decisions`（append-only 由触发器强制，`20260808000003`）、推广计划核实记录（`verified_by / verified_at / content_hash`，见 `api/clients/[id]/marketing-plan/[planId]/promo/verify`）、台账 `docs/ledger`、`RENDER_GIT_COMMIT`（`pm-todo/deploy-health-items.ts` 已在运行时使用）、开关 `ad_strategy_configs.autopilot_dry_run`。
**v0.2 = 吸收子牙（架构）与魏征（挑刺）两路审查后的版本。A 级（碰授权/签字）：还要 PM 点头才开发。**

## 给 PM 的结论
1. 新增后台页「上线签字」：列出测试清单每项的 **目标 / 通过判据 / 状态 / 真实证据 / 18 号复核**；**全部通过**才出现「签字上线」按钮，点了记 **谁、何时、对应哪个代码提交**；有一项没过按钮灰着并写差哪项。
2. **要新增 1 张追加式小表，没有现成零件能代替**：台账是仓库文件，后台点击写不进去；内核审批绑“动作运行”，签字不是执行动作；推广计划的核实挂在计划 JSON 上，没有“功能”这个对象。
3. **这一版只签字，不翻开关**，页面会明说。这是个已知缺口，不是疏漏（第 6 节）。
4. 审查改的最大几处：①回执不能由执行方自说自话——服务端要回读生产库核对；②复核必须针对具体那条回执、且不能是同一个人；③T3 失败会锁住整份清单，不能被后写的“通过”覆盖；④签字人必须是白名单里的真人会话，服务钥匙一律不行。

## 1 入口
左栏 `ADMIN_SECTIONS` 第 1 组加「上线签字」→ `/dashboard/launch-signoff`；仅管理员，沿用现有 admin 判断。

## 2 页面
页头（常驻）：功能名 · 风险级 A · **线上提交号** · 清单版本指纹 · 红字横幅“已触发停止条件”（若有）· **实时的 `autopilot_dry_run` 状态 + “此开关目前不受签字约束”** · 一句话“**通过只证明链路走通，不等于可以关演练开关或自主加预算**”。
7 行 T1–T7：目标 · 判据 · 状态 · 证据（库表+记录 id+时间，点开只读详情）· 复核人/结论/时间 · 该项被测的提交号。
**状态五种**：没测 / 待复核 / 通过 / 失败 / 已锁定；通过用中性蓝灰色，不用绿色，避免“看见绿就放松”。
读取失败（表缺失、接口报错）**一律显示“读取失败”并禁用签字**，绝不显示成“没测”。

## 3 状态规则（防自说自话）
- 一项算「通过」= 最新的 `item_result` 存在 **且** 有一条针对**这条 item_result 的 id** 的 `review=通过`。复核引用具体回执；之后再追加新回执，旧复核作废，回到“待复核”。
- **服务端写 `item_result` 时自己回读生产库核对证据**：例 T1 查 `ad_health_narratives` 当天有行；T3–T5 查 `action_runs / action_run_steps / flywheel_actions` 属于**同一条 run id**；读不到就拒写。无法机器核对的项只能标“人工确认”，页面显示出来。
- `actor` 与 `actor_role` 取自服务端鉴权（会话或各自的服务钥匙），**不接受调用方传入**；`review` 的作者必须不同于该 `item_result` 的作者（服务端强制）。
- **停止条件**：T3 失败/误动其他广告/预算异常/回执缺失 → 写一条 `halt` 事件，整份清单“已锁定”，同一执行方不能用新回执覆盖；只有一条带原因的新评审事件能解锁（清单规则“失败不重试”由此落到页面）。
- 依赖：T4、T5、T6 必须引用 T3 的同一 run id。

## 4 签字
- 「签字上线」可点条件：7 项全「通过」+ 无 `halt` + 清单指纹未变 + **提交号检查通过**（下条）。服务端**重新读库全部核对**；页面请求带“事件水位（最大事件 id）+ 清单指纹”，对不上就拒签并提示“页面已过期，请刷新”（防点击瞬间状态已变）。
- **提交号**：每条 `item_result` 记录自己被测时的线上提交号（取 `RENDER_GIT_COMMIT`）；T3–T5 提交号必须相同；签字时要求“被测提交号→当前线上提交号”之间，清单列出的代码目录（如 `src/lib/ads-strategy`、`src/lib/kernel`、广告执行链）**没有改动**，无关合并不让按钮失效；提交号取不到一律 fail-closed（按钮灰并写“无法确认线上版本”）。上线实测 `RENDER_GIT_COMMIT` 前不得开发。
- **谁能签**：只接受**真人登录会话**，邮箱在配置白名单里（建议只有 PM 本人）；服务钥匙一律拒绝；签字人不得等于任何 `item_result / review` 的作者；撤销（`revoke`）单独一档且必填原因。
- 点后弹确认框（写明“不会翻任何开关”）。写入的是服务端重读的快照：7 项的 `item_result` id 与 `review` id、清单指纹、提交号、签字人、时间。签字同时发一条 Inngest 事件 `launch_signoff.signed` 做第二留存，并在**今日待办**自动出一条“已签字，等你决定是否关演练开关”。

## 5 数据与清单
一张追加式表 `launch_signoff_events`：`id, feature_key, event_type（item_result | review | halt | unlock | signature | revoke）, item_key, status, evidence_ref, evidence_snapshot(jsonb), ref_event_id, actor, actor_role, commit_sha, checklist_hash, note, created_at`。
- 加固：`event_type` 与各类型必填字段用 CHECK；触发器禁 UPDATE/DELETE/**TRUNCATE**；`REVOKE UPDATE, DELETE, TRUNCATE` 于所有角色；RLS 用仓库铁律模板 `FOR ALL TO service_role USING (true)`（**必写 `TO service_role`**），迁移里自带“匿名读必须 0 行”自检；定时对账“事件数只增不减”。迁移属 A 级，另案、等 PM 点头。
- 清单内容：仓库里一份结构化定义 `src/lib/launch-signoff/checklists/ads-agent.ts`（key、标题、目标、判据、做法、负责人、关注的代码目录），**不从 markdown 解析**；指纹覆盖**所有**结构化字段（含判据文字），改判据=新指纹=旧签字作废，且判据变更本身须 A 级评审；另加一条测试核对该定义与 markdown 清单的 key 一致。
- 谁写：119 测完用命令写 `item_result`；18 号复核写 `review`（走服务端接口，页面只读）。没人写=「没测」。

## 6 最小范围与以后推广（及已知缺口）
- 最小：1 表、1 页、1 份清单定义、4 个接口（读 / 写事件 / 签字 / 撤销），只服务这一个功能。
- **已知缺口（风险表也写了）**：这一版没有闸。任何有权限的人仍可直接关 `autopilot_dry_run`（目前仓库的 API 路由里没有它的写入口，实际走别的路径，实现前需查清）。所以页面按钮文案是“签字上线”，旁边必须常驻“不受签字约束”提示；开关每次被翻时，**记一条“有无有效签字”的事件**（只记不拦），作为过渡。
- 推广要改：①清单登记（`feature_key → 定义`）②`requireSignoff(featureKey)`：读事件表，判“最新 signature 未被 revoke、清单指纹一致、代码目录无改动”，加到翻开关的服务端接口（A 级碰钱，**到那时“回滚=去掉入口”不再成立**，会直接影响开关接口，须单独评估）③待办提醒复用 manual-items ④A 级 PR 模板写 feature_key。

## 7 风险与回滚（v0.2）
| 风险 | 对策 |
|---|---|
| 把“签字”当成“已有保护” | 页头常驻“开关不受签字约束”+ 实时开关状态；开关被翻时记“有无签字”事件 |
| 执行方伪造回执 / 自己复核自己 | 服务端回读生产库；复核引用具体回执；作者≠复核人；角色取自鉴权 |
| 点击瞬间状态已变 | 事件水位+指纹，对不上拒签 |
| 签字后又部署 | 签字绑提交号并看代码目录差异；页面常驻“签字后代码已变”失效提示 |
| 失败被覆盖 | `halt` 锁定，需带原因解锁 |
| 表被删/配错/匿名可读 | CHECK + 触发器含 TRUNCATE + REVOKE + RLS 自检 + 对账 + 读取失败 fail-closed + Inngest 第二留存 |
| 管理员都能签 | 白名单真人会话；服务钥匙拒绝 |
| 回滚 | 本版：去掉左栏入口与接口，表留着无害；推广到闸以后：见第 6 节 |
| 没验证的 | 线上 `RENDER_GIT_COMMIT` 取值（开发前实测）；`autopilot_dry_run` 现在的真实写入路径 |
