# 「没有已批准的推广计划，不许开投/激活/加预算」硬规则 · 设计要点 v0.1 · 只设计，未写代码 · 119 号 · 2026-10-21

> 起因：PM 2026-10-21 指出流程反了——应先批计划再开投，现在页面只能显示红字「还没批准但广告在花钱」。风险级 A（碰钱、碰闸）。送子牙+魏征审后再写代码。

## 1. 规则一句话
**客户当期没有「已批准且覆盖今天」的推广计划，ME 里任何会开始花钱或花更多钱的动作一律被闸拦下**（fail-closed：读不到计划状态也拦）。

「已批准且覆盖今天」= `marketing_plans` 里该客户存在一行 `status='approved'`、`plan_data.promo` 存在、`start_date ≤ 今天(NZ) ≤ end_date`（计划起止；阶段日期另用于预算，不在本闸）。判断只在一个纯函数 `hasApprovedPromoPlan(rows, todayNz)` 里定义，所有闸复用，不许各写一遍（加架构测试：全仓只有一处读 `marketing_plans.status` 来放行花钱）。

## 2. 接在哪里（复用现有接入点，不另起一套）
| 入口 | 现有位置 | 本规则 |
|---|---|---|
| 草稿批准 → 激活 | `draft-and-gate.ts approveDraft` | 加一项前置检查（与 2999 的日预算闸**同一个检查函数里的另一项**，不是第二个闸） |
| 重新启用系列 | `meta-ads/execute` `ads.reactivate_campaign` | 同上 |
| 内核加预算/新开广告组 | `ads.scale_unit_budget`、`budget_move_plan`、`add_retargeting_adset` | 在内核的 `isWithinEnvelope` 前置条件里加「无已批准计划→不在信封内」（观察模式下本来就不自动动钱，不改变现状） |
| 内核暂停的撤回（回写 ACTIVE） | rollback handler | **不拦**（撤回是失败路径）；超限/无计划只报警出待办（同 2999） |
| 登记入口 warn 模式 | 2999 的「注册时警告」 | 同一个检查函数的 warn 输出 |
所有入口共用 2999 的「入口清单 + 架构测试」：新增任何能写 Meta ACTIVE/预算的底层方法必须登记，登记时声明是否过「计划闸」。
**不加 PM 越权开关**（默认不允许"明知没计划仍启用"）；真有特例由 PM 先批计划。

## 3. 手工建的广告（在 Meta 后台/MCP 里建，ME 拦不住创建）
ME 拦不住 Meta 后台里的操作，所以分三层，诚实写明限度：
1. **事前**：ME 内部所有入口被拦（§2）；内部员工的做法是先在 ME 批计划，再建广告。
2. **事中发现**：每日扫描（快照里 `effective_status=ACTIVE` 的广告组）发现「客户当期没有已批准计划但有在投广告组」→ 红色待办（what: 哪个账户哪些广告组在花钱；影响: 没有计划授权的花费；how: 去批计划或停广告；href: 计划页与暂停入口）。**不自动暂停**（暂停属收类动作，见内核「human_stop」信封；是否自动停需 PM 另定），先出待办。
3. **手工建广告后回报 ad_id**：新增一个"回报入口"（计划页或广告健康页的一个表单/接口：ad_id、所属计划、素材）。回报后写入 `ad_creative_links`（`link_source='registration_entry'`，走 2990 的登记函数，强绑定需签字则按 2990 规则），并把该广告挂到计划上；**没回报的在投广告**在每日扫描里归入第 2 条的待办。回报入口只做登记，不放行任何花费动作。

## 4. 计划被退回草稿/到期之后
- 退回草稿或 `end_date` 过了：新增启用/加预算立刻被拦；**已在投的广告不会被自动停**，每日扫描出红色待办（同 §3.2）。
- 计划批准动作本身不变（`requirePlanApproverAccess`、批准清单）。

## 5. 失败方式（fail-closed）
读 `marketing_plans` 失败/超时/多行状态冲突 → 一律拦，错误信息说人话（"读不到计划状态，已拦下，请稍后重试或去计划页看"）。拦下的动作写一条回执（谁、哪个入口、为什么拦），不是静默。

## 6. 范围与待 PM 一句话
- 复用：`marketing_plans`、`approveDraft`、2999 的启用闸与入口清单、2990 的登记函数；**不新增内核层、不新增表**（回报入口写既有 `ad_creative_links`）。
- 平台共享：整套规则；客户差异只有"该客户是否强制要求计划"——建议默认对所有由 ME 开投的客户强制，没有计划的客户先出"需要先做计划"待办。**这点需要 74/PM 确认**：对没有推广计划记录的老客户，是否同样拦（建议拦，符合 PM 总原则：计划先行）。
- 不做：自动暂停在投广告、PM 越权开关、改计划批准流程。
